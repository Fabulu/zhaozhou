# Zhaozhou Audio Rules — Phase 2 (wave 2)

**Status:** ratified 2026-08-14 (plan W2.1, decision D4). Single law for
AUDIO.FIFO (the FPGA side) and the tone subset of SW.MIXER (the ZRef/HPS
side). Q formats cite spec/qformats.md by section. Where this file and any
other text disagree, this file wins for audio.

---

## 1. Stream contract

- 48,000 Hz sample rate, signed 16-bit stereo (one L/R PAIR per tick),
  little-endian pair order L then R on every wire and in the PCM ring.
- **Exactly 800 pairs per frame** (48000 / 60 = 800): one displayed frame
  consumes exactly 800 pairs. The audio clock is asynchronous to the video
  raster; the 800-pair law is an ACCOUNTING law (counters, tests, captures),
  not a phase lock. Long-run slip between audio and video domains is
  absorbed by the HPS ring (§3), never by dropping or duplicating a pair
  outside an underrun event.

## 2. The FIFO law (D4) — AUDIO.FIFO

| Parameter | Value |
|---|---|
| Depth | 2048 stereo pairs (8 KiB, 4 × M10K) |
| Refill burst | 256 pairs |
| Low watermark | 512 pairs |
| Underrun action | repeat the last L/R pair, increment `audio_underruns` |
| Overflow | structurally impossible (ready/valid backpressure upstream) |

- **Underrun** = the output side needs a pair and occupancy is 0. The
  previously emitted pair is repeated (bit-exact, deterministic,
  bit-testable) and `audio_underruns` counts once PER underrun EVENT (a run
  of N starved ticks with at least one repeat each still counts 1 if the
  event is continuous; a refill followed by another starvation is a new
  event). The output stream is CONTINUOUS: no gaps, no silence insertion,
  no fade in Phase 2 (fade is a mixer-side policy, not a FIFO behaviour).
- **Refill:** when occupancy ≤ low watermark, the refill client requests a
  256-pair burst from the PCM ring (spec/memory_rules.md §4) through the
  gpu→audio domain crossing (gray-coded occupancy; credit-based ring reads;
  CDC documented per SYS.CDC).
- **Formal:** `audio_fifo_bounds` — occupancy ∈ [0, 2048] invariantly; no
  accept when full (backpressure law); the underrun law (repeat + counter,
  never a torn pair: a pair crosses as a unit).

## 3. PCM ring (HPS side)

- The mixer (SW.MIXER on the HPS, ZRef in simulation) writes pairs into the
  ring; AUDIO.FIFO reads. Ring descriptors and the memory map are defined
  in spec/memory_rules.md §4 (ring entry `PCM_RING`).
- In Verilator the harness C++ IS the HPS (plan D10): it hosts the PCM ring
  and answers ring reads deterministically.
- Accounting per frame: `pairs_in − pairs_out` bounded by ring size;
  expected audio stream for a capture is generated by `zref::MixerTone` and
  compared BIT-EXACT (a differential byte compare over the whole stream,
  not statistics).

## 4. Test tone (SW.MIXER tone subset, `zref::MixerTone`)

The Phase-2 tone is the mixer's deterministic test source and the W2.7 demo
audio:

- Phase accumulator: u32, increment per 48 kHz tick =
  `round_half_up(freq × 2^32 / 48000)` (integer, exact per tone table
  below); the top 16 bits are the `angle16` phase in TURNS (qformats.md §2).
- Sample: `s16 = fx_sin(angle16) >> 1` — the qformats.md §7.1 quarter-wave
  table (257 entries, Q1.16, error ≤ 1.3·2^-16) evaluated by `fx_sin`,
  scaled by half to leave mixer headroom, truncated (arithmetic shift)
  toward −∞, saturating to ±0x7FFF/0x8000 boundaries.
- Both channels carry the identical sample (no pan) in the Phase-2 subset.
- Frozen tone table (the only legal Phase-2 tones):

| Tone | freq (Hz) | increment (decimal) |
|---|---|---|
| TONE_A4 | 440 | 39,370,533 |
| TONE_A5 | 880 | 78,741,067 |
| TONE_C4 | 262 | 23,443,363 |

Increments are `floor(freq × 2^32 / 48000)` (checked: 440 → 39370533.546…;
880 → 78741067.093…; 262 → 23443363.157…). Rounding law: floor, stated once
here, identical in ZRef/TS/RTL.

## 5. Counters

- `audio_underruns` — catalog index per spec/counters.md; latched into the
  frame-synchronous shadow set at `frame_tick`.
- Per-frame pair accounting is a TEST/ledger quantity (800), not a counter.

## 6. Interface notes (frozen in zhao_pkg.sv)

- AUDIO.FIFO output: `{valid, l, r}` s16 pair, one per audio tick, leaf into
  the framework audio path (hardware lane adapter; Verilator sinks it into
  the harness stream file).
- The gpu↔audio domain crossing is the documented mixer→audio-clock bridge
  (`async_bridge: true`); occupancy crosses gray-coded, data crosses as
  whole pairs under a credit handshake.

## 7. Test obligations (directed at W2.4)

- Directed: steady fill (occupancy plateau); deliberate underrun ⇒ repeat +
  counter + continuous stream (byte compare across the event); full
  backpressure (ring stalls ⇒ no accept when full).
- Random: jittered refill timelines, 1k fast / 100k nightly, output stream
  bit-exact vs `zref::AudioFifo` (depth/watermark/underrun oracle incl.
  800-pair accounting).
- Formal: `audio_fifo_bounds` (occupancy bounds, no-accept-when-full,
  underrun law).
- Tone: `zref::MixerTone` full-frame streams (all three tones) are golden;
  RTL never generates the tone (mixer-side only) but the differential test
  consumes the same goldens.
