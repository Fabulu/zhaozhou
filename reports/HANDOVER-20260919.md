## 5. THE TRAPS — every one of these cost someone hours today

**Environment**

* **Bash is broken in this tree** (profile parse error mangles the command).
  PowerShell only.
* PowerShell 5.1 mangles multiline `git commit -m`. Always `git commit -F file`.
* In a PowerShell double-quoted string the **backtick is the escape character** —
  writing a comment containing a backtick-r sequence injected carriage returns
  into three source files.
* `Get-Content | -join` round-trips mangle UTF-8. Use
  `[IO.File]::ReadAllText`/`WriteAllText`.
* `git show HEAD:f > out` prepends a **UTF-8 BOM**; `git diff > out` from a
  `powershell -File` subprocess writes **UTF-16**. Use `git diff --output=`, and
  join patch lines with explicit LF (`WriteAllLines` emits CRLF and breaks
  `git apply`).

**SystemVerilog / toolchain**

* A comment line whose first token after `//` is the word **"verilator"** is
  parsed as a PRAGMA and fails the entire lint with `%Error-BADVLTPRAGMA`.
* **`verilate()` does not pass `-Wall`**, so `-Wall` errors in RTL go unseen by
  every test target. Lint explicitly. UNUSEDSIGNAL found three real correctness
  holes today, including a response port carried and never read that would have
  published a corrupt page.
* Quartus 17.0 rejects: inline `for (genvar ...)`; module-scope `if` elaboration
  guards (use `initial begin ... end`); implicit generate (needs explicit
  `generate`/`endgenerate`); unary minus on a size cast `-W'(x)` (needs
  `-(W'(x))`).
* A Verilated test main that `return`s instead of calling **`zhao::exit_hard`**
  hangs under ctest for the full timeout at ~0 CPU with an empty output file —
  `tests/harness/zhao_sim.hpp` documents the libwinpthread deadlock. **~0 CPU
  after minutes means BLOCKED, not slow.**

**Git, with several packets running — read this twice**

* **The index is SHARED.** `git commit` with no pathspec commits the WHOLE index,
  including other packets' staged work. Check `git diff --cached --name-only`
  before every commit.
* **`git commit --only` is WRONG for shared files** — it takes WORKING-TREE
  contents, sweeping in others' uncommitted edits. Correct only for files you
  exclusively own. It also cannot name untracked files.
* **The working recipe** is a private index:
  `$env:GIT_INDEX_FILE` + `git read-tree HEAD`, `git apply --cached` only your
  hunks, commit, then `git reset -q HEAD -- <paths>` (a private-index commit
  advances HEAD without touching the shared index, so your paths then read as
  staged REVERTS to everyone else).
* **`read-tree` and `commit` MUST BE ATOMIC.** Run them in separate tool calls
  and any packet committing in between makes your index describe the past — your
  commit then silently reverts everything they landed. This happened twice today,
  once for 529 deletions. Every local signal looks fine; **the only tell is the
  commit summary reporting more files than you staged.**
* If a shared file gains another packet's hunk between your read and your add,
  stage by **excluding their hunks** rather than naming yours.
* **Lint and smoke the EXACT BLOB you will commit**, via `git archive HEAD` or an
  isolated `git worktree` — not the working tree. Two packets produced broken
  staged blobs the working tree never showed.
* `git checkout -- <file>` **discards** another agent's uncommitted work and
  unstaged changes have no reflog.
* **The scratchpad is shared between agents.** Prefix every temp file.
* **A private index protects another agent's INDEX and does NOTHING for their
  WORKING TREE.** A packet rewrote `design/prod_manifest.yml` between another's
  edit and its `git add`; eight lines were lost and the wrong packet's line went
  into the wrong commit. The fix that works: build the blob from HEAD **plus your
  own lines**, install it with `git update-index --cacheinfo`, and assert the
  staged path count.
* **`open(p,'wb').write(build(open(p,'rb').read()))` TRUNCATES ON EXCEPTION.**
  Python creates the write handle BEFORE evaluating the argument, so when
  `build()` raised on a mismatched anchor it left `design/prod_manifest.yml` at
  **zero bytes**, destroying another packet's uncommitted row — which has no
  reflog. Read fully, transform, then open for writing. This is CLAUDE.md's
  zero-byte-backup lesson in new clothes and it cost real work today.
* **A generated file is ZERO BYTES while its writer runs.** `design/prod_manifest.yml`
  was observed empty for ~2 minutes while a packet rewrote it. It recovered, but
  the writer truncates before writing, so a crash in that window leaves an empty
  manifest — and every gate that reads it then passes or fails about nothing.
  This is CLAUDE.md's zero-byte-backup lesson in new clothes. If a gate suddenly
  reports something absurd, check the file has bytes before believing it.
