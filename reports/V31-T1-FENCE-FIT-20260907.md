## The prediction held

Recorded beforehand: *"the ten worst paths — all ending at `adm_accept_o` /
`adm_ready_o` / `adm_owner_o` via `wp_q → occ_o → rq_occ_c == 0 → quiet_c` —
should now be gone."*

**They are gone.** Not one of the worst 25 paths ends at an admission output.
The signature is unmistakable: reported and core→core were 75.79 against 89.09
before — a 13 MHz gap that *was* those port-terminated paths — and they now
**coincide at 77.16**. The registered logical credit did what §5.3 said it would.

Memory was predicted not to move — *"both changes are logic"* — and it did not,
to the bit.

## And it cost 12 MHz of internal headroom, which is mine

The honest internal ceiling fell **89.09 → 77.16**. The new worst path is

    fence_open_q~0_OTERM1571DUPLICATE -> fence_open_q~0_OTERM1571
    slack -2.960, data 12.804 ns

— the fence added in the same change. Behind it sit eight `credit_ok_q → Mux*~20`
paths at −2.35 to −1.63. **Both new families are mine.** Reported Fmax improved
1.8%; the block's real limit got worse, and stating only the first number would
be the more flattering half of a true sentence.

## Where the time actually goes

The per-hop walk, which is the only thing that answers *where*:

```
fence_open_q(reg) -> Add1~1 -> Mux9~24 -> Mux9~1 -> Mux9~4 -> Mux9~20
                  -> Equal1~0 -> fence_open_q~0
```

Those four `Mux9` levels total **9.136 ns of the 12.804 ns path — 71%**. They are
the 64-way select in

```systemverilog
assign wrap_block_n_c = (gen_n_c[tail_next_c] == {GENW{1'b1}});
```

Indexing `gen_n_c` — the **next-state** array — dragged the entire generation
next-state cone inside the fence's own permission loop.

## The rewrite, and why it is exact rather than approximate

Two facts settle it:

1. `gen_n_c[i]` defaults to `gen_q[i]` and is overwritten at **exactly one**
   index, `i == tail_q`, and only when `adm_fire_c`.
2. `tail_next_c` is `tail_q + adm_fire_c`.

So when the overwrite happens the read index has moved off it, and when it does
not happen the arrays agree everywhere: **`gen_n_c[tail_next_c] ≡
gen_q[tail_next_c]` in every case.** Both candidates are therefore precomputed
from registers in parallel, leaving only a 2:1 mux downstream of `adm_fire_c` —
§6.8's *"share predecoded high/low comparison terms"*.

**The timing benefit is unmeasured.** Three predictions made from reading source
today were falsified by the fitter; this one is a structural argument and a
refit decides it.

**The behaviour is not unmeasured.** 477 checks pass, unchanged. And because an
equivalence proof is only as good as the reader, the rewrite was **mutated to
check the tests still guard it**: swapping the ternary's branches — the exact
error this rewrite could have made — produces

    FAIL: FENCE: admission never fired at a wrap boundary on a non-quiescent
          island -- no early reopen              expected 0, got 2
    FAIL: every wrapping admission happened on a QUIESCENT island

caught by the checks added to case 19 earlier the same day. A correctness-
sensitive rewrite of a fence deserves that, and the mutant was built from a copy
outside the repository so the working tree was never left holding broken RTL.

## The third family is the strongest result here

Ranked ninth and below: **`gen_q[40][4] → ev_err_issue_o[*]`, `→ iss_q[*][3]`.**

That is the per-slot generation table on the critical path, independent of
anything I changed today — and it is exactly what T2's window replacement
deletes. §6.8 predicted the mechanism in the abstract:

> events no longer need a **64-way generation select** and live-bit select in
> addition to their other scoreboard reads … The fit must decide the net ALM and
> timing benefit.

**The fit has now decided part of it.** A 64-way select over `gen_*` is measured
at 71% of the worst path and appears again as its own family further down. T2 is
therefore no longer only a register-count argument (`gen_q` is 64×8 = 512
flip-flops); it has a measured timing case.

§6.8's caution still stands and is not being waved away: *"The net register
reduction is smaller than 576"*, and the replacement adds tickets, a count, fence
state and validation registers. What changed is that the **timing** side is
evidence now rather than expectation.
