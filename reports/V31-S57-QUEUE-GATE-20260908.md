## What this settles

§5.7 asks for a fit gate on the local ready queue against "the intended product
constraint" of 100 MHz. The production-shaped queue — `zhao_texture_v3bank` plus
`zhao_texture_v3rq`, driven behind a registered hash sink so the fitter cannot
delete the DUT — clears it by **35%**.

**So the ready queue is not the island's timing problem.** That is worth having
as a number rather than an impression: the island's measured limiters this
session have been the RCP selection cone (−3.243, fixed by P0-B), the RCP
completion scan into perspuv (−2.690, diagnosed in
`P0B2-THE-NEXT-LIMITER`), the palette port family (−4.977 → −2.875), and a port
path into the RCP context store (−1.900). The queue has appeared in none of
them, and now it has a standalone number saying why.

## What the probe itself guards against

Recorded because the instrument nearly shipped broken twice:

* the **registered hash sink** exists so the fitter cannot delete the DUT and
  report a clean number for an empty design;
* `texture_v3rq_probe_sanity` proves the hash is not degenerate — it moves on
  essentially every cycle across thousands of distinct values, checked before
  the gate was trusted;
* and that sanity test caught a SECOND defect on its first run: the probe drove
  `wr_en_i` into a full queue, which the DUT forbids by assertion. Quartus drops
  assertions, so the gate would have characterised a production-shaped queue
  driven with illegal stimulus and reported a perfectly clean number for it.

A 135.37 MHz pass is only worth reporting because those three things were done
first.
