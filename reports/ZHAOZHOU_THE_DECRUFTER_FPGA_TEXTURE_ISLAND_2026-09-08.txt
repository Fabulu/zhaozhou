PURPOSE
Produce a smaller, correct FPGA texture island that closes the required timing
and workload budgets. Do not optimize for the number of architectural reports,
passing anecdotes, renamed modules, or attractive isolated Fmax figures.

This is an implementation brief, not a claim that these changes have already
been implemented or fitted. Repository reads and source-derived executable
models support it. No repository RTL simulations, formal RTL proofs, Quartus
runs, or board tests were executed by the author of this document. All measured
hardware figures below are identified repository receipts. References [Sxx]
identify immutable source files; [Pxx] prior briefs; [Vxx] vendor documentation;
[Mxx] the supplied independent models. The implementation agent must replace
source-level hypotheses with its own executable RTL and physical evidence.

=============================================================================
0. THE DECISION — DELETE MACHINERY, NOT CAPABILITY
=============================================================================

Keep the V3 identity/lifetime contract. Keep the texture feature contract. Stop
retaining two hardware implementations merely to compare them forever.

The approved direction of this brief is:

  1. Repair a still-present stall defect in the metadata join.
  2. Remove migration shadows from the production elaboration, leaving them
     available in verification rather than as permanent production logic.
  3. Replace the live, early fragment-attribute selection with a synchronous,
     typed descriptor read. Eliminate dead fields instead of packing them into
     the replacement and preserving their cost accidentally.
  4. Carry palette identity through the request stages, so the late owner-indexed
     palette sidecars no longer need to exist.
  5. Integrate the existing RCP V3 as a measured candidate, with honest profile
     and throughput accounting. Do not start a new reciprocal architecture.
  6. Build a genuinely lean PERSPUV candidate: a paired arithmetic stream plus
     reserved terminal storage, not two independent schedulers that always do
     the same thing and then rejoin their answers.
  7. Only then, and only where current attribution supports it, localize owner
     control updates and attack the next remaining large resource contributor.

These are separately reviewable packets, not permission for one enormous diff.
Correctness repairs come first. The area-reduction work and the RCP timing work
can be developed against isolated source snapshots; neither should wait on an
unrelated documentation audit. Preserve the active agent's already-landed work.

The finish line has NOT moved to 13,000 ALMs or 84 MHz. Timing remains 100 MHz
with every required timing check understood and closed, followed by integration
margin and representative workload proof. The historical island redlines remain
visible: 7,500 ALMs, 9,000 registers, 14 DSPs, and the applicable memory budget.
They are not silently replaced by a conversational opinion that 13k is fine.
Any allocation revision needs count-once whole-console accounting and an explicit
owner decision. A passing fitter executable is not a passing product. [S01, P01]

This document does not promise 7,000 removable ALMs. It supplies concrete
structures to delete and tests that distinguish deletion from wishful thinking.

The central design rule:

  A transaction gets one identity, one correctly timed copy of each needed
  attribute, and storage sized for the actual readers and outstanding work.
  A verification model does not become a second permanent datapath.

1.2 What must be corrected before acting on this brief

A. “All five reads moved” is not “all five old read networks were synthesized
   away.” The old sample table remains referenced by the hardware shadow and
   per-queue diagnostic comparisons. Those uses keep storage and selection
   logic alive. Removing the production consumers alone cannot remove them.
   This is a definite source finding, not an ALM estimate. [S02]

B. The +2,778 ALM regression has NOT been attributed quantitatively to scaffolding.
   Scaffolding is present, but presence does not establish its share of the
   measured regression. Measure the same design with and without migration
   hardware before naming its price.

C. The eleven early attribute arrays declare 138 x 64 = 8,832 bits. That is not
   8,832 fitted registers, and certainly not 8,832 ALMs. Some fields already have
   no functional consumer and should be pruned by synthesis. Putting every field
   into a new wide bank can actually preserve data that the old implementation
   discarded. Audit readers first. [S02]

D. A 119-bit-wide descriptor is not one M10K just because 64 x 119 is less than
   10,240. A direct same-width simple-dual-port realization needs at least three
   parallel width slices at a maximum 40 bits per slice. A 138-bit realization
   needs four. Memory capacity, width, port mode, and read latency all matter.
   The metadata bank's 256 x 40 shape is compatible with one block; that still
   needs confirmation in the actual fit. [V01, V02, M07]

E. RCP V3 at TOKW=14 used its default NCTX=16. The island currently instantiates
   svc at NCTX=8, TOKW=14. Old standalone svc rows are not automatically a
   matched token/context/constraint comparison. The candidate is promising;
   “+25.21 MHz in the island at no area cost” is not established. [S04, S05]

F. A function reused in several expressions is shared source, not necessarily
   one physical decoder. Likewise, a single source module instantiated twice is
   two hardware instances. Check the netlist, not the prose saying “ONE BLOCK.”

G. Mosaic's historical leaf ALMs are not the price of the current counter-only
   instance. Its unused tile datapath can already be pruned in the composition.
   Removing it cannot be credited with its full standalone leaf price. [S02]

H. Packet C's current “complete” claim is too strong. The data/token register
   holds under backpressure; its directly connected metadata register does not.
   Section 3 gives a legal two-response counterexample. A dispatcher-only stall
   test cannot cover this upstream join. [S02, S03, M01]

I. A successful refactor is not licensed to remove correctness state. Required,
   issued, claimed, committed, reserved, and actually accepted are not synonyms.
   Removing one merely because another often has the same value reopens the
   exact lifetime defects this project already encountered. [S06, P01]

2. WHAT THE ISLAND SHOULD LOOK LIKE AFTER DECRUFTING
=============================================================================

Preserve these distinct access domains:

  Fragment admission
      -> V3 owner admission, atomically with frontend acceptance
      -> UV numerator storage (already a synchronous bank)
      -> early descriptor storage
      -> late material storage
      -> owner retirement-context storage

  RCP V3 -> existing numerator join -> paired PERSPUV candidate
      -> synchronous early descriptor join -> fragment expander
      -> planner with carried request metadata -> cache
      -> stall-safe synchronous sample-metadata join
      -> raw FIFO carrying ONE response record
      -> class queues carrying that SAME response record
      -> palette / nearest / bilinear / error handling
      -> V3 completion and result banks -> Combine V2 -> ordered output

The early descriptor bank, late material bank, and owner context bank are not
three unnecessary copies of an interchangeable record. They have different
consumers and different read times. Combining them into a single memory with
three unrelated read addresses would destroy the desired port geometry.
Consolidate within an access domain; share across domains only after a real
port/arbitration design is justified.

Verification lives beside this graph, not inside every production edge. One
verification scoreboard can remember the expected metadata for a token without
requiring a second production copy of sampmeta_m.

Do not build a new general transaction fabric to accomplish this. Existing
owner handles, existing class queues, existing memory wrappers where suitable,
and bounded local registers are sufficient.

3. D0 — FIX THE METADATA HOLD HOLE BEFORE DECLARING PACKET C CLOSED
=============================================================================

3.1 The exact source mechanism

At the audited HEAD, the island contains:

  r1_room_c = !r1_v_q || disp_rsp_ready;

  if (r1_room_c) {
      r1_v_q <- cache_smp_valid;
      r1_d_q <- cache_smp_data;
      r1_t_q <- cache_smp_src;
  }

The dispatcher consumes r1_d_q and r1_t_q, but consumes its metadata directly
from the bank's output through mj_meta_packed_c. The bank executes these reads
on every active edge, independently of rd_valid_i:

  rd_q     <- mem_q[rd_addr_c];
  rd_gen_q <- rd_owner_gen_i;

Only the bank's valid pulse is gated by rd_valid_i. Gating a valid pulse does
not hold the payload. The island's r1_v_q, not that pulse, drives the
consumer-visible valid. [S02:1590-1710, S03:130-180]

3.2 A legal failure sequence

Assume A and B have distinct metadata. B is a legal next response and holds its
own address while stalled. No hostile upstream protocol violation is required.

  Edge 0: join empty; dispatcher not ready; A accepted into the empty join.
          r1 holds data A/token A; synchronous RAM output becomes metadata A.

  Edge 1: dispatcher still not ready; cache presents B, which is NOT accepted.
          r1 holds A. The bank nevertheless reads B's address and replaces its
          output with metadata B.

  Edge 2: dispatcher becomes ready. It accepts data A/token A/metadata B.
          B can simultaneously enter the now-vacated join.

There can still be two accepted and two emitted responses. Conservation alone
passes. A generation-only check can also pass when A and B use the same
allocation generation. The failed property is whole-record identity and
stability, not necessarily counts or generation comparison.

The supplied model reproduces this sequence from the source equations. That is
not a claim of independently executing the composed RTL; the agent must turn
this exact sequence into a failing RTL test before applying the repair. [M01]

3.3 Minimal repair: hold the entire response, not only two of its fields

For the present one-cycle RAM interface, the least invasive candidate is:

  read_launch = cache_smp_valid && r1_room_c && legal_read_key;

  On read_launch:
      capture RAM output for that address;
      capture the expected owner generation for that SAME read;
      capture the response data/token on the matching accepted beat.

  While r1_v_q && !disp_rsp_ready:
      hold data, token, metadata, and the associated validation result.

The bank read-output register must therefore be enabled by read_launch rather
than unconditionally overwritten. Keep a separate one-cycle event-valid for
read/error statistics if needed; do not confuse it with the held packet-valid.
A clock-only RAM process with an enabled read is a candidate template. Check it
with Quartus 17 MapOnly before trusting inference. Device support for read and
clock enables is documented, but a supported feature does not prove that this
particular RTL template maps as intended. [V01]

An alternative is a reserved, fixed-latency read followed by a fabric capture
and a small response queue. That alternative must reserve space for EVERY
in-flight read before launch. It costs more state and latency. Use it only if
the enabled-read implementation fails inference or creates a measured bad cone;
do not add another queue pre-emptively.

For either implementation, the unit of transfer is:

  {response data, complete routing token, sample metadata, validation status}.

One accept, one hold condition, one release. Do not repair this by independently
adding another pipeline register to metadata while leaving data/token latency
unchanged.

3.4 Make the 40-bit story honest

The bank stores owner_gen in bits 39:32, but the island repacks its outputs with
8'd0 in those positions. The generation check happens inside the bank; the
queued word is therefore not literally the original full 40-bit descriptor.

Prefer exposing and carrying the packed record intact, using named pack/unpack
functions or a shared packed type, with one documented layout. Check stored
generation against the matching delayed request identity. If the upper bits
are intentionally removed after validation to narrow queues, make that a
separate typed representation with a carried check result. Do not call a zero
placeholder “owner-generation alignment.” [S02, S03]

3.5 Illegal sample indices and reset

Elaboration must assert the actually supported slot/index/generation widths and
record layout. The reviewed shape uses 64 slots, a two-bit sample index and
eight-bit generations; a broad-looking parameter list is not proof that larger
index widths or unrelated profiles are implemented correctly.

Sample index 3 is representable but illegal. The bank refuses it by clearing
read-result valid; the current r1 stage can still present a valid response.
This must not allow a stale RAM output to masquerade as this response's metadata.

Specify the invalid-key path explicitly: preserve the original identity and
route the declared fault/rejection treatment without reading an unwritten row
as a normal sample. Do not clamp index 3 to index 0. Do not invent a legal
completion for some other required sample. A malformed unsolicited packet and
an accepted legal request that still owes a response are different cases;
follow the existing owner rejection and completion policy for each.

Reset invalidates pending packets and cancels the old epoch's accounting. RAM
contents need not be cleared. No post-reset output may claim validity merely
because stale metadata remains at a RAM output.

3.6 Required RTL checks

Create a seam test that includes the RAM join AND the dispatcher. The existing
dispatcher leaf test remains useful, but is not enough. Require:

  - A held for several cycles while B is offered and not accepted; A's entire
    record remains stable, then both emerge with the correct identities.
  - Varied metadata on every accepted response, including palette slot and
    generation, fractions, byte select, nibble, format and owner generation.
  - Bursts across all classes, mixed hits/misses, queue saturation, long output
    stalls, full-to-draining transitions, and back-to-back acceptance.
  - Same-generation A/B to defeat a generation-only false reassurance.
  - Reset with a RAM read pending and with a held response.
  - Illegal index and stale generation faults with observed, declared treatment.
  - Accepted/emitted/cancelled conservation AND per-record comparison.

Add a stability assertion over the whole dispatcher input packet whenever its
valid is high and ready is low. Add a mutation that restores the unconditional
read; the new test must fail it. The model's repaired version passed 32 seeded
schedules of 5,000 cycles each, but that does not replace these RTL obligations.

DELIVERABLE: a small correctness commit, a failing-before/passing-after seam
receipt, and updated Packet-C status. Do not call this an ALM optimization.

4. D1 — REMOVE THE MIGRATION LABORATORY FROM THE PRODUCTION ELABORATION
=============================================================================

4.1 The definite deletion target

At the audited HEAD, sampmeta_m[64][3] still exists, is still written, and is
still read by the bank shadow and the class-queue diagnostic comparators. Its
nominal payload is 4,032 bits. The migrated palette/nearest/bilinear consumers
no longer need this reference copy after D0 is correct. [S02]

The same migration apparatus includes delayed reference fields, comparison
valids, counters for shadow comparisons and per-class alignment, and first-wrong
value/token capture registers. Their fan-in includes the old tables and indexed
selection. Hiding their output ports does not necessarily remove everything if
other diagnostics still read those structures.

Move the reference mechanism to the testbench or an explicitly simulation-only
instrumentation block. Keep the old software/reference behavior available;
do not keep the old production metadata datapath solely to prove the new one
on every hardware clock.

4.2 Make the deletion falsifiable

Use one functional implementation with an elaboration-time migration-evidence
selection, not a forked production island that starts another maintenance tree.
For example, MIGRATION_SHADOWS=1 builds the diagnostic comparator; =0 must not
elaborate its reference table, comparison cones, counters or first-error captures.
The final production configuration selects zero.

If shared output ports remain for the lab harness, the test configuration must
know which are supported. A disabled shadow reporting tied-zero outputs is NOT
a passing shadow test. Either exclude those assertions in the production
profile and assert the selected capability, or use separate thin test/production
wrappers with explicit capability contracts. Never restore the M9 failure mode
of “zero means healthy” when zero actually means absent.

Measure a controlled pair after D0, same functional source, same required
features, same constraints, same seed, differing only in migration evidence.
This gives the cost of the laboratory for THAT specimen. Do not compare one
lab design with a later functional rewrite and call the delta debug overhead.

Require two pieces of evidence:

  FUNCTIONAL: same expected retired stream, errors, ordering and declared
  counters in lab and production profiles under the same traffic.

  STRUCTURAL: no production sampmeta_m reference copy; no meta_shadow / per-queue
  compare / first-mismatch cone in the synthesized netlist. Check the RAM Summary
  and named register/resource attribution, not only a smaller total.

The old palette-binding tables cannot yet be removed in this packet because
metajoin's writer still reads them. Section 6 replaces that real dependency.

4.3 Keep real faults, not unlimited statistics

Three distinct groups must not be confused:

  Migration proof: comparison against an implementation being retired.
  Operational telemetry: counts and peaks useful for profiling and diagnosis.
  Correctness enforcement: capacity, identity, authorization and error treatment.

D1 removes the first group from shipping hardware. It does not remove the third.
The owner must still reject wrong identities and duplicates; illegal requests
must still receive the declared treatment; accepted work must not disappear.

Operational telemetry can be budgeted separately. First classify every exported
counter and trace it to an actual software or test consumer. Keep required ABI
counters and cheap sticky fault summaries. Move expensive per-class census and
first-event captures to the lab profile where no shipping consumer needs them.
Do not narrow or change saturation/wrap semantics of a software-visible counter
without versioning its contract.

A multiplexed debug bus reduces port replication; it does NOT remove the
counter registers and adders behind the bus. Likewise, disabling observation
must not prune a functional engine that the product still requires. Report
both telemetry selection and feature selection with every fit.

4.4 Virtual-pin figures are not a refund voucher

The intermediate receipt contains 1,839 virtual pins, versus 1,491 in first V3.
The number of ALMs containing virtual pins is not the number occupied exclusively
by those pins. Do not subtract it from total ALMs. Keep a like-for-like
characterization wrapper for deltas, and separately report the actual production
wrapper. Neither a loopback hash nor a serial debug interface makes arbitrary
functional logic free. [S01, P02]

DELIVERABLE: production elaboration with no migration copy of sample metadata;
a reader/deletion ledger; lab-vs-production semantic regression; MapOnly
attribution; a controlled physical difference when warranted.

5. D2 — REPLACE THE EARLY FRAGMENT ATTRIBUTE FOREST
=============================================================================

5.1 Read the consumers, not the declarations

The eleven arrays previously identified total 138 bits per owner, but their
roles differ. This is the source audit at the pinned HEAD. “Dead candidate” means
verify by an all-reader search and synthesized cone before assigning savings.

Array       Width  Current early use / decision
fctx_m        64   Expander carries it to AUX world X/Z. All 64 bits matter.
fbase_m       32   Early Mosaic uses two bytes; late full base is in mat_m.
fbind_m        8   Passed into expander; no binding output reaches the planner.
flod_m         8   Expander/planner LOD. Preserve Q4.4, not a 4-bit integer.
fcls_m         2   Captured raw class, sanitized at the read point.
faux_m         1   Whether AUX is required. Preserve.
fpsl_m         2   Early duplicate palette slot; audit its now-unused read alias.
fpgn_m         8   Early duplicate palette generation; same issue.
fsc_m          2   Zero/one/two/three sample count. Preserve exactly.
frec_m         3   Early recipe copy; late recipe is read from mat_m.
fwt_m          8   Early Mosaic weight; late weight is separately in mat_m.

The actual source paths are admission -> fc_wp=owner[13:8], then a later
fc_rp=pu_tag[13:8] read. The nominal early useful bundle, retaining today's
Mosaic inputs, is about 101 bits: context64 + Mosaic bytes16 + LOD8 + class2 +
AUX1 + count2 + Mosaic weight8. This is a reader inventory, not a promise that
all 101 bits are retained physically after optimization. [S02]

Add palette identity10 for direct forward carriage and a reserved binding
selector8 for the intended resolver contract: 119 bits. A build with no binding
consumer might prune those eight bits; record that limitation rather than
claiming binding support. There is no reason to preserve a dead early recipe
or unused base bytes merely because the old file declared them.

5.2 The proposed early descriptor

Use named fields, one canonical layout, and elaboration assertions:

  early_desc = {
      aux_context[63:0],        // current compatibility contract, not free bits
      lod_q4_4[7:0],
      raw_class[1:0],
      needs_aux,
      sample_count[1:0],
      palette_slot[1:0],
      palette_generation[7:0],
      mosaic_material_a[7:0],
      mosaic_material_b[7:0],
      mosaic_weight[7:0],
      binding_selector[7:0]
  };                            // 119 bits for the reviewed profile

The two Mosaic bytes retain the current composition's behavior; this does not
claim that taking material choices from colour bytes is the final material ABI.
The descriptor type should name that compatibility boundary explicitly.

Write the row once on the EXACT owner admission handshake, using that owner's
slot. Do not use a local rolling pointer that can drift from owner admission.
The ready predicates for owner and frontend must agree on the accepted beat.

Read it synchronously when PERSPUV presents that owner's result. The read is
not permitted to become a combinational 64-way select again through a decoder
placed before the first register.

5.3 The post-PERSPUV join

Add one bounded, stall-safe join between PERSPUV and the expander. It captures:

  {owner identity, computed U/V, saturation/zero flags as required,
   synchronous early descriptor}.

Advance all parts together. Accept from PERSPUV only when the join has a
reserved destination for its descriptor result. Hold the complete bundle while
the expander stalls. The RAM output must obey the same hold law established by
D0, or be captured into reserved output storage before it can be overwritten.

Sanitize raw class only from the captured descriptor. Feed the expander and
Mosaic with this descriptor's values, not live ingress values and not another
stage's current owner. Any required Mosaic acceptance must be included in the
fork's handshake; a future functional Mosaic branch cannot drop requests merely
because its ready was ignored in the characterization composition.

A cycle is an explicit latency trade, not an excuse to lose throughput. Demonstrate
one joined result per clock where the consumer can accept it. Measure whole
island throughput separately; local one-per-clock capability is not a claim that
the RCP issues a reciprocal per clock.

5.4 Memory geometry and a deletion gate

Implement one logical bank, with static parallel width slices as necessary.
For 119 bits read in one cycle with one write and one read, three 40-bit-capable
simple-dual-port slices are the geometric lower bound. Do not time-multiplex
three reads over one narrow block without acknowledging the added cycles and
workload cost. Leave unused storage words unwritten; validity/lifetime controls
protect reads. [V01, V02]

MapOnly must show which arrays inferred, whether output registers were absorbed,
and whether an enable or reset shape caused a fallback. It is acceptable for a
small valid/lease structure to stay in fabric. It is not acceptable for a wide
payload bank to remain thousands of flops while the report calls it RAM-backed.

After the new join passes its varied-attribute test, the original early payload
arrays must have no production readers and must be removed. Do not fit old and
new early banks plus a production shadow and expect an area decrease.

Keep these separate existing stores:

  uvw_m: already registered for the RCP-return numerator read. Do not undo it.
  mat_m: 46-bit late material, a different consumer/read time.
  owner context: late ordered output, not interchangeable with the AUX read.

Sharing the context physically across early AUX and late retirement may be a
future port-scheduling experiment. It is not a prerequisite. Paying for a second
well-mapped narrow bank can be cheaper than a multiported fabric memory.

5.5 Frontend lifetime must cover the final descriptor read

A zero-sample, no-AUX owner can become backend-ready at admission. That does NOT
prove its RCP/PERSPUV/expander work has already stopped reading the early bank.
Changing frontend latency or RCP context depth changes the window. The previous
300-zero-fragment test is useful, but not a universal proof. [S06, P01]

Required invariant:

  An owner slot cannot be recycled while any accepted frontend transaction can
  still read its old descriptor, numerators, or request metadata.

First check whether the live source already enforces it. Do not add a second
allocator. Instrument actual last-read/capture events and drive ring wrap with
frontend stalls and fast zero-work backend retirement.

If no existing invariant covers it, a bounded compatibility repair is a frontend
completion lease: set on admission; discharge only when the complete descriptor
has been copied into storage that will no longer consult the owner row; prevent
external owner release while the lease is outstanding. Gate output valid and
ready consistently, maintain one update rule for simultaneous events, and
associate the lease with the current full identity. A per-owner bit is not a
new ownership namespace, but its exact event and bypass rules still need proof.

Do not assert this lease is required because a test was once broken. Prove the
window or reproduce it. Do not delete it merely because one workload does not
reach it. Carry this obligation into the RCP and PERSPUV replacements.

5.6 Required tests

Change every descriptor field between adjacent admitted fragments. Stall RCP
return, PERSPUV output, expander acceptance and AUX independently. Mix zero work,
AUX-only, and three-sample fragments. Force more than 64 owner admissions with
slot reuse and compare full context, not just the low-16 tag. Test a descriptor
read adjacent to a write and state which same-address case is legal. No
constant-colour or constant-palette phase is sufficient evidence of identity.

DELIVERABLE: typed synchronous early descriptor, atomic output join, original
live early tables deleted, a field-level consumer map, and measured inference.

=============================================================================
6. D3 — REMOVE THE OWNER PALETTE SIDECARS BY CARRYING THEIR INFORMATION
=============================================================================

The current metajoin writer reads palslot_m and palgen_m using the planned
sample's owner slot. These tables have a real dependency today. Deleting them
before changing that writer is not decrufting; it is losing the descriptor.
[S02, S07]

The replacement is direct carriage:

  early descriptor's palette identity
      -> expander queue/current-fragment record
      -> sample request sideband
      -> each accepted planner stage
      -> accepted sample's packed metadata write.

At FQD=4, adding a 10-bit palette pair to the four-entry expander queue and its
current record represents 50 declared bits, plus the actual planner pipeline
carriage. The old pair represents 640 declared owner-table bits plus its reads.
This is a useful structural comparison, not an ALM subtraction. There is no new
owner lookup at the response end. [S07, M07]

Use the same capture enables as the request fields already in each stage.
Advance metadata when THAT request advances, not merely when input valid is
high. On stall it holds. On flush it invalidates with the request. On the three
samples from one fragment, palette identity follows the declared material rule;
it must not silently come from whichever fragment is now at the expander input.

Do not squeeze these fields into spare-looking owner token bits. There are no
free bits in the 18-bit class/sample identity contract. Keep the identity type
and the descriptor type separate.

After the accepted-sample writer consumes only the carried pair, remove:

  palslot_m / palgen_m and their admission writes;
  any unused early fpsl_m / fpgn_m copies;
  class_m if an all-reader audit confirms it has no remaining consumer;
  the obsolete read aliases and associated misleading comments.

The typed early descriptor already carries raw class. The planner's actual
resolved format/filter remain the authority for legal decode treatment; don't
weaken the existing mismatch checks in this storage change.

6.1 The binding-selector trap

The current expander accepts and stores a binding field, but does not expose a
binding selector to the planner. The planner instance is fed the top's global
bind_base_i and bind_mode_i. Therefore a declared/stored binding field is not
proof of per-fragment material resolution. [S02, S07]

For compatibility measurements, keep the current documented drain/phase rule
for changing the global binding inputs. Mark it in the workload profile. For a
feature-live configuration, capture either the resolved binding descriptor or

8. D5 — PERSPUV: REMOVE THE SCHEDULER THAT SCHEDULES NOTHING INDEPENDENTLY
=============================================================================

This is the largest new microarchitectural deletion candidate uncovered in this
audit. It is not a suggestion to serialize U and V to save one multiplier.

8.1 What the current implementation actually does

The reviewed PERSPUV service has a context table, a U work queue, a V work queue,
per-axis operand and mantissa arrays, per-axis products/results, and a two-bit
have-result mask that rejoins the axes. It supports two arithmetic lanes. [S08]

But the current control recurrence is much simpler than that machinery suggests:

  - Every accepted nonzero fragment enqueues the SAME context into both queues.
  - Both queue pointer pairs reset identically.
  - Each queue pops whenever it is nonempty.
  - There is no independent per-axis downstream ready that can stop one pop.
  - Both arithmetic pipelines have the same fixed stage structure.

Therefore queue identity and pointer equality are inductive invariants of the
current source: equal at reset, updated identically, equal after every edge.
The two queues are not implementing independent scheduling in this design.
With at most one push per clock and unconditional nonempty pop, each work queue
also has at most one queued item after an edge, subject to the stated source
recurrence. Sixteen-entry work FIFOs are not providing sixteen cycles of useful
scheduling independence. [S08:260-298, 532-660; M03]

Write assertions against the CURRENT RTL to establish this before rewriting:

  wp[0] == wp[1]; rp[0] == rp[1];
  pk_v[0] == pk_v[1];
  pk_v[0] -> pk_i[0] == pk_i[1];
  paired pipeline valids/tags correspond stage by stage.

The supplied finite model checks every twelve-cycle push schedule, 4,096 in all,
and observes the equality and maximum queue depth one. That supports the
recurrence analysis; it is not formal proof of the RTL or a measurement of area.

8.2 Replacement architecture: paired stream plus terminal credits

Build a new PERSPUV candidate beside the frozen service, for example
zhao_raster_perspuv_pairpipe. Keep two multiplier datapaths. Use ONE transaction
valid/tag/control stream that carries both U and V operands:

  Accept and reserve terminal capacity
      -> capture signed U/V numerators and reciprocal parameters
      -> two products in parallel
      -> exact rounding addition
      -> exact arithmetic rescale
      -> saturation/flags
      -> one paired result packet into reserved terminal FIFO
      -> stable ready/valid output.

The pair remains one transaction. It never needs a context-indexed rejoin.
No operand table is revisited by a later independent scheduler. No dynamic
context result lookup is required at retirement; a FIFO already contains the
complete answer in acceptance order.

Zero-denominator requests take the same ordered control pipeline, with a carried
zero flag and zero result/saturation behavior. Gate arithmetic work where
appropriate and count zero products. Do not add a separate fast zero bypass
that creates another terminal writer or lets a later zero overtake an older
nonzero result.

The source's current input order is the order in which RCP results arrive at
PERSPUV; it is not necessarily the island's original fragment order. Preserve
that PERSPUV interface order. V3 owner lifetime remains the external ordering
authority. No second island reorder buffer is authorized here.

8.3 The state that should disappear

Once the paired candidate is validated, its production cone should contain no:

  e_num_u/e_num_v indexed operand payload tables;
  e_mant_u/e_mant_v duplicated indexed mantissa tables;
  wq[0]/wq[1] and duplicated queue pointer/control banks;
  per-context e_have U/V completion join;
  random-access e_q_u/e_q_v result tables plus head-selection network;
  duplicated per-axis identity/control pipelines where one paired copy suffices.

Replace these with the actual arithmetic pipeline registers and one terminal
queue. Do not retain the old context table as a “safety check” inside production.
The reference service and testbench provide that check outside the candidate.

There will still be substantial real hardware: two signed arithmetic datapaths,
rounding and saturation, output buffering, tag carriage and credit control.
This is not a claim that PERSPUV becomes a 100-ALM wire.

8.4 Terminal capacity is reserved at acceptance, not at writeback

For a nonstallable arithmetic pipeline:

  owned = accepted_not_yet_emitted
        = pipeline_records + terminal_fifo_records + held_output_records.

Accept only with an available owned credit. A pipeline result transfers an
existing reservation into the terminal FIFO; it does NOT free that reservation.
Only external result acceptance frees it. Reset cancels the old epoch.

A test that measures FIFO occupancy but ignores pipeline occupancy repeats the
cache's already-documented lost-response bug. Do not reintroduce it in PERSPUV.
The supplied paired-stream model exercises this invariant under sustained input,
long output stalls and reset. [S09, M05]

Careful with capacity compatibility: the old service has sixteen contexts and
an additional registered output holding stage, and releases a context when it
moves to that stage. Its total outstanding storage can therefore differ from a
new “sixteen credits including output” design. Audit the exact accepted-minus-
emitted ceiling. Start the replacement with sufficient total credits to preserve
that burst capacity; seventeen is the source-based candidate for NTOK=16 plus
one output hold. Do not silently shrink it. If a padded physical FIFO is used,
keep logical credits and physical addressing distinct and define wrap explicitly.

8.5 Output-memory geometry and the read-side trap

At TAGW=16, a paired terminal record is:

  U32 + V32 + tag16 + saturation1 + depth_zero1 = 82 bits.

A direct same-cycle simple-dual-port M10K implementation needs three parallel
width slices. It is not one block because a shallow queue has few total bits.
At a genuinely sufficient TAGW=14 the record is 80 bits and can fit two slices,
but the old service exposes TAGW=16 and the island currently pads the owner
handle to sixteen. Narrowing must be a deliberate wrapper contract, not an
unverified truncation. [S08, V02, M07]

Try a conventional synchronous FIFO and a small register/MLAB implementation
only as measured alternatives. Do not add a general bank scheduler to fill a
few spare M10K words. If a synchronous read is prefetched into an output head,
reserve head/read capacity and hold the COMPLETE packet while stalled. The D0
counterexample is also the FIFO-head design checklist.

8.6 Keep exact arithmetic in the first variant

The current rescale uses six-bit shift arithmetic and 64-bit signed intermediate
behavior. A representative expression is:

  sh = six_bit(32 - k);
  rounded = signed64(product + (64-bit 1 << six_bit(sh - 1)));
  result64 = rounded arithmetic_right_shift sh;
  clamp to signed 32-bit, with saturation flag.

Do not replace this with host-language shifts that have a different out-of-range
rule, floating point, an approximate reciprocal, or a different rounding mode.
Reuse the reference law and explicit widths. Signed minimum, maximum, half-way
rounding values and negative inputs are mandatory tests. [S08]

There is a conditional later optimization: for RCP-generated k in 1..24 and a
24-bit unsigned mantissa, the signed numerator product and rounding sum fit in
56 bits. The extreme positive product leaves enough headroom for the largest
rounding constant; negative products also remain in range. The supplied model
compares 56- and 64-bit versions over directed extremes and 100,000 seeded legal
samples without disagreement. [M04]

But the public port is six bits. For k=32, sh=0 and the current rounding shift
wraps to 63. A zero product plus 1<<63 in signed64 produces a negative saturated
result; a 56-bit truncation produces zero. The supplied model explicitly shows
this counterexample. Therefore the FIRST paired variant keeps the current
64-bit arithmetic. Narrow only after documenting and enforcing the legal input
domain at a wrapper, with out-of-domain behavior decided rather than erased.

8.7 Acceptance and fallback

Use the existing tests/raster/raster_perspuv_svc_directed.cpp and
 tests/raster/tb_perspuv_pair.sv as starting references, not as proof that a new
candidate is covered automatically. Compare paired results and flags in accepted
order under stalls, zero/nonzero mixtures, saturation, signed extremes, repeated
tags, reset and full-window reuse. Verify every accepted pair appears exactly
once and never separates its axes.

Measure sustained one-pair-per-clock capacity after fill with output ready,
plus the actual output-stall burst capacity. The two-lane throughput requirement
is not negotiable in a cleanup pass. Integrate into the island only after this
leaf contract is satisfied.

First MapOnly must demonstrate the listed table/queue removals. Then fit with
the same profile and observation boundary. If the candidate is not materially
smaller or creates an unacceptable timing/throughput regression, retain the old
service and report the result plainly. A safe fallback experiment is to remove
just the provably duplicate work scheduling while keeping the existing arithmetic
and result scheme. Do not keep adding infrastructure to rescue an expensive
replacement without a deletion account.

DELIVERABLE: a smaller paired PERSPUV candidate with an actual deletion ledger,
not a renamed copy of the current scheduler.

9. D6 — OWNER CONTROL: LOCALIZE ONLY WHAT THE CURRENT REPORT JUSTIFIES
=============================================================================

The V3 owner is real state management, not 3,348 ALMs of optional checking. The
historical standalone price identifies a candidate for attribution, not a
7,000-ALM cleanup target by itself. Keep its externally visible lifetime and
rejection rules intact. [S06]

9.1 What has already been removed or made local

The old per-slot generation array has already been replaced by reconstruction
from the allocation window. Do not propose saving it again. Some retained
historical/fetch markers may have no functional reader and already be pruned;
source deletion is maintenance, not a new area win.

The payload banks are already separated into statically selected sample, AUX,
FINAL and context storage. Their registered writes and staged reads are not
cruft. Combining them into a dynamically indexed two-dimensional array can
re-create inference failures. Keep the one-writer-per-bank structure unless a
new measured port design improves it.

9.2 A bounded locality candidate

Current ISSUE handling computes a selected-row eligibility predicate and then
uses that result in per-owner updates. This can create a selected req/iss lookup
followed by a broad accepted-event fanout. A possible equivalent form makes the
final req/iss condition local to the destination row:

  current:
      global_ok = identity_ok && required[target] && !issued[target];
      row_i_update = (target == i) && global_ok;

  candidate:
      row_i_update = (target == i) && identity_ok
                     && required[i] && !issued[i];

The Boolean update is equivalent when the exact original source-bit masks and
identity conditions are retained. Whether Quartus shares or duplicates the
result beneficially is a physical question. The supplied Boolean check does not
claim to answer that. [S06:1080-1195, M06]

Do not apply this indiscriminately to every predicate. Repeating an eight-bit
compare sixty-four times can cost more than one shared check. Hoisted generation
comparisons and local updates may legitimately be different choices. Use current
fanout/mux/resource attribution to select one family, preserve its exact event
latency, and measure it.

9.3 Semantic boundaries that must survive

The C0/C1/C2/C3/C4 contract separates capture, snapshot, validation/claim, payload
write, and publication. A ready ticket must not claim the payload is committed
before the write is visible. Concurrent TMU and AUX returns to one owner merge
correctly and produce exactly one readiness claim. Separate independent ready
writers must not become an unarbitrated multiwriter RAM.

Combine reservation is not actual combine acceptance. The latter authorizes
FINAL. Claimed return is not committed return. A generation-only guard is not
interchangeable with live-window membership for dead-slot residual semantics.
Recent-event forwarding and reset/drain behavior must survive unchanged.

The generation-wrap fence uses next-state identity and explicit reopen. Do not
remove it because wrap is rare. Local owner quiet is not automatically proof
that all external producers have drained. Preserve the declared boundary policy
and escalate an actual contradiction with a counterexample, not a vague request
for another owner ruling.

9.4 Reject a random capacity haircut

Do not reduce OWNERS=64, required sample slots, CMB/OUT queue credit accounting,
or generation width to make an ALM target fit. Those changes alter capacity or
identity safety. They need an explicit workload/contract decision and tests,
not a “decruft” label. The first locality candidate changes representation only.

DELIVERABLE: at most one measured control-family change, with the existing
adversarial owner suite, event-count checks, simultaneous-return tests, wrap
and unauthorized-FINAL mutations all preserved. If owner control is not a top
remaining contributor after D1-D5, defer this packet.

be the right trade. Conversely, building a queue manager to save an otherwise

12.4 Seeds and timing causality

P-CNT's two reported seeds differed by 13.34 MHz. That disproved the casual use

Structural endpoint removal can be real even when frequency does not improve;
frequency can improve without establishing that a particular change caused it.
Keep those claims separate. Do not add leaf Fmax deltas to island Fmax.

At 100 MHz the clock period is 10 ns. A reported Fmax value above 100 from one
corner does not excuse failing hold or another required corner. Conversely,
classify characterization I/O/virtual-pin paths honestly; do not silently
false-path real internal logic because an external-looking endpoint is awkward.
The full renderer/board integration still needs its actual timing environment.

This is a bounded workflow repair, not an invitation to write another fit runner.

13.1 What would count as actual progress

The production-only map should demonstrate genuine payload/table elimination,
not just fewer diagnostic output pins. Full fits should then show lower ALMs
and/or improved worst-corner timing at the same feature and workload contract.
A change may spend RAM or a small amount of control state to remove a much larger
fabric structure; report all resource axes together.

Returning to first V3's area/timing is recovery from a regression, not completion.
A result around 13k/84 does not satisfy this brief. A result around 100 MHz that
still violates the accepted resource budget also is not closure. A new resource
allocation may be justified by whole-console integration, but that is a separate
explicit decision, not permission to paint failed rules green.

13.2 What would reject the decrufting hypothesis

Reject or revise a packet if:

  its supposed old payload was already pruned and the new bank only adds cost;
  the replacement retains the old functional/reference readers;
  it lowers measured resource use by dropping required feature behavior;
  its throughput/burst capacity degrades without an approved contract change;
  it creates a larger critical ready/enable/mux family than the one removed;
  or its matched production fit remains worse without a compensating required
  benefit.

Do not respond by preserving every added structure and asking for a larger
budget. Go back to the last measured smaller correct specimen and determine
which representation failed.

13.3 What is not established today

No current evidence gives the ALM savings of removing the migration laboratory.
No fit yet prices this proposed early descriptor or paired PERSPUV candidate.
No source audit can guarantee 7,000 free ALMs. No single leaf measurement gives
whole-island timing after composition. No clean simulation guarantees a mapped
RAM or a timing-clean board.

The reason to pursue these packets is stronger than a numerical guess: they
name unnecessary live data structures and redundant schedules that can be
replaced by strictly simpler transaction flow while preserving the contracts.
The implementation and physical measurements must validate that opportunity.
