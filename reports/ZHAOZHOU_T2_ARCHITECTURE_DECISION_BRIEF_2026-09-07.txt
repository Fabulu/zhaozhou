READ FIRST: THE DECISION AND THE NEXT ACTION
===============================================================================

RECOMMENDED OWNER RULING

An owner instance has authority from its accepted admission until its ordered
external output transfer. Once that transfer retires the owner, later events
for that instance are stale. Matching a slot's residual generation bits does
not extend the owner's authority after retirement.

A stale event must not change that owner's scoreboard, create ready work,
authorize COMBINE, publish a result, release a credit, or resurrect the owner.
The receiver may consume and discard a bad transport packet so that transport
can drain. Consuming a packet is not accepting its claimed ownership.

This ruling applies separately to:
  (a) TMU publication at C4;
  (b) AUX publication at C4;
  (c) FINAL publication at C4;
  (d) the actual COMBINE input handshake, which sets combine_issued.

The fourth event is NOT a fourth C4 return. It is a different lifecycle event
and must retain its own acceptance rule and verification property.

Preserve M6: reserving COMBINE storage is not COMBINE accepting an input. Only
the real input handshake may establish combine_issued. A valid service-error
completion for a live, issued source still counts as its one terminal result;
it is not stale merely because its status describes a service failure.

RECOMMENDED IMPLEMENTATION DECISION

Separate representation removal from semantic tightening. First complete an
exact generation-reconstruction migration, including the three overlooked C1
snapshot readers. Then apply the explicit live-owner authority checks and
snapshot/current-identity protections as a separately testable change.

There is an exact way to remove the generation table WITHOUT waiting for a
policy decision about dead rows:

  historical_generation(slot) =
      slot < allocation_slot ? allocation_generation
                             : allocation_generation - 1 modulo 256.

The current RTL already implements this function as win_gen_of_slot(). It
reconstructs the residual generation of DEAD as well as live slots. Therefore,
keeping the old generation-only predicate does not require keeping gen_q.

The earlier claim "those four guards must change semantics before the table
can be deleted" was too strong. The policy question is legitimate; treating it
as an unavoidable physical-representation blocker is not. [R01, R03, C01]

NEXT ACTION FOR THE RECEIVING AGENT

Acknowledge this file on the actual hardware branch. Preserve the in-progress
frozen island fit and already completed texture repairs. Correct the gen_q
read inventory, finish the exact migration with a synthesis-excluded literal
reference, and prepare a matched owner fit. Do not switch to terrain, restart
the architecture, relax resource gates, or equate source edits with ALM gains.

No further owner preference is needed about the intended dead-token policy
once this ruling is adopted. A new blocker must identify a concrete conflict,
missing interface, counterexample, or failed gate—not simply repeat that a
semantic decision exists.

1. EXECUTIVE ASSESSMENT: WHAT IS ACTUALLY BLOCKED
===============================================================================

The most useful conclusion is not merely "reject dead tokens." It is:

  The lifetime policy should be explicit, but the current generation table is
  mathematically redundant under the existing allocator. We can remove that
  representation safely without conflating removal with a change in policy.

The agent correctly noticed that generation equality and live-token membership
are different predicates. In a dead-but-not-reused slot, generation equality
can still be true. Strengthening it to live membership changes the next-state
function for that condition. It was reasonable to flag the difference. [R03]

However, three separate questions became tangled:

  POLICY: Should a retired transaction retain any authority? Recommendation: no.

  REPRESENTATION: Must its last generation be stored in 64 independent rows?
  No, not under strict round-robin allocation. It can be reconstructed exactly.

  PROOF: Does the normal pipeline allow publication after retirement? The
  ordering argument and existing tests are encouraging, but simulation does
  not establish unbounded reachability or arbitrary-fault safety.

The current implementation can continue on the representation question while
preserving existing behavior. This eliminates the artificial dependency that
has been used to defer deletion. The final implementation should also adopt
the stronger, explicit authority rule. [R01, R03, R04]

This is not an instruction to delete the table after changing only four lines.
The live source still samples gen_q at C1 on THREE return pipelines. Those
readers were missing from the published last-four-sites narrative. The proof
and deletion must include them. There is also a generation-next-state read for
held fence diagnostic state whose synthesis relevance must be checked. [R01]

The independent arithmetic work for this brief exhaustively checks generation
reconstruction against a literal table over the initial partial allocation
pass and more than two namespace cycles. It also checks all allocation residues,
all legal occupancies, and all slots against a literal live-owner list. These
checks support the identity, not the correctness of the entire RTL pipeline.
Their source and results are supplied separately. [C01]

3. CORRECTIONS TO THE EARLIER ACCOUNT
===============================================================================

3.1 There are three C4 publication events, not four

c4t, c4a and c4f are TMU, AUX and FINAL publication. The fourth hoisted guard
is cmb_gen_ok_c, consumed when COMBINE actually accepts an input. It sets
cbi/actual issue, not committed/final-done. The three newly added C4 assertions
do not cover that fourth event. Add a separate COMBINE-validity/lease property.
[R01]

3.2 Four remaining named guards are not all remaining functional readers

The code still contains:

  c1t_tgen_q <= gen_q [c0t_slot_q];
  c1a_tgen_q <= gen_q [c0a_slot_q];
  c1f_tgen_q <= gen_q [c0f_slot_q];

The space before '[' matters to a careless text search. Their values feed the
C2 identity predicates and therefore influence real payload write enables.
Changing the four guards alone does not make gen_q dead. [R01]

3.3 Table removal does not require win_live at every reader

The allocator-derived win_gen_of_slot() reconstructs the old table for all
slots, including dead slots. It can replace a generation-only comparison
without adding a liveness requirement. The representation and the authority
policy can be changed in separate patches. [R01, C01]

3.4 A source-level comparator hoist is not a measured ALM saving

The source was rewritten from per-row comparisons to one selected comparison
per event lane. That is an exact Boolean refactoring. Whether Quartus already
shared, replicated, or optimized any of the original logic is a netlist/fit
question. "256 comparators became four selects" describes the source expression
shape; it does not establish that 252 physical comparators disappeared.
Similarly, a SystemVerilog helper function does not guarantee one shared
hardware unit across simultaneous callers. [R01, R03]

3.5 Simulation assertions are not an unbounded proof

The three C4 dead-match assertions have not fired in the recorded adversarial
bench. That establishes something about the executed traces. It does not
establish that all protocol-legal traces satisfy the property, and it certainly
does not prove tolerance of unrestricted corruption of internal registers.
[R03, E03, E04]

The phase invariants added at 902c835a are checked on one rotating row per
cycle. That is useful sampling, but it is not "every active row at every edge."
A one-cycle violation in another row can disappear before the rotating checker
arrives. For acceptance, use all-row assertions, event-target assertions with
an inductive preservation argument, or an arbitrary constant row in a formal
proof. Do not relabel sampling as universal coverage. [R01, R12]

3.6 No policy change at C4 can retroactively prevent a C3 payload write

The payload is written before C4 publication. A late guard protects later
scoreboard changes; it does not undo a write already accepted by RAM. The
architecture must establish authority before physical mutation and keep it
valid through that mutation, not rely on a final stale check as a repair.
[R01, R04]

4. EXACT LIFETIME AND EVENT SEMANTICS
===============================================================================

4.1 Define the owner instance, not only its bit pattern

A logical owner is a particular admitted fragment instance. Its public handle
is a finite encoding of that instance; it is not an eternally unique identity
and is not cryptographic authentication.

For the current configuration:

  Public OwnerHandle = {slot[5:0], generation[7:0]}      : 14 bits
  Public SampleHandle= {slot[5:0], sample[1:0], gen[7:0]}: 16 bits
  Internal ticket    = {generation[7:0], slot[5:0]}      : 14 bits

TMU samples 0, 1 and 2 are legal. Sample index 3 is malformed, not AUX. The
AUX and FINAL ports are independently typed. Palette generation, configuration
epoch, transport identity and owner generation remain different domains.
[R01, R02, R04]

4.2 Linearization points

Admission happens at the rising edge where adm_valid && adm_ready is true.
The new token is stamped from the pre-edge allocation cursor, and row state
and counters advance from that same accepted event.

Normal retirement happens at the rising edge where out_valid && out_ready is
true for the oldest owner. Final completion, RAM write, output prefetch and
being presented with valid do not retire the owner. A blocked output still
owns its row, context and credit. [R01, R04]

Authorization checks use a consistent pre-edge state. Do not let a current
admission retroactively authorize a packet that was invalid when its snapshot
was taken. Do not use a next-state live count in one part of a predicate and
pre-edge token state in another without proving that mixed-time contract.

At full capacity, retain conservative admission: the source cannot assume a
same-edge retirement provides a bypass credit. The current registered-credit
scheme was explicitly designed to avoid a 65th-owner overwrite. A fast bypass
is a different optimization with a separate proof and timing cost.

4.3 Allowed effects by event type

A TMU/AUX publication can update committed bits and potentially create the
owner's one ready ticket only for the corresponding current live owner.

A FINAL publication can establish final_done only for the current live owner,
after a legitimate final was claimed and physically written.

An actual COMBINE input transfer can establish combine_issued only for a live
owner that already held the appropriate reservation and required completion
state. Reservation alone never authorizes a final.

A stale external return is consumed under the existing return-port transport
contract and classified as a rejection. It must not claim, write, publish or
free anything. Other legal traffic in the same clock must continue normally;
"no side effects from the stale event" is not "freeze the whole scoreboard."

A valid, issued service error still commits its declared fallback/status once.
Rejecting that error as though it were a stale identity would strand the owner
and can deadlock a namespace drain. [R01, R02]

4.4 Internal invariant failures need different diagnostics

An invalid external packet is an anticipated rejection class. A C4 record for
a retired owner is different: C4 is an internally generated publication record
that should descend from an already accepted C2 claim. It is evidence of a
broken lease, pipeline corruption, or an incorrectly implemented reset/drain.

Recommended response: suppress that event's scoreboard/ready/credit effects,
raise a dedicated sticky internal-protocol diagnostic, and route recovery
through the defined containing-system fault procedure. Do not silently count it
as successful work. Do not silently turn it into an ordinary external stale
counter and thereby invalidate the existing C2 rejection-partition accounting.

This decision does not authorize a new automatic cancellation mechanism. If the
containing system lacks safe recovery, a visible failed/stopped state is more
honest than fabricating a drain acknowledgment or freeing an arbitrary owner.

4.5 Same-edge retirement does not rewrite history

A predicate evaluated before a retiring edge sees the retiring owner as live.
After the edge that instance is dead. The stronger lifecycle invariants should
normally prevent new C4 work or a first COMBINE issue from coinciding with that
owner's output retirement at all.

Check that ordering explicitly. Do not claim that merely using post-edge
membership solves the race: post-edge membership can instead let a newly
allocated instance authorize an older packet if identity was not preserved.

5. ALTERNATIVES CONSIDERED AND SELECTED MIGRATION
===============================================================================

A. Replace every generation-only guard immediately with win_live()

Advantages: states the intended authority rule directly; eliminates selected
array reads; makes dead rows unable to accept publications.

Risks: changes behavior on dead-but-matching rows; conflates representation and
semantics; does not fix the omitted C1 reads; does not itself prevent C3 writes;
can add a subtract/compare cone to a critical event path.

Decision: this is the selected FINAL policy, not a four-line unreviewed patch.

B. Reconstruct historical generation exactly, then tighten authority

Advantages: removes the redundant table without requiring a behavior change;
uses an already present function; can preserve C1 timing and old predicates;
allows before/after behavioral equivalence to be tested independently from the
new dead-event policy. The state identity has an inductive argument and finite
exhaustive checks. [R01, C01]

Risks: if retained forever without the policy follow-up, old permissive dead-row
semantics persist; helper calls still have a physical logic cost; care is needed
for next-state diagnostic reads and reset.

Decision: SELECTED IMPLEMENTATION SEQUENCE. Adopt the authority ruling now,
execute the migration in attributable steps, and label the exact intermediate
as an intermediate—not as final lifetime-contract closure.

C. Preserve gen_q until a future owner ruling

Advantages: minimal immediate code change.

Costs: retains 512 declared generation state bits and remaining selection logic;
blocks the intended T2 area experiment for a reason that an exact representation
already resolves. It encourages indefinite peripheral test/report work.

Decision: not justified as the default once the exact reconstruction is audited.
A real counterexample to the reconstruction would change this decision.

D. Remove the guards because C4 ought to be safe

Advantages: potentially cheap.

Risks: relies on an unproven upstream lifetime argument; weakens defensive
behavior; can turn a future pipeline or drain bug into silent corruption.

Decision: rejected. Keep or strengthen authority checks at deliberate boundaries.

E. Widen all generation tags

Advantages: postpones numeric reuse.

Costs: more tag storage, wires and comparators; no fix for snapshot/current
confusion; no proof against arbitrarily delayed aliases after wrap or reset.

Decision: not the T2 solution. An outer epoch may be needed for a specific
transport/reset contract, but adding bits is not a substitute for defining it.

6. THE MATHEMATICS OF TABLE REMOVAL
===============================================================================

6.1 State

Let S=64 be the owner capacity and Q=16384 the ticket namespace. Let:

  A : next allocation ticket, modulo Q;
  E : next externally retiring ticket, modulo Q;
  U : live-owner count, 0..64;
  F : next owner whose final-row read has not yet been reserved.

Initially A=E=64 and U=0. The first internal ticket is 64, while its public
owner handle is 0x0001: slot zero, generation one. Those are DIFFERENT numeric
values because the public and internal bit orders differ.

Admission advances A; ordered output transfer advances E. Consequently:

  U_next = U + admission_taken - output_taken
  U      = (A - E) modulo Q

within the invariant 0<=U<=64. Since 64 is much smaller than Q, A==E means
empty, not full. The usual ambiguity of a FIFO pointer truncated to the storage
index does not apply to these full 14-bit tickets. [R04, C01]

6.2 Full-token membership

  is_live(ticket) = unsigned_14(ticket - E) < U.

This is membership in the short modular interval [E,A), not a generic signed
ordering of arbitrary tickets. Compute the full 14-bit distance before comparing
against the widened live count. Do not shorten it to six bits merely because
there are 64 slots. Old generations would alias into the current window.

Finite sequence arithmetic has wrap-specific comparison rules; RFC 1982 is a
useful primary reference for why ordinary integer ordering cannot simply be
reused. The formula here is derived for this bounded ownership interval, not
an adoption of every RFC operation or a proof of transport safety. [E01]

6.3 Historical generation for EVERY physical slot

Write A={G,P}, with G=A[13:6] and P=A[5:0]. Strict allocation order gives:

  H(s) = G                    when s < P
       = G - 1 modulo 256     when s >= P.

Reason: slots below the current allocation cursor have been allocated in the
current pass through the ring; slots at or ahead of it retain the previous
pass's generation. Retirement does not modify gen_q. Therefore H describes
both live and dead rows. [R01]

Inductive argument:

  Reset: G=1, P=0. Every slot takes G-1=0, exactly the reset table.

  Non-wrapping admission at P<63: only row P is changed from G-1 to G;
  P advances to P+1. That is exactly the row moving between the two ranges.

  Admission at P=63: row 63 becomes G; P becomes 0 and G increments modulo
  256. Every row is now in the previous-pass range and evaluates to the old G.

  No admission, including retirement alone: neither G nor P nor gen_q changes.

These cases exhaust the existing table's functional update rule. This argument
fails if allocation becomes a free list, skips slots, independently changes
row generations, or resets only part of the identity state. Such changes are
outside this decision. [R01, C01]

6.4 Historical reconstruction and live reconstruction are NOT interchangeable

For a known-live slot, another useful reconstruction is:

  offset = unsigned_6(slot - E.slot)
  ticket = E + offset modulo Q, with offset < U.

Without the final condition, this can name a FUTURE owner rather than the last
owner of a dead slot.

Concrete example: A=65, E=65, U=0 after ticket 64 retired. Slot zero's historical
generation is one. But E + unsigned_6(0 - E.slot) is 65+63=128, generation two.
The two reconstructions differ exactly on a case that matters to preserving a
generation-only dead-row guard.

Use H(s), derived from A, for exact legacy generation replacement. Use full
membership or a checked live-slot reconstruction for current authority.

6.5 Exact intermediate code shape

Illustrative fixed-shape helpers, not a tested drop-in patch:

  function automatic logic [GENW-1:0] hist_gen(input logic [SLOTW-1:0] s);
    hist_gen = (s < tail_q) ? sh_alloc_gen_q
                           : GENW'(sh_alloc_gen_q - GENW'(1));
  endfunction

  // Existing public handles must be unpacked and repacked into ticket order.
  wire [OWNERW-1:0] t_ticket = {c4t_gen_q, c4t_slot_q};

  // Exact representation-only replacement:
  assign c4t_gen_ok_c = (hist_gen(c4t_slot_q) == c4t_gen_q);

  // Final policy, in a separately tested step:
  assign c4t_owner_ok_c = win_live(t_ticket);

Do not infer that the single helper means all callers share one arithmetic
resource. Parallel event lanes require parallel decisions; synthesis chooses
how much common logic to share. Measure the resulting network.

6.6 Slot liveness without a per-slot live table

Given the contiguous live interval and U<=64:

  slot_is_live(s) = unsigned_6(s - E.slot) < U.

This six-bit distance is safe ONLY for whether an internal physical slot is in
the occupied slot interval. It does not authenticate an external full handle.
For U=64 all slots are occupied; for U=0 none are. Full returned identities must
continue to use all generation bits. [C01]

6.7 Counter partition and width

The implementation has unf_cnt_q for not-yet-fetched owners and out_res_q for
fetched/reserved-but-not-emitted owners. The intended invariant is:

  U = unfetched + output_reserved,
  [E,A) = [E,F) disjoint-union [F,A).

The current partition assertion casts the sum back to CNTW. Strengthen the
checker by WIDENING both operands and the comparison, and separately bound each
counter. A truncated sum can hide an overflow in precisely the corrupted state
an assertion is meant to detect. This is checker strengthening, not a claim
that the current valid execution overflows. [R01]

===============================================================================
8. C1/C2/C3/C4: PREVENTING STALE SNAPSHOTS AND LATE WRITES
===============================================================================

The current return path is:

  C0 capture packet
  C1 capture row-state snapshot and identity information
  C2 decide whether the return may claim the source
  C3 registered write enable commits payload to the designated bank
  C4 publish completion to narrow control state and evaluate readiness.

This separation is valuable and must survive T2. The original architecture
explicitly requires snapshot-time identity plus current-claim identity, or a
proved equivalent lease. The inspected C2 predicates presently use the captured
c1_live/c1_tgen pair. They do not independently recheck the current window in
the shown acceptance predicates. Do not mark that requirement closed merely
because ISSUE and READY eligibility now call win_live(). [R01, R04]

8.1 Why two time points matter

Future-token example:
  At snapshot, ticket 65 is not yet live: A=65, E=64, U=1.
  Before claim, ticket 65 is admitted: A=66, E=64, U=2.
  A current-only check now returns true, even though the stored row snapshot
  was not a valid snapshot of that instance.

Retired-token example:
  At snapshot, ticket 64 is live: E=64, U=1.
  Before claim, it retires: E=65, U=0.
  A snapshot-only Boolean remains true even though authority has ended.

These are contract counterexamples to one-time validation, not claims that the
entire present pipeline necessarily reaches both schedules under valid traffic.
That distinction is why the lease argument must be proved rather than assumed.
[C01]

8.2 Selected final validation shape

At C1, capture:
  packet's full identity and payload;
  snapshot_identity_valid;
  the corresponding required/issued/claimed/committed facts.

At C2, require:
  packet valid and range legal;
  snapshot_identity_valid;
  current full-ticket membership;
  source required and actually issued;
  source not already claimed/published;
  no matching recent accepted claim in the forwarding interval.

Preserve the existing ordering of rejection classifications where observable.
Do not let multiple rejection classes count the same packet, and do not lose
one of two concurrent lane errors to sequential assignment precedence.

A valid service-error result takes the accepted-completion path, preserving its
status and fallback payload; it does not disappear into identity rejection.

8.3 Claim-to-write ownership lease

A successful claim creates an obligation to complete the corresponding
registered write and publication. The owner must not be released or reused
while that obligation exists. For normal samples, COMBINE cannot be eligible
until publication; FINAL follows actual COMBINE acceptance; ordered output
follows final_done. That is the intended lease argument. [R01]

Express it at the physical boundary:

  sample-bank write enable -> current instance owns this slot and source;
  AUX-bank write enable    -> current instance owns this slot;
  FINAL-bank write enable  -> current instance owns this slot and final claim.

Keep actual RAM write enables registered. Do not insert an uncontrolled
late combinational window predicate immediately before a bank write-enable
and recreate the input-to-RAM timing problem the design was built to remove.
If the lease cannot be established, add an explicit registered validation /
reservation stage and account for its extra latency and storage.

8.4 C4 authority and the meaning of a C4 drop

The final C4 predicate checks the full current identity and the applicable
accepted publication record. On an invalid record, suppress that event's
committed/final_done update and its ready-ticket contribution.

This is containment for an internal protocol violation, not a guarantee that
arbitrary earlier corrupted C3 traffic left memory intact. Detect earlier
violations before the write boundary. Under an unrestricted upset model,
protecting every state bit would require a separate fault-tolerance design;
this brief does not make that claim.

8.5 Counters must match accepted effects

The current d_commit_c increments from raw c4t_v_q/c4a_v_q. If C4 is allowed
to reject an internally invalid record, the implementation must decide whether
that counter means "publication record observed" or "accepted sample commit."
Do not leave it ambiguously claiming successful commits. [R01]

Recommended split: accepted sample-publication count advances only for accepted
C4 sample effects; internal rejected-publication diagnostics are separate.
Count simultaneous TMU and AUX accepted publications as two. Preserve the
existing FINAL accounting convention rather than silently adding finals to a
counter whose meaning was sample/AUX commits.

If preserving the current public counter ABI is necessary for an intermediate,
retain its documented raw-record meaning and add the new accepted-effect metric
under a distinct name. The final acceptance report must state which it uses.

===============================================================================
9. COMBINE IS ITS OWN FOURTH EVENT
===============================================================================

Do not turn the fourth guard into a C4-specific proof.

The three relevant moments remain:
  1. local readiness/candidate reservation;
  2. central result-bank read/storage reservation;
  3. actual COMBINE input transfer on cmb_valid && cmb_ready.

Only moment 3 may set combine_issued. The M6 repair already makes that
separation. Keep it. [R01, R02]

The final contract should assert:

  cmb_valid -> presented token is a current live owner with a valid lease;
  cmb_fire  -> live owner, existing reservation, required inputs published,
               and no prior actual issue for that instance;
  cmb_valid && !cmb_ready -> next offered token and data remain stable;
  final claim -> actual COMBINE issue occurred for the same instance.

At minimum add a fourth dead-match/live-authority property for cmb_fire.
The existing a_c4t/a_c4a/a_c4f_never_dead_match triplet does not check it. [R01]

If a supposedly valid COMBINE queue entry is stale, do not merely suppress
cbi after delivering the bad packet and claim nothing happened: the consumer
has already accepted an input. A valid design prevents that situation through
the lease from reservation through transfer. A fault handler must explicitly
coordinate any cancellation; withdrawing valid while stalled is not a normal
ready/valid operation. Published AXI protocol-checker assertions illustrate the standard
stable-valid/stable-payload rule; Zhaozhou's own interface contract remains the
actual authority here, not a claim that this interface is AXI. [E05]

The ordinary no-cancellation path is simpler: no owner can retire before its
COMBINE transfer, final claim, final write, final publication and ordered output
have all occurred. Keep that dependency chain intact while simplifying storage.

10. RESET, GENERATION WRAP, AND THE LIMITS OF FINITE TOKENS
===============================================================================

10.1 A finite tag cannot identify an arbitrarily old identical packet

Once a numeric 14-bit ticket is reused, an old packet with exactly those bits
is indistinguishable from a packet for the new instance if those bits are all
the receiver has. win_live() cannot solve that. Neither can the old gen_q table.
This follows directly from the identical input/state observation, not from a
particular FPGA or timing result. [C01]

The external producer/transport contract must prevent such an old obligation
from surviving into numeric reuse, or carry a separately managed epoch whose
lifetime is long enough and whose reuse is itself controlled.

10.2 The current fence is transitional

The source implements OPEN / STOP / FINISH / REOPEN and authorizes one wrapping
admission before resuming the legacy per-slot check. It explicitly lacks the
producer-acknowledgment interfaces for QUIESCE_PRODUCERS and
DRAIN_RESIDUAL_TRANSPORT. quiet_c describes local state; it is not a promise
that an external producer can never emit another old response. [R01]

Preserving this transitional fence during the representation-only migration is
acceptable if its limitation remains visible. Do not call it the complete
feature-live namespace barrier. Do not accidentally replace it with permission
that remains open across unrelated reused identities.

10.3 Final integrated fence sequence

The previously selected architecture requires a complete barrier before global
namespace reuse. Starting at ticket 64, the first approach to zero follows
16,320 allocations; later full numeric cycles contain 16,384. [R04]

Required causal sequence:

  STOP_NEW_OWNERS: stop new admissions, not service work for existing owners.

  FINISH_LIVE: allow already admitted owners to issue, receive their required
  normal or error terminals, complete COMBINE, and retire in order.

  QUIESCE_PRODUCERS: obtain acknowledgments tied to this held barrier/epoch,
  stating that all accepted old work is completed or canceled by an agreed
  protocol. Do not block a producer before it can finish the work needed to
  empty the live window.

  DRAIN_RESIDUAL_TRANSPORT: empty old queues, capture stages, pending reads,
  skids and invalid/duplicate traffic that still consumes transport storage.

  VERIFY_EMPTY_AND_REOPEN: only after every obligation is discharged, advance
  or authorize reuse of the namespace and reopen registered admission.

The exact handshake implementation belongs to retained-service integration.
An optional barrier-generation identifier or explicit request/ack phases must
prevent an old level-high acknowledgment from satisfying a new request.
A timeout may report failure. It may not assert that old traffic disappeared.

10.4 Reset is a separate alias boundary

Reset currently reinitializes owner identity so the first new public token can
be the same 0x0001 previously issued. A block-local reset does not magically
flush a remote service or a transport FIFO. The reset bench clears its pending
final queue before post-reset operation; it therefore does not demonstrate
safety against an arbitrarily delayed old final after the same token has been
reissued and COMBINE accepted again. [R02]

The supported policies must be explicit:
  coordinated reset of the whole obligation domain; or
  drain/acknowledge first, then reset the owner; or
  transport carries a protected outer epoch and rejects old-epoch traffic.

Do not introduce an uncoordinated local-reset guarantee that the available
identity bits cannot support. Do not clear all payload RAM to compensate for
an identity problem; invalidation and ownership control should make stale RAM
contents unobservable.

10.5 Cancellation must not punch holes

The short live window depends on oldest-first retirement. A per-owner error
should generate an ordered terminal/tombstone under the existing contract,
not free an arbitrary interior row. Any cancellation design needs explicit
completion of writes, reads, reservations and transport obligations. The
present ruling does not authorize ad hoc out-of-order freeing. [R04]

    Every active row at every relevant edge: committed subset claimed subset

  V14 — Throughput is not merely eventual completion
    Preload contiguous completed owners and measure a long zero-bubble output

For every new directed case, report its actual trigger/cover count and run at
least one relevant mutant. A test that checks only successful traffic cannot
distinguish a correct guard from a fail-open guard. A test that checks only
rejection cannot distinguish it from reject-everything.

12. FORMAL PROOF BOUNDARIES AND NON-VACUITY
===============================================================================

Use three distinct evidence classes:

  Arithmetic identity proof: the bounded interval and reconstruction formula.
  RTL safety proof: actual pipeline/state transitions under explicit assumptions.
  Physical implementation evidence: synthesis mapping and placed timing.

None substitutes for the others.

A focused formal harness should use the real owner control RTL, a literal
reference owner sequence, and explicit producer assumptions. Treat arbitrary
external token values as possible where the interface promises to reject them;
do not assume every incoming token is live to make the identity theorem pass.

For ordinary C4 reachability, prove or inductively establish the chain:
  accepted claim -> authorized write -> publication -> readiness -> reservation
  -> actual COMBINE acceptance -> final claim/write/publication -> ordered output.

Prove separately that ownership cannot terminate while a legal pending claim,
write, publication or reserved COMBINE packet requires it. Do not assume the
no-late-C4 assertion as an input constraint while claiming to prove it.

Use covers for full occupancy, empty occupancy, concurrent events, wrapped
identity, accepted error terminals, stalled output and the dangerous boundary
conditions. A safety assertion with an unreachable trigger can pass vacuously.
The formal tool's assume/assert/cover distinctions matter here. [E03]

A bounded model check proves only the searched depth. An unbounded proof mode
and its actual result must be reported as such; UNKNOWN is not PASS. Formal
parameters and assumptions must be archived. Reduced-owner experiments are
useful, but the current source assumes a full 64-slot ring in places. Do not
change OWNERS alone and call the resulting under-specified configuration a
proof of the production machine. [E04, R01]

A practical all-row invariant method is an arbitrary constant row selected by
the formal solver, constrained only to a legal index. Proving the invariant
for every possible choice establishes the universal row claim; a deterministic
rotating runtime selector does not.

Formal proof infrastructure should remain focused on these obligations. Do not
turn it into an unrelated framework project that delays the texture fit and
integration work.

14. PHYSICAL MEASUREMENT AND RESOURCE POLICY
===============================================================================

14.1 Keep the resource failure visible

At 5,709 ALMs, reaching a 1,800-ALM owner allocation would require roughly a
68.5% reduction. T2 removes redundant identity state and selection logic; it
has not demonstrated that entire reduction. Removing 512 declared flops is not
the same as saving 512 ALMs, and not evidence for a multi-thousand-ALM saving.
ALMs contain logic and storage whose packing and routing interact. The fit must
measure the net effect. [R05, R06]

If a coherent optimized owner still misses its allocation, reconcile the
whole-island architecture and resources. Retain and report a useful failing
intermediate; do not quietly change max_alms to match whatever was measured.
A proposed allocation revision is a versioned decision, not retroactive success.

14.2 Do not manufacture an island total

Do not add the old integrated island to a replacement owner, count V1 and V2
COMBINE together, or sum alternative reciprocal tiles as simultaneous hardware.
Shared source code also does not imply shared silicon: two instantiated cores
are two cores unless explicitly scheduled onto one physical instance.

The existing master handoff proposes a 69-M10K feature-live profile. That is a
proposed revised profile, not an automatic pass of an older 64-block target.
The seven M10Ks occupied by small owner packet queues need explicit mapping
experiments, not optimistic subtraction from the ledger. [R04, R06]

14.3 Report the complete physical specimen

For each accepted comparison archive:
  exact source commit and content digest, dirty-state capture, source list;
  module parameters, device, tool version, seed and optimization settings;
  wrapper / virtual-pin / registered-boundary scope;
  fitted ALMs and registers separately from mapped ALUTs/registers;
  memory instance names, logical dimensions, physical modes and block totals;
  DSP count;
  worst setup/hold/recovery/removal/pulse-width results at required corners;
  unconstrained-path status and actual interface/clock constraints;
  top path families and relevant functional/throughput evidence.

A short report naming the changed path family is more useful than repeated
claims that all current failures are merely boundary artifacts. Interfaces are
part of the machine and need appropriate constraints or composed measurement.

14.4 One-time setup success is not robust closure

The product requirement remains 100 MHz with the actual selected feature set
and supported timing conditions. A 90–95 MHz result can be progress; it is not
acceptance. An isolated 100+ MHz result can be useful; it is not proof that
integration will preserve it.

Use the specified device/operating corners and appropriate board constraints.
Do not relax a hold requirement, make a false path, or declare a multicycle
path without a real architectural justification and corresponding functional
contract. A same-edge hold violation is generally not cured by lowering the
clock. Inspect the failing path before prescribing its repair. [E02]

14.5 Memory inference: no new folklore

PERSPUV's reset/control/read-write structure must be inspected as a whole before
promising RAM recovery. Vendor guidance explicitly warns that resetting RAM
contents during operation causes logic-cell implementation on these devices.
Removing one output mux is not sufficient evidence of RAM inference, and blindly
removing reset is not sufficient evidence of correct behavior. Preserve valid
state and write-before-read guarantees, then inspect the actual RAM summary.
[E06, R09]

17. RISKS, NON-GOALS, AND CLOSURE CONDITIONS
===============================================================================

Principal risks:

  Hidden consumers keep the old table synthesized. Mitigation: complete
  whitespace-tolerant inventory plus elaborated/mapped confirmation.

  Identity arithmetic becomes the new critical path. Mitigation: preserve
  register boundaries, evaluate per-lane cost, and pipeline validation with
  explicit credits/leases where necessary; never assume a helper is free.

  Snapshot and current state disagree across a lifetime boundary. Mitigation:
  capture full identity and snapshot validity, recheck at claim, preserve leases
  through physical writes, and exercise both stale and future schedules.

  A local quiet signal is mistaken for global transport completion. Mitigation:
  explicit producer acknowledgments, residual-drain accounting and reset policy.

  Verification becomes circular or sampled without disclosure. Mitigation:
  independent literal reference, covers/mutants, actual write observation and
  universal/event-specific phase properties.

  Partial physical wins are presented as product closure. Mitigation: separate
  owner, existing island, successor services and final feature-live scopes;
  publish all timing classes and keep failed allocations visible.

Non-goals:
  a new game/console architecture;
  removal of exact texture functionality to make a fit attractive;
  arbitrary out-of-order cancellation;
  protection against arbitrary Byzantine producers or unrestricted state upset;
  wider tags as a substitute for an epoch contract;
  terrain/projector implementation;
  predictions of final ALM or MHz savings unsupported by a fit.

T2 identity closure requires all production table readers gone, correct identity
checks at the necessary pipeline times, a coherent supported lifetime contract,
passing positive/negative tests and a matched physical result. The old table may
remain in verification-only code. It may not remain required by synthesis.

Full texture closure additionally requires the selected V3.1 services and
storage integrated, all required capabilities live, workload/throughput gates
met, resource allocation reconciled, and timing accepted for the actual
composition and supported constraints/corners. No arbitrary 90 MHz milestone
replaces these conditions.

18. READY-TO-PASTE OWNER DECISION
===============================================================================

OWNER DECISION — TEXTURE T2 LIFETIME AND TABLE REMOVAL

Texture remains first. Do not switch to terrain or reset/restart the working
architecture. Preserve the already running frozen island fit and its evidence.

An owner has authority until its ordered out_valid && out_ready transfer retires
it. After retirement, its old token has no authority, even if an unreused slot
still contains matching generation bits. Consume/reject stale transport as
required for draining, but do not let it change scoreboard state, create ready
work, authorize COMBINE, publish a result, free a credit, or resurrect an owner.
Keep valid issued service-error completions and the M6 actual-acceptance rule.

Apply that rule separately to TMU/AUX/FINAL C4 publication and actual COMBINE
acceptance. The fourth guard is not a fourth C4 event. Internal late-publication
violations must be visible and have their effects suppressed; a C4 check does
