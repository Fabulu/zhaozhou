0. DECISION AND IMMEDIATE WORK ORDER
===================================

Keep the banked payload architecture and exact arithmetic work. Replace the
way the owner block identifies a live transaction, updates its narrow state,
finds ready work, and feeds global quiescence back into admission.

The main architectural change is this:

  Current implementation:
    per-slot generation records + repeated dynamically indexed state reads
    + three producer-class ready FIFOs + broad quiescence feedback

  Proposed implementation:
    one bounded live-sequence window + source-owned control bitplanes
    + eight local ready selectors with two tiny candidate registers each
    + explicit registered drain control and reserved output capacity

A 64-owner ring with ordered allocation and ordered final release already
contains much more structure than an arbitrary 64-entry associative table.
Use that structure. Do not pay for the general problem when the machine obeys
a much narrower one.

DELIVERY-TIME FINDING THAT CHANGES THE PRIORITIES
------------------------------------------------
While this review was in progress, commit 756f08c finally published an entity
census from the OLD COMPOSED island's already-existing map report. It attributes
13,459 of 27,973 mapped registers to the TOP ITSELF, not to the leaf blocks.
This is not a new fit, and it is not an attribution of the 5,678-ALM V3 owner.
It is direct evidence that a control-only replacement cannot be bolted under
the old top-level capture/reorder scaffolding and expected to meet the budget.
[R12]

Therefore run TWO concrete reduction lanes, not another broad rewrite:

  CONTROL: the sequence-window / row-local / candidate design in sections 6-14;
  TOP STORAGE: the synchronous numerator/descriptor joins and single lifetime
               inventory in sections 17.10-17.16.

The top-storage lane can first make a controlled legacy comparison without
waiting for the whole new owner to be finished. Its final destination is the
single V3.1 transaction file, not a second set of equivalent banks beside it.
The staged owner work below remains useful, but its success alone is not the
whole island success criterion.

The existing lifetime law survives intact:

  admission -> work issued -> terminal claimed -> payload written
            -> result published -> COMBINE accepted -> final published
            -> ordered output accepted -> owner released

Neither receipt of a sample nor a memory-read launch frees the owner.

The implementation order is deliberately NOT "rewrite all this at once":

  M0  Recover owner physical attribution and timing endpoint classes; read the
      existing old-island census immediately, without queuing a redundant map.
  M1  Fix ready-queue occupancy and separate quiescence from hot admission.
  M2  Replace per-slot generations with the sequence-window implementation.
  M3  Narrow validation and use source-owned row-local control updates.
  M4  Replace ready FIFOs with the eight-group candidate structure.
  M5  Move wide holding queues to explicitly credited RAM-backed storage.
  M6  Distinguish COMBINE reservation from actual input acceptance.
  M7  Integrate the retained services and remove superseded top-level capture/ROB
      storage. Run the section 17.10 top-storage lane in parallel with M1-M6.
  M8  Fit the feature-live island, then the real renderer composition.

M6's correctness test must be written at M0, even if the interface change lands
later. Any existing behavior that accepts a final result before COMBINE has
accepted the corresponding input is not something to preserve for parity.

The first two changes can be assessed on the old payload banks and old
buffering. That gives an early answer without a giant migration. The later
changes are independently attributable rather than one inseparable gamble.

This is a serious rearchitecture, but it is not a new console architecture.
No change to reciprocal precision, texture formats, blend rounding, sample
counts, or permanent terrain semantics is proposed.


1. CORRECTING THE EVIDENCE BEFORE DESIGNING FROM IT
=================================================

1.1 The physical baselines
--------------------------

The transitional composed texture island measured:

  16,193 ALMs; 27,097 registers; 17 DSPs; 25 M10Ks; 63.54 MHz.

The later COMBINE V2 plus W9b repair composition measured:

  16,192 ALMs; 28,490 registers; 17 DSPs; 32 M10Ks; 67.57 MHz.

Those are different source/capability points. W9b restored real nearest/format
and alpha processing that had previously been optimized away. The tiny ALM
delta does not isolate the area cost of the COMBINE redesign. The old V2 run
also had rtlCleanAtHead=false, so its nominal source commit alone does not
reconstruct the fitted bytes. Keep the run's provenance caveat in every
comparison sheet. [R08, R09]

The isolated RCP24 V3 full fit measured:

  1,230 ALMs; 1,944 registers; 3 DSPs; 6 M10Ks; 90.54 MHz.

The isolated owner/completion demonstrator measured:

  5,678 ALMs; 4,864 registers; 0 DSPs; 17 M10Ks;
  20,640 reported block-memory bits; 75.79 MHz; 952 virtual pins.

Its map-only row had 4,220 registers and 6,532 ALUTs. Its fitted ALM count was
3.15 times the assigned 1,800-ALM budget. That budget failed; the result is not
a successful area closure merely because it is smaller than the entire old
texture island. [R04, R05]

The raw old and new owner register comparisons should also be kept honest:
9,431 for the 64-deep legacy FRAGROB is a mapped comparison figure; 4,220 is the
new mapped figure; 4,864 is after fitting. Use map versus map for a precise
register delta. Do not silently pair mapped old with fitted new and present
it as a controlled before/after experiment.

1.2 The 372-ALM probe was not a texture owner prototype
----------------------------------------------------

The source of zhao_probe_banked_rf is explicit: it is a Field register-file
characterization probe. It has four banks and three replicated read copies,
serving seven logical operands. It does not implement texture ownership,
terminal validation, duplicate suppression, ready events, or ordered release.

The 372-ALM / 10-register / 12-M10K / 93.14-MHz row is therefore NOT evidence
that the texture transaction-control machinery can be built for a few hundred
ALMs. It shows a useful memory shape can map economically. That is a much
narrower result. Earlier interpretations that treated it as the texture
transaction demonstrator were wrong. [R06]

This matters because otherwise a failed owner fit looks like a mysterious
physical reversal. It is not a reversal of the same experiment. It is a
measurement of a much more complicated block.

1.3 A path that STARTS at a register is not necessarily an internal path
----------------------------------------------------------------------

The demonstrator report names these paths:

  ready-queue write pointer -> adm_accept_o
  ready-queue write pointer -> ev_quiet_o

Both named endpoints are top-level OUTPUTS. They are not register-to-register
paths wholly inside the block. The RCP report's named done-queue path similarly
ends at r_tok_o, an output. Classifying paths only by their startpoint and then
calling the register-origin group "internal" is insufficient. [R04, R05]

This does NOT prove 75.79 MHz or 90.54 MHz is fictitious. The official Fmax
report may include same-clock ports as well as registers, and the constrained
interfaces must ultimately work. It means the claim "removing the boundary
would buy nothing because these are internal paths" was not established by
that classification.

Classify both endpoints. Produce register-to-register, input-to-register,
register-to-output, and input-to-output reports separately. Then fit a
registered service wrapper with explicit interface timing. The difference
between a boundary contract failure and a long internal arithmetic path
changes the cheapest repair. [V01, V02]

1.4 Quiescence really is on the observed ready-pointer path
---------------------------------------------------------

The source provides the chain:

  queue wp/rp -> body_occ -> occ_o -> quiet_c
             -> wrap_block gating -> adm_ready_o -> adm_accept_o

This is not a speculative diagnosis of unnamed logic. It is visible in the
assignments. The generation-wrap condition puts an infrequent drain policy
on an ordinary admission output cone. [R01, R02]

Fixing that cone can improve an interface path without changing the payload
RAMs or the arithmetic. Whether it closes the whole block is a new fit
question, not something the source alone answers.

1.5 There is a real occupancy omission
--------------------------------------

zhao_texture_v3rq defines:

  body_occ = wp - rp
  occ_o    = body_occ + head_valid + spare_valid

But rp advances when a synchronous read is launched. Until ld_q is consumed,
the removed body entry has not yet reached either head register. The total
must include that in-flight read:

  logical_occupancy = body_occ + head_valid + spare_valid + ld_q

For a single queued ticket, there is a cycle with body_occ=0, both head valids
zero, and ld_q=1. The exported occupancy says zero while a ticket still exists.
[R02]

In the present block live_cnt normally prevents that isolated omission from
making the whole island quiet. Therefore do not claim an observed corrupted
frame or demonstrated wrap failure from this finding. It is nevertheless an
incorrect queue-level conservation signal and an unsafe foundation for a
reworked drain protocol. The supplied model includes this exact counterexample.

1.6 The exact 5,678-ALM attribution is still missing
--------------------------------------------------

The public-facing demonstrator report says attribution is not yet available.
The pinned run_block_fit script archives the map report, fit summary, STA
summary and timing paths, but its shown harvest loop does not archive the full
blockfit.fit.rpt. That is precisely the detailed fitted resource report needed
for entity-level physical attribution. [R04, R07]

The map-report path exists in the repository. Its text was not usefully exposed
by the connector in this session. No per-entity ALM table was recovered here.
Consequently this document does not claim that a measured 3,000 ALMs belong to
one mux or that a measured 2,000 belong to a queue.

A later delivery-time census DOES identify the old composed island's top-level
mapped registers and ALUTs (section 17.10). It does not fill this separate
owner-fit attribution gap. The two reports describe different netlists.

Instead it identifies costly structures that the source definitely contains,
proposes changes with explicit functional proofs, and requires ablations to
measure each contribution. This is the boundary between diagnosis and guessing.


2. WHAT THE CURRENT OWNER RTL ACTUALLY BUILDS
===========================================

2.1 Persistent control is 30 bits per owner, before its access logic
------------------------------------------------------------------

The source declares, for 64 owners:

  live                         1 bit
  generation                   8 bits
  required                     4 bits
  issued                       4 bits
  claimed                      4 bits
  committed                    4 bits
  ready_claimed                1 bit
  combine_issued               1 bit
  final_claimed                1 bit
  final_done                   1 bit
  fetched                      1 bit
                              -------
                               30 bits/owner = 1,920 bits

It then declares a corresponding next-state structure and folds issue, claim,
publication, readiness, combine selection, fetch, release, and admission into
it. A next-state copy is not automatically another 1,920 flip-flops; synthesis
can collapse the combinational aliases. The real costs are the state, its
read selectors, event decode, update enables, priority, and routing. [R01]

The lesson is not "always_comb is expensive." The lesson is that the control
problem was implemented as a broadly indexed multi-consumer table even though
allocation and release are ordered and individual fields have distinct writers.

2.2 Generation is queried in many places
----------------------------------------

Examples include admission's next generation, TMU issue validation, AUX issue
validation, three return snapshots, two readiness decisions, and publication
checks. That is a large access network around only 512 stored generation bits.

The publication loop deserves particular care. It compares gen_q[i] with the
return generation inside the loop over all 64 owners, for TMU, AUX and final
publication. At RTL elaboration that describes 64 x 3 comparison sites, not
one comparison per lane. The comment's "one 8-bit compare per lane" is not an
accurate description of the elaborated source structure. [R01]

Quartus may factor some logic. Do not turn 192 source comparison sites into an
unmeasured claim of 192 independent fitted comparators. But neither should a
comment describing three comparisons substitute for inspecting the loop.

2.3 Return snapshots are wider than the validation needs
-------------------------------------------------------

TMU and AUX each snapshot live, generation, all four required bits, all four
issued bits, all four claimed bits, and all four committed bits. AUX needs one
source bit. A TMU return needs one of the three sample-source bits. If claimed
is retained through release and committed implies claimed, separately reading
committed to reject duplicates is redundant.

The replacement should exploit those invariants at the read boundary rather
than carry every mask everywhere and discard most of it later.

2.4 Readiness performs another set of indexed state reads
--------------------------------------------------------

After writing the payload, the current block computes updated committed masks
by indexing cmt_q with the TMU and AUX publication slots. It then indexes live,
generation, required, ready_claimed and combine_issued again to discover which
owner became ready. A same-owner comparison merges simultaneous TMU/AUX events.

The result is logically sensible and much safer than losing simultaneous
updates. Physically it is a second table-query machine after terminal
validation. A row-local committed mask can absorb those events once and expose
a one-bit local eligibility signal without a second global query.

2.5 Three deep ready FIFOs are real; invented extra FIFOs are not
----------------------------------------------------------------

The inspected owner file contains READY_TMU, READY_AUX and READY_INITIAL,
each a 64 x 14 synchronous queue with a two-register show-ahead head. It also
has separate wide COMBINE and final-output holding queues. Do not diagnose
six owner issue-order FIFOs: that is not what the pinned file contains.

A source analysis must stay tied to the actual file, particularly when several
versions and agents have been discussed in the same conversation.

2.6 The wide holding queues remain expensive state
--------------------------------------------------

At the default parameters, the COMBINE holding queue stores:

  4 x (owner14 + four result40) = 696 bits.

The ordered output holding queue stores:

  4 x (owner14 + result40 + context64) = 472 bits.

Together they declare 1,168 payload bits before read/capture stages, pointers,
reservations and output multiplexers. Their outputs are dynamically indexed
from the current read pointer. These are deliberately small structures, not
the original giant tables, but they are not free. [R01]

Some storage may be optimized or mapped into memories by the tools. The
resource report, rather than the word "registers" in a source comment, decides
what it physically became. The replacement inventories these queues explicitly.

2.7 COMBINE-issued is set earlier than its name suggests
-------------------------------------------------------

cbi is set when the ready token is popped and a bank read is reserved, not
when cmb_valid_o && cmb_ready_i actually accepts the COMBINE input. The final
return validator uses cbi as its evidence that COMBINE was issued. [R01]

That is enough for a cooperative fake COMBINE which never returns early. It is
not the exact meaning of an issued operation. A deliberately injected final
packet arriving while the COMBINE input is stalled deserves a directed test.
The replacement uses different bits for reservation and actual acceptance.

2.8 The payload-bank implementation is worth retaining
------------------------------------------------------

zhao_texture_v3bank has the appropriate narrow role: one synchronous writer,
one synchronous reader, no payload reset, and a direct memory-read capture.
The sample banks are statically instantiated. Registered write enables isolate
terminal validation from RAM control. Keep that shape. [R03]

Do not generalize its comments into the false rule that every SystemVerilog
wire alias inserts logic or that a generate loop cannot connect a register to
a memory. Those are limitations of a source checker, not silicon laws.


3. DIAGNOSIS: ESTABLISHED STRUCTURES VS UNMEASURED ATTRIBUTION
===========================================================

The working diagnosis has four parts.

First, the implementation successfully moved persistent wide payload into
RAM but left control access generalized. Narrow state can still be expensive
when read many ways, updated from many events, and routed globally.

Second, readiness queries replicate information already present in the rows.
The new candidate structure changes where selection happens: local eligibility
and local slot capture first, global selection of a few registered candidates
second. It does not invent a global 64-way priority encoder feeding wide data.

Third, generation and liveness are over-represented. Ordered allocation and
ordered release imply that live identities form one short consecutive sequence
window. An indexed per-slot generation table is unnecessary for that model.

Fourth, global observability and rare drain conditions feed ordinary interface
outputs. Quiet and occupancy must be correct, but correctness does not require
a combinational tour through every queue pointer on the admission path.

None of these four statements tells us the exact fitted savings. They justify
experiments and implementation changes. M0/M1/M2 are intentionally separated so
we can discover whether timing changes came from boundary isolation, identity
compression, or the ready selector.

Rejected explanations at this point:

  "RAM did not infer."       Contradicted by the reported payload storage.
  "The whole V3 idea failed." Contradicted by useful arithmetic/storage results.
  "Only the queue is costly." Not established by a worst timing path.
  "Only debug outputs matter." Not established by endpoint names alone.
  "Just use 32 owners."      Changes the experiment and hides a capacity cost.
  "Raise the budget to 5678." Records acceptance without solving the problem.

There is still a possibility that a fully correct 64-owner design costs more
than the original allocation. The plan includes a decision point for that
outcome. It does not assume all bad numbers are optimizer mistakes.


4. NON-NEGOTIABLE FUNCTIONAL AND THROUGHPUT CONTRACTS
===================================================

4.1 Capacity and lifetime
------------------------

Keep 64 simultaneous owners. Allocate in sequence order. Release only when the
ordered final output is accepted. Maintain the entire 64-bit opaque context
until then. Internal source completion and final-result production can be out
of order; external emission cannot be.

Individual owners are not freed out of order. An error produces a terminal
status/result through ordinary retirement, unless a whole-domain abort drains
or resets the entire island and all of its external work under an explicit
barrier. This condition is essential to sequence-window identity compression.

4.2 Source identities
---------------------

Four required-source bits retain their current meanings:

  bit 0 sample zero; bit 1 sample one; bit 2 sample two; bit 3 AUX.

A TMU packet with sample index three is malformed, not an alternate AUX packet.
AUX keeps its typed return port. Final COMBINE completion is a distinct channel.
All external handles retain slot plus generation. Internal slot-only tickets
are legal only where a proved ownership lease prevents reuse for their lifetime.

4.3 Simultaneous work
--------------------

Support one TMU terminal, one AUX terminal and one final terminal each cycle
on their separate channels, including TMU and AUX for the same owner. Preserve
one-per-clock admission in the unstalled steady case, one-per-clock COMBINE
input transfer when the consumer and completed owners permit it, and one-per-
clock ordered output when contiguous final results and the consumer permit it.

These are interface peak rates, not a claim that the complete textured material
pipeline produces one complex fragment every clock.

4.4 Fault and exactness behavior
--------------------------------

Reject malformed, stale, unissued and duplicate returns before their payload
can change a live result. Preserve status8 independently of its RGB diagnostic
representation. A refused sample can be transformed by a material recipe while
its error status must still survive.

Do not recover area by forcing alpha to 255, dropping CLUT4 nibble selection,
turning off nearest decoding, reducing sample count, replacing exact fixed-point
operations with approximations, or detaching useful AUX/Mosaic outputs.

4.5 Performance is measured on complete workloads
------------------------------------------------

A narrower interface may add registered latency, but it must not quietly lower
accepted-job throughput or usable owner capacity. Every additional pipeline
stage requires reservation accounting and a test that saturates the affected
service. A latency-tolerant architecture is not an architecture with infinite
contexts or free buffers.

No command or gameplay decision is made here from wall-clock fitter timings.
Execution-latency and queue-organization changes are internal implementation
changes; any capture-visible timing contract or performance-profile version
must be updated explicitly.


5. REPLACEMENT ARCHITECTURE AT A GLANCE
======================================

                          ALLOCATION / RELEASE
               alloc_seq A, emit_seq E, live_count C
                   full identity exists in [E, A)
                                |
                    admission context/material banks
                                |
         +----------------------+--------------------------+
         |                      |                          |
    ISSUE notices         TMU / AUX returns         final returns
    range + window        capture -> bit snapshot   capture -> snapshot
    + required check      -> claim + window check   -> claim + window check
         |                      |                          |
         v                      v                          v
   +----------------------------------------------------------------+
   | Eight control groups, eight owners/group                        |
   | required / issued / claimed / committed, source-owned bitplanes  |
   | active / combine_reserved / combine_issued / final_claim / done  |
   | local eligibility -> two small registered candidate slots       |
   +----------------------------------------------------------------+
                          |                         |
                8-way candidate arbiter      registered final cursor
                          |                         |
                  reserve packet credit      reserve output credit
                          |                         |
                  registered bank address    registered bank address
                          |                         |
                sample/AUX/material banks    final/context banks
                          |                         |
                credited COMBINE ingress     credited ordered output
                          |                         |
                retained COMBINE V2           accept -> E advances
                          |
                     final return

No ready-queue occupancy subtraction feeds admission.
No per-slot generation RAM/flop table is required in the selected identity mode.
No publication event performs another global required/committed lookup.
No final result is authorized merely because a COMBINE input read was reserved.
No payload bank is reset to make invalid reads look harmless.

A diagnostic snapshot network runs beside this pipeline. It reports real counts
but is not a combinational participant in acceptance or arbitration.


6. REPLACE THE PER-SLOT GENERATION TABLE WITH A SEQUENCE WINDOW
============================================================

This is the highest-leverage structural simplification in this proposal.
It uses an invariant the current RTL already maintains instead of introducing
a probabilistic tag trick.

6.1 Representation
------------------

Keep the external OwnerHandle layout:

  owner handle = {slot[5:0], generation[7:0]}
  sample handle = {slot[5:0], sample_index[1:0], generation[7:0]}

Internally, repack an owner handle into a sequence number:

  sequence = {generation[7:0], slot[5:0]}

This is a rearrangement of fields, not a narrower identity. External clients
continue carrying all 14 identity bits. A sample index is not part of the owner
sequence and must be range-checked separately.

Define:

  A : 14-bit next allocation sequence
  E : 14-bit next emission sequence
  F : 14-bit next final-result fetch sequence
  C : 7-bit live owner count, range 0..64

Initialize A=E=F=64. That is slot zero, generation one, matching the current
per-slot generation increment from reset-zero on its first admission.

On accepted admission, issue the external handle repacked from A, then A++.
On accepted external output, E++.
On an accepted final bank-read reservation, F++.
All arithmetic on the 14-bit sequences is explicitly modulo 16,384.

C updates once:

  C_next = C + admission_accept - output_accept.

A separate unfetched count can retain the existing efficient update form:

  U_next = U + admission_accept - final_fetch_accept.

Do not rebuild C or U by wide subtraction in the admission critical path.

6.2 Live membership
-------------------

For a decoded return sequence R:

  distance = (R - E) modulo 16,384
  is_live  = distance < C

C never exceeds 64, so no two live owners share a slot, and a previous-generation
return with the same slot lies outside the window. This is an exact membership
test for a circular interval of known bounded length, including the interval
crossing numeric zero.

The circuit is one bounded-width subtraction and comparison per validation
lane. It is not a 64-entry generation read followed by a comparison, and it is
not 64 parallel generation comparisons.

If timing requires it, exploit the small distance bound:

  upper distance bits must be zero;
  the remaining seven bits must be less than C.

Do not truncate the subtraction before checking those upper bits. Doing so
would alias stale generations back into the live window.

6.3 Why this is equivalent to the existing per-slot generation counters
----------------------------------------------------------------------

Allocation is strictly round-robin by slot. Therefore every time a slot is
allocated, all slots before it in that round have already been allocated once
and slots after it have not. Its generation is exactly the high sequence field
associated with that allocation round.

The existing implementation resets each generation to zero and increments the
selected slot's generation at admission. Starting the new full sequence at
slot zero/generation one produces the same external handle sequence. The
supplied trace compares 33,281 admissions against an explicit legacy array of
64 eight-bit generation counters, including two full namespace drains. [E01]

A mathematical proof is simple induction:

  Base: slot zero receives generation one in both systems.
  Step within a round: both advance to the next slot with that round's generation.
  Step across slot 63: both return to slot zero and increment its generation.

The old implementation checks wrapping separately when each slot would reuse
generation zero. A single full-namespace barrier is sufficient before the first
such reuse because all old work is drained globally. Requiring the same global
drain for each of the following 63 slots is not a correctness necessity.

6.4 Conditions under which compression is NOT valid
---------------------------------------------------

This representation requires:

  * allocation advances by one slot in order;
  * final release advances by one slot in the same global order;
  * at most 64 owners are live;
  * individual owners are not removed from the middle of the interval;
  * reset/abort cannot leave old external work alive while resetting the window;
  * a full handle namespace is not reused without a real barrier.

Out-of-order sample completion and COMBINE execution do not violate these
conditions. Out-of-order FREEING does.

A future free-list allocator, arbitrary cancellation, or multiple independent
retirement heads would need a different identity representation. The code and
contract must assert these preconditions so a later extension cannot silently
invalidate the proof.

6.5 Reconstructing a full token from an internal slot-only candidate
-------------------------------------------------------------------

A candidate is reserved while its owner is live and cannot outlive that owner.
It therefore needs only the slot inside the ready-control network.

Given slot S and current emission sequence E:

  offset = (S - E[5:0]) modulo 64
  sequence = E + offset modulo 16,384

Require offset < C, or equivalently an active reserved row for that slot plus
the global membership assertion. The resulting sequence is the unique live
owner with that slot. Repack it into the external {slot,generation} layout
when submitting to COMBINE.

This reconstruction is done after central candidate selection and is
registered before it accompanies the bank read. It is not replicated per row
or mixed with wide payload selection.

A token reconstructed with the pre-edge E remains correct if E advances on
that edge: the chosen reserved owner is not the owner being emitted unless
the lifecycle is already broken. Candidate ownership prevents that case.

6.6 Snapshot identity must survive pipeline races
------------------------------------------------

A return pipeline reads narrow control at one edge and claims later. Between
those edges an old owner might retire and the slot might be reused. Do not
replace the generation table with only a stale Boolean captured several clocks
before the write.

The proposed validator uses:

  identity_valid_at_snapshot
  AND identity_valid_in_current_live_window_at_claim
  AND issued_snapshot
  AND NOT claimed_snapshot_or_recent_claim

A future-generation packet that was not live at the snapshot cannot become
valid simply because a new admission happened later. An old-generation packet
that ceased to be live before claim cannot write the replacement owner.

The current-window check is cheap precisely because it no longer needs an
indexed generation table. This is a reason to simplify identity before adding
more return pipeline depth.

Fault classification is evaluated at the documented validation point. A packet
that becomes stale while waiting may be classified stale rather than duplicate.
Tests must compare the stated classification law, not undocumented timing of
the predecessor's error counters.

6.7 What this saves structurally
--------------------------------

It removes the 512-bit per-owner generation array and its update path, replaces
its many read ports with small sequence-window checks, and removes per-row
generation comparisons from trusted internal publication. It also permits
internal ready candidates to carry six-bit slots instead of fourteen-bit
handles.

Those are source-level structural savings. Their ALM effect must be measured.
A 512-bit register deletion is not automatically a 512-ALM saving, and a reused
subtractor is not automatically cheaper than every possible mapped mux.


7. SOURCE-OWNED, ROW-LOCAL CONTROL BITPLANES
==========================================

7.1 The replacement state inventory
-----------------------------------

For each owner slot retain:

  active                        1
  required                      4
  issued                        4
  claimed                       4
  committed                     4
  combine_reserved              1
  combine_issued                1
  final_claimed                 1
  final_done                    1
                               --
                               21 bits x 64 = 1,344 bits

This is 576 fewer persistent control bits than the current 1,920-bit table.
Global A/E/F sequences, counts, ready candidate registers and pipeline records
are additional state and must be counted separately.

active is retained as an inexpensive local eligibility gate. It is not a
substitute for full sequence validation on external packets. Keeping 64 active
bits avoids reconstructing live-window membership independently at every row
just to determine local readiness.

ready_claimed is replaced by combine_reserved, set when a local candidate is
created. The old per-owner fetched bit is removed because F advances exactly
once per accepted fetch and output capacity is explicitly reserved. Actual
combine_issued is separate from reservation.

7.2 Static field ownership
--------------------------

View the four source bits as four independent planes with common owner indices:

  required[s]  written on admission, immutable thereafter;
  issued[s]    set by the successful issue event for source s;
  claimed[s]   set by accepted terminal validation for source s;
  committed[s] set by publication of the corresponding completed payload write.

TMU can affect one of bits 0..2 on a cycle. AUX can affect bit 3 on the same
cycle. They do not need competing read-modify-writes to a single mask register
if the fields are organized explicitly.

A row's next committed mask is the OR of its present mask and the independent
registered source publication strobes for that row. Same-owner simultaneous
TMU/AUX events coalesce naturally at the row. Different-owner events update
independent rows. No global same_owner lookup is necessary to discover the
combined result.

Admission clears all dynamic phase bits for the newly allocated row and writes
its required mask. The old owner has already been released before ordinary
reuse; with conservative admission credit, there is no same-edge full-ring
release/reallocation ambiguity to optimize away prematurely.

7.3 Physical grouping
---------------------

Partition the control physically into eight groups of eight consecutive slots:

  group = slot[5:3]
  row   = slot[2:0]

Each group owns its active/phase bits, local ready selector and two candidate
registers. Use static generate boundaries or separate instances that make the
intended grouping visible to synthesis and reporting.

Register or factor event-address decode so a local update is driven by a
small group-valid and row-select signal, not by a fresh full token comparison
replicated inside every row.

Do not broadcast forty-bit payloads through the control groups. Payload belongs
to the corresponding source bank and the registered bank-write record. Control
needs the addressed slot, source bit, event validity and limited status.

7.4 Avoid both extremes
-----------------------

Do not put this genuinely concurrent control into one impossible multiported
M10K. Admission, issue, claim, publication, reservation and release can affect
different rows simultaneously.

Do not expand every predicate into 64 full identity comparisons either. The
sequence-window validator authenticates a return centrally per lane. A trusted
accepted event is then decoded to the row that owns the relevant bit.

Narrow fabric bitplanes are intentional. A 64-to-1 ONE-BIT read can be a
reasonable selector; a dozen wide 64-row state reads is a different design.
The structural gate must distinguish those cases instead of banning all arrays
or all asynchronous fabric control reads by name.

7.5 Invariants that permit narrower validation
---------------------------------------------

For every live row:

  committed is a subset of claimed;
  claimed is a subset of issued;
  issued is a subset of required;
  final_done implies final_claimed;
  final_claimed implies combine_issued;
  combine_issued implies combine_reserved.

These are assertions and induction obligations, not comments to assume.

They let a terminal snapshot carry the selected issued and claimed bits rather
than all four required/issued/claimed/committed masks. required remains fully
stored for issuing and readiness; its validation condition is implied by a
valid issued bit. committed cannot admit a duplicate that claimed would miss
because claimed remains set until owner reuse.

7.6 Update precedence
---------------------

Use one defined precedence per state field, not several accidental nonblocking
assignments whose source order decides the answer.

Normal same-cycle events are accumulated before the single update. Admission
initializes a new row only after old ownership is gone. A coordinated reset or
abort overrides normal events only under the domain-reset protocol. An illegal
attempt to admit into an active slot is an assertion/fault, not a clever
precedence rule.

A useful implementation style is separate small next-state equations per
source bit, plus explicit row-init and row-release. This preserves simultaneous
updates without forcing the entire owner record through one broad update mux.


8. NARROW TERMINAL VALIDATION AND EXACT CLAIM FORWARDING
======================================================

8.1 Baseline stage schedule
---------------------------

For a terminal observed at edge T:

  T     R0 capture: type, full handle, payload and range result.
  T+1   R1 snapshot: selected issued/claimed bits and snapshot identity validity.
  T+2   R2 claim: current-window recheck, duplicate forwarding, accept/reject;
                 update claimed and register bank-write record.
  T+3   W  write: registered address/data/enable write the payload bank.
  T+4   P  publish: set the source committed bit in its local row.
  T+5   Q  earliest local candidate claim using the published row state.

The exact names need not reproduce the old C0/C1/C3 nomenclature. The ordering
must. The bank's write enable is a register output formed before the write
edge. A source is not readable until the later publication edge.

With separate TMU, AUX and final lanes, each stage accepts one packet per cycle
per lane. Invalid packets occupy pipeline stages but never reserve a payload
write or a ready candidate.

8.2 Snapshot fields
-------------------

TMU R1 needs:

  packet-valid; legal sample index; full sequence/sample identity;
  snapshot-window-valid; selected issued bit; selected claimed bit;
  payload40.

AUX R1 needs the same information with its source fixed to AUX.

Final R1 needs:

  packet-valid; full sequence; snapshot-window-valid;
  actual combine_issued bit; final_claimed bit; payload40.

The source index is not dynamically decoded again at the RAM write boundary.
Create the one-hot sample bank enable in R2 and register it.

8.3 Duplicate forwarding
------------------------

R1 samples before an R2 claim applied on the same edge becomes visible in
stored state. Therefore the following cycle's R2 may contain a snapshot that
missed the previous claim.

Keep the accepted R2 claim record from the preceding cycle. Compare it against
the new R2 packet by FULL sequence plus source. Treat a match as already
claimed. TMU, AUX and final have separate writers and their own relevant claim
history.

For the baseline one-edge snapshot-to-claim separation, one previous accepted
claim record per channel is sufficient. If an extra registered mux stage is
inserted, derive the history length from the actual visibility distance and
extend it. Never keep FWD_WINDOW=1 merely because the predecessor used one.

The cost of this tiny recent-event comparison is intentionally paid instead of
reading a large state table combinationally at the write enable.

8.4 Issue and return on adjacent or identical edges
-------------------------------------------------

The issue event must mean that the service accepted work, not that the planner
wanted to issue it. A required bit alone is not proof of an outstanding request.

A return can legally be very fast. The implementation must define the minimum
issue-to-return latency at each adapter. If a terminal can be captured on the
same edge as issue, R1's snapshot must incorporate the appropriately validated
issue event or its forwarding record. Otherwise a legal warm hit can look
unissued simply because issue and snapshot updated on the same edge.

Do not fix that by marking every required source issued at admission. That
would make an unsolicited response appear legitimate and erase a distinct
lifetime phase.

An implementation may stage issue validation, but must add a directed test for
same-edge issue/return and one-edge-later return. Either support both explicitly
or enforce the documented minimum latency at the real producer seam. The
architectural checker supplied here isolates terminal claim forwarding; it is
not evidence that a new staged issue adapter already handles these cases.

8.5 Error priority and counters
-------------------------------

Use a stated mutually exclusive classification order:

  malformed source/range;
  identity not live at snapshot or claim;
  not issued;
  already claimed, including forwarding;
  accepted.

For final returns use actual COMBINE acceptance and final-claim state. An early
final result is an error even when the owner has a ready-candidate reservation.

Count accepted write records separately from committed results and external
emissions. Under traffic in flight those totals need not match on every cycle;
at a completed drain they must satisfy their conservation identities.

8.6 No unsafe simplification at the wrap boundary
------------------------------------------------

Full-handle comparison remains on external inputs. Slot-only identity is used
only inside leases whose owner cannot be released before their use ends.
A stale external reply must never be converted to a slot-only internal event
before identity validation.

An eight-bit generation is not protection against arbitrarily old messages
after an entire namespace reuse. The drain protocol, external credit return
and transport reset/acknowledgement establish that old work is gone. Widening
a counter delays the problem but does not remove the protocol obligation.


9. COMMIT AND PUBLICATION WITHOUT A SECOND GLOBAL TABLE LOOKUP
============================================================

9.1 Trusted accepted events
--------------------------

Once R2 accepts a source terminal, the accepted record owns exactly one payload
write and its later publication. In ordinary operation that owner cannot be
freed between claim and publication:

  the source is not committed yet;
  readiness therefore cannot legitimately advance this required source;
  a valid final output cannot have completed that owner;
  only final output acceptance frees it.

For a final terminal, final_done cannot be true before its own write/publish,
so retirement likewise cannot overtake the accepted write record.

This is the proof that allows internal publication to update a predecoded row
without re-reading all generation state. The previous per-row publication
compare did not protect the preceding payload write from a hypothetical
post-validation corrupted token anyway. It was not an end-to-end soft-error
protection mechanism.

9.2 Row-local coalescing
------------------------

For a particular row i:

  published_bits_i = tmu_publication_for_i | aux_publication_for_i
  committed_next_i = committed_i | published_bits_i

The source masks are disjoint on a same-cycle TMU/AUX pair. No event disappears
through last-assignment-wins behavior. Required and issued masks are immutable
or monotone through the appropriate stages.

The local ready selector observes the updated row on the next cycle. A one-cycle
later ready decision is acceptable because it does not lower the number of
rows that can become ready or the steady selection rate. It removes the need
to ask two global indexed queries which publication made the owner ready.

9.3 Cancellation is not an exception to ownership
------------------------------------------------

Do not add "clear live now" for a convenient cancellation after accepting a
terminal. That invalidates the claim-to-write proof and would require a kill
check at every in-flight stage plus a delayed credit protocol.

The baseline cancellation choices are:

  ordered error completion for an individual owner; or
  stop admission and drain/reset the whole domain with external acknowledgement.

A later fast-cancel feature is a separate architecture amendment, not an
unreviewed branch inside this pipeline.

9.4 Read-during-write is explicitly unobservable
------------------------------------------------

The useful data read of a source row occurs only after publication. The useful
final/context read occurs only after final publication and the earlier context
write. Any free-running physical RAM read on the same address as a write has
invalid consumer timing and cannot affect a valid output.

That permits a read-during-write don't-care implementation if verified against
the actual primitive and consumer-valid rules. It does not permit an agent to
add no_rw_check to arbitrary memories just to get smaller results. [V03, V04]

Reset clears ownership and pipeline validity. It does not clear every payload
row. Poisoned/uninitialized payload tests must verify that missing required
sources never leak through a supposedly valid result.


10. REPLACE DEEP READY FIFOS WITH LOCAL CANDIDATE REGISTERS
=========================================================

10.1 Why change the ready representation
----------------------------------------

There are never more than 64 live owners, and each can become eligible for
COMBINE once. Readiness is already represented by local monotone state.
Maintaining three separate 64-deep histories of which producer caused that
transition is not necessary to execute the material.

The replacement stores at most two SELECTED candidates per group, not an
unbounded event queue. Unselected ready work remains represented by its own
row. There is no event to lose because readiness persists until reserved.

This is an amendment to the earlier V3 requirement for three producer-owned
FIFOs. It should be recorded as such, not made to look like compliance with an
unchanged requirement.

10.2 Local eligibility
----------------------

For each of the eight rows in a group:

  eligible = active
             && !combine_reserved
             && ((committed & required) == required)

A zero-source owner is eligible after admission initializes its required mask
and local active bit. A normal owner becomes eligible only after all required
payload writes have published.

No generation query participates in this local eligibility calculation. The
row's active lifetime and internal reservation lease identify the owner.

10.3 Two candidate registers per group
-------------------------------------

Each group has:

  head_valid, head_row[2:0]
  spare_valid, spare_row[2:0]
  local round-robin cursor[2:0]

The group number supplies the high three slot bits. Sixteen total candidates
therefore need only small slot indices and valid bits, not three 64x14 memory
bodies and their pointer arithmetic.

Each cycle a group may reserve at most one eligible unreserved row. It sets
combine_reserved for that row on the same edge that inserts the candidate.
That bit prevents the row from being selected again while it waits.

A simultaneous central pop can free one of the two candidate registers. The
local selector can refill that capacity from a different eligible row on the
same edge. Data and validity update in one explicit head/spare transition.

Two registers matter: they separate local readiness from global arbitration
without forcing a bubble on every refill. The supplied model checks an
isolated hot group delivering all eight rows on eight consecutive grants.

10.4 Global arbitration
-----------------------

The central arbiter sees eight REGISTERED candidate heads. It does not see the
64 raw committed masks, the payload banks, or return packets.

It uses deterministic round-robin selection across valid heads. It pops a
candidate only when the downstream bank-read/COMBINE packet reservation has
capacity. Selection, reconstructed full owner sequence, and bank address are
registered together.

Local round-robin advances on candidate reservation. Global round-robin
advances on central pop. Neither cursor advances just because work was looked
at or a consumer happened to be ready.

10.5 Progress and fairness
-------------------------

A ready row remains eligible until it receives a local reservation. An existing
candidate remains valid until the central arbiter pops it. A popped candidate
owns downstream storage until COMBINE accepts its input. These three facts
replace producer-event queue conservation.

A continuously valid group cannot be starved by other continuously valid groups
under central round-robin. A row cannot be starved by later rows within its
group under local round-robin. Consumer stalls can delay all progress, but do
not discard readiness or cause a duplicate selection.

Do not publish an arbitrary cycle bound such as "always under eight clocks."
Two levels of arbitration, candidates already ahead, local refill latency and
downstream stalls all matter. Verification must measure service opportunities
and prove bounded fairness under explicit downstream-progress assumptions.

10.6 What happens when all 64 owners are ready
---------------------------------------------

At most sixteen occupy candidate registers. The other ready owners remain in
the bitplanes with combine_reserved clear. As candidate slots drain, local
selectors reserve the remaining rows.

No extra ready FIFO capacity is required, and no readiness event is overwritten.
The owner capacity remains 64. This is not the rejected trick of reducing each
producer queue to 64/3 entries.

10.7 Counter semantics
----------------------

The number of local claims on an edge can be as high as eight in an artificial
all-ready batch. A global ticket counter's delta must therefore be at least
four bits if it counts those claims. Do not retain a two-bit delta from the old
three-producer design and silently wrap it.

An alternative is per-group counters with an explicit snapshot reduction. In
either case diagnostic reduction must not feed scheduling or admission.

At a complete drain every admitted owner must have exactly one ready reservation,
one actual COMBINE issue, and one final output. Mid-flight counts have different
pipeline meanings; document them.


11. COMBINE RESERVATION IS NOT COMBINE EXECUTION
==============================================

11.1 Three distinct events
--------------------------

The replacement distinguishes:

  local candidate reservation:
    the owner is claimed for eventual COMBINE admission;

  central bank-read reservation:
    storage is reserved for the operand/material packet that will arrive later;

  actual COMBINE acceptance:
    the complete input packet transfers on valid && ready.

Only the third sets combine_issued and authorizes a final terminal.

The old cbi bit was set at the second event. The new combine_reserved bit covers
the first two ownership stages; the new combine_issued bit covers execution.

11.2 Preserve out-of-order completion
-------------------------------------

A young owner whose source work completes first can be selected first. Its
final result is written to its own final bank row. Global emission waits for E,
not whichever final packet arrived most recently.

This is why the single external ordering boundary is retained. Do not restore
a global in-order COMBINE issue queue just to simplify a testbench; that would
reintroduce head-of-line blocking between source completion and material work.

11.3 Final-return test that must be added
----------------------------------------

Construct an owner with all source results committed. Let it become reserved
and enter the COMBINE input staging path. Hold cmb_ready low. Inject a final
return with the correct owner token before COMBINE accepts the input.

Expected behavior:

  final error is recorded;
  no final payload write is authorized;
  final_done remains false;
  the owner is not released;
  after real COMBINE acceptance, a legitimate final return succeeds.

This test distinguishes a reservation bit from an issue bit. A cooperative
stub that always responds after input acceptance cannot exercise it.

11.4 Retain the V2 material kernel
----------------------------------

Do not rewrite the paired byte-product organization merely because the owner
control implementation failed. Preserve the exact recipe equations, rounding,
alpha behavior, and status propagation. Adapt its input ownership, packet
staging and tag path; measure those adaptations separately from its arithmetic.

A future direct reservation into a COMBINE execution context might eliminate
an intermediate wide packet queue. It also occupies execution contexts during
bank-read latency and can reduce throughput. Treat that as a later measured
alternative, not a free optimization assumed in the baseline architecture.


12. CREDITED BANK READS AND WIDE PACKET BUFFERING
================================================

12.1 A reservation covers the entire data path
---------------------------------------------

Once a candidate is popped, the following payload transfer cannot depend on the
consumer remaining ready. Reserve capacity before the bank read. Release that
capacity only when the packet is accepted at the final consumer of this path.

For COMBINE ingress, reservation accounting includes:

  address/identity stages in flight;
  bank read/capture stages;
  a queued packet body;
  queue prefetch in flight;
  show-ahead head/spare registers;
  the offered but stalled COMBINE packet.

For final output, the same rule extends until out_valid && out_ready. Prefetching
a final row is not emission and does not release the owner.

12.2 Keep the old queues for the first control ablations
-------------------------------------------------------

M1-M4 retain the existing four-entry wide holding queues so a measured control
change cannot be confused with a simultaneous buffering change. Their costs
remain visible. This is the baseline for the attribution experiments, not the
final memory-efficient profile.

12.3 Selected memory-efficient profile
--------------------------------------

For M5 use RAM-backed packet storage with a logical reservation capacity of
sixteen for COMBINE ingress and sixteen for final output. Sixteen is not a new
owner limit; both paths draw from the same 64-owner lifetime.

The physical body can be sixteen rows deep while the logical capacity includes
all pipeline/head reservations. A packet moved from body to a prefetch register
still consumes one logical reservation. Body capacity and total logical
capacity must never be confused.

Use two registered show-ahead slots and a synchronous body, with the exact
pending-read accounting missing from the old ready queue corrected. The body
has one writer and one reader. Its useful read cannot collide with an
unpublished write. No full packet is read through a combinational sixteen-way
mux directly onto the external consumer port.

For the isolated owner demonstrator the COMBINE packet is 174 bits:
owner14 plus four result40 values. Five width slices are the conservative
simple-dual-port M10K allocation.

For the feature-live adapter, provision a 240-bit row:
owner14 + material48 + four result40 + required4 = 226 useful bits, with fourteen
explicitly reserved/padded bits. Six width slices are allocated. The exact
material binding contract must be checked before freezing this row; no field
may be dropped merely to preserve 240.

The output packet provisions 120 bits:
owner14 + result40 + context64 = 118 useful bits, plus two reserved bits.
It allocates three simple-dual-port M10K width slices.

The additional memory is deliberate. It buys a fixed-size physical store rather
than another collection of wide fabric queues. It is not promised to reduce ALMs
until the M5 fit measures the whole body/head/control structure.

12.4 Capacity and sustained rate
--------------------------------

A registered-credit interface that refuses to borrow same-edge returned credit
needs enough capacity for the complete request-to-consumption latency plus
margin. Otherwise it can insert periodic bubbles despite a perfectly willing
consumer.

The supplied model checks six reservations with a four-cycle modeled data
latency and also sixteen reservations with an eight-cycle modeled latency.
Both can sustain one launch per clock in the corresponding unstalled model.
The real RAM FIFO's exact edge schedule must be measured; the model does not
establish that its implemented latency is eight.

The selected sixteen-slot profile is intentionally larger than the minimum
inferred from the old three-stage bank-read path. Width determines most of the
small M10K allocation here, so deeper logical buffering need not consume more
M10Ks while it removes fragile same-edge-ready arithmetic.

12.5 No hidden credit borrowing
-------------------------------

Prefer available_credit_q > 0 for launching a read. Update credit once using
launch and terminal-consumption deltas. Do not put consumer ready through a
subtract/compare back into the selection logic unless the design explicitly
needs same-edge reuse and the timing report justifies it.

If the measured latency exceeds the allocated window, stop and reconcile the
capacity rather than silently adding an uncounted wide skid register.

12.6 Validity of absent sources
------------------------------

The bank read may physically return values from all four source planes.
For unrequired sources the values are not semantically initialized. The packet
assembly stage must mask those lanes to the reference-defined bypass value
before presenting them as valid COMBINE inputs.

Do not reset all sample RAMs to zero and then call the test green. Initialize
only real admitted context/material records and publish real source results.
Poison missing-source rows in simulation so illegal consumption is visible.


13. ORDERED RETIREMENT WITHOUT A PER-OWNER FETCHED BIT
====================================================

13.1 The fetch cursor already names the next unfetched owner
----------------------------------------------------------

F advances only when a final bank read has been reserved. It never scans past
an incomplete owner. Therefore no owner can be fetched twice if F and the
reservation counters are correct.

Require:

  U != 0;
  active[F.slot];
  final_done[F.slot];
  output packet capacity available.

Then reserve output capacity, register F's full token/address, and increment F
once. Remove the per-owner ftc/fetched array. It represented a property already
encoded by a monotone ordered cursor.

13.2 Three positions, three different meanings
----------------------------------------------

E is next externally emitted owner.
F is next final row not yet reserved for output reading.
A is next owner to allocate.

In circular interval terms:

  [E, F) : owners reserved/fetched for output but not yet externally emitted;
  [F, A) : owners not yet fetched;
  [E, A) : all live owners.

At most 64 owners inhabit the union. The output reservation count corresponds
to the first interval, including data in flight, unless an explicitly separate
stage owns a documented portion. Avoid two counters whose overlap is inferred
only from naming.

13.3 Output release
-------------------

On out_valid && out_ready:

  require offered full sequence equals E;
  require its row is active and final_done;
  release output packet reservation;
  clear active for that slot;
  increment E;
  decrement live_count.

The payload/context banks may retain their old bytes. They are invalid after
active clears and become owned only by a later admission with a new sequence.

13.4 Stalls and synchronous memory
----------------------------------

Hold owner/result/context stable while out_valid && !out_ready. Internal
prefetch may fill other reserved slots, but it cannot replace the offered head.
The second show-ahead register and pending-read reservation absorb the already
launched RAM read when the consumer stops.

This is a cycle-level property, not something a final CRC detects reliably.
A consumer that is always ready is not an adequate retirement test.


14. QUIESCENCE, GENERATION WRAP, RESET, AND ABORT
================================================

14.1 Remove quiet from the ordinary admission cone
--------------------------------------------------

Use an explicit controller:

  RUN -> STOP_ADMISSION -> DRAIN_LOCAL -> WAIT_EXTERNAL -> REOPEN

Ordinary admission depends on the registered run/admission-enable state and
available owner capacity. It must not combinationally depend on a sum of all
queue pointer differences.

Detect approaching namespace reuse from A. At the last allocation before the
full 14-bit namespace rolls to the next reused value, arm the barrier. Do not
wait for an unrelated downstream pin to propagate through quiet in the same
cycle that the next request is accepted.

14.2 Local drain condition
--------------------------

The local controller requires:

  no live owners;
  no unfetched/fetched output reservations;
  no context or packet writes still pending;
  no raw/snapshot/claim/write/publication terminal records;
  no ready candidates;
  no COMBINE ingress or execution reservations;
  no RCP/PERSPUV/sample/palette/AUX work or captured returns;
  no unpublished status or abort-completion action relevant to the epoch.

Use registered local-empty indications and explicit reservation totals.
A registered reduction tree is acceptable; it may add a few drain cycles.
It must not produce a premature done merely because the ordinary data path was
stalled during the snapshot.

14.3 External acknowledgement
-----------------------------

The owner demonstrator has no real cache/memory/palette fabric attached. Its
local quiet output cannot prove external transactions are gone.

The production controller needs a request/acknowledgement barrier covering all
adapters that can later return a handle from the old namespace. Each adapter
acknowledges only after its request, response, retry and completion queues are
empty and its downstream outstanding credits have returned.

Latch the acknowledgement for the requested barrier epoch. Do not sample a
combinational global "empty" wire while admission remains open. Late injected
old packets before reopening must either delay the barrier or be drained and
classified invalid under the defined transport fault policy.

After all acknowledgements, reopen the reused namespace. An arbitrarily delayed
or maliciously regenerated old packet after the barrier cannot be distinguished
by a finite reused tag alone; the transport contract must exclude that behavior
or carry a larger nonreused outer epoch. State this limitation plainly.

14.4 Reset
-----------

Resetting only the owner block while a memory or service adapter still holds
its old returns is invalid. Coordinate reset across the transaction domain, or
perform the barrier before resetting the owner namespace.

Clear active/valid/count/phase state. Do not asynchronously clear payload RAM.
Do not treat old numerical zero in a payload row as proof that a valid result
exists. If a queue requires initialization or a free-context preload, expose
initialization completion before admitting traffic.

14.5 Abort
-----------

The safest initial production abort stops admission and drains already accepted
work to terminal error results in order. A destructive abort may discard the
whole domain only after every producer/consumer acknowledges cancellation and
no in-flight write can reappear.

Do not add per-owner out-of-order free as a shortcut. It invalidates both the
sequence-window representation and the claim-to-publication lifetime proof.

14.6 Debug quiet versus control barrier
---------------------------------------

A registered ev_quiet snapshot is useful observability. It is not itself an
external drain protocol. Give the control acknowledgement a separate name and
state machine so software cannot mistake a delayed debug statistic for a
barrier that guarantees absence of future responses.

The old queue occupancy omission is fixed even if the three ready FIFOs are
about to be replaced. That provides a clean baseline and prevents the same
bug being copied into the new packet queues.


15. EXACT BANK INVENTORY AND REVISED MEMORY SPENDING
==================================================

15.1 Count families, bits, ports and physical width slices separately
--------------------------------------------------------------------

The existing owner experiment declares:

  OWNER_CONTEXT                 64 x 64       4,096 bits
  SAMPLE_RESULT_0/1/2         3 x 64 x 40      7,680 bits
  AUX_RESULT                    64 x 40       2,560 bits
  FINAL_RESULT                  64 x 40       2,560 bits
  READY_TMU/AUX/INITIAL       3 x 64 x 14      2,688 bits
                                             ----------
                                             19,584 bits

That is nine logical memory families. It is not necessarily nine physical
M10Ks. A Cyclone V simple-dual-port M10K supports up to forty bits at its
widest listed port configuration; a simultaneously read/written 64-bit row
requires two width slices in this ordinary mapping. The six payload families
therefore have a conservative seven-M10K minimum and the three ready queues
add three, for ten rather than nine physical blocks before other storage.
[V03]

The fit's total of seventeen M10Ks and 20,640 memory bits exceeds that inventory.
The difference is not automatically evidence of waste. Nor may it be assigned
to a particular queue without the per-instance RAM report. The whole point of
M0 is to identify each physical memory and its originating array.

An aggregate minimum-memory-bits gate is useful but not sufficient. One missing
payload bank can be hidden by an unrelated new memory with enough bits. Require
per-bank names, logical geometry, physical mode and useful connectivity.

16. RCP24 V3: KEEP THE ARITHMETIC, REPAIR THE OUTPUT SEAM
=======================================================

16.1 What has actually succeeded
--------------------------------

The exact product reduction halves measured DSP use from six to three. The
sixteen-context implementation measured essentially four clocks per nonzero
reciprocal across the complete 24-bit nonzero denominator domain. That work is
valuable and should not be discarded because the owner experiment was large.
[R05]

Retain the exact 32x32/product-correction identity, all signed-wrap behavior,
the seed table, and four product jobs per nonzero reciprocal. The negative
correction case must continue to be tested with arbitrary x,w inputs because
friendly denominator-derived iterates do not reach every correction case.

16.2 The queue header's promise is not its implementation
--------------------------------------------------------

zhao_raster_ticketq's commentary says a FIFO head is a register. Its actual
output is:

  assign dout_o = mem_q[head_q];

That is a dynamically indexed combinational output from a flop array. It may
be entirely reasonable for a small internal FIFO, but it is not a registered
head. The named full-fit path from u_doneq memory to r_tok_o is consistent with
that actual implementation. [R10]

Start with the DONE queue/output seam. Do not rewrite the multiplier first.

16.3 Registered token handoff
-----------------------------

Introduce a real registered head and a spare/prefetch slot, with exact queue
occupancy and context-credit conservation. For narrow context-ID queues,
small fabric storage can still be cheaper than dedicating an M10K. The goal
is an explicit timing boundary, not maximizing the count of RAM primitives.

If the body is synchronous, include the pending read in total occupancy.
If the body is a small combinational fabric array, capture its selected head
before driving the external result packet. Keep the token and reciprocal
result associated through the same output reservation.

No context is freed until the result is safely transferred under the declared
handoff law. If a result row is copied into an owned output buffer, context
reuse is legal only when that buffer holds the complete needed result and tag.
A narrow token alone is not a copy of a mutable result row.

16.4 Do not replace every ticket queue blindly
----------------------------------------------

FREE, NEW, CONTINUATION and DONE have different traffic and initialization
requirements. PRELOAD in the present generic queue writes every free context
ID during reset. A RAM-backed replacement would need a preload sequence or a
different free-context representation and an initialization-ready contract.

Repair DONE first and measure it. Then decide whether the other queues need
the same structure. A working four-job feedback scheduler should not be widened
or slowed merely to make all queue modules look alike.

16.5 Context count and rate must be rechecked
--------------------------------------------

Sixteen contexts was the measured knee for the previous pipeline. If a repair
changes the arithmetic feedback loop, admission queue latency or context reuse
latency, rerun eight/sixteen/thirty-two-context rate comparisons. The old knee
is evidence about the old topology, not a universal number.

An output-only register cut can improve the external interface without
changing multiplier initiation interval. That is the preferred first experiment.
An extra stage inside the recurrence is a different change and requires its
own throughput evidence.

16.6 Timing claims remain bounded
---------------------------------

90.54 MHz is a real reported leaf result, not 100-MHz closure. Its named
register-to-output path does not establish the worst register-to-register path.
Run the endpoint-separated and registered-wrapper reports before deciding how
many stages are needed or predicting 115 MHz.


17. INTEGRATING THE RETAINED TEXTURE MACHINERY
============================================

17.1 One owner lifetime remains the common identity
--------------------------------------------------

The sequence-window representation is internal control compression. It does
not authorize shortening external cache, palette, AUX, RCP or COMBINE tokens.
Full owner generation must survive every queue or adapter that can delay a
return beyond the direct producer's current cycle.

A slot-only ticket is permitted only inside a lease whose owner cannot be
released while the ticket or derived operation remains outstanding. Write that
lease's start/end beside the storage declaration.

17.2 RCP admission and terminal commit
--------------------------------------

RCP_PENDING retains the denominator until a local RCP execution context accepts
it. The owner remains live independently of that context. The final reciprocal
result commits to the owner's RCP_RESULT bank before sample expansion uses it.

A free local RCP context is not a free global owner. A completed RCP is not a
completed material. The two capacity domains must have separately named credit
counters.

17.3 Paired PERSPUV
------------------

Keep the paired U/V organization and exact signed arithmetic from the prior
architecture. Carry only arithmetic control and a narrow local lease through
the deep product/shift stages; keep wide side metadata in an explicitly
accounted queue if that variant actually saves registers.

The side metadata queue must follow the pair through all stalls and depth-zero
behavior. Zero-depth work must not take a shortcut that overtakes an earlier
pair and picks up its metadata. Recheck every exponent, signed extreme, rounding
tie, saturation flag, and U != V case.

A one-pair-per-clock claim requires a saturated RTL test with the real output
reservation scheme, not an arithmetic unit driven with ready permanently high.

17.4 Binding and configuration ownership
-----------------------------------------

Resolve immutable per-owner material/binding/envelope identities. Do not read a
live global format or base-address pin after owner admission and call it a
captured descriptor. A later configuration command cannot change the meaning
of a fragment already in flight.

Configuration epochs, palette generation compatibility, and reset/drain behavior
remain explicit. A double-buffered configuration path spends storage; it is
not hidden inside the nominal single-copy bank allocation.

17.5 Cache credits and response capture
---------------------------------------

Retain the repaired cache reservation behavior. A response queue slot must be
reserved for a probe whose answer will arrive later. A full consumer must not
cause an already accepted warm hit to disappear.

Raw returns are captured before format decode or palette dispatch. The prepared
response pool, class queues and palette-return credits retain their separate
writers and ownership. The new owner control plane is downstream of those
services; it does not excuse losing a packet before terminal validation.

The feature-live test must repeat the old warm-hit loss case and queue-wrap
stress, not just check a fresh cold miss with an always-ready output.

17.6 All formats and alpha remain active
----------------------------------------

Include CLUT8, CLUT4, RGB565, ARGB1555 and ARGB4444 in the conformance workload.
CLUT4 must exercise both nibble parities with distinct palette results.
Nearest/direct-color decoding must actually produce accepted work. Filtered
alpha retains the fourth channel phase and its declared cost.

Deliberately force the old broken behaviors during mutation testing: whole-byte
CLUT4 lookup, forced RGB565 decode, opaque alpha, and a disabled nearest path.
Each must fail the intended test rather than merely change a counter nobody
asserts.

17.7 AUX and Mosaic
-------------------

AUX geometry is independent of opaque context. Keep its real envelope path
alive in physical conformance tests. No hard-coded envelope may remove the
expensive part while the report claims to cover production AUX.

Mosaic output must influence the binding/detail choice actually consumed by
the sampler. Connecting its counters while its useful outputs dangle does not
include Mosaic in the measured architecture.

Keep AUX offer and terminal queues distinct where their writers can act on the
same edge. The row-local owner commit can merge TMU and AUX publication without
forcing their payloads into a multiwrite memory.

17.8 COMBINE status and recipe fidelity
--------------------------------------

Retain COMBINE V2's local scheduling organization unless a fresh measured
bottleneck points there. Feed it required source results and captured material
parameters; propagate error/status through its tag or explicitly accounted
metadata row.

The final color alone is not the status. A recipe can legitimately transform
an error-colored source. The final status must still record the source failure.
Run all recipes at zero, one, two and three sample requirements where legal,
including the ordering-sensitive multiply/lerp cases and exact /256-style law.

17.9 Feature-live synthesis is the integration gate
---------------------------------------------------

The physical test wrapper must vary every supported feature enough that its
hardware survives synthesis. Then inspect what remained, by source closure,
RAM instance, DSP site, and output observability.

Passing a behavioral test before synthesis does not prove the physical wrapper
kept that same feature alive. A permanently tied configuration or unobserved
result can produce a smaller but incomplete machine.

17.11 Count accesses per cycle, not source-level read sites
---------------------------------------------------------

The new census's statement that an array has at most two read sites is not,
by itself, proof it fits one two-port memory. Two simultaneous readers PLUS a
writer are three accesses. True dual port does not mean two arbitrary readers
in addition to an unlimited write port. Its width modes also differ from
simple dual port. [V03]

For each legacy array, record:

  which event writes it;
  whether two readers can request the same cycle;
  whether a reader can be time-multiplexed without reducing the contractual rate;
  whether a row is immutable between write and last read;
  whether two physical copies are required for two independent read streams;
  collision behavior and when an output is actually valid.

Where several fields have the SAME admission writer and SAME later read event,
pack them into one logical descriptor row. This removes independent address,
enable, and validity machinery. Width may still require several physical M10Ks.
Where two consumption stages genuinely need a field independently, keep two
explicit read replicas or schedule a read; do not declare an impossible port.

This document's final V3 transaction file already partitions fields by consumer.
The legacy retrofit below is a controlled intermediate experiment, not an excuse
to retain both that file and the old arrays permanently.

17.12 Numerator join: the first safe synchronous-read conversion
---------------------------------------------------------------

The current top does the following at the reciprocal completion boundary:

  uvw_rd = uvw_m[rcp_tok.slot];           // combinational 64-bit selected read
  PERSPUV.valid = rcp_result_valid;
  PERSPUV.numerators = uvw_rd;
  PERSPUV.mantissa/k/depth_zero = current reciprocal output;
  RCP.ready = PERSPUV.ready.

Registering uvw_rd alone is WRONG: the reciprocal, token and valid would still
refer to the current request while the numerators refer to the previous read.
A green test with identical U/V or repeated tokens can miss exactly this error.
[R13]

Replace that boundary with a credited numerator-result join:

  N0: accept the reciprocal packet into an owned join slot; capture full token,
      mantissa, exponent and depth-zero status; reserve its complete output slot.
  N1: issue the immutable numerator-bank read at the captured slot address.
  N2: capture the RAM output at the agreed primitive latency, without decode
      between the memory and its first register.
  N3: assemble numerator pair plus the matching reciprocal fields; expose stable
      valid/data to PERSPUV through a registered head.
  N4: PERSPUV accepts; release this join slot, NOT the global owner.

The edge numbers are a conservative proposed pipeline, not a measured minimum.
If the chosen memory primitive combines N1/N2 differently, change the latency
and reservation proof together. Maintain an owner/token pipeline beside the
RAM read; do not reread a current output pin to recover metadata later.

At least one reciprocal output may arrive per cycle at this seam in a burst.
The read pipeline must accept bursts at that rate while credit exists, even
though the long-run reciprocal rate is approximately one result per four
clocks. Pick the join depth from measured burst size and downstream latency,
not from the average rate alone. A sixteen-slot credited implementation is a
reasonable first shared profile, but its actual width and RAM/head cost must
be added to the inventory or replace an existing reserved RCP/PERSPUV handoff.

There is no free extra join outside the 69-M10K allocation. The final design
should reuse the already planned RCP_RESULT/SAMPLE_DESC and PERSPUV input
reservation domains. Any transitional legacy queue is measured separately and
removed or accounted for at integration.

Required tests include alternating distinct numerator pairs, shuffled reciprocal
completion order, depth zero between nonzero results, generation reuse, and a
consumer stopping immediately after a read launch. Compare every coordinate
and status bit, not only fragment counts.

17.13 Descriptor join: stop treating PERSPUV completion as an async table bus
---------------------------------------------------------------------------

The second old top read point uses pu_tag to read context, base color/alpha,
binding, LOD, raw class, AUX flag, palette slot/generation, sample count, recipe,
and weight. These values feed several downstream operations. The capture
arrays are immutable per admitted fragment; the consumers are not permitted to
observe a new configuration halfway through that fragment. [R13]

Introduce an explicit fragment descriptor join after PERSPUV:

  D0: capture U/V, tag, flags and an output reservation when PERSPUV transfers;
  D1: read the corresponding immutable descriptor plane(s) synchronously;
  D2: capture raw row values and associated valid/token;
  D3: validate/sanitize class from CAPTURED raw class, resolve immutable binding
      identity, and assemble one stable internal fragment descriptor;
  D4: hand the descriptor to the expansion/owner issue stage under its credit law.

Sanitization and the invalid-class counter stay after capture. An invalid class
must complete with the specified error behavior, not disappear from the return
stream. Do not move the old independent class pin unchanged into the final
production ABI if class can instead be derived from the effective binding,
format and filter. That semantic change has an explicit transition wrapper.

The descriptor must not be broadcast as an unacknowledged one-cycle pulse to
FRAGROB, AUX and Mosaic. Either one expansion controller accepts the descriptor
and owns all subsequent subrequests, or each consumer gets a reserved fork with
per-consumer accepted flags. An OR of several ready signals is not a fork.

The final V3.1 organization prefers ONE expansion controller and immutable
per-owner/per-sample banks. This preserves one fragment lifetime without adding
a second unbounded metadata copy at each consumer.

17.14 Where every old field goes in the final organization
----------------------------------------------------------

The old top's storage MUST disappear by explicit field ownership, not by a
blanket deletion before replacement parity:

  old fctx_m:
    exactly one OWNER_CONTEXT 64x64 bank, read at final ordered output;
    no duplicate full-context copy in a legacy FRAGROB and another final ROB.

  old uvw_m:
    sample numerator/descriptor bank fields feeding the paired perspective
    service; shared reciprocal belongs in RCP_RESULT. The legal three-sample
    profile must preserve independent descriptors rather than duplicating one
    coordinate pair and calling that three samples.

  old fbase_m, frec_m, fwt_m, fsc_m:
    MATERIAL row, subject to the frozen layout. Base RGBA32 + recipe3 + weight8
    + sample_count2 use 45 bits before other flags, consistent with the proposed
    48-bit material plane only if the remaining fields really fit.

  old fbind_m, flod_m, class_m and sample routing metadata:
    SAMPLE_DESC, immutable binding resolution, and SAMPLE_METADATA under their
    declared writer/reader schedules. Do not silently enlarge a 40-bit row or
    drop binding/LOD bits to keep an old table pretty.

  old faux_m:
    the required-source mask and separately captured AUX geometry/control.
    Geometry is not reconstructed from opaque context or assumed equal to UV.

  old fpsl_m / fpgn_m:
    explicit palette identity and palette-generation compatibility. This is
    PALETTE generation, not OWNER generation. The sequence-window proof does
    not eliminate palette versioning or authorize dropping those fields.

  old fseq_m, seq_alloc_r and final R6 reorder payload/tag storage:
    replaced by A/E/F sequence identity, FINAL_RESULT and OWNER_CONTEXT plus
    bounded output packet reservations. Remove the old reorder machinery only
    once this replacement proves the same external order under real internal
    reordering and long output stalls.

The old top's comment says its final consumer exposes only the low sixteen
context bits, while V3 requires full context64 to survive. That is a stronger
observability contract with a real cost. Preserve and measure it rather than
claim identical feature coverage between the old fit and the new full-context
wrapper. [R13]

This inventory is the acceptance check against duplicated scaffolding. A new
owner ring sitting underneath fseq_m plus an old independent reorder buffer
has not completed the rearchitecture.

Do not leave an available large storage win waiting on a new ready-selector

  L0: read the archived map and identify every current array/read site;
  L1: implement the numerator join and its reservation tests;
  L2: implement the immutable descriptor join and captured class handling;
  L3: inspect RAM inference, per-entity registers and latches in map-only output;
  L4: measure the changes against the same feature-live wrapper;
  L5: transfer the proven bank/join primitives into V3.1 and remove the legacy

Do not merge two owners' edited versions of zhao_texture_island_top.sv by
convenience. Keep the L-series top in an isolated experiment until the single
integration owner chooses a merge. Helpers and their independent tests can
land separately.

A large map-only reduction is meaningful structural evidence, but it is still
not a new fitted ALM result. Conversely, if a correct minimal legacy repair
achieves the practical whole-island goal sooner than the complete control
replacement, retain that option. V3.1 is an engineering proposal, not an
obligation to discard a measured better implementation.

based only on a historical line number.

Likewise, the old composed report's RCP path and the isolated V3 RCP path refer

ticket output mux can both be real findings without being the same path.

The old-island census strengthens the case for explicit synchronous joins.
It does not establish that registering every array is optimal, that two read
sites guarantee legal memory ports, or that the complete island will hit a
particular ALM/Fmax number. Those are precisely the claims L1-L4 must measure.


18. TIMING ANALYSIS THAT DOES NOT MISCLASSIFY OUTPUT PATHS
=========================================================

18.1 Four endpoint classes
--------------------------

Report separately:

  register -> register;
  input port -> register;
  register -> output port;
  input port -> output port.

Include embedded-memory and DSP-related endpoints in the appropriate internal
collections; do not let an overly narrow register-name query omit them. Check
collection sizes and compare the categorized totals with an unrestricted report.

A startpoint-only partition is insufficient. The demonstrator's queue-pointer
paths ending at adm_accept_o and ev_quiet_o belong in the output class even
though their logic is inside the module.

18.2 Three physically distinct measurements
-------------------------------------------

Measure the old and new DUTs in:

  A. The same legacy virtual-pin harness, for historical comparability.
  B. The same registered ready/valid service wrapper, with explicit I/O timing.
  C. The actual renderer/island composition, once functionally ready.

A wrapper may improve one boundary while adding registers, routing and latency.
Count that hardware. Do not compare a bare old block with a heavily buffered
new block, discard wrapper cost, and call the difference a pure DUT saving.

A leaf result is neither a guaranteed upper nor lower bound on the complete
machine's frequency. Composition can eliminate unrealistic leaf boundary
pressure or create new long paths and placement congestion.

18.3 Use slack for sign-off, not a single Fmax cell
--------------------------------------------------

Archive setup, hold, recovery/removal and minimum pulse-width analysis where
applicable, all relevant operating corners, clock relationships, and any
unconstrained endpoints. A positive setup result does not repair a hold failure.
Ordinary same-edge hold timing does not improve simply by lowering the clock.
[V01, V02]

The previous owner report had negative hold slack as well as setup failures.
That remains a genuine sign-off failure. The distinction between output and
register-to-register paths guides the repair; it does not erase the report.

18.4 The first critical-path experiments
----------------------------------------

Run M1 with only:

  correct pending-read occupancy;
  a registered local-empty/quiet report;
  an explicit registered generation-drain state;
  no quiet-pointer arithmetic in ordinary admission.

Then compare endpoint classes. If the bad queue-pointer output paths disappear
but register-to-register timing remains weak, proceed with identity/control
cuts. Do not celebrate a good-looking output-only metric as complete closure.

For RCP, register the actual DONE handoff and inspect whether the newly worst
path is in the recurrence, context scheduling, or another interface.

18.5 Exceptions are not a performance feature
---------------------------------------------

Do not false-path a normal ready/valid signal because it sometimes stalls.
Do not assign a multicycle exception merely because the operation's total
latency exceeds one cycle. Every real pipeline register still has its actual
capture relationship.

An exception requires a semantic timing guarantee and a checked implementation
of that guarantee. A permanently convenient exception to make a fit green is
not an architectural repair.

18.6 Corner and seed reporting
------------------------------

State the exact FPGA part and speed grade, Quartus version, operating corner,
SDC, seed, optimization settings and wrapper. Report the worst accepted corner,
not the first Fmax row in a concatenated report.

Use at least a small seed comparison on representative old/new configurations
before attributing a tiny frequency change to the architecture. The old RCP
seed spread already demonstrated that a few MHz can be placement variation.
A large repeatable change is more persuasive than a single lucky seed.


19. AREA ATTRIBUTION AND FALSIFIABLE ABLATIONS
============================================

19.1 Preserve and inspect the actual physical report
----------------------------------------------------

Recover or rerun the existing failed owner experiment on its exact frozen
closure. Preserve the full fit report/database needed to query hierarchy.
Extract:

  ALMs used for combinational logic, registers and memory modes;
  ALUT counts and packing metrics where available;
  register duplication/retiming summaries;
  RAM instances, widths, depths and physical blocks;
  resource utilization by entity;
  high-fanout signals and locations of critical paths.

ALUTs are not ALMs. Logical memory bits are not physical block capacity.
A report with 6,532 ALUTs cannot be converted to a trustworthy ALM result by
blindly dividing by two.

19.2 The attribution table must balance
---------------------------------------

Use categories with no double counting:

  per-owner state;
  owner-state read selectors and identity validation;
  issue/claim/publication decode and update logic;
  readiness selection and queues;
  wide COMBINE holding path;
  final read/holding/output path;
  counters and diagnostics;
  RAM-side glue and fitter-added replication;
  wrapper and unassigned remainder.

Some flattened logic will not map cleanly to a source entity. Record an
unattributed remainder rather than assigning it to the most convenient suspect.
The sum must reconcile with the full reported total under the tool's accounting.

19.3 Ablation matrix
--------------------

Preserve the same owner capacity, payload widths, output observability and
traffic contracts. The production candidate is always fully functional.
Controlled stubs are diagnostic variants with explicitly reduced scope.

  A0  Exact current owner baseline.
  A1  A0 + queue occupancy fix + registered drain separation.
  A2  A1 + sequence-window identity, old ready/holding queues retained.
  A3  A2 + narrow snapshots + row-local source publication.
  A4  A3 + local candidate-ready structure.
  A5  A4 + RAM-backed wide ingress/output holding profile.
  A6  A5 + exact COMBINE-issued distinction and final-return tests.

M6 correctness can land earlier; A6 labels a measurement point, not permission
to leave the early-final hole undetected during previous testing.

For each row record source digest, parameters, passed behavioral tests, mapped
registers, ALUTs, RAM geometry, fitted ALMs, setup/hold by class, and saturated
rate. Never add area deltas from different seeds and wrappers as though the
whole design's packing were linear.

19.4 Small isolating experiments
---------------------------------

Useful experiments include a control-only wrapper with all state observable,
a standalone candidate selector, and a packet queue with genuine dynamic data.
They diagnose a mechanism. They do not become the published whole owner count.

Avoid a constant-output stub that causes synthesis to delete the control being
measured. If an event source is stubbed, make its legal values dynamic and
observable. Inspect the resulting netlist or resource hierarchy for survival.

19.5 A clear stop condition
---------------------------

If M2/M3 remove the intended state/query structure but area barely changes,
stop attributing the problem to generation or masks. The experiment disproved
that explanation's dominance. Inspect wide queues, fitter duplication,
input/output replication and actual mapping before another architectural rewrite.

If M1 fixes the observed output path but true internal setup remains slow,
stop calling the remaining problem a virtual-pin artifact. Fix the reported
internal cone.

This plan is valuable only if it can tell us our preferred explanation was wrong.


20. PHYSICAL ARCHITECTURE AND IMPLEMENTATION PATTERNS
====================================================

20.1 Group control, not every memory indiscriminately
----------------------------------------------------

Eight control groups are intended to keep per-row event updates and local
selection small. They do not require eight copies of every payload bank.
The global payload planes already have clear single-writer/single-reader ports.
Retain those unless the fit shows a real placement reason to partition them.

The wide packet read occurs after central slot selection. Keep the data bus
away from local arbitration. A little duplicated scalar decode can be cheaper
than routing a broad shared control cone across every payload and status bank.

20.2 Define register boundaries by purpose
------------------------------------------

Every added register has a named purpose: input capture, state snapshot,
accepted claim record, bank write, publication, candidate head, packet
reservation, RAM result capture, or externally stable output.

Do not indiscriminately pipeline the entire 64-owner record. That multiplies
state and adds forwarding obligations without identifying a useful boundary.
Do not carry context64 down an arithmetic pipeline that only needs owner14.

20.3 Keep genuinely dynamic small state in fabric
------------------------------------------------

The candidate heads, local round-robin cursors, four-source phase bits, and
small credit counters are not payload RAMs. Their fabric implementation is
intentional. The budget must include their muxes and updates.

Conversely, a sixteen-deep 240-bit packet body is payload storage. Putting it
in a resettable flop array because "it is only sixteen entries" defeats the
memory-spending choice of this architecture.

20.4 Reset and clock enables
----------------------------

Payload memories and their data outputs use clock-only storage processes.
Validity is reset separately. Control resets should be localized and reviewed
for fanout; do not let one asynchronous reset enable accidentally prevent RAM
inference across a payload hierarchy.

A registered write-enable signal may pass through ordinary wiring or hierarchy.
A source checker should follow aliases or elaborated drivers, not reject a
harmless wire because its name ends in _c. A raw validation expression feeding
a RAM write-enable is the problematic logic shape, not the presence of a wire.

20.5 No premature hard floorplanning
------------------------------------

Use hierarchy and explicit stage boundaries first. Inspect placement before
adding rigid location constraints. A hard partition can protect locality or
prevent the fitter from solving a better placement; it is not a universal cure.

Measure the cost of replicated high-fanout controls. Spare ALMs can help timing,
but they do not guarantee a useful placement or replace a missing pipeline
reservation.

20.6 Numerical width discipline
-------------------------------

Use explicitly sized unsigned arithmetic for sequence and occupancy operations.
Use separate types/names for owner sequence, slot, generation, source index,
local execution-context index and packet credit.

The sample-handle repacking is not a cast: extract slot, sample and generation
by their documented fields, then concatenate generation/slot for membership.
Tests must use nontrivial high generation bits and mixed source indices so an
accidental layout swap cannot pass on zeros.


21. RESOURCE TARGETS, ACCEPTANCE GATES, AND FALLBACK DECISIONS
============================================================

21.1 Retain the difference between a goal and an observed cost
-------------------------------------------------------------

The original owner allocation of 1,800 ALMs remains an aggressive target, not
something this document has proven attainable. The original whole-island
5,500-6,600 goal and 7,500-ALM redline likewise do not become achieved because
we can draw a smaller-looking block diagram.

The RCP's earlier 600-ALM allowance is already contradicted by its 1,230-ALM
leaf result. Any new total must reconcile that fact. Do not make a spreadsheet
balance by retaining known-false component allocations.

This proposal offers concrete structural reductions and exact functional
proof obligations. It does not offer a fabricated prediction of 1,650 ALMs
at 118 MHz.

21.2 Intermediate gates
-----------------------

M1 must correct queue conservation and remove the known drain feedback cone
without changing useful capacity or functionality. Its value is a classified
timing result, not an arbitrary resource target.

M2/M3 must prove identical legal identities/results and show the intended
state/access network actually disappeared in synthesis. Record the real area
delta; stop if it is absent.

M4 must show exactly-once selection, fairness, and one-per-clock hot-group
throughput. It must not replace a known throughput problem with a smaller
single-candidate bottleneck.

M5 must show the declared packet bodies in their assigned memories and count
head/prefetch state. It must pass the same deep-stall tests and sustained rate.

An equivalent-scope owner block substantially below the current 5,678 ALMs
and timing-clean at 100 MHz would be meaningful progress. It would NOT by
itself satisfy the old 1,800-ALM allocation or prove a 7,500-ALM full island.

21.3 Production gates
----------------------

Before long composition:

  all interfaces and records frozen for this implementation version;
  all required features live in tests and in synthesis;
  actual register/ALUT/RAM/DSP attribution reconciled;
  no illegal duplicate or stale payload writes;
  throughput gates passed under finite credits;
  no unaccounted wide state or unconnected important status;
  exact source/test/constraint snapshot archived.

Then require correct operation and full timing sign-off at the product clock
on the real composed design. Standalone headroom remains desirable, but a
single leaf Fmax is not a transferable reserve account.

If the project retains the 7,500-ALM / 9,000-register / 14-DSP island redlines,
report violations against those same redlines. Revising a redline is a
whole-machine budget decision, not a successful fit of the original budget.
The proposed 69-M10K profile is an explicit memory-allocation revision.

21.4 What to do if the reduced control is still too large
--------------------------------------------------------

First establish which category remains expensive. Then choose a measured option:

  * Reduce duplicated wide staging through direct reserved COMBINE-context fill,
    after proving the context occupancy and rate implications.
  * Retain a cheaper scalar ready mechanism if the eight-group candidate
    structure does not actually improve area/timing.
  * Use a more deeply scheduled control-memory engine only after deriving its
    event-rate capacity against real workloads, including simultaneous returns.
  * Renegotiate the island's area allowance from a complete current machine
    inventory if the extra cost buys necessary correctness and throughput.

The last option is legitimate engineering, but it is not evidence that the
original allocation was right. Do not start by reducing owners, sample count,
formats, alpha, or status coverage.

21.5 What is not an acceptable fallback
---------------------------------------

No unclocked giant table; no output that changes under stall; no same-slot
stale alias; no lifetime shortened to fit a buffer; no swallowed error pulse;
no scalarized four-product reciprocal claimed to retain old throughput;
no dead AUX/Mosaic path used to advertise a smaller physical result.

A failed but fully observed fit is more useful than an apparently successful
fit of an incomplete machine.


22. VERIFICATION MATRIX AND HOSTILE SCHEDULES
============================================

22.1 Identity model independent of the RTL representation
--------------------------------------------------------

Maintain an oracle list of complete admitted owner identities and their
required/issued/result state. The oracle should not reuse the implementation's
sequence-window formula to decide which identity exists. Compare the formula
against explicit membership.

Exhaust a reduced namespace completely, then exercise the real fourteen-bit
namespace at every head position and every legal occupancy. Test zero, one,
63 and 64 live owners, intervals crossing numeric zero, and same-slot handles
from earlier and later generations.

Compare the produced handle sequence against the old per-slot generation
increment model. Test a full wrap barrier and verify that a stale external
packet cannot be converted to a slot-only internal event before rejection.

22.2 Phase-control invariants
----------------------------

Assert at every edge for every active row:

  committed subset claimed subset issued subset required;
  combine_issued implies combine_reserved;
  final_claimed implies actual combine_issued;
  final_done implies final_claimed;
  every candidate refers to an active reserved owner;
  no candidate owner occurs twice anywhere in the candidate network;
  no released owner has an unconsumed legal internal lease.

Use error/refusal paths as well as successful samples. A required refused
sample still needs a terminal result/status and must not leave the owner
permanently waiting for a success that will never arrive.

22.3 Completion timing
----------------------

Test back-to-back duplicate returns for the same owner/source, duplicates
separated by the snapshot/claim distance, and duplicates after commit. Reverse
TMU sample order. Return AUX before all samples, after all samples, and on the
same edge as the final required sample.

Use the exact case:

  required 1111, committed 0011;
  source2 and AUX publish together;
  exactly one local eligibility/reservation outcome.

Test two simultaneous publications for different owners, plus a zero-work
admission elsewhere. Check every payload and status, not only the number of
tickets or outputs.

Inject stale old-generation packets while the old owner is being emitted,
while its slot is empty, and just after that slot is reused. Vary their
position across R0/R1/R2/W/P so pipeline snapshots are tested rather than
only the easy no-traffic boundary.

22.4 Issue races
----------------

Test a return before any issue, on the issue edge, one edge after issue, and
through a staged issue adapter. Exercise independent TMU and AUX issue for the
same owner. Repeat an issue notification and verify it does not create a
second outstanding request or erase a previously claimed result.

Malformed sample index three must never address AUX through the TMU port.
Use generation values with high bits set and all low slot values. Small
zero-valued tokens are an inadequate layout test.

22.5 Ready selection
-------------------

Fill all sixty-four owners, make them all ready, and stall COMBINE for a long
period. At most sixteen candidates may occupy the local head registers; all
other ready rows must remain eligible without losing a transition.

Release the stall and require every owner exactly once. Use all ready owners
in one group, alternating groups, and all eight groups simultaneously. Verify
continuous hot-group output after warm-up. Check local and global round-robin
state advances only on the actual reservation/pop events.

A single global always-ready random test is not enough: it may never fill a
local spare register or expose a registered-pop refill bubble.

22.6 Wide packet queues
----------------------

For each queue, score data, identity, order, capacity and conservation across:

  empty -> first write -> synchronous read in flight -> first head;
  head/spare both full -> consumer stalls;
  body read lands on the same edge as head pop;
  simultaneous write/read at every occupancy;
  pointer wrap while head/spare still contain older packets;
  no free downstream reservations with upstream bank reads in flight;
  maximum legal reservation count;
  consumer ready toggling on every edge.

Assert logical occupancy equals body + pending read + all head/staging ownership
for the scope named by that counter. Assert the bank-read reservation counter
covers the even earlier stages as well. Do not sum two counters that represent
overlapping ownership domains.

22.7 COMBINE and final output
----------------------------

Inject an early final return while COMBINE input is stalled. It must fail.
Then accept the real input and return a valid final result; it must succeed.

Make different material jobs finish in genuinely different orders. Prove the
internal system executed younger ready work, then prove final output is still
exactly the admitted sequence with unchanged 64-bit context.

Hold out_ready low long enough to fill all output reservations. No owner may
be freed early, no final row overwritten by reuse, and the offered head must
remain stable. Resume output and compare every value and token.

22.8 Reset and epoch drain
-------------------------

Request a barrier with work in each possible pipeline and queue location.
Delay one external adapter's acknowledgement. The namespace must not reopen.
Return a late old packet during local drain. Exercise an empty body with a
pending queue read, the exact state the old occupancy omitted.

Test coordinated reset separately from an illegal partial reset. The illegal
case must be refused by integration assertions or explicitly treated as a
fatal domain protocol error, not passed because a friendly simulator happened
to clear both ends simultaneously.

An endless malformed external stream can prevent a clean drain. Define timeout
and fault reporting; do not force tag reuse as a recovery shortcut.

22.9 Feature coverage after integration
---------------------------------------

Repeat all previous texture format, palette, cache and arithmetic differential
suites on a verified rebuild. Add interleaved binding epochs, nibble parity,
missing palette entries, real AUX envelope variation, live Mosaic selection,
three-sample recipes, filtered alpha and output status propagation.

The owner skeleton's fake COMBINE and tokenized fake services must not appear
in the feature-live fit closure. List them explicitly in a forbidden-source
check for production measurements.

22.10 Mutation campaign
------------------------

At minimum, demonstrate the RTL tests fail when each of these changes is made
in an isolated disposable checkout:

  use slot-only identity for external validation;
  truncate membership subtraction before rejecting upper bits;
  remove the current-window claim recheck;
  remove recent-claim forwarding;
  publish before payload write;
  replace same-row source OR with last-writer assignment;
  omit combine_reserved on local candidate insertion;
  authorize final from reservation instead of actual acceptance;
  pop a candidate without downstream storage credit;
  omit pending synchronous reads from queue occupancy;
  advance F without a reserved packet slot;
  free the owner at final write or prefetch instead of output acceptance;
  reopen the namespace before one external adapter acknowledges;
  force old broken CLUT4, alpha, nearest, or global-binding behavior.

Record the exact failing assertion and restored source digest. A mutation that
fails to compile is not evidence that a behavioral detector caught it.
The Python negative witnesses supplied here are NOT this RTL mutation campaign.

24. FIT INFRASTRUCTURE AND EVIDENCE PRESERVATION
================================================

24.1 Archive the reports that answer the next question
------------------------------------------------------

Retain the full .fit.rpt in addition to .fit.summary. Keep the map report,
STA report, setup/hold path details, entity utilization, RAM instance summary,
SDC/QSF, parameter values, tool logs and any database needed for later queries.
For a failed allocation, attribution is the next question by definition.

A file that exists but could not be decoded/read is not an empty report. Preserve
its raw bytes and decode its actual encoding explicitly. In this session the
connector exposed an empty text body for a nonempty map-report path; that was
not a basis for inventing the missing hierarchy table.

24.2 The manifest must identify the complete build input
-------------------------------------------------------

Record original relative paths as well as hashes. Flattening copied source paths
to basenames requires a duplicate-basename preflight or can overwrite a different
file with the same name. Include transitive HDL includes, package definitions,
ROM/MIF/HEX data, generated constants and relevant configuration.

Record parameter overrides, top entity, source digest, constraints digest,
Quartus version, FPGA part/speed grade, seed and optimization settings. Two
runs with identical source bytes but different NCTX values are not the same
physical configuration.

24.3 Preserve failures without destroying the previous valid result
-------------------------------------------------------------------

An infrastructure failure, killed process, timeout, parse failure, map failure,
fit failure, timing failure and resource-allocation failure are different states.
Keep the last valid measurement and the new failed attempt as separate records.
Do not replace a known numeric result with nulls or make an aborted run disappear.

The existing row-level digest and parameter-variant improvements are retained.
The new work completes their evidence story; it does not pretend those repairs
never happened.

24.4 Process and disk safeguards
--------------------------------

Use an immutable workspace per fit and independent mutation/build workspaces.
Supervise the process tree belonging to that run; do not kill every Quartus
process started after its timestamp. The repository already encountered that
cross-run watchdog defect.

Check available disk before launch and during report preservation. Mutation
backup/restore must verify a nonempty, hash-correct backup before modifying any
source, or preferably operate in a disposable version-controlled checkout.
Do not infer that ignored render intermediates will clean themselves up.

These are not FPGA architecture features, but they determine whether an
expensive physical measurement can be trusted and recovered.

24.5 Stale-row detection
------------------------

A row must be compared against the full fitted source closure and configuration,
not merely the latest commit touching its top module. Source-only comments,
parameter changes, packages and included tables affect freshness differently;
record enough information to distinguish them.

A stale old row remains valid evidence of its historical fitted configuration.
It is not a current physical measurement of the latest source. Flag that fact
without deleting the comparison point.


25. WHOLE-MACHINE CONSEQUENCES AND SCOPE LIMITS
==============================================

25.1 This does not prove the console has 10-15k spare ALMs
---------------------------------------------------------

The existence of 41,910 ALMs on the provisional target does not establish a
current complete-machine budget. Several major blocks have not been fitted in
their final composition, and adding stale leaf figures can double count shared
or alternative configurations while omitting new work.

Likewise, an old shell measurement plus a new isolated texture estimate is not
a machine-size prediction. There can be overlapping logic, missing features,
new interface costs and different physical packing.

The project is not disproved by a failed owner budget. But this document does
not finance new gadgets using an unmeasured remainder. Close the functional
machine and measure the actual resource/time margins first.

25.2 Larger but correct is a valid decision, not an invisible one
----------------------------------------------------------------

If a correct, timing-clean texture island requires more than the original
allocation, a complete-machine ledger can justify reallocating area. That is
a legitimate architecture decision. It must identify which other functionality,
reserve or throughput budget gives way.

The unacceptable version is silently calling 5,678 ALMs an 1,800-ALM success
because the alternative would require that conversation.

25.3 Do not confuse source-code sharing with physical sharing
-------------------------------------------------------------

Two modules instantiating the same projection-core source still normally create
two hardware instances. Moving duplicate equations into one shared source module
improves maintainability; physically time-sharing one execution unit requires
one instance plus arbitration, state/context ownership and a throughput model.

The geometry projection fit belongs on the whole-machine roadmap, but it must
not be interpreted as proof of physical sharing merely from the word "shared"
in a source file or header.

25.4 FIELD and terrain remain separate work
-------------------------------------------

The Field register-file probe and Field v3 throughput work do not measure this
texture control plane. Terrain command framing, LOD-deviation generation,
source-ID width repair, epoch policy and HPS arbitration are important but not
fixed by rebuilding the texture owner.

Do not start a second world/terrain rearchitecture inside this change. Integrate
at the agreed interfaces and keep each unmeasured subsystem visible in the
whole-machine inventory.


26. FINDINGS AND LIMITS OF THE EXECUTED MODELS
=============================================

26.1 What was executed
-----------------------

The included Python program ran successfully in this session. Its recorded
results are reproduced in Appendix C. The most substantial checks were:

  10,494,976 membership/reconstruction case instances;
  33,281 handle allocations compared with the legacy generation-array model;
  two full namespace drains in that generation trace;
  4,049 ready-selector batches and 97,916 exactly-once grants;
  120,000 cycles of the isolated sample/AUX completion-control model;
  10,111 accepted claims/writes/publications in that run;
  216,049 rejected packets in that hostile run;
  4,686 ordered stub retirements;
  simultaneous same-owner and different-owner terminal cases;
  216 legal publication-mask combinations;
  saturated and stalled reservation models;
  eight explicit bad-state witnesses;
  six actual in-memory mutations of the Python model, all caught by assertions.

These are counts of different experiments. Do not add them into a grand total
and label it "eleven million RTL tests."

26.2 What these checks establish
--------------------------------

They support the mathematical equivalence of sequence-window identity under
its stated ring invariants, demonstrate that the candidate structure need not
bubble on a single hot group, exercise recent-claim forwarding and publication
ordering in an independent model, and expose the queue occupancy omission.

They also check that conservative registered credits can sustain full rate when
capacity exceeds the chosen model latency. That is a capacity theorem for the
modeled pipeline, not a measurement of Quartus timing or actual RTL latency.

26.3 What they do NOT establish
-------------------------------

They do not compile SystemVerilog, verify synthesis mapping, model metastability,
prove CDC, reproduce the cache/format/palette arithmetic, or establish all
production COMBINE/final-output behavior. The completion test uses identity-valued
stubs for the rest of the material path and a reduced namespace to encounter
wrap more often.

The six model mutants changed executable model behavior: stale identity
truncation, omitted ready reservation, omitted claim forwarding, premature
publication, premature retirement, and early packet-credit release. Each failed
its designated baseline model test; none edited repository RTL. The mutation
runner also checked that the baseline model file remained byte-identical.

The eight bad-state witnesses are not a mutation campaign against the RTL.
Some are direct minimal counterexamples to an invariant. Their purpose is to
make the obligation falsifiable, not to inflate coverage claims.

The full-namespace membership test samples boundary/interior offsets at every
head/occupancy; the reduced namespaces are exhaustively enumerated. The general
identity is justified by the interval proof in Appendix A, not by pretending
that finite testing enumerates an arbitrary future architecture.

26.4 Why the supplied model is useful anyway
--------------------------------------------

It gives an implementation lane a small, executable standard to start from,
including seeded hostile schedules and explicit conservation assertions.
It can fail quickly before a long RTL build or fit. It does not replace the
existing 467-check RTL demonstrator, the new directed cases, or the independent
physical review.

28. DECISION RECORD AND CHANGE-CONTROL CHECKLIST
================================================

The following are explicit recommendations that alter the previous V3 plan:

  D1  Compress per-slot generation storage into a single live sequence window,
      conditional on ordered allocation and ordered release.
  D2  Keep phase state as source-owned row-local fabric bitplanes.
  D3  Replace three producer-class ready FIFOs with eight local two-candidate
      groups and central round-robin selection.
  D4  Separate COMBINE reservation from actual input acceptance.
  D5  Remove per-owner fetched state in favor of the ordered F cursor.
  D6  Separate quiescence from hot admission with an acknowledged drain FSM.
  D7  Offer an explicit RAM-backed sixteen-reservation packet profile rather
      than leaving wide staging uncounted in fabric.

APPENDIX A. MATHEMATICAL IDENTITY AND LIFECYCLE OBLIGATIONS
========================================================

A.1 Circular interval membership
--------------------------------

Let M=16,384 and N=64. Let E be the next external emission sequence, and let
C be the number of live owners, 0 <= C <= N. By ordered allocation and release,
the live set is

  L(E,C) = { (E+j) mod M : 0 <= j < C }.

For any sequence R define d=(R-E) mod M, with d represented as an unsigned
integer in [0,M). Addition of E is a bijection modulo M. Therefore

  R is in L(E,C)  if and only if  d < C.

There is no signed half-range convention hidden in this result. It is ordinary
membership in an explicitly sized circular interval. The bound C<=64 matters
for unique slot reconstruction, while C<M suffices for the membership identity.

The representation is an EXACT compression of the current live generation and
slot identities, provided the lifetime invariants hold. It is not a hash and
has no random collision probability. Its finite-namespace reuse limit is still
real and is handled by the barrier, not denied by the mathematics.

A.2 Preservation of the interval
--------------------------------

Initially C=0 and A=E=64, so the live set is empty and A=(E+C) mod M.

Admission appends A to the end and increments C and A. This preserves the set
formula. Emission removes E from the beginning and increments E while reducing
C. Simultaneous admission/emission performs both operations, preserving C and
shifting both endpoints. Stalls change neither endpoint.

No other event may remove a live owner or advance E. In particular, ready
reservation, COMBINE acceptance, final completion, and output prefetch do not.
Those internal events can happen out of order without changing the live set.

The initial implementation does not borrow a credit from a same-edge emission
while C=64. This avoids a combinational downstream-ready dependency in admission
and a simultaneous old/new ownership transition in one physical row. Its full
boundary may bubble once. That is acceptable only if the agreed sustained-rate
workload tolerates it; otherwise implement registered credit lookahead as a
separate measured refinement, not an undocumented arithmetic shortcut.

A.3 Unique slot reconstruction
------------------------------

Suppose two distinct live sequences share the same six-bit slot. Their unsigned
distances j,k from E differ by a nonzero multiple of 64. But both distances lie
in [0,C), and C<=64, so |j-k|<64. Contradiction. There is at most one live owner
for every physical slot.

For a candidate with slot S:

  offset = (S - E.low6) mod 64.

If it is a valid live candidate, offset is exactly its distance from E, because
that distance is between 0 and 63. Thus E+offset modulo M reconstructs the
full sequence. Validate offset<C or the equivalent active-row invariant.

A candidate has a stronger lease than a bare slot: after combine_reserved is
set, the owner cannot be emitted before the candidate is popped, its complete
input reaches COMBINE, and a valid final result is produced. That proves that
E moving while the candidate waits does not make the candidate refer to a new
owner. The reconstruction must use a coherent E snapshot at the grant edge.

A.4 Why external packets still need generation
-----------------------------------------------

The lease proof applies only to internally trusted candidates. An external
terminal packet can be delayed, duplicated or stale, so its slot alone proves
nothing. It carries the full slot/generation identity. Repacking preserves all
fourteen bits and the live-window check validates them together.

At full namespace reuse a sufficiently old full token could equal a new one.
No finite tag can solve arbitrary delayed replay forever. The barrier requires
all legitimate producers and transports to discharge old transactions before
reuse. A hostile component capable of inventing a matching token after its ACK
is outside that finite-token fault model; support for that threat requires an
additional nonreused domain or stronger endpoint integrity protocol.

A.5 Source phase monotonicity
-----------------------------

Within a single owner lifetime, for each source:

  committed => claimed => issued => required.

Required is frozen at admission. Issued is set only by a valid issue event.
Claimed is set once by the terminal validator and retained until the owner is
released/reinitialized. Committed is set only by a publication event after the
physical payload write. None of these phases clears midway through a live
transaction.

Consequently duplicate suppression needs claimed, not a separate read of
committed; unissued rejection implies rejection of unrequired traffic if the
issue invariant is independently enforced. Keep the assertions for those
implications. Removing a lookup without preserving its supporting invariant
would remove a safety check rather than simplify a representation.

A.6 Claim forwarding
---------------------

A snapshot taken on the same edge as a prior packet's claim normally observes
pre-edge scoreboard state. Without forwarding, the immediately following
packet for that same full owner/source could also pass the duplicate check.

The validator therefore compares against every accepted claim that can be
missing from its snapshot. In the proposed R1->R2 one-edge organization,
one recent accepted record per terminal lane covers the hazard. TMU and AUX
have disjoint source identities; final completion has a separate phase bit.
If a future pipeline adds two cycles, forwarding must cover those cycles too.

Current live membership is checked at claim, not only in the old snapshot.
This prevents an old packet from using a formerly valid identity after the
owner has emitted and the slot is free/reused. A snapshot that was invalid
when taken must not become a valid old-state snapshot merely because the same
identity later appears at admission.

A.7 Why accepted writes do not need another general generation lookup
---------------------------------------------------------------------

An accepted required-source terminal has claimed but not yet committed that
source. The owner cannot legitimately become ready without it. Therefore the
owner cannot have produced and emitted its legitimate final result before
this accepted record's payload write and publication. Its slot lease remains
valid through both operations.

For a final terminal, its final_done bit cannot be true before its own write
and publication. Ordered emission therefore cannot overtake it either.

This is an induction over accepted event ownership, not protection against
arbitrary bit corruption in a pipeline register. Reset/abort must preserve or
jointly cancel those leases. Per-owner destructive cancellation would invalidate
the argument and is not included in the baseline architecture.

A.8 Exactly-once readiness without event FIFOs
----------------------------------------------

Readiness is persistent state: active, all required committed, not reserved.
A local candidate claim atomically sets reserved and occupies a candidate slot.
The same row cannot be selected again because reserved is already set.

If no candidate slot is free, nothing is lost: the row remains ready. If two
sources publish together, they update that row's disjoint committed bits; the
next local selection sees one eligible row, not two independent transition
events. A zero-source row follows the same rule after admission.

Candidate transfer removes it from exactly one local head and reserves exactly
one downstream packet. Actual COMBINE input acceptance changes execution state,
not the lifetime of unrelated candidates. Round-robin service at each level
provides progress under explicit downstream-progress assumptions.

A.9 Packet conservation
-----------------------

For a packet output path let K be its logical reservation capacity. Count every
accepted read that has not yet been consumed externally:

  reserved = address/read stages + returned data awaiting body write
           + unread body entries + body reads in flight + head/spare entries.

The categories are disjoint. Moving a packet between them changes no logical
reservation. Only a new read launch increments reserved; only accepted final
consumption decrements it. Thus 0<=reserved<=K proves bounded storage if every
stage's physical capacity is also respected.

A RAM body read subtracts one unread body entry and adds one pending read. If
a displayed occupancy omits that pending read, it can be zero while reserved
is nonzero. The existing ready FIFO provides a concrete example. Correctness
must be established for the complete sum, not a favored subexpression.

A.10 Final ordering
-------------------

F names the first owner whose final row has not been reserved for output.
A read advances F exactly once, so a separate fetched bit per row is redundant.
The output FIFO preserves the order of those reads. Its head token must equal
E on every transfer. Therefore external emission remains exactly allocation
ordered even when source and COMBINE completion orders differ arbitrarily.

This proof requires synchronous bank data and its token to remain aligned.
The separate numerator/descriptor joins in section 17 follow the same rule:
a registered payload without equally delayed identity/valid is not a correct
latency conversion.


APPENDIX B. REPRESENTATIVE IMPLEMENTATION SKETCHES
=================================================

These sketches communicate widths and state boundaries. They are NOT compiled
RTL, not a replacement for the independent implementation, and not evidence of
Quartus inference or timing. Validate syntax against the project's conservative
SystemVerilog subset and use its real packet types. In particular, the sketches
do not define every reset, counter, assertion, and ready/valid port.

B.1 Full identity repacking and membership
------------------------------------------

  typedef logic [13:0] owner_seq_t;
  typedef logic [13:0] owner_handle_t;

  function automatic owner_seq_t unpack_owner(input owner_handle_t h);
      // External: slot6 followed by generation8.
      // Internal: generation8 followed by slot6.
      return {h[7:0], h[13:8]};
  endfunction

  function automatic owner_handle_t pack_owner(input owner_seq_t q);
      return {q[5:0], q[13:6]};
  endfunction

  owner_seq_t return_seq_c, distance_c;
  logic [6:0] live_count_q;  // 0 through 64, not a six-bit counter
  logic member_c;

  assign return_seq_c = unpack_owner(captured_owner_q);
  assign distance_c   = return_seq_c - emit_seq_q;
  assign member_c     = (distance_c[13:7] == 7'd0)
                     && (distance_c[6:0] < live_count_q);

The subtraction is fourteen bits. The high-bits-zero test is mandatory. A
six-bit subtraction would make a stale same-slot token look current.

For SampleHandle16={slot6,sample2,generation8}:

  owner_seq = {sample_handle[7:0], sample_handle[15:10]};
  source_index = sample_handle[9:8];
  valid_tmu_source = source_index != 2'd3;

Never reinterpret source index three as AUX. The typed AUX channel has its own
identity and reserved publication writer.

B.2 Cursor/capacity state
-------------------------

  admission_fire = run_enable_q && (live_count_q < 7'd64) && input_valid;
  output_fire    = out_valid_q && output_ready;

  // One update to each counter. Sized casts are illustrative.
  live_next = live_count_q + 7'(admission_fire) - 7'(output_fire);

  if (admission_fire) alloc_seq_q <= alloc_seq_q + 14'd1;
  if (output_fire)    emit_seq_q  <= emit_seq_q  + 14'd1;
  if (fetch_fire)     fetch_seq_q <= fetch_seq_q + 14'd1;
  live_count_q <= live_next;

Use a registered admission permission for wrap/drain control. Do not replace
run_enable_q with a combinational sum of all queue pointer differences.

B.3 Row-local source update
---------------------------

For each static group/row and source bit, form named event hits from captured,
validated records. Make the update priority visible:

  if (admit_this_row) begin
      required_q <= admitted_required;
      issued_q   <= 4'b0000;
      claimed_q  <= 4'b0000;
      committed_q <= 4'b0000;
  end else begin
      issued_q    <= issued_q    | issued_mask_for_this_row;
      claimed_q   <= claimed_q   | claimed_mask_for_this_row;
      committed_q <= committed_q | publication_mask_for_this_row;
  end

A row-local update is not permission to run another dynamic read of the entire
64-row array before it. Source masks can be formed with static per-source
writers and registered row/group address decode. Synthesis and timing determine
whether a shared or localized decoder is the better physical implementation.

The property to enforce within a live lifetime is:

  (committed & ~claimed) == 0;
  (claimed & ~issued) == 0;
  (issued & ~required) == 0.

A publication record was already accepted; it does not require a new general
64-row generation mux. A reset/cancel boundary must not allow that record to
write a different lifetime.

B.4 Candidate head/spare transition
-----------------------------------

For one group, let local_new be the chosen unreserved eligible row. The local
choice and room decision use old registered heads plus this edge's central pop.

  next_head = head;
  next_spare = spare;

  if (central_pop_this_group) begin
      next_head = spare;
      next_spare.valid = 0;
  end

  if (local_claim) begin
      if (!next_head.valid)
          next_head = {valid:1, row:local_new};
      else if (!next_spare.valid)
          next_spare = {valid:1, row:local_new};
      else
          ERROR; // local_claim must already have reserved capacity
  end

  if (local_claim) combine_reserved[local_new] = 1;

The notation is intentionally structural pseudocode, not a packed-struct literal
for an unspecified type. Set the row reservation and candidate validity at the
same clock edge. Advance local round-robin on local_claim, not on inspection.

B.5 The synchronous packet FIFO invariant
-----------------------------------------

  physical_tickets = body_unread_q + body_read_pending_q
                   + head_valid_q + spare_valid_q;

A return from an upstream bank-read pipeline may additionally own a reservation
before it enters this FIFO; count it at that enclosing reservation domain.
Do not add the same packet twice merely because it has both a slot number and
a pending-write valid bit. Write out the ownership transfer edge for each stage.

When a non-stallable memory read is launched, reserve head/spare capacity first.
A downstream ready signal may disappear on the next cycle. A register on ready
without the capacity for that already-launched answer is not elasticity.

B.6 Data/token alignment for the legacy numerator join
------------------------------------------------------

  on accept_rcp_packet:
      join_slot owns {owner, mantissa, exponent, depth_zero};
      reserve one eventual PERSPUV input packet;
      register numerator_bank_read_address = owner.slot;

  on numerator_read_return:
      capture raw_u_over_w, raw_v_over_w;
      associate with the SAME join_slot and owner;
      mark the assembled packet ready only after all fields are present;

  on PERSPUV_input_transfer:
      release join_slot;
      do not free global owner;

Write the latency constants once in the primitive/interface contract. If the
memory's read output has an optional register, select its setting explicitly
and propagate the corresponding valid through exactly that number of edges.
No assumption that the old RCP valid stays asserted for the right cycles may
substitute for the join's own reservation.

  constraints_digest: hash of actual SDC and relevant settings
  wrapper: leaf / registered-service / feature-live island / board
  feature_profile: observable formats, sample counts, AUX/Mosaic, context width
  stage_status: map, fit, STA, structural-gate, timing-gate separately
  resources: ALMs, registers, M10Ks, MLABs, memory bits, DSPs

#!/usr/bin/env python3
"""Executable checks for the proposed V3.1 control architecture.

This is a Python architectural model, NOT RTL simulation or a physical fit.
It checks finite-window identity, owner-generation compression, ready selection,
claim/write/publication discipline, registered credit conservation, and the
old ready-queue occupancy omission. Seeds are fixed. No third-party packages.

from __future__ import annotations
import argparse, collections, hashlib, json, random, time
from dataclasses import dataclass
from pathlib import Path


def inside(seq: int, emit: int, live: int, width: int = 14) -> bool:
    return ((seq - emit) & ((1 << width) - 1)) < live


def window_checks() -> dict:
    checks = 0
    # Exhaust the entire reduced state space, not merely friendly traces.
    for w, n in ((5, 4), (6, 8)):
        m = 1 << w
        for emit in range(m):
            for count in range(n + 1):
                explicit = {(emit + k) % m for k in range(count)}
                for seq in range(m):
                    assert inside(seq, emit, count, w) == (seq in explicit)
                    checks += 1
    # Full production sequence width: every head, every legal occupancy,
    # boundary probes and a deterministic interior probe.
    w, n, m = 14, 64, 1 << 14
    for emit in range(m):
        for count in range(n + 1):
            for offset in {-1, 0, count // 2, count - 1, count, count + 1, 63, 64, m - 1}:
                seq = (emit + offset) & (m - 1)
                assert inside(seq, emit, count, w) == (0 <= (offset % m) < count)
                checks += 1
            # Reconstruct a live owner's full token from slot + head.
            if count:
                distance = (emit * 17 + count * 13) % count
                seq = (emit + distance) & (m - 1)
                slot = seq & (n - 1)
                reconstructed = (emit + ((slot - emit) & (n - 1))) & (m - 1)
                assert reconstructed == seq
                checks += 1
    return {'membership_and_reconstruction_cases': checks}


def generation_trace() -> dict:
    rng = random.Random(0xA110C)
    n, m = 64, 1 << 14
    old_gen = [0] * n
    allocation = emission = 64  # slot zero, first generation one
    live = collections.deque()
    admitted = emitted = cycles = wraps = 0
    drain = False
    target = 2 * m + 513
    while emitted < target:
        cycles += 1
        if allocation == 0 and admitted and not drain:
            # A single namespace barrier; all owners drain before reuse.
            drain = True
        if live and (drain or admitted >= target or rng.random() < .62):
            seq = live.popleft()
            assert seq == emission
            emission = (emission + 1) & (m - 1)
            emitted += 1
        if drain and not live:
            wraps += 1
            drain = False
            # Discharge this boundary once. The following admission must occur
            # here so the same A==0 state is not mistaken for another wrap.
            force_admit = True
        else:
            force_admit = False
        if admitted < target and not drain and len(live) < n and (force_admit or rng.random() < .71):
            slot = allocation & (n - 1)
            old_gen[slot] = (old_gen[slot] + 1) & 255
            legacy_seq = (old_gen[slot] << 6) | slot
            assert legacy_seq == allocation
            live.append(allocation)
            allocation = (allocation + 1) & (m - 1)
            admitted += 1
        assert ((allocation - emission) & (m - 1)) == len(live)
        assert len({s & 63 for s in live}) == len(live)
        if cycles > 10 * target:
            raise AssertionError('generation trace failed to make progress')
    return {'admissions_compared_to_legacy_per_slot_generation': admitted,
            'emissions': emitted, 'cycles': cycles, 'namespace_drains': wraps}


class Ready:
    """Eight groups, eight rows/group, two slot-only candidate registers/group."""
    def __init__(self):
        self.eligible = set()
        self.reserved = set()
        self.q = [collections.deque() for _ in range(8)]
        self.local_rr = [0] * 8
        self.group_rr = 0

    def step(self, new=(), credit=True):
        # Selection observes only the previously registered candidate heads.
        grant = None
        if credit:
            for off in range(8):
                bank = (self.group_rr + off) % 8
                if self.q[bank]:
                    grant = self.q[bank].popleft()
                    self.group_rr = (bank + 1) % 8
                    break
        self.eligible.update(new)
        claimed = []
        # One local claim per group; a simultaneous pop can free a slot.
        for bank in range(8):
            if len(self.q[bank]) >= 2:
                continue
            for off in range(8):
                row = (self.local_rr[bank] + off) % 8
                slot = bank * 8 + row
                if slot in self.eligible and slot not in self.reserved:
                    self.q[bank].append(slot)
                    self.reserved.add(slot)
                    self.local_rr[bank] = (row + 1) % 8
                    claimed.append(slot)
                    break
        tickets = [v for q in self.q for v in q]
        assert len(tickets) == len(set(tickets))
        assert len(tickets) <= 16
        assert all(len(q) <= 2 for q in self.q)
        assert set(tickets) <= self.reserved
        return grant, claimed


def ready_checks() -> dict:
    rng = random.Random(0x8B8)
    batches = grants = max_wait = 0
    # Include all 256 readiness masks in each isolated group (hot-group case).
    sets = [{8 * b + i for i in range(8) if mask & (1 << i)}
            for b in range(8) for mask in range(256)]
    sets += [set(range(64))]
    sets += [{i for i in range(64) if rng.random() < .7} for _ in range(2000)]
    for eligible in sets:
        r = Ready()
        todo = list(eligible)
        rng.shuffle(todo)
        seen = []
        claimed = []
        for tick in range(500):
            take = min(len(todo), rng.randrange(4)) if tick < 80 else len(todo)
            new, todo = todo[:take], todo[take:]
            grant, cl = r.step(new, credit=(tick >= 100 or rng.random() < .67))
            claimed += cl
            if grant is not None:
                assert grant not in seen
                seen.append(grant)
            if not todo and len(seen) == len(eligible):
                break
        assert set(seen) == eligible
        assert len(claimed) == len(eligible)
        assert set(claimed) == eligible
        batches += 1
        grants += len(seen)
        max_wait = max(max_wait, tick)
    # Saturated single-group no-stall burst must deliver eight consecutive slots.
    hot = Ready()
    hot.step(range(8), credit=True)
    burst = [hot.step((), True)[0] for _ in range(8)]
    assert burst == list(range(8)), burst
    # Global RR does not starve any group while all groups have ready heads.
    allr = Ready()
    allr.step(range(64), False)
    allr.step((), False)
    first = [allr.step((), True)[0] // 8 for _ in range(8)]
    assert first == list(range(8)), first
    return {'batches': batches, 'exactly_once_grants': grants,
            'longest_batch_cycles': max_wait + 1, 'hot_group_consecutive_grants': burst,
            'first_eight_group_grants': first}


@dataclass
class State:
    seq: int
    required: int
    issued: int = 0
    claimed: int = 0
    committed: int = 0
    writes: dict = None
    def __post_init__(self):
        self.writes = {}


def completion_checks() -> dict:
    """Two independent terminal lanes; snapshot-to-claim distance one.

    This isolates the claim hazard, not the entire renderer. An immutable
    explicit owner table is the identity oracle. A separate sequence window
    implements membership. Accepted claim records own writes; publish is later.
    """
    rng = random.Random(0xC014C4)
    w, n, m = 10, 64, 1 << 10  # more frequent namespace wraps
    emit, allocation = 64, 64
    owners = {}
    # Each lane: raw capture, snapshot, accepted write record, publish record.
    lanes = [[None, None, None, None] for _ in range(2)]
    prior_claim = [None, None]
    claims = rejects = writes = publishes = cycles = retired = 0
    different_same_cycle = both_same_owner = 0
    max_cycles = 120000
    for tick in range(max_cycles):
        cycles += 1
        # New admissions are suppressed at modular wrap until local pipelines
        # drain; an external quiescence ACK is assumed in this isolated model.
        wrap_blocked = allocation == 0 and (owners or any(any(p is not None for p in lane) for lane in lanes))
        if len(owners) < n and not wrap_blocked and rng.random() < .72:
            assert allocation not in owners
            req = rng.randrange(1, 16)
            owners[allocation] = State(allocation, req)
            allocation = (allocation + 1) & (m - 1)
        assert len(owners) == ((allocation - emit) & (m - 1))
        # Issue law: only required sources. Traffic may issue TMU and AUX together.
        if owners:
            for _ in range(2):
                st = owners[rng.choice(tuple(owners))]
                if rng.random() < .85:
                    st.issued |= st.required
        next_lanes, new_prior = [], [None, None]
        accepted_this = []
        for li, (raw, snap, pending_write, pending_publish) in enumerate(lanes):
            # Publication occurs one clock after the actual write.
            if pending_publish is not None:
                seq, src, value = pending_publish
                st = owners[seq]
                assert src in st.writes and st.writes[src] == value
                st.committed |= 1 << src
                publishes += 1
            if pending_write is not None:
                seq, src, value = pending_write
                st = owners[seq]
                assert src not in st.writes
                st.writes[src] = value
                writes += 1
            good = None
            if snap is not None:
                seq, src, value, was_live, issued, claimed = snap
                valid_src = (0 <= src < 3) if li == 0 else src == 3
                recent = prior_claim[li]
                forwarded = recent is not None and recent[0:2] == (seq, src)
                current_live = inside(seq, emit, len(owners), w)
                assert current_live == (seq in owners)
                acc = valid_src and was_live and current_live and issued and not (claimed or forwarded)
                if acc:
                    st = owners[seq]
                    bit = 1 << src
                    assert st.required & bit and st.issued & bit
                    assert not (st.claimed & bit)
                    st.claimed |= bit
                    good = (seq, src, value)
                    new_prior[li] = good
                    accepted_this.append(good)
                    claims += 1
                else:
                    rejects += 1
            new_snap = None
            if raw is not None:
                seq, src, value = raw
                was_live = inside(seq, emit, len(owners), w)
                assert was_live == (seq in owners)
                st = owners.get(seq)
                valid_src = (0 <= src < 3) if li == 0 else src == 3
                bit = 1 << src if 0 <= src < 4 else 0
                # A snapshot is of pre-claim state at this edge. Roll back the
                # bit from this edge's newly accepted claim to model NBA timing.
                cl = bool(st and st.claimed & bit)
                if good is not None and good[0:2] == (seq, src):
                    cl = False
                new_snap = (seq, src, value, was_live,
                            bool(st and st.issued & bit and valid_src), cl)
            # Mix legal required results, duplicates, wrong-class/range and stale IDs.
            incoming = None
            if owners and rng.random() < .93:
                seq = rng.choice(tuple(owners))
                if rng.random() < .15:
                    seq = (seq - n - 3) & (m - 1)
                src = rng.randrange(4) if li == 0 else 3
                value = rng.getrandbits(40)
                incoming = (seq, src, value)
            # Repeating the raw request makes back-to-back claim forwarding active.
            if raw is not None and rng.random() < .19:
                incoming = raw
            next_lanes.append([incoming, new_snap, good, pending_write])
        if len(accepted_this) == 2:
            if accepted_this[0][0] == accepted_this[1][0]:
                both_same_owner += 1
            else:
                different_same_cycle += 1
        lanes, prior_claim = next_lanes, new_prior
        # Retirement of complete owners is globally ordered and can stall.
        # This model uses identity-valued COMBINE/output stubs, not their RTL.
        st = owners.get(emit)
        if st and st.committed == st.required and rng.random() < .74:
            assert st.claimed == st.required
            assert set(st.writes) == {s for s in range(4) if st.required & (1 << s)}
            del owners[emit]
            emit = (emit + 1) & (m - 1)
            retired += 1
        for st in owners.values():
            assert st.committed & ~st.claimed == 0
            assert st.claimed & ~st.issued == 0
            assert st.issued & ~st.required == 0
    assert claims > 1000 and retired > 1000 and rejects > 1000
    assert writes <= claims and publishes <= writes
    return {'cycles': cycles, 'claims': claims, 'rejected_packets': rejects,
            'payload_writes': writes, 'publications': publishes,
            'ordered_stub_retirements': retired,
            'simultaneous_claims_different_owners': different_same_cycle,
            'simultaneous_claims_same_owner': both_same_owner,
            'scope': 'sample/AUX control only; COMBINE and final path are stubs'}


def credit_checks() -> dict:
    def run(depth, latency, clocks, stall=False):
        rng = random.Random(0xC0ED17)
        reserved = 0
        pipe = collections.deque()
        head = collections.deque()
        launches = emits = 0
        for t in range(clocks):
            # Read availability before return credit: no downstream-ready path.
            launch = reserved < depth
            emit = bool(head) and (not stall or t % 311 > 47) and (not stall or rng.random() > .3)
            if emit:
                head.popleft()
                emits += 1
            while pipe and pipe[0][0] == t:
                _, v = pipe.popleft()
                head.append(v)
            if launch:
                pipe.append((t + latency, launches))
                launches += 1
            reserved += int(launch) - int(emit)
            assert reserved == len(pipe) + len(head)
            assert 0 <= reserved <= depth
        return launches, emits
    # Four cycles from request to head materialisation, earliest consumption
    # next edge => six credits avoid the full-to-empty combinational shortcut.
    continuous = run(6, 4, 2000)
    assert continuous[0] == 2000
    stressed = run(6, 4, 50000, True)
    deep = run(16, 8, 4000)
    assert deep[0] == 4000
    return {'continuous_launches_in_2000_cycles': continuous[0],
            'stressed_50000_cycles_launches_emits': stressed,
            'reserved_credits': 6, 'response_latency_cycles': 4,
            'deep_profile_16_credits_8_cycle_latency_launches': deep[0]}



def coalescing_checks() -> dict:
    cases = transitions = 0
    for req in range(16):
        for committed in range(16):
            if committed & ~req:
                continue
            for tmu in (0, 1, 2, 4):
                for aux in (0, 8):
                    # Only genuinely new authorized publications.
                    bits = tmu | aux
                    if bits & ~req or bits & committed:
                        continue
                    before = (committed & req) == req
                    after_mask = committed | tmu | aux
                    after = (after_mask & req) == req
                    logical_transition = int(after and not before)
                    # The row-local design computes eligibility once from the
                    # merged mask, rather than once per arriving producer.
                    assert logical_transition in (0, 1)
                    if tmu and aux and after and not before:
                        transitions += 1
                    cases += 1
    assert transitions > 0
    # Full 1111 requirement, previous 0011, source2 + AUX on one edge.
    assert (3 | 4 | 8) == 15
    return {'legal_publication_combinations': cases,
            'same_owner_two_source_ready_transitions': transitions}


def negative_checks() -> dict:
    caught = []
    # Explicit fault witnesses; these are mutations of MODEL obligations.
    def require(name, predicate):
        try:
            assert predicate()
        except AssertionError:
            caught.append(name)
        else:
            raise AssertionError('bad model was not caught: ' + name)
    require('slot-only stale identity', lambda: ((64 & 63) == (128 & 63)) == inside(64, 128, 1))
    require('queue occupancy omits pending read', lambda: 0 + 0 + 0 == 0 + 0 + 0 + 1)
    require('publish before write', lambda: 0 in {})
    require('ready duplicate reservation', lambda: len([3, 3]) == len(set([3, 3])))
    require('owner freed at read launch', lambda: (1 - 1) == 1)
    # A stale snapshot says unclaimed although last edge accepted same source.
    snapshot_claimed, previous_same_claim, actual_claimed = False, True, True
    require('missing recent-claim forwarding', lambda: snapshot_claimed == actual_claimed)
    require('final before actual combine acceptance', lambda: (True and not False) == (False and not False))
    require('ninth owner in eight-owner toy capacity', lambda: 9 <= 8)
    return {'model_negative_witnesses_caught': len(caught), 'names': caught,
            'not_an_rtl_mutation_sweep': True}


def main():
    p = argparse.ArgumentParser()
