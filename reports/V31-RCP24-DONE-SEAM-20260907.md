# S01 §16.2 confirmed: the ticket queue's header promises a register it does not build

*2026-09-07. Diagnosis only — no RTL changed. Written while the `zhao_texture_v3own`
refit holds the fit lane, on a block outside its closure.*

---

## The claim, and it is exactly true

§16.2 says:

> `zhao_raster_ticketq`'s commentary says a FIFO head is a register. Its actual
> output is `assign dout_o = mem_q[head_q];` That is a dynamically indexed
> combinational output from a flop array.

Both halves check out in the source:

```systemverilog
// line 18:  contexts felt like a ceiling. A FIFO's head is a register.
// line 64:
assign dout_o  = mem_q[head_q];
```

## And the fit agrees, which is the part worth having

§16.2 adds that *"the named full-fit path from u_doneq memory to `r_tok_o` is
consistent with that actual implementation."* The harvested setup report for
`zhao_raster_rcp24_v3@v3-full` — every one of its worst paths:

    -1.045  zhao_raster_ticketq:u_doneq|mem_q[6][3]  ->  r_tok_o[2]
    -1.001  zhao_raster_ticketq:u_doneq|head_q[1]    ->  r_tok_o[5]
    -1.000  zhao_raster_ticketq:u_doneq|mem_q[6][3]  ->  r_o[15]
    -0.975  zhao_raster_ticketq:u_doneq|head_q[1]    ->  r_o[4]
    -0.951  zhao_raster_ticketq:u_doneq|mem_q[6][3]  ->  r_o[19]

They start in the DONE queue's **flop array** or its **head pointer** and end at
the external result ports. That is the unregistered head driving the result
packet, named by the fitter.

The block reports **90.54 MHz** against a core→core of **129.18** — a 38 MHz gap
that is exactly this seam.

## Feasibility, checked rather than assumed

**The throughput gate has room.** `raster_rcp24_v3_directed` asserts *"a
saturated V3 tile costs under 4.6 clocks per reciprocal"* and *"not under four,
which would mean a launch was skipped"*. A registered head adds **latency**, not
per-item cost; across the 256-request batch the gate measures, one extra cycle is
≈0.004 clocks/reciprocal against 0.6 of headroom. §16.1's *"four clocks per
nonzero reciprocal"* is preserved **provided the pop rate is preserved**.

**And the pattern is already proven in this repository.** §16.3 asks for *"a real
registered head and a spare/prefetch slot, with exact queue occupancy"* — which
is precisely `zhao_texture_v3rq`'s two-head-plus-pending-read structure, and its
sustained rate was **measured today**: one external pop per clock, zero bubbles
in 400 cycles, with the counter fire-tested by starving supply. So the design
that keeps the throughput gate green is not hypothetical.

**§16.4's restriction must be honoured.** *"Do not replace every ticket queue
blindly. FREE, NEW, CONTINUATION and DONE have different traffic and
initialization."* `zhao_raster_ticketq` is instantiated **four** times in
`zhao_raster_rcp24_v3`; only `u_doneq` is on this path. The change therefore
belongs behind a parameter that only the DONE instance sets, not in the shared
body.

## Why it is not done in this pass

It is a **protocol** change, not a local one: registering the head moves when
`dout_o` is valid relative to the pop, so `zhao_raster_rcp24_v3`'s consumer logic
changes with it, under a throughput gate. Started with a fit already holding the
lane it would need for measurement, that is the shape of work that gets left
half-finished — and the tree currently has six verified changes in it.

Recorded with its measured evidence so the pass that owns it starts from the fit
report rather than from a reading, which is the failure this repository keeps
paying for.

## The one-line summary for the next pass

Give `zhao_raster_ticketq` a `REG_HEAD` parameter defaulting to **0**; set it on
`u_doneq` only; implement it as v3rq's head/spare pair so one pop per clock
survives; then refit and compare **90.54 reported / 129.18 core→core** on matched
scope.
