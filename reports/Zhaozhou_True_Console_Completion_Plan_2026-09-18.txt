with all mandatory functions and the real platform boundary represented. Then
measure that exact implementation, including a documented failure to fit if it
is too large. A complete collection of isolated leaf blocks is not that machine.

  recover existing work -> freeze the required capability set -> reuse/adapt the

1. NON-NEGOTIABLE BEHAVIOR AND THE MEANING OF COMPLETE
=====================================================
1.1 Preserve the selected visible machine
----------------------------------------
Keep deterministic 60-Hz simulation/presentation, the existing three presentation
modes, two-view Duo, shared simulation between the views, deformable persistent
terrain, FIELD, ordinary correctly clipped/depth-tested/textured geometry,
creature animation and lighting, bounded particles/spells, fog, post and 2D,
audio and controller input. Preserve the accepted fixed-point, rounding,
saturation, ordering, fault and replay laws. [R01,R07]

Do not quietly select 30 fps, halve FIELD population, remove emission, replace
terrain normal detail with ordinary lighting, or use a fixed flat color to make
a compile green. Those would be explicit product decisions, not completion.
A smaller implementation preserving all required behavior is welcome; silently
lowered admitted workload is not.

Do not add deferred features back in merely because a contract filename exists.
GEOM.WARP is deferred in the inspected release definition; generic tangent-space
normal maps are refused for v1. Terrain's separately accepted normal-detail law
must not be deleted on that basis. Optional POST.ECHO needs an explicit current
selection, not automatic inclusion or omission. [R02]

The existing reserve objectives remain visible: provisional physical capacity
41,910 ALMs / 112 DSPs / 553 M10Ks; the Golden Path's 37,500-ALM design-to-cost
portfolio and 37,719 working limit protect roughly 10% fabric reserve. These are
constraints to work toward, NOT measured predictions. Verify actual board part,
speed grade and memory arrangement independently. [R06]

1.2 Separate four verdicts
--------------------------
FUNCTION-COMPLETE:
  Each selected required operation has a real executing path from its input
  source to an observable endpoint; no mandatory response comes from an oracle,
  a constant, an LFSR, a rival/probe or a testbench replacement.

SCOPE-COMPLETE MEASUREMENT:
  The exact selected implementation and platform files elaborate and synthesize;
  the source/configuration identity, hierarchy and all resource categories are
  retained. A failed over-capacity fit is an honest outcome, not a missing row.

REAL-TIME-COMPLETE:
  Required workload cases finish in the actual allowed phases, with resource,
  memory bandwidth and practical timing reserve, using the same configuration.
  A 60-Hz scanout repeatedly displaying old frames is not this verdict.

BOARD-PROVEN:
  The selected top loads on the actual device and passes physical memory,
  clock/reset, input/audio/video, replay and stress tests.

A design may be function-complete and scope-complete while failing capacity or
real-time. That is a valuable, precisely labelled checkpoint, not a release.
The goal of this request is to reach the first honest complete specimen and
expose all deficits, not manufacture a premature release pass.

2. A CAPABILITY LEDGER THAT CANNOT HIDE MISSING ORGANS
====================================================
2.1 One logical obligation is not necessarily one physical module
---------------------------------------------------------------
Several capability contracts can map to one physical owner. FIELD profiles are
adapters around one semantic engine, not five private executors. Terrain and
geometry can share the light-term arithmetic and the projection service.
Liquids and shadows should feed existing geometry/material endpoints.

Conversely, a single module name does not establish the entire capability. A
shared light-term leaf is not the multi-light RGB producer. A topology generator
is not a vertex evaluator. An arena return adapter is not the geometry request
producer. A program cache is not an executable FIELD pipeline.

Maintain two linked views, extending existing tooling rather than replacing it:
  CAPABILITIES: required behaviors, producer -> owner -> consumer, tests, scope.
  PHYSICAL OWNERS: actual instantiated engines/memories, parameters, costs,
                   schedule and whether any other row charges the same instance.

Each capability row must contain:
  immutable ID; current required/selected-optional/deferred status and authority;
  source implementation paths and exact selected parameters;
  one physical/software owner; real producer and consumer;
  reference symbol plus existence/compiled-call evidence;
  functional evidence; negative control; boundary/lifetime tests;
  current integration, synthesis, timing, workload and board evidence SEPARATELY;
  unbuilt/unverified work; target checkpoint; explicit cost UNKNOWN when unpriced.

A row cannot be declared absent only by a filename heuristic. A row cannot be
called implemented only because a similarly named historical block exists.
An external input must name its real provider: "asset memory" is not a complete
provider until an actual fetch path and arbitration route exist.

3. SELECTED ARCHITECTURE AND PHYSICAL OWNERSHIP
===============================================
3.1 Connected dataflow
----------------------
HPS/ARM:
  game truth, canonical terrain collision/save state, Form runtime, immutable
  assets/streaming policy, exact uniform FIELD preparation, audio mixing,
  packet construction and input consumption.

HPS DDR:
  sealed frame rings, asset staging, clip banks, particle ping-pong populations,
  world persistence, PCM ring, captures, optional bounded event journals.

FPGA core:
  command intake -> epoch/frame scheduler -> typed client requests
     |
     +-> one upload mover -> guard/arbitration -> fresh local-SDRAM slots
     |                              -> coherent residency publication
     |
     +-> terrain world/load -> composed terrain caches -> FIELD Earth/reduction
     |       -> selected tessellation + normals/material/light attributes
     |       -> projector client B -> terrain arenas/replay
     |
     +-> geometry fetch/decode -> pose/skin or rigid transform -> world records
     |       -> world normals/lighting -> projector client A -> geometry arenas
     |
     +-> particles: state -> update/collide -> compact/spawn -> commit
     |       -> representation + soft/poly endpoints -> same renderer
     |
     +-> Forge/shadows/liquids/sky -> common typed geometry/material endpoints
     |
     `-> Measure/admission/counters, not an independent source of game truth

ONE shared projection provider serves A and B; one selected clip/setup/binner
and raster/texture/depth/blend/resolve path consumes their output. Immutable
attributes travel via bounded sidecar RAM handles where possible, not wide
copies through every queue. [R01,R06,R10,R18]

Resolved framebuffer -> exclusive post lease -> world planes/displacement/
glow/haze/grade/flash/ink -> HUD -> framebuffer terminal -> slot publication ->
CDC -> video scanout. Audio and input use their real platform paths separately.

3.2 Reuse arithmetic only at an economically sensible scope
-----------------------------------------------------------
Choose local shared services for identical or compatible work inside a domain:
  * one geometry/terrain projector, with real request arbitration;
  * one lighting producer/core family shared across normal producers;
  * bounded particle update/collision arithmetic shared across recipe/response
    cases that cannot execute simultaneously in a single worker;
  * one upload mover for all immutable resource families;
  * selected FIELD banks/services reused by its profile adapters;
  * one post world sample for combined displacement effects.

Do NOT build a console-wide universal arithmetic crossbar. Long operand routes,
all-to-all muxes, wide tags and incompatible deadlines can cost more than a
small local lane. The required unit of optimization is the complete service:
engine + input/output routing + context storage + queues + scheduling + stalls.

For new domains, pick the smallest lane count with a proved workload schedule.
Do not pick one lane just because area is frightening. FIELD and shared
projection already have high combined demand; blindly serializing them is not
an area rescue if it makes the machine miss every frame.

3.3 Cost is charged by instance, never by prose
----------------------------------------------
One physical instance has one owner ID. Capabilities using it cite that owner.
A parent including the texture island must not also bill that island as a
separate root. The selection-swap dry run already found this exact double count.
The dry run's successful elaboration of a new RESOURCE top does not establish
functional installation. [R20]

Retain old implementations as reference/test-only files, not live ancestors of
the production root. Record their exclusion with a reason and prove the new
hierarchy does not instantiate both. Never subtract an old estimate from a new
fitted total to create a purported measured saving.


4. COMMON CONTRACTS: HANDLES, MEMORY, BACKPRESSURE, PUBLICATION
==============================================================
4.1 Compact identities, late payload access
-----------------------------------------
A queue should carry the smallest sufficient token:
  domain-local context index + generation/epoch + source/order identity.
Keep immutable material, vertex, plane, species and light-set records in their
own synchronous stores. Read them when the consumer needs them. Share a record
only while lifetime/last-reader ownership prevents reuse.

Do not carry an arbitrary proposed 64-bit tag through every stage without a
bit budget. Define widths from maximum live contexts and the existing ABI.
Do not widen public handles or narrow generations silently. Existing material
handles have an 8-bit public generation component while residency records use
16 bits: this needs an explicit incarnation/epoch check, not truncation and hope.
Before reuse/wrap, drain readers and invalidate or move to a new epoch. [R12,R13]

4.2 RAM design sheet for every new state structure
-------------------------------------------------
Record depth, width, access phases, readers/writers per cycle, physical banking,
replication, read latency, collision policy, initialization method and expected
M10K geometry. Count active/inactive banks and output registers.

For ordinary single/simple-dual-port M10K planning use documented legal shapes,
including 256x40, 512x20, 1024x10, 2048x5, 4096x2 and 8192x1. True dual-port has
no 256x40 mode. Two independent reads plus one write are not "one dual port".
Use explicit port copies, banking or scheduling; never divide logical bits by
10,240 and call that the physical count. [V01]

No reset loop over payload RAM. Reset validity/control; perform a bounded scrub
where prior contents could otherwise be observed. Generation tagging alone does
not make random power-up tags valid or prevent generation wrap. Read output must
be genuinely synchronous; an attribute saying M10K is not proof of inference.
Same-address mixed-port read/write semantics must be explicitly implemented or
proved unreachable. [V02,V03]

Examples, shape estimates only:
  16 x 256-bit material records: seven 256x40 slices if read as one wide word;
  64 x 64-bit narrow payload organization: two 256x40 slices, at extra cycles;
  256 x 76-bit binding row: two simple-dual-port slices, four true-dual-port
    slices before copies, depending on selected organization;
  nine 512-pixel source lines at RGB565: 73,728 logical bits, not a proof that
    nine M10Ks satisfy every simultaneous access or additional plane need.

Use narrow/burst storage for low-rate material/descriptor fetches where its
latency is harmless. Avoid a seven-block 256-bit read just because the public
record is 32 bytes. Public packing does not mandate a 256-bit internal datapath.

4.3 Ready/valid and service completion
--------------------------------------
Hold valid payloads stable until accepted. A fixed-latency producer cannot be
backpressured by simply freezing downstream tags while products continue to
arrive. Reserve downstream storage at issue or use enough elastic buffering.
Define exact acceptance, landing, retirement and terminal events separately.

Arena sealing waits for landed writes, not requests accepted at a deep pipeline
input. Frame publication waits for all physical memory writes to retire, not
just the framebuffer writer's issue count. A legal abort stops new work, drains
or cancels old work by identity and releases ownership exactly once.

An empty queue is not automatically the end of a frame. End markers, issued /
retired accounting and producer closure distinguish "idle now" from "finished".

4.4 Reset and outstanding memory writes
---------------------------------------
A local abort cannot erase knowledge of writes already accepted by an external
memory interface. Quarantine the destination until those writes drain. Otherwise
a late write can corrupt a newly allocated owner even if its response is dropped.
A generation tag protects interpretation, not physical bytes already being
written to a reused address.

For a global transport reset, define the hardware barrier proving no old write
can arrive before allocator reuse. For soft domain reset, preserve/drain the
outstanding transaction or use an externally owned quarantine record. Include
reset-mid-upload, reset-mid-particle-commit and reset-mid-frame in tests.

4.5 Counter storage is useful but not magic
------------------------------------------
Keep immediate fault/credit/ownership bits in fabric. Move cold histograms and
large indexed statistics to RAM with a defined update schedule. For back-to-back
updates to the same histogram bin, add forwarding or a conflict stall; otherwise
read-modify-write loses counts. Never delete required diagnostics as a covert
product cut. A production-debug build may exclude optional probes only with a
separate selected configuration and clear evidence.


5. UPLOAD, MATERIAL RESOLUTION AND COHERENT RESIDENCY
===================================================
5.1 One generic upload controller
---------------------------------
Start from the existing zref_mem_upload.hpp verdict and the existing HPS/VRAM
transaction conventions. Reuse the CRC32C implementation. FRAMEBLIT supplies a
useful transport precedent, not permission to retain its framebuffer lease or
canvas-length restrictions in the resource uploader. [R12,R14]

Suggested controller states:
  IDLE -> CAPTURE -> VALIDATE -> RESERVE_FRESH_SLOT -> READ_BURST
  -> STAGE_BEATS -> ISSUE_GUARDED_WRITES -> NEXT_BURST
  -> CLOSE_ISSUER -> WAIT_RETIRE -> VERIFY -> PUBLISH_MAPPING -> COMPLETE
  Any error -> STOP_NEW_ISSUES -> DRAIN_OLD_WRITES -> QUARANTINE/RELEASE -> ERROR.

Use existing 64-byte bursts and a narrow beat datapath. One or two small RAM
burst buffers suffice as a STARTING design; actual bridge stalls determine the
required depth. Do not create one DMA per animation, terrain, texture, palette,
mesh, sky and Sunder family. The owner/allocator chooses region and destination;
the mover transports validated bytes unchanged.

Descriptor legality order must match the existing oracle:
  zero length; alignment; unreachable high HPS address; source arena bounds;
  destination guard bounds; stale epoch. Check endpoints wider than addresses.
The new support library and optional RTL validator implement that ordered
predicate, not the full upload engine. [R14]

The owning configuration must itself be valid: source regions fit the supported
HPS address aperture; destination regions fit the real local memory and allowed
resource map. Revalidate epoch and slot ownership at publication, not just at
request acceptance. Freeze source staging bytes or pin them until all reads end.

5.2 Atomic publication is a mapping transaction
-----------------------------------------------
Old slot A remains immutable/pinned. Upload into fresh, unpublished B. All B
writes retire; CRC and guard checks pass. Then atomically publish B with its
new generation. Retain A until the final frame/cache reader's pin is released.
CRC failure discards B and leaves A's bytes and mapping unchanged.

The state variable "generation changed" does not make in-place overwrite atomic.
Do not claim end-to-end copy verification from a source-stream CRC alone: state
whether the contract verifies staged bytes, actual readback, or both. Hardware
memory integrity/readback qualification is a separate property.

There is one residency mapping/publication owner. Cache tags include enough
resource incarnation to make an old entry structurally unable to match new
bytes. Explicit invalidation can reclaim capacity and support wrap barriers; it
must not be an easily forgotten per-cache correctness checklist. [R12]

5.3 HPS and local-SDRAM arbitration changes are part of the implementation
-------------------------------------------------------------------------
The inspected HPS arbiter was a two-client interface. Upload and particle state
cannot be attached by inventing an unregistered identity or bypassing the guard.
Extend or hierarchically compose arbitration with named clients, bounded burst
lengths and a liveness/fairness rule. Preserve scanout and required render
service; reserve enough progress for background uploads so a resource cannot be
starved forever. Schedule publication deadlines, not a fictional promise that a
shared-memory upload can never influence latency.

Count request tags, retirement routing, buffers and arbitration in Backend.
A software memcpy from HPS to a testbench memory is not FPGA uploader completion.

5.4 Material resolver
----------------------
Consume the existing 32-byte ZhMaterialRecord emitted by the ABI generator and
zref::material::Resolver/record_legal. Resolve at meshlet/draw granularity, not
per fragment. A direct-mapped cache is adequate as the default structure; start
with the current reference's 16-line organization, then justify any size change
against hit behavior/counter semantics. [R13,R15]

A low-area implementation uses narrow synchronous words plus a single output
record assembly register. Sequence the lookup over several clocks. Store tag,
residency generation, material identity and any semantic quality-tier component
in the same coherent cache entry. If quality currently does not affect record
selection, document that rather than silently adding a new interpretation.

On a miss, issue a real guarded fetch, check the frozen record, and only then
fill and reply. Missing residency faults the frame; a cache miss backpressures
within its allowed work window. Never fabricate material zero.

Translate the public material sample fields into the CURRENT Packet-B binding
selector/generation representation in one named adapter. Do not let the old
FRAGROB terminology generate a second texture residency owner. The resolver
owns lookup; the texture island owns its established sample lifecycle.

Acceptance:
  all eight ratified recipes; zero to three samples; legal mode fields;
  reserved-word rejection; generation republish WITHOUT an explicit flush;
  byte-for-byte cold/hit response equivalence; held misses under stalls;
  stale handle/refused table cannot create a fragment; all three-sample material
  outputs actually reach the combiner and influence the final pixels.


6. GEOMETRY, SHARED PROJECTION, ANIMATION AND ATTRIBUTES
======================================================
6.1 Build the request path, not another projector
------------------------------------------------
Reuse MESHFETCH, ASSETFETCH, VDECODE, the memory adapter, ASSEMBLE, SKIN and
available normal/pose stages. Static vertices use the ruled rigid transform;
skinned vertices use the selected palette and exact skin arithmetic. Their
world-coordinate records feed client A of the shared service.

The newly added zhao_geom_proj_lane consumes returned projected vertices and
fills the geometry arena. It is a useful piece. It does not remove the need to
fetch/decode/transform/issue real vertices. Its non-stallable result assumption
currently relies on the arena accepting every fill: changing arena banking must
preserve that or add issue-time credits/reserved landing space. [R10]

Geometry request sequence:
  validate/pin mesh/material/clip resources -> open arena with incarnation
  -> fetch required vertex/index records -> decode + transform/skin
  -> prepare world normal/light sidecar -> issue tagged projection request
  -> count result landings -> seal -> replay indices as triangles
  -> join attributes -> clip -> setup -> binner -> shared renderer.

Preserve source IDs, index order, view identity, topology and rejection behavior.
Each viewpoint projects world data separately; simulation/skin work is shared
where its identity is genuinely view-independent. Billboard orientation and
camera-dependent effects are not view-independent merely because positions are.

6.2 One provider at the composition root
---------------------------------------
The terrain pipe can already own a projection subsystem. If using it, route
geometry into its exposed A interface; do not instantiate a second subsystem
next to it. Alternatively extract one common parent provider and use thin client
adapters, in one deliberate migration. Prove exactly one physical core is
reachable from the selected root. [R18]

Freeze MATW, ROWS_PER_PASS, arena capacities, validity mode and queue sizes for
one workload-qualified profile. ROWS_PER_PASS=3 is the fully parallel three-row
setting in the inspected core; do not describe it as the serialized setting.
The RPP=1 alternative changes throughput and cannot be selected from its resource
count alone. A 6,598-ALM service at one parameter point is not proof of savings
against differently configured geom/terrain wrappers. Reprice matched parents.

A request scheduler must obey both clients' deadlines and the result interface.
If result A cannot stall, acceptance reserves its landing slot. Configuration
writes cannot reinterpret vertices already in flight: use frozen per-frame/view
state, explicit epoch barriers or banked configuration with lifetime tracking.

6.3 Pose, palette and Transform Loom
------------------------------------
Resident clip bytes come through upload and generation-tagged residency. The
pose cache identity includes clip-bank generation, type, clip, frame and subframe
where applicable, plus any deformation/scale identity that changes the pose.
Animation state shared among identical instances should decode once, not once
per creature, while instance-specific patches remain explicit. [R12,R16]

For optional uniform per-bone scale tracks introduced on the art branch, treat
identity scale as a no-op and preserve source/midpoint validation. Do not assume
an art/reference feature automatically exists in hardware. Reconcile that asset
format and its matrix/normal consequences before declaring animated-asset parity.

Loom is a parent-before-child transform composer, not a graph processor. The
compiler/HPS supplies order, local transforms and keep-world reparent results.
No recursion, cycle-finding engine, general matrix inversion or gameplay events
in the FPGA. Use the exact affine compose law and a small sequenced MAC unit;
store parent records in the ruled local-SDRAM region with a working cache, not
1,024 wide flip-flop matrices. [R16]

General affine product cost is 36 products per node. A single lane's arithmetic
issue floor for 1,024 nodes is 36,864 clocks before setup/fetch/rounding. This is
an illustrative bound, not the actual frame workload or proof of sufficiency.
Do not replace the real transform-node count with creature count or assume a
1,024-node stream bound limits the number of streams per frame.

6.4 Complete attribute carriage is a first-class missing cost
-------------------------------------------------------------
Packet D's 1,157-bit three-plane record does not prove full Gouraud RGB, fog,
emission and required world/AUX attributes are priced. List every selected
profile explicitly: what produces each attribute, where clipping interpolates
it, how triangle setup stores it, and what fragment stage consumes it. [R06]

Use one authoritative profile descriptor, a compact per-triangle handle and
RAM-backed plane/material records. Thin consumers fetch needed planes/fields;
keep counters and metadata to establish ordering. Avoid one giant universal
pipeline record copied at every stage if most consumers need a few fields.

Do not change interpolation laws while changing storage. Attrgrad's rounded
horizontal step may differ from recomputing an exact rational per pixel. Match
accepted behavior, including ties and signed rounding. Any numeric-law change
needs an explicit version/golden decision, not a smaller implementation label.

Sharing attribute setup dividers is attractive AFTER their true job count and
setup schedule are known. The supplied DIV32 research is a candidate, not a
completion dependency. In particular, a three-plane budget cannot be silently
reused for RGB+emission+fog+AUX profiles without charging their requests.

6.5 Depth, clip and terminal completion
---------------------------------------
Carry guarded w to the canonical depth producer and ensure the same selected
profile reaches reference and RTL. Do not leave one producer emitting old
Q16.16 1/w while a consumer interprets it as invw24. Preserve strict depth ties,
clear value and explicit decal/shadow bias. [R07]

Complete renderer return/terminal paths and scanout wiring now, not in an
unpriced final-glue phase. Both normal completion and faults release exactly
one lease; dropped/aborted work must not strand it. Test all-zero/fully-clipped
frames, malformed materials, memory refusal and reset under backpressure.


7. LIGHTING, NORMAL DETAIL, EMISSION AND FOG
===========================================
7.1 Use the one existing light-term law
--------------------------------------
The existing zhao_terrain_shade takes a world normal and implements the shared
light-term arithmetic. Do not build a second engine because GEOM.LIGHT has a
different name. The missing work includes selecting/configuring independent
lights, per-light response, RGB accumulation, ambient/spill/emission carriage,
and the real throughput-qualified composition. [R11]

Use the compiled shade_from_world_normal_unclamped entry point, not a new
standalone oracle that merely restates the RTL. For each independent light:
  signed base response + that light's allowed normal-detail response;
  clamp that light's response independently;
  accumulate its gain and emission terms in exact declared wide lanes;
  add ambient/spill; apply the ruled final saturation/application order.
A negative second light may not subtract the first light's illumination.
Emission shares the light response but remains the separately required additive
term; zero emission is the exact revert control, not authorization to omit it.

7.2 Low-area architecture without an impossible schedule
--------------------------------------------------------
Store the bounded light set and material/tint configuration in small immutable
per-frame banks. Prepare uniform light data on the ARM only using the exact
existing fixed-point functions and existing authorization. Produce/reuse a world
normal and magnitude at their correct identity. Never normalize independently
for every light if the law allows a common magnitude. Never pre-round a shared
quantity in a way that changes a boundary result.

One candidate architecture has a normal/magnitude frontend, a pipelined light-
term service, a small RGB accumulation context store, and a deterministic light
walker. The service's lane count is chosen from the full deadline, not a guess.

A critical warning: 120,000 vertices x four lights = 480,000 evaluations in a
particular stress profile. A scalar 147-cycle service would require 70,560,000
cycles before overhead if serialized, not fit in a 100-MHz/60-Hz frame. The
current service's ACTUAL initiation interval, not just its latency, decides this.
Use preparation, invariant reuse and pipeline/context overlap; if those still
miss, retain enough parallelism and report the cost. [R06,R11]

Do not count four lights as guaranteed on every vertex without checking the
ruled profile; conversely, do not assume culling or sparse lights without traces.
The admission model must include the worst accepted content, not an attractive
average demo.

7.3 Terrain normal producer is not resolved by G8B
-------------------------------------------------
The current terrain projection pipe explicitly omits TERRAIN.NORMALS and
canonical depth. Its tessellator emits a vertex fill pass and an index/reference
pass; there is no world-triangle stream for the old normal unit. [R18]

Default architecture to investigate: retain world positions in a compact banked
arena during fill; reconstruct the exact world triangle alongside replay and
feed the existing normal law. Read ports are real costs. A three-vertex read
may require bank/copy organization or a short sequencer; price it with the
required triangle rate. Do not turn this into another third full tessellation
pass if that breaks two-view throughput. Per-cell precomputed normals are an
alternative ONLY if the same accepted shading law/results can be demonstrated.

Selected terrain normal detail remains separate from ordinary world normals
and base lighting. Give it an owner, actual sampler/input records and its
per-light combination point. Do not use flat unlit terrain as the completion
fixture that happens not to activate this entire debt.

7.4 Fog placement
------------------
Compute the accepted fog factor from the selected guarded w and the frozen
frame-constant reciprocal/preparation. Transport and interpolate the factor
separately from unfogged RGB. The path is:
  lighting -> attribute interpolation -> toon if selected -> material combine
  -> fog final source color -> depth/alpha/additive blend as specified.
Explicit bypass classes remain explicit: HUD/sky and ruled emissive classes.
Do not modulate the fog color by the texture or quantize fog into toon bands.
[R07,R11]

Acceptance must show lit textured geometry and terrain with independent lights,
colored overlap, zero/high emission, toon boundaries, distant fog and explicit
bypasses at final resolution. Also compare exact arithmetic/counters under
pipeline stalls and resource-generation changes.

8. COMPLETE FIELD V3 AND TERRAIN MAINTENANCE
===========================================
8.1 What completion actually entails
------------------------------------
FIELD is the heart of this machine and is not a feature-cut candidate in this
plan. The frozen v1/v2 engines remain valuable exact references. They do not
satisfy the selected v3 Earth60 production contract. Existing v3 services, RF,
dispatch and experimental compositions are material to reuse, not a reason to
report the executor as already paid for. [R08,R09,R17]

Make a production extraction matrix before copying a probe:
  existing source -> production responsibility -> retained arithmetic/state
  -> removed laboratory stimulus -> required external real provider -> evidence.

The relevant experimental shapes include zhao_probe_v3_exec, _engine, _full,
_walk_earth and _patch_acc. Their source contains real machinery and also probe
policies/rivals/test surfaces. Extract or parameterize a production-only
composition without instantiating a rival agent or a probe table as a consumer.
Do not rewrite their validated arithmetic merely to remove the word "probe".

Inspect actual elaboration for multiplier ownership. The inspected full probe
describes an executor bank AND a service-path bank; treating them as one bank,
or crediting a saving from merging them without a complete schedule, is wrong.
Do not assume every occurrence of the same source module means one physical
instance. Conversely, one shared four-wide bank is not four full FIELD CPUs.

8.2 Prepared plans, contexts and exact execution
-----------------------------------------------
Preserve canonical Field IR, validator, program identity and zfield::interpret.
FPLAN is a generated derived representation, not a second manually encoded ISA.
Exact uniform preparation runs once per association using the same fixed-point
functions. Store uniforms in the scalar bank; generate varying lattice inputs
at the profile adapter instead of streaming twelve inputs per point from HPS.

Use the existing ready-context scheduling idea: eligible contexts issue bounded
micro-operations; long operations park a context until a tagged completion;
writeback retires through the real RF arbitration. Each context has one explicit
lifecycle and enough identity to distinguish old results from reused storage.
Keep cold context payloads and instruction data in synchronous memories; keep
small live ready/busy/credit state in fabric when concurrent update ports make
RAM inappropriate.

Required dispatch closure:
  every admitted FPLAN opcode -> exactly one operation owner -> declared operand
  width -> request format -> service credit -> result width -> RF destination
  -> sticky status -> context release -> exported result at END.

No opcode may be classified long by the executor and permanently refused by the
dispatcher. The old full-probe header documented this failure for SPLINE/RING
forms. Recheck the current actual table; do not assume that old diagnostic text
is either current fact or already fixed. Prepared RING and varying-radius RING
are different admitted forms, not interchangeable opcode labels.

Cold/unsupported programs must be refused at admission or routed through the
explicit exact software/fallback path already allowed by the contract. They
cannot silently zero outputs, deadlock a context, or claim Earth60 certification.
Every mandatory real-time program must retain its certified production route.

8.3 Writeback, credits and resource liveness
------------------------------------------
The existing probes found that treating a writeback announcement as an accepted
write loses results under arbitration. Preserve the actual skid/credit solution.
A fixed-latency multiply reserves a writeback slot at issue; a returning long-op
cannot be starved by endless simple ALU work. Use the measured policy or improve
it with a separately proven bounded schedule. [R17]

Maintain these invariants and fire failing controls:
  accepted uops = retired + in_flight + explicitly faulted/cancelled;
  one result updates its original context/destination exactly once;
  context reuse waits until old tagged work is drained or safely invalidated;
  no RF source is read before its producer completes;
  no stale service result writes a fresh context;
  required completion paths have bounded progress under allowed stalls;
  all mask lanes and partial final vector groups preserve order/status.

A single universal priority mux over all nested services is not automatically
smaller or deadlock-free. Identify requests that themselves need another bank,
reserve before launch, and do not hold a shared lane while waiting for a service
that also needs that lane.

8.4 Earth adapter and ordered reduction
---------------------------------------
Earth generates x/z from patch origin, pitch, row and lane mask. Full 33x33
row-major update uses 297 four-wide groups, not 273: each 33-wide row needs nine
groups. Flat INIT/DRAIN can use 273. Uniform SatLedger status must combine with
varying execution exactly as the canonical interpretation requires. [R09]

Use the existing command-order reductions:
  height and nav: declared saturating chain, never reassociated casually;
  material: last covering writer in command order;
  velocity: its declared exact accumulation;
  outputs: collected from the plan's actual exported registers.

Results may execute in parallel but must commit to each patch/vertex in the
required order. Use field-major epochs plus a bounded reorder/context scheme;
never reduce saturation in completion order. The patch accumulator can use
banked RAM, with a deterministic access schedule and hazard bypass for successive
updates to the same vertex.

The inspected Earth budget requires <=6,000 cycles per full association and
<=850,000 for the 128-association slice including init/finalize and setup.
Those are admission limits to test, not achieved measurements of this handoff.
They also do not license spending an independent full frame on all downstream
terrain and rendering stages. [R09]

8.5 Other profile adapters
--------------------------
Flow: consume the frozen particle/population input identity and return bounded
acceleration to the selected update law. Formation: supply instance/index
inputs and export transforms/offsets without creating gameplay events. Stamp:
generate its bounded stencil inputs and commit to the ordinary surface owner.
Any selected Warp profile must follow its current authority; do not resurrect
deferred GEOM.WARP as a compulsory separate engine.

Each adapter owns input mapping, scheduling and output transport, not arithmetic
semantics. One program evaluation must not be reduced by two slightly different
rules in the CPU and FPGA. Track combined bank/table demand across all admitted
profiles, including simultaneous Earth plus particles/formation scenes.

8.6 Terrain world, bake and persistence
---------------------------------------
Compose the existing island directory, residency, page loader/streamer, load
queues, composed-cache frontend, patch representation, tessellation and replay.
A sky/void region is not a failed memory fetch. Dirty persistent layers survive
eviction and reload. Mutable surface/cache identity changes invalidate exactly
the dependent records; a view change must not unnecessarily recompute canonical
terrain truth.

Use the existing bake_v2 and cliff-RAM candidates where their latest functional
and physical evidence permits adoption. Do not count their predicted savings
before a matched current parent shows them. Bake's slower sweep may be lawful
under the existing deferral contract; that does not mean user-visible live
terrain deformation may be postponed by an arbitrary number of frames.

Separate immediate live FIELD deformation from persistent scar baking, mip
maintenance and eventual writeback. Tag committed terrain snapshots so rendering,
particle collision and shadows refer to the same tick's allowed terrain state.
A cache miss that is late because of arbitration must not nondeterministically
turn solid ground into no-contact if the law expects resident data.

Acceptance scene: two views, overlapping Earth fields, terrain material/nav/
velocity outputs, new craters and moving debris, bake/writeback, evict, return,
replay. Every required output is observed; an attractive height image alone does
not prove material/nav or persistence paths execute.


9. PARTICLES: ONE ECONOMICAL STATE/UPDATE/COLLIDE/SPAWN SUBSYSTEM
================================================================
9.1 Reconcile the numeric law before adding hardware
----------------------------------------------------
Use qformats.md section 10, not obsolete contract paragraphs:
  position: three signed18 components in 1/256 m relative to population origin;
  velocity: three signed11 components in 1/256 m per 60-Hz tick;
  age10, species7, size6 (relative world radius /16), spin6,
  flags4 with the reserved bit zero, variation8; exactly 128 bits.
Population rebasing occurs only between complete ticks and is captured. Do not
silently clamp a population origin change or reinterpret size as screen pixels.
[R07]

There is a genuine documentation conflict: the older UPDATE eight-step prose
places age/collision/events differently from the newer qformats tick list. Freeze
one canonical composed-tick transition and make old docs point to it. Use the
newer ratified numeric law as authority where it clearly supersedes older prose;
where event timing is still ambiguous, propose an explicit compatibility decision
and independent vectors. Do not let two subagents implement different orders.
This is a concrete pre-implementation resolution, not a request to design a new
particle language.

9.2 Default physical organization
----------------------------------
One state streamer owns read-A/write-B ping-pong generations in HPS DDR, not a
population of register records on the FPGA. Small RAM staging queues decouple
bursts from the worker. Keep species/constants/curves in compact epoch-frozen
on-chip tables; only the active particle/context lives in fabric.

One bounded worker family shares arithmetic across the fixed recipe and response
cases. Do not build twelve spatial recipe pipelines and five separate collider
engines. Do not turn the recipes into a second programmable FIELD processor.
Flow remains a service input from the actual selected FIELD path.

Start with a single complete update/collision worker and a small number of
contexts where memory/sample latency requires overlap. Select additional lanes
only from the worst accepted mix and a measured service schedule. A target II8
for 32,768 particles costs 262,144 issue clocks; II16 costs 524,288. These are
issue floors, not complete tick times: add memory, Flow, collision sampling,
spawn admission, fill/drain and publication. [R06]

9.3 Deterministic survivor-first commit
---------------------------------------
Read the old committed generation without overwriting it. Update/collide each
particle through the exact law. Write survivors in original relative stream
order into the new generation. Only after the survivor count is final can
children be appended under the survivor-over-child priority. The whole new
population publishes after all stores retire; abort leaves the previous
population and count intact. [R19]

Do not stream children immediately behind each parent: later survivors have
priority. Do not hold 32,768 full records in fabric to solve this ordering.

Two implementable storage-conscious choices:
  A. Bounded event journal in HPS DDR. Record only information needed to derive
     children later, including stable parent identity and the correct post-update
     parent state or a justified reconstructible locator. After survivors finish,
     walk the journal deterministically and append admitted whole groups.
  B. A deliberate second read/compute pass over immutable old input, reconstructing
     the same events after survivor count is known. Lower journal storage, but
     charges extra reads and arithmetic; choose from measured bandwidth/time.

Default to A if bandwidth permits; it makes ordering and reset recovery clear.
Store a small number of journal records in RAM staging, not a full FPGA journal.

For strict-prefix whole-group admission, there is a useful bound: after retained
valid requested groups cover the maximum possible child capacity, later groups
cannot be selected for ANY final survivor count. Later requests still contribute
the exact counters but need not carry a full child payload. This bounds retained
nonempty group descriptors by population capacity. Confirm the strict-prefix
policy before relying on that bound; the supplied model labels it a proposal.
Do not silently skip an earlier oversized legal group and accept a later small
group if that changes the ruled priority.

A 32-byte journal entry x 32,768 entries is 1 MiB; writing and reading all of it
adds up to 2 MiB/tick (~125.8 MB/s at 60 Hz) before other traffic. That is an
explicit worst-case candidate debit, not "free host RAM." Narrower journals or
second-pass recomputation may be necessary. Admission counts must reflect real
accepted event patterns, with an overflow behavior that cannot drop survivors.

9.4 Stable particle identity is a specification seam, not free bits
-------------------------------------------------------------------
The 128-bit record has no dedicated particle_id, while contracts name stable
identifiers for stateless hashing. Reuse the already ratified identity scheme
if implemented. If it is not defined, resolve it explicitly before completion.
A compacted stream index changes from tick to tick and cannot automatically be
called a stable lifetime identifier.

One possible proposal is a parallel 32-bit identity sidecar in HPS DDR, combined
with population incarnation. That preserves 128-bit public particle packing but
adds 128 KiB per population buffer at 32,768 particles, 256 KiB for the pair,
and up to 0.25 MiB/tick of roundtrip traffic (~15.7 MB/s at 60 Hz). Wrap/reuse
needs an incarnation barrier. These numbers are storage arithmetic, not a new
ratified ABI. The support model receives stable_id externally and deliberately
does not invent the hash or modify the frozen record.

9.5 Spawn rules and atomic groups
----------------------------------
Use the closed event vocabulary and bounded children: parent order -> event
order -> child index, maximum16 per event, no same-tick recursion. A malformed
17-child descriptor is refused, not truncated into a different effect. Reserve
space for an admitted whole group before its writes; reset must not publish
half of it. Capacity refusals are deterministic, not based on response arrival.
[R19]

Keep children_requested, emitted and refused separately, including requests
beyond capacity. If four events can occur for one parent, 16 is a per-EVENT
bound, not automatically a per-parent bound. Define combined event ordering.

9.6 New collision candidate: reuse, then qualify
-----------------------------------------------
The current zhao_part_collide candidate shares a velocity datapath across its
responses and reports directed property tests. Preserve that work. Its commit
explicitly says it has no independent oracle and no Quartus measurement. [R05]

Complete the following before calling it production:
  reconcile canonical particle formats and tick order;
  establish the exact independent response reference and non-circular vectors;
  prove the heightfield sample, contact measure and placement use the same
    geometry, including sloped and moving terrain;
  bind unavailable-sample behavior to declared residency/sample availability,
    not arbitrary memory latency;
  test IGNORE/DIE/STICK/SLIDE/BOUNCE, grazing contact, zero restitution/friction,
    origin rebasing, saturated velocities and one-response-per-tick;
  test response stability/order under stalls and reset;
  map and then measure it inside the complete worker, including muxes/contexts.

Plane/heightfield selection, normal format and clearance epsilon must remain
named, ruled/validated inputs. Do not make a local 20-mm or one-LSB constant a
new gameplay/visual law by hiding it in the implementation.

9.7 Draw path and bandwidth
---------------------------
Convert the world-radius multiplier through the existing selected projection
law. Reuse the common geometry/raster endpoints for polygon particles and the
existing soft endpoint for soft particles. Changing representation must not
change simulation identity, spawn order or the next tick's hash.

At32,768 particles, 16-byte read plus 16-byte write is 1 MiB/tick, about62.9 MB/s
at 60 Hz. This alone excludes species loads, event journals, sidecars, child
append traffic, Flow and all other clients. Keep those additions visible in a
shared HPS bandwidth ledger and a complete arbitration stress run.

11. POST, 2D, MEASUREMENT AND DIAGNOSTICS
========================================
11.1 One bounded world stream
-----------------------------
POST.GATHER already existing is not POST.COMPOSITE completion. Implement the
frozen order: world + restricted world planes; combine displacement contributions
once; coherently sample world color/glow/ink; haze; bloom; curves/matrix; flash;
exterior ink; HUD. The three displaced outputs must share coordinates so outlines
do not detach. [R22]

Keep compact quarter-resolution effect planes. The selected +/-8 horizontal,
+/-4 vertical reach motivates nine source lines and explicit lifetime tracking.
Use synchronous line banks and narrow output staging, not a second full FPGA
framebuffer or one framebuffer pass per effect. At edges and in Duo, clamp within
the correct view BEFORE forming addresses. [R22]

A single source fetch into the line system is distinct from arbitrary repeated
accesses within resident line RAM. Count line fill, output writes, compact-plane
reads and any glow-prep passes. Do not equate work-item count with cycles if a
pixel requires several serialized operations.

If post modifies the back/resolve buffer in place, defer writes until no future
displaced sample can reach the old line. Never post-process the currently
scanned-out front buffer. The post lease is exclusive after resolve and before
publication; its tail shares the frame deadline with prior serial work.

11.2 Exact color tables and small shared arithmetic
---------------------------------------------------
Use existing per-channel curves and matrix law. A promising exact preparation
stores unrounded matrix-product vectors for each curve entry, sums them and
performs the original final bias/round/saturate. This was already explored in the
Golden Path; it needs actual generated-table equivalence and parent pricing,
not another new color math convention. [R06]

For 32/64/32 entries with three signed 24 products per entry, capacity is9,216
logical bits. Three simultaneous72-bit reads suggest six simple-dual-port
M10K slices before active/inactive banks. Six, not one. Count normal line/glow/
displacement memory separately. A three-product sequenced worker is another
candidate, but do not add its saving to the table version's saving: they replace
the same work.

Do not introduce a generic65,536-entry RGB565 remap that contradicts the selected
resource/semantic design. Full-frame lookup tables and ignored port replication
are not free memory tricks.

11.3 HUD, 2D and completion
----------------------------
HUD is last and must not force a second world-frame read. Duo's rendered3D area
and its displayed canvas differ; count/CRC the correct one. Include the48 HUD
scanlines and per-view clamping in captures. Post completion issues the same
owned terminal protocol, not an independent slot swap.

11.4 Measure and statistics
----------------------------
Reuse governor/tokens. Complete their inputs from real counters/histograms and
reported demand. Do not let a guessed workload become an automatically enforced
feature cut. Keep distinct resource-demand axes: texture nearest/bilinear,
projection, lighting, FIELD banks, memory service and completion tails.

For a RAM-backed histogram, aggregate per-cycle same-bin events and implement
read-after-write forwarding or scheduled stalls. A one-read/one-write port cannot
accept arbitrary simultaneous updates to many bins without extra hardware.
Snapshots/clears need epoch or double-bank semantics so a host read sees one
complete interval, not a mixture. Choose widths from the documented interval and
saturation/wrap policy, not arbitrary32-bit counters everywhere.

11.5 Required visibility without measurement self-deception
------------------------------------------------------------
Maintain source-level faults/counters and small trace records. Large captures
belong in host memory. Make counters useful for liveness: each mandatory
functional stage sees positive work in a fixture and a deliberate bypass/mute
changes the expected result. Optional laboratory probes are a separately costed
build configuration, not silently part of production or silently excluded from
mandatory evidence.

audio paths. The provisional5CSEBA6U23I7 fitting target does not establish the
board's actual populated resources or timing. No pin map is invented here.

Keep the wrapper thin: exactly one clock/reset network, one physical memory
endpoint per actual device, one video and audio output path, and the required
host/input bridges. Do not retain an entire test framework plus an independent
Zhaozhou video subsystem when the production configuration needs only one.
But do not subtract indispensable scaler/framework logic on paper before an
actual selectable thin build exists.

12.2 Clock and reset implementation
-----------------------------------
Use vendor PLL primitives behind wrappers, with model equivalents in simulation.
Generate documented GPU/video/audio clocks from the real oscillator. Assert
reset on external reset/unlocked PLL as appropriate; synchronize deassertion in
each domain. Preserve frame/transaction reset barriers; a synchronized reset
release is not a memory-drain certificate.

Constrain all clocks/generated clocks and real I/O interfaces; inspect setup,
hold, recovery/removal and unconstrained paths per domain. Cross-domain false
paths are permitted only at actual CDC structures, not to erase a real slow
synchronous path. Test reset while FIFO data/commands/frame terminals are active.
Do not claim a physical-pin fit of a344-port internal leaf is a realistic board
configuration; internal signals belong inside a constrained wrapper.

Do not require a new200/400-MHz arithmetic island for initial completion. The
existing100-MHz target and independent video/audio domains are the default.
Double-pumping is an explicitly priced later experiment, not a way to hide
unclosed timing in the baseline.

12.3 SDRAM/HPS integration
--------------------------
Connect the existing controller to actual pins and correct board timing. Test
addresses across all selected banks, byte lanes, bursts, refresh, arbitration,
read/write turnaround, reset and saturation. Keep physical controller evidence
separate from abstract-memory simulation. Model the HPS bridge's real word/byte
address conversion and supported aperture; a64-bit descriptor field does not
make a32-bit bus physically reach every address.

Maintain a host-visible submission/completion ring with stable descriptors,
release/acquire publication and the chosen cache-coherence/DMA ownership rules.
The exact mechanism depends on the platform runtime; implement it once in a
transport adapter and test stale-cache behavior rather than assuming volatile
makes DMA coherent.

12.4 Runtime required to use the machine
-----------------------------------------
Deliver a boot/load/submit/poll/present loop, resource upload/residency API,
frame/input sequencing, audio feed, terrain streaming/writeback, timeout/fault
recovery and capture/replay. Use the existing generated command and asset ABI.
Do not write a second packed packet format in a new host helper.

Frame submission preserves immutable data until completion. A failed frame
retains the previous complete image and records its fault; a failed upload
retains the old resource generation. Timeouts report which owner/credit stalled,
not simply "GPU hung." Debug transport must not be the only path able to draw.

CPU work already assigned by the charter (game truth, exact preparation, audio
mixing, streaming policy) is legitimate. Moving an additional mandatory FPGA
service to CPU requires a named backend choice, equivalent behavior, CPU budget
and bandwidth validation; it is not a zero-ALM placeholder for missing hardware.

12.5 Input/audio and deterministic timing
------------------------------------------
Connect input snapshot and rumble to the actual selected controller transport.
If SNAC is selected, include its real interface, supported number/type of ports,
synchronization and electrical assumptions. If the framework already supplies
the supported pads, do not duplicate an input engine solely to satisfy a
filename heuristic. Capture the exact input snapshot used for each simulation
tick; late host polling must not relabel old input as a different tick.

Audio uses the charter's HPS fixed-point48-kHz mixer, PCM ring, FPGA FIFO and
actual output bridge. Include timing/rate conversion, underflow/overflow policy
and stereo channel/order checks. Do not add an FPGA synthesis engine to replace
the CPU mixer already allocated by the architecture. Audio clock requirements
are checked independently of the GPU clock.

12.6 Acceptance image and physical demonstration
-------------------------------------------------
The final bring-up program must exercise the actual selected machine: upload a
mesh/material/clip; draw animated lit geometry and terrain; run a FIELD program;
spawn and collide particles; produce a bounded spell/shadow; run post/HUD; use
two inputs/two views; play audio; persist a terrain modification and reload it.
A colored test pattern or software-blitted reel is valuable early bring-up, but
must carry that label and cannot close console functionality.

14.4 Area preservation priorities for NEW work
----------------------------------------------
1. Eliminate duplicated ownership/engines by construction.
2. Store payload, tables, contexts and cold statistics in correctly shaped RAM.
3. Move invariant computation to upload/configuration/exact preparation.
4. Sequence mutually exclusive arithmetic using a proved service calendar.
5. Keep internal widths exact but no wider than proven necessary.
6. Use compact handles/late reads rather than repeated wide records.
7. Pipeline clear long cones where needed; do not over-pipeline blind slack.
8. Keep existing hardware that already meets its contract rather than rewrite
   everything to a new generic framework.

These rules preserve ALMs without demanding an impossible tiny quota for every
missing organ. Size each complete domain from measurements; if a quota is missed,
report its actual debit. Do not distribute the negative residual of an overfull
37.5k portfolio as if missing organs have positive remaining budget.

14.5 Old research goes into the optimization queue, not the completion gate
--------------------------------------------------------------------------
Keep DIV32, shared attribute dividers, edge-boundary raster search, RAM validity,
exact reciprocal refinement, native ternary arithmetic and measured divider
fusion as ranked candidates. Their integer-model proofs are useful; they are
not complete hardware savings. Freeze behavioral boundaries so those candidates
can be substituted after the full structure exists.

Do not count a candidate's savings twice if it relies on slack consumed by
another change, or if it removes logic already removed by a shared parent.
Your200-ALM-per-added-M10K rule is a useful ranking heuristic only on NET parent
measurements; a timing/DSP fix below that rate can still be necessary. Physical
M10K reserve must be measured, not inferred from18.2% logical bit occupancy.

14.6 When timing work belongs before completion
-----------------------------------------------
Fix hard combinational monsters and unsafe clock/reset structures while their
interfaces are being integrated. Do not spend an unbounded sequence of fits
on small Fmax increments in a parent that will be replaced next.
A functionally verified but timing-failing integration checkpoint is allowed;
record its intended clock and failure. You cannot claim it runs correctly on
hardware at 100 MHz until the relevant paths close. Faster divider throughput is
not automatically faster Fmax; distinguish those two benefits.

14.7 No escape hatch is silently selected
----------------------------------------
The 30-fps render alternative, greater CPU offload and visible feature cuts
remain separate owner decisions. They are not needed to call a failing full
measurement honest. Keep their architectural seams reversible, but do not use
them to hide an absent function in the first complete selected design.

15.2 Exact limitations
-----------------------
The Python tests were executed locally. They validate this package's algorithms,
not the connected repository, its complete reference, Verilator behavior or the
FPGA. The material/lighting/particle-force/FIELD arithmetic has NOT been invented
in Python as a substitute for missing authoritative references.

The particle admission model uses an explicit strict-prefix, whole-group policy
and external stable IDs. Confirm that policy against reconciled current rulings;
do not silently impose it as a new frozen particle law.

The upload model tracks individual retired words in a Python set so duplicate
credits are testable. This is a software checking model, NOT an instruction to
build a bitmap/set of every uploaded word in FPGA fabric. The hardware uses the
actual ordered/tagged memory-transaction contract and bounded counters/credits.

The upload guard checks request-acceptance epoch. The parent must separately
revalidate ownership/epoch on publication and drain old accepted writes on abort.
The guard is not a substitute for source/destination configuration validation.

No HDL simulator or Quartus was available for successful execution in this
session. The RTL candidates and supplied testbench are therefore labelled
UNVERIFIED RTL. An attempted environment setup did not yield a simulator; no
HDL pass, physical resource count or timing number is asserted. Run the bench
and repository-equivalent gates before even considering adoption.

The completion seed is manually reconciled from cited sources, not generated
from an elaborator. The Python ledger checker cannot prove functional
reachability; the real integrated tests and post-synthesis hierarchy must supply
that evidence. It correctly refuses release with unresolved scope/candidates.

"""Offline completion support, not a replacement for the repository's oracles.

Python 3.10+, standard library only. Implements:
* the ruled particle128 packing (qformats.md section 10);
* survivor-first, whole-child-group admission as a proposed transaction model;
* upload descriptor validation and a drain-before-publication transaction model;
* physical-shape M10K planning and necessary provider-calendar checks;
* a fail-closed completion ledger checker.
No function claims FPGA area, timing, complete ISA semantics or board validation.
"""
from __future__ import annotations
from dataclasses import dataclass, field
from enum import IntEnum
from pathlib import Path
from typing import Iterable, Mapping, Sequence
import argparse
import hashlib
import json
import math
import sys

LAYOUT = (
    ('x', 0, 18, True), ('y', 18, 18, True), ('z', 36, 18, True),
    ('vx', 54, 11, True), ('vy', 65, 11, True), ('vz', 76, 11, True),
    ('age', 87, 10, False), ('species', 97, 7, False),
    ('size', 104, 6, False), ('spin', 110, 6, False),
    ('flags', 116, 4, False), ('variation', 120, 8, False),
)


def checked_uint(value: int, bits: int, name: str) -> int:
    if type(value) is not int or not 0 <= value < (1 << bits):
        raise ValueError(f'{name} must be an unsigned {bits}-bit integer')
    return value


def pack_particle(values: Mapping[str, int]) -> bytes:
    """Pack exactly 16 little-endian bytes. Does not invent update arithmetic."""
    if set(values) != {x[0] for x in LAYOUT}:
        raise ValueError('particle fields must exactly match the ruled layout')
    word = 0
    for name, shift, width, signed in LAYOUT:
        value = values[name]
        low, high = (-(1 << (width-1)), (1 << (width-1))-1) if signed else (0, (1 << width)-1)
        if type(value) is not int or not low <= value <= high:
            raise ValueError(f'{name} outside [{low}, {high}]')
        if name == 'flags' and value & 8:
            raise ValueError('reserved particle flag bit 3 must be zero')
        word |= (value & ((1 << width)-1)) << shift
    return word.to_bytes(16, 'little')


def unpack_particle(data: bytes) -> dict[str, int]:
    if len(data) != 16:
        raise ValueError('particle record must contain exactly 16 bytes')
    word = int.from_bytes(data, 'little')
    result = {}
    for name, shift, width, signed in LAYOUT:
        raw = (word >> shift) & ((1 << width)-1)
        result[name] = raw - (1 << width) if signed and raw & (1 << (width-1)) else raw
    if result['flags'] & 8:
        raise ValueError('reserved particle flag bit 3 is nonzero')
    return result


@dataclass(frozen=True)
class ParticleRecord:
    stable_id: int  # Adapter input, NOT a new field silently inserted into particle128.
    payload: bytes
    def __post_init__(self):
        checked_uint(self.stable_id, 64, 'stable_id')
        unpack_particle(self.payload)


@dataclass(frozen=True)
class SpawnGroup:
    parent_order: int
    event_order: int
    children: tuple[ParticleRecord, ...]
    def __post_init__(self):
        if self.parent_order < 0 or not 0 <= self.event_order < 4:
            raise ValueError('invalid parent/event order')


@dataclass(frozen=True)
class TickResult:
    records: tuple[ParticleRecord, ...]
    children_requested: int
    children_emitted: int
    children_refused: int
    malformed_groups: int


def finish_particle_tick(survivors: Sequence[ParticleRecord], groups: Sequence[SpawnGroup],
                         capacity: int) -> TickResult:
    """Proposed whole-group, prefix-priority admission policy.

    Update/collision are external exact oracles. Groups must already be in
    parent/event order. After a legal group cannot fit, later legal groups are
    refused even if smaller: this preserves the strict-prefix policy documented
    in the handoff. Confirm that policy against current owner rulings before
    production adoption. A >16-child group is malformed, refused atomically.
    """
    if type(capacity) is not int or capacity < 0 or len(survivors) > capacity:
        raise ValueError('cannot evict survivors to meet capacity')
    keys = [(g.parent_order, g.event_order) for g in groups]
    if keys != sorted(keys) or len(set(keys)) != len(keys):
        raise ValueError('groups must have unique, ordered parent/event keys')
    output = list(survivors)
    requested = emitted = refused = malformed = 0
    exhausted = False
    for g in groups:
        count = len(g.children)
        requested += count
        if count > 16:
            malformed += 1
            refused += count
            continue
        if count == 0:
            continue
        if exhausted or len(output) + count > capacity:
            exhausted = True
            refused += count
        else:
            output.extend(g.children)
            emitted += count
    ids = [p.stable_id for p in output]
    if len(set(ids)) != len(ids):
        raise ValueError('duplicate stable particle identity')
    return TickResult(tuple(output), requested, emitted, refused, malformed)


class UploadVerdict(IntEnum):
    OK = 0
    UNALIGNED = 1
    ZERO_LENGTH = 2
    OUTSIDE_GUARD = 3
    EPOCH_STALE = 4
    CRC_FAIL = 5
    SOURCE_OUTSIDE_ARENA = 6
    SOURCE_UNREACHABLE = 7


def upload_verdict(hps_addr: int, vram_addr: int, length: int,
                   source_base: int, source_bytes: int, dest_base: int, dest_bytes: int,
                   request_epoch: int, current_epoch: int) -> UploadVerdict:
    """Mirror zref_mem_upload.hpp predicate order, with unbounded host addition."""
    checked_uint(hps_addr, 64, 'hps_addr')
    for name, value in [('vram_addr', vram_addr), ('length', length),
                        ('source_base', source_base), ('source_bytes', source_bytes),
                        ('dest_base', dest_base), ('dest_bytes', dest_bytes)]:
        checked_uint(value, 32, name)
    checked_uint(request_epoch, 16, 'request_epoch')
    checked_uint(current_epoch, 16, 'current_epoch')
    if length == 0:
        return UploadVerdict.ZERO_LENGTH
    if (hps_addr | vram_addr | length) & 63:
        return UploadVerdict.UNALIGNED
    if hps_addr >> 32:
        return UploadVerdict.SOURCE_UNREACHABLE
    if not source_base <= hps_addr or hps_addr + length > source_base + source_bytes:
        return UploadVerdict.SOURCE_OUTSIDE_ARENA
    if not dest_base <= vram_addr or vram_addr + length > dest_base + dest_bytes:
        return UploadVerdict.OUTSIDE_GUARD
    if request_epoch != current_epoch:
        return UploadVerdict.EPOCH_STALE
    return UploadVerdict.OK


@dataclass
class UploadTransaction:
    """Transaction-level model; retirement is external memory acknowledgement.

    Abort quarantines the destination until all previously issued writes drain.
    reset() is deliberately absent: global reset requires a transport-drain
    contract, not forgetting outstanding writes. Late foreign responses do not
    credit this transaction. Models one transaction, not a full DMA engine.
    """
    token: int
    expected_words: int
    epoch: int
    generation: int
    destination_slot: int
    issued: int = 0
    retired: int = 0
    issue_closed: bool = False
    crc_ok: bool | None = None
    failed: bool = False
    published: bool = False
    _seen: set[int] = field(default_factory=set, repr=False)

    def __post_init__(self):
        if type(self.expected_words) is not int or self.expected_words <= 0:
            raise ValueError('positive integral word count required')
        for name, value in [('epoch', self.epoch), ('generation', self.generation)]:
            checked_uint(value, 16, name)

    def issue(self, count: int = 1) -> None:
        if type(count) is not int or count < 0 or self.issue_closed or self.failed or self.published:
            raise ValueError('issue after transaction closure or invalid count')
        if self.issued + count > self.expected_words:
            raise ValueError('issued too many words')
        self.issued += count

    def retire(self, token: int, first_word: int, count: int = 1) -> bool:
        if token != self.token:
            return False
        if (type(count) is not int or type(first_word) is not int or count < 1
                or first_word < 0 or first_word + count > self.issued):
            raise ValueError('retirement not backed by issued writes')
        indices = set(range(first_word, first_word+count))
        if self._seen & indices:
            raise ValueError('duplicate write credit')
        self._seen |= indices
        self.retired += count
        return True

    def close_issue(self) -> None:
        if self.issued != self.expected_words and not self.failed:
            raise ValueError('successful issuer cannot stop early')
        self.issue_closed = True

    def complete_crc(self, ok: bool) -> None:
        if type(ok) is not bool:
            raise ValueError('CRC verdict must be boolean')
        if self.crc_ok is not None:
            raise ValueError('CRC already supplied')
        self.crc_ok = bool(ok)
        if not ok:
            self.failed = True

    def abort(self) -> None:
        if self.published:
            raise ValueError('cannot abort already published generation')
        self.failed = True
        self.issue_closed = True  # Caller has cancelled unsent issues first.

    @property
    def drained(self) -> bool:
        return self.issue_closed and self.retired == self.issued

    @property
    def reclaimable(self) -> bool:
        return self.failed and self.drained and not self.published

    def publish(self, current_epoch: int, new_slot_unpublished: bool,
                old_mapping: tuple[int, int]) -> tuple[int, int]:
        checked_uint(current_epoch, 16, 'current_epoch')
        if type(new_slot_unpublished) is not bool:
            raise ValueError('slot visibility must be boolean')
        if self.published:
            raise ValueError('duplicate publication')
        if current_epoch != self.epoch:
            self.failed = True
        if not (self.drained and self.issued == self.expected_words and self.crc_ok is True
                and not self.failed and new_slot_unpublished
                and self.destination_slot != old_mapping[0]):
            raise ValueError('publication preconditions not met')
        self.published = True
        return (self.destination_slot, self.generation)


# Single/simple-dual-port shapes; true-dual-port has no 256x40 mode.
SDP_SHAPES = ((256,40),(512,20),(1024,10),(2048,5),(4096,2),(8192,1))
TDP_SHAPES = ((512,20),(1024,10),(2048,5),(4096,2),(8192,1))


def memory_plan(depth: int, width: int, mode: str = 'sdp', copies: int = 1) -> dict:
    """Shape estimate, never a fitted count. Port-copy factor must be supplied."""
    if any(type(v) is not int or v <= 0 for v in (depth, width, copies)):
        raise ValueError('depth, width and copies must be positive integers')
    if mode not in ('sdp', 'tdp'):
        raise ValueError('mode must be sdp or tdp')
    shapes = SDP_SHAPES if mode == 'sdp' else TDP_SHAPES
    choices = []
    for d,w in shapes:
        banks = (depth+d-1)//d
        slices = (width+w-1)//w
        blocks = banks*slices*copies
        choices.append((blocks, banks, slices, d,w))
    blocks,banks,slices,d,w = min(choices)
    return dict(evidence='shape_estimate_not_fit', blocks=blocks, mode=mode,
                primitive_depth=d, primitive_width=w, depth_banks=banks,
                width_slices=slices, physical_copies=copies,
                logical_bits=depth*width*copies,
                physical_capacity_bits=blocks*10240)


def provider_bound(jobs: int, issue_slots: int, lanes: int, window_cycles: int,
                   overhead_cycles: int = 0) -> dict:
    """Necessary capacity test ONLY. Passing does not prove a legal schedule."""
    vals = (jobs,issue_slots,lanes,window_cycles,overhead_cycles)
    if any(type(v) is not int for v in vals) or min(jobs,issue_slots,overhead_cycles) < 0:
        raise ValueError('nonnegative integral demand required')
    if lanes <= 0 or window_cycles <= 0:
        raise ValueError('positive lanes and window required')
    cycles = (jobs*issue_slots+lanes-1)//lanes+overhead_cycles
    return dict(necessary_cycles=cycles, window_cycles=window_cycles,
                impossible_even_without_stalls=cycles > window_cycles,
                schedule_proven=False)


class LedgerError(ValueError):
    pass


def check_ledger(doc: dict, root: Path | None = None, release: bool = False) -> list[str]:
    """Check honest classification; optional declared evidence/file existence.

    This DOES NOT elaborate RTL or discover functional reachability. Reachability
    and liveness require external reports/tests. Facts cannot be self-certified
    by inventing a JSON row. Unknown mandatory scope and manual-review items
    fail release even when names happen to match existing files.
    """
    if doc.get('schema') != 1 or not isinstance(doc.get('capabilities'), list):
        raise LedgerError('schema=1 and capabilities[] required')
    if not isinstance(doc.get('owners'), dict):
        raise LedgerError('owners{} required')
    ids: set[str] = set()
    problems: list[str] = []
    required = {'id','policy','state','owner','implementation','evidence','notes'}
    policies = {'required','optional_selected','deferred','excluded','needs_reconciliation'}
    states = {'absent','candidate','unit_verified','integrated','mapped','fitted','hardware_proven','not_applicable','unknown'}
    for row in doc['capabilities']:
        if not isinstance(row,dict) or not required <= row.keys():
            raise LedgerError('incomplete capability row')
        name = row['id']
        if not isinstance(name,str) or not name or name in ids:
            raise LedgerError('duplicate/invalid capability id')
        ids.add(name)
        if row['policy'] not in policies or row['state'] not in states:
            raise LedgerError(f'{name}: unsupported policy/state')
        active = row['policy'] in ('required','optional_selected')
        if row['policy'] == 'needs_reconciliation':
            problems.append(f'{name}: requirement status unresolved')
        if active and row['owner'] not in doc['owners']:
            problems.append(f'{name}: no physical/software owner')
        if active and row['state'] in ('absent','unknown','candidate','unit_verified','not_applicable'):
            problems.append(f"{name}: not connected-and-proven ({row['state']})")
        if active and not row['implementation']:
            problems.append(f'{name}: no implementation path')
        if active and not row['evidence']:
            problems.append(f'{name}: no supporting evidence')
        if row['state'] in ('integrated','mapped','fitted','hardware_proven'):
            need = {'functional_path','negative_control','scope_digest'}
            if not need <= row['evidence'].keys():
                problems.append(f'{name}: missing integration/liveness evidence fields')
        if root is not None:
            base = root.resolve()
            for path in row['implementation']:
                target = (base/path).resolve()
                if not target.is_relative_to(base) or not target.is_file():
                    problems.append(f'{name}: missing/outside implementation file {path}')
    for name, owner in doc['owners'].items():
        if owner.get('kind') not in ('rtl','software','mixed','platform'):
            raise LedgerError(f'{name}: invalid owner kind')
        area = owner.get('fitted_alms')
        if area is not None:
            if not isinstance(area,(float,int)) or area < 0:
                raise LedgerError('invalid fitted ALM count')
            if owner.get('area_evidence') != 'matched_fit':
                raise LedgerError(f'{name}: fitted ALMs require matched_fit evidence')
        if owner.get('candidate_savings_alms') is not None:
            raise LedgerError('do not subtract speculative savings in the completion ledger')
    # A complete capability list alone is not a release certificate.
    # These references need external review; this checker cannot verify their truth.
    release_evidence = doc.get('release_evidence', {})
    for requirement in ('function_complete', 'selected_scope_complete', 'target_fit',
                        'timing', 'workload', 'board'):
        claim = release_evidence.get(requirement, {})
        if not (isinstance(claim, dict) and claim.get('status') == 'pass'
                and claim.get('path') and claim.get('scope_digest')):
            problems.append(f'release: {requirement} not evidenced')
        elif root is not None:
            target = (root.resolve() / claim['path']).resolve()
            if not target.is_relative_to(root.resolve()) or not target.is_file():
                problems.append(f'release: {requirement} evidence file missing/outside root')
    if release and problems:
        raise LedgerError('\n'.join(problems))
    return problems


def snapshot_files(root: Path, paths: Iterable[str]) -> dict:
    """Hash explicitly supplied files; no claim that this is the RTL closure."""
    base = root.resolve()
    rows = []
    for name in sorted(set(paths)):
        p = (base/name).resolve()
        if not p.is_relative_to(base) or not p.is_file():
            raise ValueError(f'missing/outside path {name}')
        data = p.read_bytes()
        rows.append(dict(path=name, bytes=len(data), sha256=hashlib.sha256(data).hexdigest()))
    wire = json.dumps(rows,sort_keys=True,separators=(',',':')).encode()
    return dict(files=rows, manifest_sha256=hashlib.sha256(wire).hexdigest(),
                scope='explicit_file_list_not_elaboration_proof')

// Candidate completion primitive, NOT installed in Fabulu/zhaozhou.
// One synchronous memory read port, one whole-word write port, no RAM reset.
// Capacity is RAM_WORDS + ONE output register, explicitly; not a drop-in
// replacement for a FIFO whose externally promised capacity is RAM_WORDS.
// A full memory refuses push even when a same-edge fetch frees a word. This
// avoids same-address read/write and a combinational output-ready -> input-ready
// path. Payload is uninterpreted; the caller includes tags/generations in WIDTH.
// Reset discards queued work. Use only where the owning transaction allows that.
// HDL simulation / Quartus inference / area / timing: NOT performed here.
`default_nettype none
module zhao_cpl_ram_fifo #(
    parameter integer WIDTH = 128,
    parameter integer RAM_WORDS = 16,
    parameter integer ADDR_W = 4
) (
    input wire clk,
    input wire rst_n,
    input wire in_valid_i,
    output wire in_ready_o,
    input wire [WIDTH-1:0] in_data_i,
    output wire out_valid_o,
    input wire out_ready_i,
    output wire [WIDTH-1:0] out_data_o,
    output wire [ADDR_W:0] memory_words_o
);
    (* ramstyle = "M10K" *) reg [WIDTH-1:0] memory [0:RAM_WORDS-1];
    reg [ADDR_W-1:0] wr_ptr, rd_ptr;
    reg [ADDR_W:0] memory_words;
    reg out_valid;
    reg [WIDTH-1:0] out_data;
    wire push, fetch, output_free;
    localparam [ADDR_W:0] LIMIT = RAM_WORDS;
    localparam [ADDR_W-1:0] LAST = RAM_WORDS-1;

    initial begin
        if (WIDTH < 1 || RAM_WORDS < 1 || ADDR_W < 1 ||
            RAM_WORDS > (2 ** ADDR_W))
            $fatal(1, "invalid FIFO geometry");
    end
    assign in_ready_o = rst_n && memory_words < LIMIT;
    assign push = in_valid_i && in_ready_o;
    assign output_free = !out_valid || out_ready_i;
    assign fetch = rst_n && output_free && memory_words != 0;
    assign out_valid_o = rst_n && out_valid;
    assign out_data_o = out_data;
    assign memory_words_o = memory_words;

    // Deliberately separate from reset logic. fetch/push are suppressed in reset.
    always @(posedge clk) begin
        if (push) memory[wr_ptr] <= in_data_i;
        if (fetch) out_data <= memory[rd_ptr];
    end

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            wr_ptr <= 0;
            rd_ptr <= 0;
            memory_words <= 0;
            out_valid <= 1'b0;
        end else begin
            if (push) wr_ptr <= (wr_ptr == LAST) ? 0 : wr_ptr + 1'b1;
            if (fetch) rd_ptr <= (rd_ptr == LAST) ? 0 : rd_ptr + 1'b1;
            case ({push,fetch})
                2'b10: memory_words <= memory_words + 1'b1;
                2'b01: memory_words <= memory_words - 1'b1;
                default: memory_words <= memory_words;
            endcase
            if (output_free) out_valid <= fetch;
        end
    end
`ifndef SYNTHESIS
    always @(posedge clk) begin
        if (rst_n && push && fetch && wr_ptr == rd_ptr)
            $fatal(1, "FIFO must not rely on same-address RAM collision semantics");
        if (rst_n && memory_words > LIMIT)
            $fatal(1, "FIFO occupancy overflow");
    end
`endif
endmodule
`default_nettype wire

// Candidate request validator for the missing MEM.UPLOAD path.
// NOT the uploader. No transfer, CRC, residency publication, pinning, quarantine,
// cache invalidation or late-write cancellation is implemented by this leaf.
// Mirrors zref_mem_upload.hpp verdict precedence. Input regions must themselves
// be validated by the owning epoch configuration; wider endpoints never wrap.
// One request at a time, variable latency, held result under backpressure.
// Inline/share these request latches with the real uploader where appropriate;
// do not blindly keep two permanent copies of the complete upload descriptor.
// HDL simulation / Quartus synthesis / area / timing: NOT performed here.
`default_nettype none
module zhao_cpl_upload_guard (
    input wire clk,
    input wire rst_n,
    input wire req_valid_i,
    output wire req_ready_o,
    input wire [63:0] hps_addr_i,
    input wire [31:0] vram_addr_i,
    input wire [31:0] length_i,
    input wire [31:0] source_base_i,
    input wire [31:0] source_bytes_i,
    input wire [31:0] dest_base_i,
    input wire [31:0] dest_bytes_i,
    input wire [15:0] request_epoch_i,
    input wire [15:0] current_epoch_i,
    output wire rsp_valid_o,
    input wire rsp_ready_i,
    output wire [3:0] verdict_o
);
    localparam [3:0] IDLE=0, BASIC=1, SRC_LO=2, SRC_HI=3,
                     DST_LO=4, DST_HI=5, EPOCH=6, ANSWER=7;
    localparam [3:0] OK=0, UNALIGNED=1, ZERO_LENGTH=2,
                     OUTSIDE_GUARD=3, EPOCH_STALE=4,
                     SOURCE_OUTSIDE_ARENA=6, SOURCE_UNREACHABLE=7;
    reg [3:0] state, verdict;
    reg [63:0] hps_addr;
    reg [31:0] vram_addr, length_q, source_base, dest_base;
    reg [32:0] source_end, dest_end, requested_source_end, requested_dest_end;
    reg [15:0] request_epoch, epoch_at_accept;

    assign req_ready_o = rst_n && state == IDLE;
    assign rsp_valid_o = rst_n && state == ANSWER;
    assign verdict_o = verdict;

    // Payload has no reset value: it is read only after an accepted request.
    // Resetting only ownership/control is intentional, not a source of validity.
    always @(posedge clk) begin
        if (req_valid_i && req_ready_o) begin
            hps_addr <= hps_addr_i;
            vram_addr <= vram_addr_i;
            length_q <= length_i;
            source_base <= source_base_i;
            dest_base <= dest_base_i;
            source_end <= {1'b0,source_base_i} + {1'b0,source_bytes_i};
            dest_end <= {1'b0,dest_base_i} + {1'b0,dest_bytes_i};
            requested_source_end <= {1'b0,hps_addr_i[31:0]} + {1'b0,length_i};
            requested_dest_end <= {1'b0,vram_addr_i} + {1'b0,length_i};
            request_epoch <= request_epoch_i;
            epoch_at_accept <= current_epoch_i;
        end
    end
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            state <= IDLE;
            verdict <= OK;
        end else begin
            case (state)
                IDLE: if (req_valid_i && req_ready_o) state <= BASIC;
                BASIC: begin
                    if (length_q == 0) begin verdict <= ZERO_LENGTH; state <= ANSWER; end
                    else if (|{hps_addr[5:0],vram_addr[5:0],length_q[5:0]})
                        begin verdict <= UNALIGNED; state <= ANSWER; end
                    else if (|hps_addr[63:32])
                        begin verdict <= SOURCE_UNREACHABLE; state <= ANSWER; end
                    else state <= SRC_LO;
                end
                SRC_LO: begin
                    if (hps_addr[31:0] < source_base)
                        begin verdict <= SOURCE_OUTSIDE_ARENA; state <= ANSWER; end
                    else state <= SRC_HI;
                end
                SRC_HI: begin
                    if (requested_source_end > source_end)
                        begin verdict <= SOURCE_OUTSIDE_ARENA; state <= ANSWER; end
                    else state <= DST_LO;
                end
                DST_LO: begin
                    if (vram_addr < dest_base)
                        begin verdict <= OUTSIDE_GUARD; state <= ANSWER; end
                    else state <= DST_HI;
                end
                DST_HI: begin
                    if (requested_dest_end > dest_end)
                        begin verdict <= OUTSIDE_GUARD; state <= ANSWER; end
                    else state <= EPOCH;
                end
                EPOCH: begin
                    verdict <= (request_epoch == epoch_at_accept) ? OK : EPOCH_STALE;
                    state <= ANSWER;
                end
                ANSWER: if (rsp_ready_i) state <= IDLE;
                default: begin state <= IDLE; verdict <= OK; end
            endcase
        end
    end
endmodule
`default_nettype wire

def vectors():
    rng=random.Random(20260918)
    cases=[]
    for i in range(4096):
        source_base=(rng.randrange(1024)+1)*4096
        dest_base=(rng.randrange(1024)+1)*4096
        source_bytes=dest_bytes=4096
        length=64*rng.randrange(1,65)
        hps=source_base;dst=dest_base
        re=ce=rng.randrange(65536)
        mode=i%12
        if mode==1:length=0;hps+=1
        elif mode==2:hps+=1
        elif mode==3:dst+=1
        elif mode==4:length+=1
        elif mode==5:hps+=(1<<32)
        elif mode==6:hps=source_base-64
        elif mode==7:hps=source_base+4096
        elif mode==8:dst=dest_base-64
        elif mode==9:dst=dest_base+4096
        elif mode==10:ce=(ce+1)&65535
        vals=(hps,dst,length,source_base,source_bytes,dest_base,dest_bytes,re,ce)
        cases.append((vals,int(upload_verdict(*vals))))
    for length in (64,128):
        vals=(0xffffffc0,8192,length,0xffffff80,128,8192,1024,3,3)
        cases.append((vals,int(upload_verdict(*vals))))
    return cases
