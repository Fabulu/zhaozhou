EYE_CHECK firing on 41 frames rather than ~240 is a CONSISTENCY CHECK, not a
weak control. It acts only inside the three check windows (kHastyChecks spans
9+9+7 = 25 keys), and the symmetric triangle is EXACTLY ZERO on the first and
last key of each window -- so the number the authored curve predicts is smaller
than the window count, and 41 is it.

A control whose footprint matches its authored extent is better evidence than
one that simply changes everything: "240/240 differ" would be equally true of a
knob wired to the wrong thing.
