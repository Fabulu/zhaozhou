the frame demand derived from Sacrifice's SCAR system (20,000 stamp texels per

No behavioural change: the five stamp modes, material conversion, age/decay and
capture-exact ordering are out of scope by instruction and stay bit-identical.

### 2026-08-23 14:5x — Where the 28 DSPs are. Answer: all six are in the COVERAGE GEOMETRY

The coordinator asked whether the multipliers might be in the material
conversion or the age/decay path. **They are not, and this is worth stating
plainly because it changes nothing about the plan but rules out a whole branch
of it.** Read straight out of the RTL:

| # | expression | operands | rate |
| ---: | --- | --- | --- |
| 1 | `r_outer2_c = rad_ext * rad_ext` | signed 64×64 | once per stamp |
| 2 | `r_inner2_c = rin_ext * rin_ext` | signed 64×64 | once per stamp |
| 3 | `numx = 41'(st_spanx) * 41'(two_i_1)` | signed 41×41 | **every clock** |
| 4 | `numz = 41'(st_spanz) * 41'(two_j_1)` | signed 41×41 | **every clock** |
| 5,6 | `d2 = dxw * dxw + dzw * dzw` | two signed 64×64 | **every clock** |

`zhao_surface_blend` — which is where the five stamp modes, the ABI mapping and
the age/decay shift all live — contains **no multiply at all** and fits on its
own at **64 ALMs / 0 DSPs** (already in the report). The material conversion is
`strength >> 8`, a wire. The age rate is a shift, *deliberately*, and the
contract records the rejected `unit_mul` form precisely because it would have
cost a multiplier. **So the block's own contract already refused to spend a DSP
on behaviour; every DSP it has is geometry.**

Two of the six are **per-stamp constants that still got silicon**, because they
are written as combinational expressions off the command port. That is not
over-provisioning by 83×, it is provisioning something that needed no rate at
all.

### 2026-08-23 15:0x — Design fixed (details in SPEC_v1.md §The architecture)

Three moves, in decreasing order of how much argument they need:

1. **`numx`/`numz` become accumulators.** `numx = spanx*(2i+1)` advances by
   `2*spanx` per `i`. **This is bit-identical for every input, in the domain
   and outside it** — the shipped form truncates the product to 41 bits and the
   accumulator produces the same residue mod 2⁴¹. Two multiplies gone with no
   domain argument owed.
2. **One shared sequential shift-add squarer** serves all four remaining
   squarings (`r²`, `r_inner²`, `dx²`, `dz²`). A square is `|v|²`, so one
   unsigned engine covers all four. Accumulating mod 2⁶⁴ reproduces exactly the
   truncation the shipped `dxw*dxw` already performs, so this too is
   bit-identical for every input including `v = −2³⁵`.
3. **The cursor loop goes multi-cycle.** Nothing else in the block moves: the
   two-stage sheet pipeline, S4's acquire-before-write structure, the
   ready/valid discipline, the scan order, the counters and `stamp_results` are
   untouched.

**Decision recorded: the datapath is NOT narrowed to the ±4,096 m domain.** The
contract flags that as "a real optimisation and a real risk". The DSPs come out
without it, so paying the risk would buy nothing but ALMs.

**Rejected: the 64-entry `dx²` table.** It would restore one texel per clock at
0 DSPs, but it costs ~4,000 flops and a 62-bit 64:1 mux (est. 2,000+ ALMs) to
buy 37× the throughput of a block that already meets demand 2.2× over — the same
over-provisioning sin in a different resource — and it would give up the
contract's "Memory ownership: **None**".

## Decisions Made

| # | Decision | Reason |
| ---: | --- | --- |
| 1 | Target 0 DSPs, not 2 | No `*` survives; a DSP can then only appear by accident, and its appearance is a *diagnostic*. |
| 2 | Accumulator, not narrowed multiply, for the texel centres | Bit-identical mod 2⁴¹ with no domain argument owed. |
| 3 | One shared squarer, block-local | Standing ruling: share within a subsystem only, smallest local farm. |
| 4 | No domain narrowing | Contract calls it a real risk; it buys no DSPs here. |
| 5 | `SQ_RADIX ∈ {1,2,4}` as the frontier axis | All three meet the texel demand, so the frontier's wall is on the **Fmax** axis — which is the axis that matters, since `gpu_clk` is shared. |
| 6 | Re-fit the pristine baseline | The shipped row has **no Fmax at all**; without re-fitting there is no honest "before". |
