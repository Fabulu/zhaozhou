# TASK Q009: tracearm-ordering
## Brief
`DebugTraceArm` (opcode 0xF003) is a new command that arms the console's trace
ring. `zhao_cmd_exec` walks a sealed command packet byte by byte and lowers each
record's effect; `zhao_cmd_decoder` walks the SAME byte stream in parallel (the
two are forked off one stream) and offers each record to `zhao_debug_trace` as
it goes. `zhao_debug_trace` stores an event only if the stage's bit is set in
`arm_mask_i`.

The author makes a GUARANTEE, in those words, and it is what you are checking:

> CMD.EXEC applies the mask at this record's LAST BYTE, during the walk.
> CMD.DECODER offers a record to the ring at the record's byte 15 (the end of
> its header), so:
>     the DebugTraceArm record itself is NOT traced;
>     every record after it in the same packet IS.
> That is a guarantee, not an approximation -- the next record's header cannot
> complete for at least sixteen more byte-cycles.

A second, separate claim: the arm is applied WITHOUT waiting for the packet's
verdict, unlike every other command this block executes, and a record with a
reserved bit set in `stage_mask` or `flags` is REFUSED WHOLE and counted in
`trace_arm_refused_o` rather than having the bad bits masked off.

A directed run measured `armed=0000001 stored=9 dropped=0 against decoder
records=11, arms=1, arm_refused=0` on an 11-record packet, and the author says
`stored = records - 2` because BeginFrame AND the DebugTraceArm record are both
offered to the ring before the arm lands. (The packet has since grown to 13
records and stored=11.)

You are shown the relevant slices of CMD.EXEC, the whole decoder, the whole
trace ring, and the C++ reference model the RTL is supposed to match.

    7| // THE ONE LAW THAT MATTERS MORE THAN THE OTHERS

    9| // **THIS BLOCK DROPS. IT NEVER STALLS.**
   10| //
   11| // A trace ring exists to observe a machine without changing it. A ring that
   12| // back-pressured its producer would make the act of tracing alter the timing
   13| // being traced — the pipeline would run differently while being watched, and
   14| // the capture would describe a machine that does not exist when the trace is
   15| // off. So a full ring counts what it lost and the pipeline runs on untouched.
   16| //
   17| // There is no ready signal on the event port. That absence is the law: there is
   18| // nothing for a producer to wait on, so no producer can be delayed by tracing.
   19| //
   20| // ---------------------------------------------------------------------------
   21| // WHAT IS RATIFIED AND WHAT WAS CHOSEN
   22| // ---------------------------------------------------------------------------
   23| // Ratified elsewhere and NOT this block's to invent:
   24| //   - the 32-byte record layout (capture_format.md chunk 0x000A)
   25| //   - source_id packing, { kind:4, module:12, index:16 } (capture_format.md §5)
   26| //   - the seven trace sources (charter §20.6)

   29| //   - stage numbers are the charter's list order, 0..6. A stage outside that
   30| //     range is NOT A LEGAL EVENT: it is not stored and it is not counted as a
   31| //     drop, because nothing was ever offered that this block understood.
   32| //   - arming is a seven-bit MASK, not a selector, so two stages can be traced
   33| //     in one run. Correlating two stages is the entire point of a trace ring.
   34| //   - an unarmed stage is not an event either. It is not stored and NOT counted
   35| //     as a drop; `dropped` means "a real event was lost to a full ring", which
   36| //     is the only reading that lets someone trust a capture.
   37| //
   38| // ---------------------------------------------------------------------------
   39| // THE RECORD, word by word
   40| // ---------------------------------------------------------------------------
   41| // Eight 32-bit words per event, little-endian, exactly the capture layout:
   42| //
   43| //     0 tile        1 primitive   2 pixel       3 { rsv[3]=0, stage }
   44| //     4 expected_fx 5 actual_fx   6 source_id   7 command_seq

   46| // Word 3 carries `stage` in its LOW byte with the three reserved bytes zero,

   48| // reserved bytes are zero rather than undefined so that two captures can be
   49| // compared byte for byte; undefined padding is how a trace format rots.
   50| //
   51| // A WHOLE RECORD IS WRITTEN IN ONE CYCLE, into a 256-bit entry. The obvious
   52| // alternative -- eight 32-bit writes over eight cycles -- gives the block a
   53| // BUSY window, and an event offered during that window would be lost without
   54| // even being counted as a drop. Silent loss is strictly worse than a counted

   56| // hold a producer off with, so the write must not take a window at all.
   57| //

   59| // selected after the register, with the selector delayed to match.
   60| //
