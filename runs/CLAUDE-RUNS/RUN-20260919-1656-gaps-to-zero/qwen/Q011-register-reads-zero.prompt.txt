# TASK Q011: register-reads-zero
## Brief
`completion_register.py` is the single number an entire engineering campaign is
being steered by. It parses a large SystemVerilog file's comment header — a
numbered list of "entries", each describing one function the console is
supposed to have and does not — plus a YAML capability ledger, and prints

    MANDATORY GAPS REMAINING : 27   (14 tie-offs + 11 disconnected + 2 unbuilt)

Work stops when that reaches ZERO, and a very expensive FPGA place-and-route
run is then started on the strength of it.

This codebase has a written law about exactly this situation:

> A broken instrument lies in ONE direction. The defect always made the answer
> look BETTER, SMALLER or SIMPLER than the truth. A parser that silently drops
> what it cannot match reports fewer problems. A self-check whose pattern
> matches nothing reports "no silent drops". **A number that is exactly zero is
> a broken instrument until proven otherwise** — precision at zero is a tell,
> not a result. Nobody audits good news.

YOUR JOB IS TO ATTACK THE TOOL, NOT THE DESIGN. Assume the design is full of
gaps and ask: what could this program fail to count? I am not asking whether
the 27 is right. I am asking what it would take for this program to print 0
while gaps remain.

It has a self-test that plants a gap and checks the parser classifies it. Treat
that self-test as a claim like any other.

## Questions
1. **Silent drops.** Find every place a regex, `if`, `continue`, `try/except`,
   `.get(...)` default or `startswith` can cause an entry, a capability or a
   line to be skipped WITHOUT being counted or reported. For each, say what
   input reaches it and whether the skip makes the total smaller.
2. **The zero path specifically.** Trace what has to be true for the printed
   total to be 0. Name every way the total can be 0 other than "there are no
   gaps" — an empty parse, a file that moved, a section header that changed
   spelling, an exception swallowed somewhere, a list that never got appended
   to.
3. **The self-test.** Does the planted gap exercise the SAME code path as a
   real entry, or a narrower one? Could the self-test pass while the real parse
   silently drops entries? Name what the self-test does NOT cover.
4. **Excuses.** Entries can be excused (deferred, superseded, waiting on a
   board). Can an entry be excused by a note that does not actually cite
   anything, or by a stale note whose claim is no longer true of the tree? Is
   the citation CHECKED or merely required to be non-empty?
5. **Asymmetry.** For each defect you find, state the DIRECTION of the error:
   does it make the count too high or too low? Rank your findings by "too low"

Be concrete: file and line, the input that triggers it, and the direction.

  404| def ledger_blocks() -> list[dict]:
  405|     """Every `kind: rtl` block, with the fields that decide whether it is ours.
  406| 
  407|     `implementation:` would be the obvious source and it is NOT usable: only 6
  408|     of 98 rtl blocks carry one. So the module is resolved by the repository's
  409|     naming convention and then CHECKED against the filesystem -- a convention
  410|     that resolves to nothing is reported as unresolvable rather than counted as
  411|     missing, because a name heuristic over-reports and an over-reported gap list
  412|     sends people to build things that already exist.
  413|     """
  414|     if not BLOCKS.exists():
  415|         return []
  416|     text = BLOCKS.read_text(encoding="utf-8", errors="replace")
  417|     out: list[dict] = []
  418|     cur: dict | None = None
  419|     for line in text.splitlines():
  420|         m = re.match(r"\s*-\s*id:\s*(\S+)", line)
  421|         if m:
  422|             if cur:
  423|                 out.append(cur)
  424|             cur = {"id": m.group(1), "kind": None, "deferred": None,
  425|                    "blocked_on": None, "implementation": None,
  426|                    "deferred_note": None, "blocked_note": None,
  427|                    "superseded_by": None}
  428|             continue
  429|         if cur is None:
  430|             continue
  431|         # `superseded_by:` takes the WHOLE rest of the line, because its value
  432|         # is a citation (a ruling, a file, a test), not a token. See
  433|         # superseded_verdict() for what it must carry to excuse anything.
  434|         # Every block carries the field, and 118 of them say `null`.
  435|         m = re.match(r"\s*superseded_by:\s*(.+?)\s*$", line)
  436|         if m:
  437|             v = m.group(1).strip().strip('"').strip("'")
  438|             cur["superseded_by"] = None if v in ("null", "~", "") else v
  439|             continue
  440|         for key in ("kind", "deferred", "blocked_on", "implementation"):
  441|             m = re.match(r"\s*%s:\s*(\S+)" % key, line)
  442|             if m:
  443|                 cur[key] = m.group(1)
  444|                 if key == "deferred":
  445|                     cur["deferred_note"] = line
  446|                 elif key == "blocked_on":
  447|                     cur["blocked_note"] = line
  448|     if cur:
  449|         out.append(cur)
  450|     return [b for b in out if b["kind"] == "rtl"]

  747| def superseded_in_closure() -> list[tuple[str, list[str]]]:

  749| 
  750|     OWNER RULING, 2026-09-19, verbatim and unambiguous:
  751| 
  752|         "YOU ONLY GET TO FIT THE LATEST VERSION. IF IT IS BROKEN YOU FIX IT."

  754|     It was issued because the console had composed the ENTIRE v1 FIELD datapath
  755|     -- alu, seq, ring, rot, noise, mul, len, normalize -- while all FOURTEEN
  756|     `zhao_field_v3_*` modules sat outside the closure. Fitting that measures a
  757|     machine nobody ships: it spends ALM and DSP budget on dead weight and makes
  758|     the eventual resource number describe the wrong design, on a device already

  765|     flattering direction and it belongs with the five already fixed here: a gap
  766|     closed by composing the wrong version is not a gap closed.
  767| 
  768|     TWO NAMING SHAPES, because this tree uses both:
  769| 
  770|         suffix  zhao_texture_cache_pipe_v2  supersedes  zhao_texture_cache_pipe
  771|         infix   zhao_field_v3_len           supersedes  zhao_field_len

  773|     `successor_in()` handles the suffix shape and only to REDUCE the count. This
  774|     is the opposite question and it is asked of the closure rather than of a
  775|     capability: what have we actually wired that something newer exists for?

  778|     v1 -> v3 swap is in flight as this lands, and a hard failure would block

  780|     the swap is committed -- a report nobody is forced to read is how the v1
  781|     datapath got composed in the first place.

  784|     # nothing elaborates costs the fitter nothing -- Quartus builds what is
  785|     # reachable from the top -- so flagging it would be a false alarm, and a
  786|     # check that cries wolf about dead sources is a check people learn to skip.

  813| def board_addition() -> set[str]:

  816|     WHY THIS EXISTS, and why it is not "widening the register".

  818|     `zhao_console_board` instantiates `zhao_console_core` and drives it from
  819|     `zhao_sys_pll` and `zhao_sys_reset`. It is the only module in this tree that
  820|     could be programmed onto hardware; the core is an organ of it. So SYS.PLL
  821|     and SYS.RESET are COMPOSED -- they have a real producer (the 50 MHz board
  822|     oscillator characterised in `board_truth.json`), a real implementation, and
  823|     a real consumer (every clock and reset the core runs on). The owner's
  824|     standard is that a capability is absent when it is "a disconnected
  825|     implementation". These are not disconnected. They are one level up.
  826| 
  827|     THE OBJECTION THE BOARD PACKET RAISED, AND WHY IT DOES NOT SURVIVE
  828|     MEASUREMENT. It declined to re-point this register because "that would
  829|     change what CONNECTED means for all 77 capabilities at once, in the

  831|     is the reason this function returns a DIFFERENCE rather than a union of

  836|                                         zhao_sys_reset_sync}

  877| def _reach(root: str, decl: dict, inst: dict) -> set[str]:
  878|     if root not in decl:
  879|         return set()
  880|     seen, stack = {root}, [root]
  881|     while stack:
  882|         cur = stack.pop()
  883|         for child in inst.get(decl[cur], ()):
  884|             if child not in seen and child in decl:
  885|                 seen.add(child)
  886|                 stack.append(child)
  887|     return seen

  890| def _board_addition_from(decl: dict, inst: dict) -> set[str]:
  891|     """The difference, split out so the self-test can drive it on a toy graph."""
  892|     board = _reach(BOARD_ROOT, decl, inst)
  893|     # THE GUARD, and it is the whole safety of this function: a board that does
  894|     # not contain the core is not the machine's top, so nothing under it is
  895|     # "composed into the console" by any reading.
  896|     if CONSOLE_ROOT not in board:
  897|         return set()
  898|     return board - _reach(CONSOLE_ROOT, decl, inst)

  940| def successor_in(mod: str, closure: set[str], live: set[str]) -> str | None:
  941|     """Is a VERSIONED SUCCESSOR of `mod` composed instead of `mod` itself?
  942| 
  943|     TEXTURE.CACHE resolves by convention to `zhao_texture_cache`, which nothing
  944|     composes -- but `zhao_texture_island_v3_top` IS composed and instantiates
  945|     `zhao_texture_cache_pipe_v2`. The capability is present; the resolver was
  946|     naming the superseded file. Counting that as a mandatory gap inflates the
  947|     number and sends someone to compose a module the tree has already replaced.
  948| 
  949|     THIS CORRECTION MAKES THE NUMBER SMALLER, which is the flattering direction,
  950|     so the bar is deliberately high: the successor must be BOTH in the closure
  951|     AND instantiated, and its name must be `mod` plus a version suffix -- never a
  952|     fuzzy match. The successor is reported by name so every reduction is
  953|     auditable rather than asserted.
  954|     """
  955|     for cand in sorted(closure & live):
  956|         if cand == mod or not cand.startswith(mod + "_"):
  957|             continue
  958|         tail = cand[len(mod) + 1:]
  959|         # THE TAIL MUST BE A VERSION AND NOTHING ELSE.
  960|         #
  961|         # The first draft allowed `(?:\w+_)?v\d+`, and it immediately produced a
  962|         # FALSE reduction: it matched `zhao_texture_tmu_plan_v2` as a successor
  963|         # of `zhao_texture_tmu`. That file's own third line says it is the
  964|         # successor of `zhao_texture_tmu_plan.sv` -- the PLANNER, not the
  965|         # sampler. Two different modules whose names happen to share a prefix.
  966|         #
  967|         # Same for `zhao_texture_cache_pipe_v2` (successor of
  968|         # `..._cache_pipe`) and `zhao_texture_aux_pipe_v2`. A loose prefix rule
  969|         # retires a real gap by coincidence of naming, and it does so in the
  970|         # direction that makes the campaign look further along than it is --
  971|         # which is the one direction this register must never fail in.
  972|         if re.fullmatch(r"v\d+", tail):
  973|             return cand
  974|     return None

  982| def superseded_verdict(note: str, cmake_text: str,
  983|                        exists=lambda rel: (ROOT / rel).exists()) -> str | None:
  984|     """Does a ledger `superseded_by:` note EXCUSE its capability? None = yes.
  985| 
  986|     Added 2026-09-19 for owner ruling R16: a hardware block whose function a
  987|     RULING moved to another provider (TERRAIN.VISIBLE, moved into SW.STREAM by
  988|     T5) is a duplicate provider, and removing it is allowed -- but only if the
  989|     replacement is really there. THIS MAKES THE NUMBER SMALLER, so the bar is
  990|     the one `successor_in()` sets, applied to prose: every condition below is
  991|     checked against the TREE, and a note that fails any of them is counted AS A
  992|     GAP (reported with the uncited excuses), never as a pass.
  993| 
  994|       1. it cites a RULING by name (`ruling T5`, `R16`), not an opinion;
  995|       2. it names at least one repository file, and EVERY file it names exists
  996|          -- a supersession pointing at a deleted file is an uncashed cheque;
  997|       3. at least one named file is a test under `tests/` that
  998|          `tests/CMakeLists.txt` actually builds -- "implemented and tested" is
  999|          the ruling's own condition, and a test nothing compiles tests nothing.
 1000|     """
 1001|     if not re.search(r"\bruling\s+[A-Z]+\d+\b|\bR\d+\b", note):
 1002|         return "cites no ruling"
 1003|     paths = _CITED_PATH.findall(note)
 1004|     if not paths:
 1005|         return "names no file"
 1006|     missing = [p for p in paths if not exists(p)]
 1007|     if missing:
 1008|         return "names files that do not exist: %s" % ", ".join(missing)
 1009|     tests = [p for p in paths if p.startswith("tests/")]
 1010|     built = [p for p in tests if p[len("tests/"):] in cmake_text]
 1011|     if not built:
 1012|         return "names no test that tests/CMakeLists.txt builds"
 1013|     return None
