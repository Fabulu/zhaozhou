4. NON-NEGOTIABLE TEXTURE CONTRACT
==========================================================================

This is the common semantic core of S01 and S02. Nothing in a failed ALM
allocation authorizes weakening it without an explicit owner decision.

4.1 Identity and ownership
--------------------------------------------------------------------------

An accepted fragment acquires one of 64 global owners. That owner lives through
service issue, all terminal returns, payload publication, COMBINE execution,
final-result publication, output prefetch and output stall. It is released
normally ONLY by the ordered final output ready/valid handshake.

Keep the full 64-bit opaque caller context. It is neither scratch space for
recipe flags nor a hidden pair of world coordinates. Internal completion can
be out of order; the caller receives exactly admission order. An individual
error creates an ordered terminal result, not an out-of-order free hole.

OwnerHandle = {slot[5:0], generation[7:0]}              14 bits
SampleHandle = {slot[5:0], sample[1:0], generation[7:0]} 16 bits

TMU sample indices 0, 1 and 2 are legal. Index 3 is malformed, not AUX. AUX and
final returns use their distinct typed ports. Palette generation, owner
generation, configuration epoch and local arithmetic context are different
namespaces. A representation change in one does not eliminate the others.

4.2 Completion and exactness
--------------------------------------------------------------------------

For every required source, keep these distinct facts:

  REQUIRED -> ISSUED -> CLAIMED -> PHYSICALLY WRITTEN -> PUBLISHED.

A request is issued only when its service accepts it. An unsolicited reply to
an unissued required source is invalid. The first authorized reply claims it;
subsequent duplicates must not write or publish again. A legitimate service
failure still supplies one typed terminal result/status for the required job.

Preserve all specified formats: CLUT8, CLUT4, RGB565, ARGB1555 and ARGB4444;
nearest and legal filtering; per-sample fractions/byte/nibble metadata; real
alpha; all eight material recipes and exact rounding/saturation order. Preserve
independent sample descriptors for legal multi-sample materials. Three copies
of one coordinate pair are not three independently described samples.

Status8 travels independently of diagnostic RGB. Material math may legitimately
alter magenta; it may not erase the fact that the source failed. Preserve real
AUX geometry/envelopes and Mosaic's useful effect on consumed binding/selection.
An instantiated counter is not proof the useful datapath survived synthesis.

4.3 Peak contracts and workload contracts are different
--------------------------------------------------------------------------

Preserve the selected owner interfaces' capacity to accept, where supplied and
credited, one admission per cycle, one TMU terminal plus one AUX terminal plus
one final terminal per cycle on independent ports, one COMBINE input packet
per cycle, and one ordered output per cycle from contiguous finished owners.

These are peak interface rates, not a promise that a complex three-sample
material emerges every clock. Average texture workload, sample/filter phases,
cache misses and arithmetic rates remain separate performance obligations.
Do not replace a peak-rate join with a smaller serial join merely because the
average RCP completion rate is lower.

Every new cycle carries a storage/identity obligation. Latency can increase
only with explicit credit accounting and measured workload throughput. Avoid
infinite-buffer assumptions, hidden skid stages and same-edge ready shortcuts.

5. ONE LIVE SEQUENCE WINDOW, NOT 64 GENERATION READ PORTS
==========================================================================

Source basis: S01 §6 and S02 §6. This changes identity REPRESENTATION, not the
external token width or the requirement to authenticate delayed replies.

5.1 State and encoding
--------------------------------------------------------------------------

Use internal sequence order {generation[7:0], slot[5:0]}, a permutation of the
public owner handle. Define 14-bit A (next allocation), E (next emission), and
F (next reserved final-result fetch); C is a seven-bit live count in 0..64.
Initialize A=E=F=64 and C=0 to match legacy first-use slot0/generation1.

On admission, emit the public handle repacked from the PRE-EDGE A, initialize
that row and advance A by one modulo 16384. On external output transfer advance
E. On reserved final read advance F. Update counts exactly once:

  C_next = C + admission_taken - output_taken;
  U_next = U + admission_taken - final_fetch_reserved.

Use the same accepted event for token stamping, storage initialization and
counter update. Mixing current_tail data with next_tail identity corrupts a
valid-looking transaction.

A returned sequence R is live precisely when:

  distance = unsigned_14(R - E);
  live = distance < C.

This is modular interval membership, not ordinary R>=E && R<A. Check the whole
distance before exploiting the small 64-owner bound. Truncating the subtraction
to six or seven bits aliases stale generations. Never subtract public handles
without first undoing the slot/generation permutation.

5.2 Proof obligations, not implementation assumptions
--------------------------------------------------------------------------

The representation is valid because admission advances in slot order and
release advances in the SAME global order. Live owners are one short contiguous
interval. At most 64 are live, so no live identities share a physical slot.

This stops being true with arbitrary free-list allocation, independent retire
heads, out-of-order freeing or local cancellation that removes an interior
owner. Such an extension requires a new design, or ordered tombstones. An
ordered error result preserves the interval and is the default local-failure
policy. A whole-domain abort has its own acknowledged protocol.

An independent verification model should store a literal ordered collection
of live full handles, not use the new interval formula as its own oracle.
Compare the public token sequence against explicit legacy per-slot generation
counters. Exercise every slot and occupancy, including 0, 1, 63, 64, numeric
zero crossing and high generations.

5.3 Validate identity twice around a delayed control snapshot
--------------------------------------------------------------------------

A full token authenticates a packet at the state-snapshot edge AND at the
later claim edge. A future token that was not live at snapshot cannot become
authorized simply because admission catches up with it. An old token that
retires between snapshot and claim cannot write a new occupant's row.

Retain snapshot_valid_identity and recheck membership in the current window at
claim, or establish an equivalent explicit lease preventing invalidation.
Revalidation is the first implementation because its reasoning is direct.
Do not carry a stale Boolean instead of the full identity across a new stage.

5.4 Internal slot-only candidates require a real lease
--------------------------------------------------------------------------

An internally reserved candidate cannot outlive its owner. For a selected slot S:

  offset = unsigned_6(S - E.slot);
  R = E + offset (modulo 16384), with offset < C.

There is exactly one live identity for that slot. Reconstruct and register the
full token after central arbitration, before the corresponding bank read.
This compression is legal only inside the candidate lease. External cache,
AUX, palette/service or final replies must not be reduced to a slot before
validation. Reusing an owner while an old candidate exists is a fault, not a
reason to keep progressively wider internal tags around broken lifetime logic.

5.5 Finite namespace reuse is still a protocol problem
--------------------------------------------------------------------------

Starting at A=64, the first approach to zero occurs after 16,320 allocations;
subsequent complete namespaces span 16,384. Before reusing sequence zero, stop
new owners and complete the namespace barrier in section 6.

One global barrier before this reuse replaces the legacy per-slot generation-
zero quiet checks. The public token order stays the same; the drain scheduling
is an explicit implementation change. Preserve safety assertions while updating
tests that accidentally demand the predecessor's exact per-slot drain timing.

No finite reused tag distinguishes a maliciously regenerated or arbitrarily
late IDENTICAL old token after a completed namespace cycle. The external
producer contract must guarantee old obligations are gone, or an outer epoch
must remain non-reused over the real transport lifetime. A timeout is not that
guarantee. Widening a counter only postpones the same obligation.

6. FINISH FOURTH: REGISTERED ADMISSION AND AN ACKNOWLEDGED FENCE
==========================================================================

Source basis: S01 §14; S02 §§5,6,11. This is the next incomplete texture step,
not an external excuse for a terrain detour. Keep the working NEXT-state credit.

6.1 Ordinary admission must be local
--------------------------------------------------------------------------

The intended hot decision is a conjunction of REGISTERED permission/credits:

  owner_credit_available_q;
  admission_staging_credit_q;
  epoch_and_fence_open_q.

No ready-queue pointer subtraction, aggregate occupancy, global service quiet,
COMBINE-ready chain or output-ready full-ring bypass belongs in this cone.
At full capacity, conservatively refuse same-edge admission even if output
returns a credit on that edge. Add such a bypass only after a measured need and
specific same-slot/ready-path proof.

For the intermediate per-slot-generation implementation, do not put a flop on
wrap_block and call it solved. The tail can advance onto a wrapping slot while
the previous permission stays high for one cycle. Compute the permission from
the same next-state tail/generation event that commits, or implement the fence
alongside the sequence-window transition with separate, attributable tests.
A phase machine—not an indiscriminate delayed quiet bit—owns reopening.

6.2 Selected causal phase sequence
--------------------------------------------------------------------------

  OPEN
    Admit owners using registered local credits. Existing work executes.

  STOP_NEW_OWNERS
    Close admission; latch fence reason, request identity and epoch.
    Do NOT shut service issue for already admitted owners.

  FINISH_OWNERS
    Let old owners issue their remaining required work, receive terminals,
    combine, publish and emit. Wait for live owners and output reservations
    to reach zero through their normal acceptance events.

  QUIESCE_PRODUCERS
    Request acknowledgement from adapters that could later return old work.
    Establish that no upstream path can generate another old-epoch request.

  DRAIN_RESIDUAL_TRANSPORT
    Finish pending writes/reads and drain invalid, stale or duplicate captures
    that may exist without a live owner. Empty visible heads alone is not
    enough. Phases may overlap only with a documented causal proof.

  FENCE_COMPLETE / REOPEN
    Every required acknowledgement belongs to the HELD request and remains
    valid. Apply the permitted namespace/configuration change, consume the
    reopening permission exactly as specified, and return to OPEN.

The legacy transitional fence may authorize exactly one wrapping admission and
then resume normal checks. The final sequence-window fence authorizes a new
namespace after one complete barrier. These must not be combined into an
accidental 64-drain policy or an indefinitely open reuse permission.

6.3 What a producer acknowledgement means
--------------------------------------------------------------------------

ACK means all accepted old work has completed or been canceled under an agreed
contract; none remains in RAM bodies, pending reads, heads, retries, output
stages or external-return queues; no upstream actor may create more old work;
and ACK stays valid while its particular request remains asserted.

A zero local FIFO count before upstream is stopped cannot be latched as a
permanent drained fact. A debug idle signal is not a cancellation agreement.
Use explicit outstanding-obligation counters where they establish the same
meaning. A fake responder may supply this in the owner experiment; production
must have real adapters and real old-epoch obligations in the test.

6.4 Local drain inventory
--------------------------------------------------------------------------

Include C, U and fetched-but-unemitted reservations; admission/context writes;
all terminal capture/snapshot/claim/write/publication stages; candidate heads
or transitional ready queues; COMBINE input and execution ownership; RCP,
PERSPUV, planner/cache, palette and AUX requests and responses; raw invalid
transport; final output heads and pending synchronous reads. List each source
of future work exactly once and state how its upstream can no longer refill it.

Registered reduction trees can add drain latency. They must not report early
completion. Diagnostic ev_quiet may be a delayed snapshot with a documented
meaning, but it must be separate from the protocol acknowledgement that permits
namespace reuse.

6.5 Reset, abort and reconfiguration
--------------------------------------------------------------------------

Differentiate whole-domain reset, controlled island reset AFTER drain, fault
abort with outstanding external work, and configuration change without reset.
A reset of only the owner while adapters retain old replies is illegal unless
a larger epoch/protocol prevents aliasing. Payload RAM is not bulk-cleared.
Reset validity, count, ownership and phase state; wait for any required free-
queue preload/initialization before admitting work.

A recoverable owner failure retires an ordered error. A destructive abort may
discard the entire interval only when producers and consumer acknowledge the
same boundary, including a final packet already held valid under backpressure.
A cancellation cannot let an accepted write reappear after its row is reused.

Freeze binding/material/envelope interpretation per owner. Destructive palette
or descriptor reuse drains first in the simple profile. Multiple retained
versions are possible, but their storage and references enter the budget.
Palette generation is not replaced by the owner sequence-window proof.

6.6 Fence acceptance tests
--------------------------------------------------------------------------

Test the last pre-wrap admission, new work offered on every edge, non-full
wrapping tails, simultaneous admission/output, delayed acknowledgements, every
occupied pipeline location, false visible-empty during RAM prefetch, and old
invalid replies during residual drain. Assert no new owner after STOP, existing
owners can still progress, and no reused namespace before the final ACK.

Demonstrate that the naive registered permission and a removed-fence mutant
fail. An expected-failure suite stays a tracked defect until restored RTL
passes the intended safety property; do not make the mutant green by changing
the property to fit the shortcut.

7. LOCAL CONTROL, CLAIM FORWARDING AND PUBLICATION
==========================================================================

Source basis: S01 §§7–9; S02 §§7–8. This is a connectivity redesign, not merely
replacing one for-loop with 64 hand-written copies of the same mux network.

7.1 Selected persistent control inventory
--------------------------------------------------------------------------

Per owner: active1, required4, issued4, claimed4, committed4,
combine_reserved1, combine_issued1, final_claimed1, final_done1.
Total: 21 bits/owner, 1,344 across 64. Global sequences, credits, pipeline
packets, candidate state, counters, heads and physical duplication are EXTRA.
This is not a prediction of fitted registers or ALMs.

Keep active as a local eligibility gate. Full external identity still comes
from sequence-window validation. Keeping 64 active bits avoids reconstructing
global membership independently in every row just to ask whether it is eligible.

Split source phases into independently owned bitplanes. Admission initializes
required and clears dynamic phase bits. TMU issue/claim/publication can affect
one of sample bits 0..2; AUX affects bit3 on the same clock. Final control has
its own events. Different fields do not need every event as a mux input.

Within each field define one next-state equation and one storage update.
Disjoint source events OR together. Same-owner publication does not become a
last-assignment-wins race. Admission is not a license to overwrite an active
row; assert the impossible collision rather than hide it in precedence.

7.2 Physical groups and narrow events
--------------------------------------------------------------------------

Start with eight groups of eight consecutive owner slots:
  group=slot[5:3]; local row=slot[2:0].

Register/factor event decode once per event lane, then distribute narrow
valid/group/row/source strobes. Do not broadcast full payload or opaque context
through all control groups. Keep sample/final data on its assigned bank path.

Each group owns its phase bits and candidate registers. A small one-bit state
selector can be reasonable fabric. Repeated wide 64-row reads and global update
fans are the structures to remove. No blanket prohibition of every array,
wire alias, dynamic bit read or always_comb block is justified.

Eight-way hierarchy expresses intended locality, not guaranteed placement.
Inspect routed fanout and duplication. Four groups of sixteen and sixteen of
four are later controlled alternatives, not simultaneous mandatory lanes.
A single RAM holding the entire multiwriter control row requires serialization,
forwarding and a throughput proof; it is not the initial default.

7.3 Phase invariants
--------------------------------------------------------------------------

For a live owner, assert:
  committed subset claimed subset issued subset required;
  final_done implies final_claimed;
  final_claimed implies actual combine_issued;
  combine_issued implies combine_reserved.

These permit a return snapshot to retain the selected issued and claimed bits
instead of all four required/issued/claimed/committed masks. Required remains
stored for issue and readiness. Claimed stays set until reuse, so a separately
selected committed bit is not needed to reject duplicates if the subset law
is actually enforced.

7.4 Concrete terminal stages
--------------------------------------------------------------------------

For each independent TMU, AUX and final terminal lane:

  R0: capture packet, full handle, type/range and payload/status.
  R1: snapshot selected narrow state and identity validity.
  R2: revalidate current identity; apply recent-claim forwarding; accept or
      classify rejection. Acceptance sets the claim and captures write record.
  W:  write using registered enable, address and data as one aligned record.
  P:  publish AFTER the memory write edge.
  Q:  local readiness can observe the new published state on the next edge.

The names and exact number of cycles may change, but capture, exclusive claim,
physical write and consumer-visible publication cannot collapse into an unsafe
same-cycle RAM-enable cone. Every authorized claim already owns downstream
write/publication capacity. A payload row reserved by that owner is such a
capacity, provided exactly-once and port concurrency are proved.

A malformed or stale packet can occupy transport stages and be drained without
acquiring a write. A legitimate service error does acquire the required source's
one result/status publication; otherwise it becomes an owner leak.

7.5 Forward recent claims by FULL identity
--------------------------------------------------------------------------

A snapshot can miss a claim stored on its capture edge. Retain prior ACCEPTED
claim records and compare full sequence plus source. For one edge between
snapshot and claim, the preceding accepted claim record covers the window.
If another mux/capture stage is added, derive and extend the visibility window.
Do not keep a magic FWD_WINDOW=1 through arbitrary retiming.

AUX, TMU and final lanes have their own relevant histories. Two sources of one
owner are not duplicates. Two adjacent TMU returns for the same source are.
Invalid earlier packets must not create phantom forwarding claims.

Issue is separately authorized. A same-edge or next-edge legal warm return
needs a defined issue-notice bypass or a producer minimum-latency guarantee
that is enforced at the actual seam. Never mark all required sources issued
at admission to avoid dealing with this race.

7.6 Publish trusted work without another global generation-table query
--------------------------------------------------------------------------

An accepted required-source claim cannot normally be overtaken by owner release:
that source has not published, so valid readiness/final output cannot yet
complete the owner. A final claim likewise precedes its own final_done. This
lifetime lets a validated internal write/publication record update its decoded
local row without 64 repeated generation comparisons.

Do not extend this reasoning across an unacknowledged abort or corrupted
internal identity. Coordinate reset/abort to kill or drain the whole accepted
pipeline before reuse. A late generation comparison after a RAM write would
not protect the write itself anyway.

Publish same-owner TMU and AUX as disjoint source bits in one merged row update.
Readiness follows registered committed state. A one-cycle-later local readiness
observation can preserve throughput while eliminating a second global table
query on every publication.

7.7 Optional remaining-result counter: a DIFFERENT measured candidate
--------------------------------------------------------------------------

S02 proposes remaining=popcount(required), in 0..4. At publication it decreases
by the number of unique TMU/AUX publications for that row (0,1,2). A nonzero
initial count emits one ready event on remaining>0 && remaining_next==0.
A zero-work admission emits its initial event once. Same-owner simultaneous
last TMU/AUX publication selects one producer queue deterministically.

This can replace committed4 plus a sticky ready flag in a QUEUED readiness
implementation, while keeping required/issued/claimed. Its advertised 18-bit
row omits the active/reservation organization of the selected candidate design.
Do not paste the 18-bit inventory onto that different design. Combining the
counter with candidates needs its own complete state/conservation account.

Removing sticky readiness is legal only with immutable requirements, unique
monotonic publications, reserved ready-event capacity, and no cancellation
that changes the count behind the model. Keep ghost committed masks in tests
and check remaining against them. This alternative is deferred until a correct
window/local-control baseline can establish a meaningful cost comparison.

8. READY WORK: REGISTERED LOCAL CANDIDATES, NOT A GLOBAL SCAN
==========================================================================

Source basis: S01 §10; S02 §§8–9 describe the transitional queue alternative.
The selected replacement is eight groups with two registered candidates each.

8.1 Eligibility persists until reservation
--------------------------------------------------------------------------

For each local row:
  eligible = active && !combine_reserved
             && ((committed & required) == required).

Zero-work owners become eligible after admission initializes their row.
A normal owner becomes eligible only after all needed writes have published.
Unselected eligibility remains in the row; it is not a pulse that disappears
because a small candidate cache is full.

Each group stores head_valid/head_row[2:0], spare_valid/spare_row[2:0], and
local round-robin state. At most one local row is reserved per group per edge.
Candidate insertion and combine_reserved update are atomic. This prevents
re-selection while its token waits in the candidate or downstream join.

8.2 Central choice sees only registered heads
--------------------------------------------------------------------------

The central round-robin arbiter sees eight registered valid/slot heads. It does
not inspect 64 raw committed masks or any wide data. Pop only when the complete
operand-read path has a reservation. Reconstruct the full owner sequence and
register it with the bank address before payload selection.

Local round-robin advances on actual local reservation; central round-robin
advances on actual central pop. Not on a speculative choice or ready alone.
A stalled offered candidate remains valid and does not change identity.

Two candidates per group allow head pop, spare promotion and refill to overlap.
Prove a hot single group can deliver eight ready rows on eight consecutive
central grants after warmup. A one-candidate implementation that bubbles on
every refill is not automatically equivalent performance.

8.3 All-ready is not an overflow
--------------------------------------------------------------------------

With all 64 owners ready, at most sixteen occupy the candidate registers; the
remaining rows retain eligibility. Draining candidates reveals more local
work. Owner capacity remains 64, not sixteen. No three queues have been shrunk
to 64/3 while pretending arbitrary producer bursts still fit.

Check no duplicate owner across all local candidates and downstream joins.
Readiness cannot be dropped by simultaneous local refills, central pops,
publication and zero-work admission. Use deterministic local/global fairness
under explicit downstream progress assumptions. Do not promise a wall-clock
bound through an arbitrarily stalled consumer.

A global counter summing local claims may see eight on one edge; its delta
needs at least four bits. An old two-bit three-producer delta would wrap.
Prefer local counters plus registered diagnostic snapshots rather than a broad
sum feeding hot admission.

8.4 Transitional producer queues remain a useful controlled baseline
--------------------------------------------------------------------------

During identity and locality ablations, preserve the three existing ready
queues, with repaired logical occupancy and stable heads. Each queue's physical
body, read pending and both visible heads count inside its logical capacity.
The global once-only 64-owner invariant bounds total outstanding tickets; still
assert overflow and illegal writes rather than rely on unchecked prose.

Do not retain both the old full queue system and the new candidate system as
independent sources of COMBINE work. Switch exactly once at an explicit
integration milestone. A retained cheaper queue implementation is a legitimate
measured fallback if candidates do not pay for their new arbitration.

9. COMBINE, CREDITED PACKET STORAGE AND ORDERED RETIREMENT
==========================================================================

Source basis: S01 §§11–13, S02 §§9–10. These protocols are part of the resource
architecture, not polish to add after a good ALM number.

9.1 Three events that must have three meanings
--------------------------------------------------------------------------

  Candidate reservation: owner claimed for eventual COMBINE input.
  Bank-read reservation: a home reserved for the future joined packet.
  COMBINE acceptance: complete packet transfers on cmb_valid && cmb_ready.

Only the THIRD sets actual combine_issued and authorizes a final terminal.
The current owner sets cbi on the second. The M6 adversarial case captures the
resulting bug; it is not desired predecessor behavior to preserve.

Test a ready, reserved owner with COMBINE stalled. Inject a final carrying its
correct token. Expect an error, no final RAM write, no final_done, no emission
and no release. Then accept the true input and verify one legitimate final
still succeeds. Remove the expected-failure wrapper only when the DUT passes
that intended property. Do not weaken the test to match early authorization.

9.2 Retain the material kernel; adapt ownership
--------------------------------------------------------------------------

Keep COMBINE V2's two byte-product sites and paired phase organization. Its
bounded execution contexts are latency hiding, not the global owner count.
Preserve all recipes, input/base alpha, refusal status and exact /256-style
rounding/saturation. Do not substitute /255 or merge observable intermediate
steps. Keep phase/job counters: duplicate computation may return identical
colors while wasting the throughput budget.

Younger ready owners can be selected before older ones. Their finals write
reserved per-owner final rows. Only the output frontier enforces final order.
Do not introduce global in-order COMBINE issue merely to simplify the bench.
Direct filling of reserved execution contexts is an optional way to remove a
wide join buffer, but holds contexts during RAM latency; measure its rate and
occupancy before claiming a saving.

9.3 Reserve the ENTIRE read-to-consumption path
--------------------------------------------------------------------------

A bank read that has launched must have a destination regardless of subsequent
ready changes. A logical reservation includes early address/token stages, RAM
read/capture, packet body, FIFO prefetch in flight, head/spare and an offered
but stalled packet. Moving between these places transfers physical location,
not ownership credit.

COMBINE-ingress credit returns at actual COMBINE packet acceptance. Final-output
credit returns at actual external transfer. Global owner credit returns only
at that external transfer, never at a sample write, COMBINE completion, final
write, final read or insertion into a queue.

Use accepted pushes minus accepted external pops as the logical queue count.
For a synchronous body with two heads:
  L = body_owned + pending_read + head_valid + spare_valid.

Additional queue-owned stages belong in L; earlier bank-read reservations may
be a wider domain. Name the overlap rather than summing overlapping counts.
Reserve a head position before issuing body prefetch. Do not infer emptiness
from !out_valid while a pending read owns a packet.

9.4 Keep buffering constant for early control measurements
--------------------------------------------------------------------------

The existing four-entry COMBINE holding queue declares
  4*(owner14 + four result40) = 696 payload bits.
The four-entry output holding queue declares
  4*(owner14 + result40 + context64) = 472 payload bits.
Together: 1,168 before capture stages, pointer logic, muxes and reservations.

Keep these initially so a window/control delta is not confused with a changed
buffer architecture. Their real mapped/fitted cost stays in the total.

For the later selected RAM-backed profile use sixteen logical reservations
on each path, with a synchronous body and two show-ahead slots:
  owner-demo COMBINE packet: 174 useful bits; five 40-bit width slices;
  feature-live COMBINE packet: 226 useful bits in a 240-bit row;
    owner14 + material48 + four result40 + required4;
    fourteen explicit reserved bits; six width slices;
  output packet: 118 useful bits in a 120-bit row; three width slices.

The row geometry is a proposed mapping profile, not a measured M10K total.
If a real descriptor requires more bits, revise the row and resource inventory;
do not drop fields to maintain a pretty width. Sixteen body rows plus heads
must not advertise eighteen logical credits. Capacity includes pending stages.

S02's smaller joins remain alternatives only if they sustain the selected
interface peak rates under actual RAM latency. Choose using measured bursts,
not just average service rate. Conservative registered-credit launch avoids a
consumer-ready arithmetic feedback path; sufficient capacity must hide its
credit-return latency. An uncounted skid is not extra free capacity.

9.5 Uninitialized payload must stay unobservable
--------------------------------------------------------------------------

Required lanes are read only after their writes publish. Unrequired sample
banks may contain old poison; packet assembly substitutes the reference-defined
bypass/default for those lanes. Do not reset every payload word and accidentally
make an invalid missing-source read return the expected zero.

Prefer staging that makes same-address read-during-write behavior unobservable
to useful consumers. A no_rw_check attribute is a promise about collisions,
not proof of that promise. Debug reading is not a free additional memory port.

9.6 One contiguous final-fetch frontier
--------------------------------------------------------------------------

F names the next owner whose final row has not been reserved for reading. Fetch
requires U>0, the local row active, final_done set and output-path credit. Reserve
capacity, capture the full token/address and advance F exactly once. Do not scan
past an incomplete older owner. No per-owner fetched bitmap is needed under
that contiguous, non-retrying reservation law.

  [E,F): fetched/reserved but not externally emitted;
  [F,A): not yet fetched;
  [E,A): all live owners, never more than 64.

These intervals use bounded modular order, not naive unsigned inequalities.
Keep per-owner final_done because completion is out of order. On output_taken,
assert offered full sequence equals E, release its output reservation and row,
advance E and decrement C. The stale payload bytes may remain in RAM.

While output valid && !ready, context/result/status/token remain stable. Internal
prefetch may fill other reserved slots but cannot replace the offered head.
A new final publication becomes fetchable on a later registered observation;
do not add a same-edge RAM collision/bypass to save a cycle without a measured
need and a dedicated correctness proof.

==========================================================================

Source basis: S01 §§17.10–17.16. This is texture work and can proceed in an
isolated lane while the owner fence/control work continues. It must not be
substituted with terrain because the owner step is hard.

10.1 The old top is not merely wiring
--------------------------------------------------------------------------

The published old-island map excerpt includes these self counts:

They identify real conversion targets, not a guaranteed 9,568-ALM saving.
Different access patterns need different port schedules. Two independent reads
PLUS a concurrent write are three accesses, not a free use of two-port RAM.
Pack fields only when their writer and read event genuinely coincide.

10.2 Numerator-result join: do not just delay uvw_rd
--------------------------------------------------------------------------

The old top combinationally selects uvw_m using a returned RCP token and feeds
PERSPUV with the reciprocal currently on the service pins. Registering only the
numerators pairs yesterday's U/V with today's mantissa/token.

Use a credited join:
  N0 accept/capture full reciprocal token, mantissa, exponent, zero flag and
     reserve its complete destination;
  N1 issue immutable numerator-bank read by captured owner address;
  N2 capture the RAM output at the agreed primitive latency;
  N3 assemble numerators and THEIR captured reciprocal into a stable packet;
  N4 PERSPUV accepts; return join credit, NOT owner credit.

These stage labels are a conservative design, not a measured latency minimum.
Any collapsing of stages changes the reservation proof and tests together.
The seam can burst one result/cycle even if average RCP rate is one per four.
Test distinct U/V, shuffled completions, zero/nonzero interleaving, slot reuse,
and ready dropping just after a read launches.

No extra sixteen-slot join is free outside the bank budget. In the final design
reuse or explicitly account for RCP_RESULT, sample-descriptor and PERSPUV-input
reservation domains. A transitional legacy join is removed or costed at merge.

10.3 Immutable descriptor join after PERSPUV
--------------------------------------------------------------------------

Capture U/V, full identity and flags with a join credit. Read the matching
context/material/sample/configuration descriptor planes synchronously. Capture
raw rows before sanitization/interpretation. Resolve class from effective
binding/format/filter rather than keeping two independent routing authorities.
Then present one stable descriptor to the expansion controller.

The descriptor is not an unacknowledged pulse broadcast to FRAGROB, AUX and
Mosaic. Prefer one expansion controller owning every subsequent subrequest;
an alternative fork requires a separate reserved destination and acceptance
bit per consumer. OR-ing ready signals is not a correct multi-consumer fork.

10.4 Final field ownership / mandatory deletion inventory
--------------------------------------------------------------------------

  OLD FIELD / STORE                FINAL OWNER
  -------------------------------  ----------------------------------------
  fctx_m + duplicated context       One OWNER_CONTEXT 64x64, final read only.
  uvw_m                            Independent SAMPLE_DESC numerator fields;
                                   shared reciprocal in RCP_RESULT.
  base/recipe/weight/sample-count   MATERIAL row: 45 basic bits before flags;
                                   verify remaining flags fit the 48-bit row.
  binding/LOD/class/sample metadata SAMPLE_DESC + immutable binding resolution
                                   + SAMPLE_METADATA by named access events.
  faux_m / AUX request bookkeeping  Required mask + independent AUX geometry.
  palette slot/generation           Captured palette identity/version; not
                                   eliminated by owner generation compression.
  fseq_m + separate final ROB       A/E/F identity, FINAL_RESULT, OWNER_CONTEXT
                                   and bounded output-path reservations.

Remove old lifetime/reorder machinery only after replacement parity under real
internal reordering and long external stalls. Then actually remove it. A new
owner plus old fseq tables plus old global final ROB is not the intended final
architecture. Full context64 observability is stronger than the old low16 tag
output and may legitimately add scope/cost; state that in comparisons.

10.5 Controlled top-storage series
--------------------------------------------------------------------------

L0 read archived/current array and port inventory; L1 numerator join;
L2 descriptor join; L3 map-only inference and register attribution;
L4 comparable feature-live fit; L5 reviewed integration and old-store removal.

Use a separate worktree and top variant for these experiments. One integration
owner controls the shared top, record layouts and build manifests. Do not let
control and storage agents each replace the same live top concurrently.
If a controlled legacy repair reaches the practical goal sooner, retain that
measured option rather than treating a chosen architecture name as sacred.

11. RETAINED SERVICES AND THE FEATURE-LIVE ISLAND
==========================================================================

Source basis: S01 §§16–17; S02 §§13–14. A good owner demonstration is necessary
but not a complete texture island. Fake services must disappear from production
fit source lists, not remain hidden behind a green token test.

11.1 RCP24 V3: keep exact arithmetic, inspect the actual handoff
--------------------------------------------------------------------------

Retain normalization, seed ROM, MW0/MX0/MW1/MX1, final rounding/clamp, zero-input
behavior, exponent convention and the exact reduced-product correction. Four
product launches belong to a nonzero reciprocal. Zero is a scheduled terminal
case, not a claim that four real products occurred.

Preserve direct arithmetic testing with arbitrary x,w operands. Negative
correction may be unreachable through friendly denominator-derived iterates;
that does not make an arithmetic-core contract disappear. Do not delete a
required correction because the ordinary service differential misses it.

Keep sixteen execution contexts initially: the reported context sweep found
8 underutilized the pipeline and 32 did not improve the approximately four
clocks/nonzero-result rate. This is topology-specific evidence, not a universal
constant. A changed feedback/context-release latency requires a new sweep.

The raster ticket queue's mem_q[head_q] output is not a registered head just
because its commentary says so. Start with the DONE packet/token handoff and
match the result with its owner through a real registered boundary. Free a
local context only when its whole needed result/tag has safely transferred or
been copied into separately owned storage. A narrow token is not a copy of a
mutable result row.

FREE, NEW, CONTINUATION and DONE have different ownership and preload rules.
Do not blindly replace all with the texture ready queue. A RAM-backed free
queue needs initialization readiness; an asynchronous reset loop over every
payload element may destroy inference. Narrow fabric queues are legitimate
when their measured total is better.

In composition, the reciprocal belongs in the global RCP_RESULT plane. A
standalone local result table may be redundant, or may serve a real output
obligation. Remove it only with a named transfer point; do not deduct imaginary
integration savings from the measured 1,230 ALMs in advance.

11.2 Paired perspective service
--------------------------------------------------------------------------

U and V share reciprocal/exponent but retain independent signed numerators and
saturation outcomes. Preserve exact rescale, sign, depth-zero and exponent
behavior. Pair scheduling must not revert to an unnecessary general per-axis
join simply because the predecessor had one.

Carry only arithmetic operands and a narrow leased identity through deep stages.
Wide descriptor/context state belongs in explicitly accounted side storage.
A metadata queue must remain aligned through every stall, wrap and zero-depth
case. A zero shortcut must not overtake the pair whose metadata it would read.

One pair/cycle is a target requiring saturated RTL measurements with real
output reservations. Number of product lanes alone does not prove that rate.
When changing tags or side storage, test U != V, opposite signs, high exponent,
rails, ties, alternating bindings and zero between nonzero requests.

11.3 Binding and response metadata
--------------------------------------------------------------------------

Freeze an owner's material/binding/envelope interpretation at its accepted
configuration epoch. Resolve base address, format, filter, palette identity
and envelope against that stable version. Do not consume live global mode/base
pins after a different fragment has been offered at ingress.

Keep sample metadata with its full identity: effective format/filter, fractions,
byte select, CLUT4 nibble select, palette slot/generation and status. The
metadata read is a credited stage with a stable token, not an asynchronous
side-table convenience at three independent return consumers.

The final production class is derived from the effective descriptor. A legacy
independent class pin may remain in a transition wrapper to detect disagreement;
it is not a second production authority. Malformed class/format must reach a
defined terminal refusal/status, not vanish and stop ordered retirement.

Token-width migration is explicit: the old island packed class bits beside a
four-bit FRAGROB slot inside its sixteen-bit response token. The selected full
sample handle already uses all sixteen bits for six-bit owner slot, two-bit
sample index and eight-bit generation. Do not retain the old class-bit packing
by truncating the owner slot. Derive class from captured metadata or carry a
separately budgeted field through the new adapter. Layout equivalence is not
a cast; test owners above slot15 and high generations. [S01 §§5,17; E08]

11.4 Cache invariants already paid for: do not regress them
--------------------------------------------------------------------------

The repaired cache reserves response capacity at PROBE ISSUE, including results
in flight. A hit transferring into the response FIFO does not refund that
capacity; only the response consumer does. A miss cancels and refunds the
specific probes it squashes before replay. Already queued responses retain
ownership. [E09]

Maintain static per-lane data/tag banks, compatible synchronous read/write
processes, and a raw RAM-output capture before broad comparison. Tag and valid
must be sampled for the same memory observation; old tag plus newly set valid
can otherwise become a false hit during fill. Keep one blocking miss and
multicast unless a separate measured redesign replaces their contract.

Re-run the warm-hit loss scenario: fill response storage, keep accepted probes
in flight, stall downstream, then drain and compare EVERY token and value once.
A cold-miss-only always-ready test does not cover the original failure.

Global owner lifetime and cache transport are related but different. Local
cache requests/fills can still be pending while a convenient internal queue
looks empty. They participate in the namespace/configuration barrier.

11.5 Raw response preparation, filtering and palette
--------------------------------------------------------------------------

Capture raw cache returns before format decode/class routing. The prepared
response pool, its class queues and palette terminal reservations have named
writers and independent ownership. Do not duplicate wide sample payload into
several class FIFOs without counting it.

Direct-color nearest must decode the captured format. Bilerp sequences R,G,B,A
through its channel engine with the correct sample fractions and token. The
fourth alpha phase is real work; forcing alpha opaque to obtain three-phase
numbers changes the feature. Check channel order and independently varied
colors/alphas, not merely nonzero output.

CLUT4 requires both byte and nibble parity carried from planning. Give adjacent
nibbles distinct indices/colors and assert both parities were exercised. CLUT8
must also preserve halfword-byte selection. Do not infer stimulus diversity
from a loop that accidentally generates only even addresses.

A palette lookup that returns without consumer-ready must acquire a terminal
slot BEFORE issue. The credit includes its pending synchronous read. Preserve
BEGIN/load/END, coverage/CRC, cold/stale rules and palette generation. Lookup
during reload, repeated generation, missing entry and a delayed completion
merge must all produce defined accounted outcomes.

11.6 AUX and Mosaic are useful hardware, not counter decoration
--------------------------------------------------------------------------

AUX receives independent world geometry and real envelope identity. Do not
slice context64 into X/Z, assume geometry equals UV, or hardcode a 0..65536
envelope in a production-conformance wrapper to fold away expensive logic.
Keep offers and terminals separate where their ports can act simultaneously.
Full six-bit owner slot and eight-bit generation survive every adapter.

Mosaic selection must influence the binding/detail that the sampler consumes.
Demonstrate that changing the selection changes a final reference-checked
output. Merely preserving its statistics can let synthesis remove useful work.

AUX remains its own typed source; it is not quietly substituted for texture
sample2 by a color-like encoding in the final production contract. Reconcile
any legacy adapter with the selected material/AUX semantics explicitly.

11.7 No scope-cheating in the fit wrapper
--------------------------------------------------------------------------

Before a feature-live fit, inventory all supported paths and their observability.
Exercise independent configurations and outputs so real decode, alpha, palette,
AUX/envelope and Mosaic logic survives synthesis. Inspect the mapped hierarchy,
RAM names, DSP sites and warnings. A functional test of a richer top does not
prove a reduced fit wrapper retained the same capabilities.

List owner-demo fake COMBINE/sample responders as forbidden production sources.
A focused attribution probe can stub a service, but must label its scope and
keep the control being measured dynamic and observable. Its number is not the
complete island's number.

12. MEMORY, REGISTERS, DSPs AND THE ALLOCATION THAT MUST BALANCE
==========================================================================

Source basis: S01 §§15,21; S02 §§12,16. These are inventories and adopted or
proposed limits, not forecasts manufactured from diagrams.

12.1 Logical transaction planes and access ownership
--------------------------------------------------------------------------

13. VERIFICATION THAT SURVIVES REARCHITECTURE
==========================================================================

Source basis: S01 §22, S02 §18. Use the repository's real build/test definitions.
Discover registered test names rather than inventing commands. Rebuild checked
source before running a binary; an old executable passing is not current proof.

13.1 Verification layers
--------------------------------------------------------------------------

Maintain an independent transaction oracle, RTL differential/adversarial tests,
and exact-tool physical evidence. Each has its own scope. Algorithm checks do
not compile RTL; RTL tests do not prove RAM inference; successful place-and-
route does not prove semantics or clean timing.

Ghost ownership sets, explicit legacy generation arrays and committed masks
belong in verification. Do not synthesize redundant proof state into production
and then wonder why the control-plane reduction disappeared.

13.2 Required directed coverage
--------------------------------------------------------------------------

IDENTITY:
  all owner/sample pack/unpack fields, high generations, slots0..63;
  C=0/1/63/64 and intervals spanning numeric zero;
  old/future token at capture, snapshot, claim and reuse;
  no interior cancellation holes; full namespace fence.

COMPLETION:
  all 16 required-mask combinations including zero;
  issue and return in varied orders; TMU sample index 3 rejected;
  duplicate before claim, during forwarding, after write and after publish;
  same-owner and different-owner simultaneous TMU/AUX;
  required1111 / committed0011 + simultaneous source2/AUX -> exactly one ready
  reservation; service error still satisfies its required terminal obligation.

READINESS:
  all 64 ready while COMBINE is stalled; one hot group and all eight groups;
  head/spare full, central pop plus refill, zero-work admissions;
  no duplicate/reservation loss; accepted-event RR advancement;
  sustained hot-group grants and fairness under eventual consumer progress.

PACKET QUEUES:
  single push -> body read in flight -> first head without external pop;
  head/spare/pending combinations at every occupancy;
  simultaneous push/pop/read-return, pointer wrap, long output stalls;
  exact sequence, payload, status and transfer-history conservation;
  every read already owns a destination even after ready drops.

COMBINE/OUTPUT:
  M6 early final while COMBINE has only reserved, not accepted;
  younger work actually executes/completes before older work;
  final output nevertheless admission-ordered, high context bits preserved;
  all output reservations full, no premature owner release;
  stable offered packet under changing ready and unrelated admissions.

DRAIN/RESET:
  every work-holding location occupied at barrier request;
  one adapter ACK delayed independently;
  stale/invalid residual transport with zero live owners;
  existing owners allowed to finish issuing after new owners stop;
  no early reopen, distinct legal domain reset versus illegal partial reset;
  defined fault for never-ending bad traffic, never timeout-as-proof-of-drain.

FEATURE-LIVE:
  interleaved immutable bindings and configuration epochs;
  both CLUT4 nibbles, both byte parities, all direct formats and independent
  alpha, palette load/CRC/coverage/generation failures;
  real varying AUX envelopes/coordinates and Mosaic-dependent output;
  all material recipes, sample counts and status transport;
  exact warm-hit response-reservation loss regression.

13.3 Conservation after a normal completed drain
--------------------------------------------------------------------------

For each relevant identity and source class—not just summed colors—establish:

  admitted owners = externally emitted owners;
  required jobs actually issued = terminally resolved required jobs;
  accepted unique claims = payload writes = publications;
  ready reservations = actual COMBINE acceptances = completed owners;
  final claims = final writes = final_done publications;
  final reads reserved = produced final packets = emitted owners.

While running, transient pipeline differences are expected and must match
explicit ownership counts. A final aggregate equality alone can hide one lost
and one duplicated owner; compare complete token/value/status sequences too.

13.4 Mutations must fail the intended detector
--------------------------------------------------------------------------

Run each in a disposable isolated checkout and verify restoration by hash:
  external identity reduced to slot only;
  truncated membership distance / removed current-window recheck;
  removed recent-claim forwarding;
  publication one edge before actual write;
  last-writer update replacing same-row OR;
  omitted combine_reserved on candidate insertion;
  final authorized from bank-read reservation;
  candidate popped or F advanced without packet credit;
  pending read omitted from occupancy or !valid used as drained;
  owner freed at final write, prefetch or output-valid rather than transfer;
  namespace reopened without one producer's ACK;
  old global-binding, whole-byte CLUT4, RGB565-only, opaque-alpha or dead-
  nearest behavior restored; AUX/context conflated.

A compile failure is not a behavioral detector firing. A reachable intermediate
rounding case is not enough unless its wrong value affects an asserted output.
Record the named failing property and exact restored source. The original
briefs' Python witnesses are not this RTL mutation campaign.

13.5 Formal work with concrete limits
--------------------------------------------------------------------------

Prioritize queue conservation, output stability, C bounds, window equivalence,
phase-subset invariants, unique claims/publications, at-most-once candidates,
ordered fetch/release and no early namespace reuse. Covers should reach full
capacity, simultaneous publications and a pending read during drain.
Liveness assumes eventual downstream progress; do not prove a false unconditional
promise against a consumer allowed to stall forever.

15. IF THE NEXT OWNER OR ISLAND FIT STILL FAILS
==========================================================================

Do not commission another full rewrite from a headline alone. Ask which of
these independent gates failed:
  protocol/identity correctness;
  storage inference or port geometry;
  area/register/DSP allocation;
  setup versus hold/reset/interface timing;
  actual cycle throughput;
  feature-live composition or board-specific integration.

If the generation structure is gone but area barely changes, its dominance was
not established. Attribute holding queues, state selectors, decoder fanout,
diagnostics, fitter replication and wrapper. If interface cuts remove the old
worst path but another core path remains, diagnose that family; do not keep
calling it a virtual-pin artefact.

Keep an equivalent-scope improvement even if not sufficient. Label allocation
failure honestly. Consider the measured queue fallback, different local group
sizes, remaining-counter readiness, direct reserved COMBINE fill, or scheduled
control RAM only when each has a capacity/throughput account and a specific
remaining cost it addresses.

A whole-machine budget reallocation can be legitimate. It requires a complete
current inventory and an explicit owner decision about what reserve/subsystem
pays. It is not achieved by changing an alarm after the fit. Feature reduction,
precision changes, fewer owners, fewer samples, dead alpha/AUX/Mosaic or swallowed
errors are not default area optimizations.

The required report is not "all green" or "still too big." It is a balanced
comparison with the next falsifiable action. Avoid a new oversized architecture
manifesto when one missing attribution, assertion or pipeline boundary is the
actual next piece of work.

16. TIMING, ATTRIBUTION AND TOOLING DISCIPLINE
==========================================================================

Source basis: S01 §§18–20,24; S02 §§15–16,21; current timing reports. These
rules apply to texture now and terrain later. They do not authorize an
unbounded general-tool rewrite ahead of the next texture implementation.

16.1 Compare actual paths and actual scopes
--------------------------------------------------------------------------

Classify BOTH endpoints: sequential -> sequential, input -> sequential,
sequential -> output, input -> output. Include memory and DSP sequential
endpoints, reset recovery/removal, clock control and CDC correctly. In a
characterization wrapper also distinguish DUT-internal, DUT-to-DUT, synthetic
source/sink and wrapper-only paths. Hierarchical names alone do not prove
production-data-path ownership.

An output path with an internal start is not register-to-register core timing.
A constrained real interface cannot simply be ignored because the leaf uses
virtual pins. A registered wrapper is a useful comparison, with its registers,
latency and wiring counted. The production composition must time real neighbors.
A leaf fit is not a guaranteed upper or lower bound on its future composition.

After identifying a failing family, read its actual per-hop data/clock details
and the next failing families. A viewport fix does not fix row rescaling simply
because both are in project_core. A normal-product register cannot close a
pair limited by the tessellator. Counting source multiply expressions is useful
for hypotheses, not a physical-delay or fitted-DSP measurement.

16.2 A proposed cut is not its refitted delay
--------------------------------------------------------------------------

Dividing a saved path into 6.611 ns and 9.295 ns gives a candidate boundary;
it does not include every new clock-to-Q, setup, skew, uncertainty and placement
change. A DSP product register may map into hard resources, but this depends on
mode, width, enables, resets and synthesis. Verify actual register use. Do not
promise zero fabric cost from the existence of an internal DSP register.

Likewise, 28.080 ns divided into four average stages is not proof of four
balanced paths. Two ideal cuts give three stages in arithmetic; extra margin
may motivate more. Neither averages nor source helper names establish the
number of stages needed. Preserve ownership, then measure each candidate cut.

16.3 Complete timing acceptance
--------------------------------------------------------------------------

Archive setup, hold, TNS, recovery/removal and minimum pulse-width checks where
applicable, all relevant corners, clock relationships, input/output delay,
uncertainty, exceptions and unconstrained endpoints. Fitter success only means
a placement/routing result exists.

The original owner reports include negative hold at the stated slow corners;
that cannot be repaired simply by lowering the clock. Conversely, do not
manufacture hold success by deleting a real interface clock or false-pathing
ordinary data. A multicycle operation does not justify a multicycle exception
across pipeline registers that are still updated/captured each clock.

Use preselected seeds on a candidate and its comparable baseline when changes
are modest. Publish every result, worst/median/best and critical families.
Several MHz can be placement variation. Do not run until one favorable seed
lets a failed structure be described as closed.

16.4 Preserve the exact experiment
--------------------------------------------------------------------------

Manifest: top entity, full source closure and relative paths, all packages and
includes, ROM/MIF/HEX content, generated constants, parameter overrides,
QSF/SDC and their digests, exact Quartus version, FPGA part/speed grade, corners,
seed and optimization mode. A directory called snapshot is insufficient if
some QSF paths still reference live files outside it.

Keep full .fit.rpt, .fit.summary, MAP reports, full and summarized setup/hold
paths, messages, RAM/DSP/entity attribution, and the database needed for missing
queries. A nonempty binary/encoded report returning empty connector text is
not a physically empty report. A table's stale line number is not the variable
in today's source; match warned signal and fitted bytes first.

Status must distinguish infrastructure timeout, killed job, parser failure,
map failure, placement failure, resource-allocation failure and timing failure.
Keep the prior valid specimen and the new failed attempt separately. Neither
nulling the old row nor retaining only the last good row is honest history.

16.5 Tool sanity checks
--------------------------------------------------------------------------

A timing-path parser must bound one path before the next and distinguish clock
versus data sections. Count and sum hidden/sub-threshold hops. Reject impossible
attribution totals, missing clocks and ambiguous endpoint classes rather than
printing a flattering zero.

The recent path_anatomy bug crossed into the next path and reported more DSP
delay than the entire current path. Its correction is useful but does not prove
every aggregate now has the desired meaning. Recheck representative raw paths
by hand. Distinguish the sum of two DSP CELL hops from a larger multiplier-
associated category including other hops; do not compare them as one metric.

Resource tables must distinguish ALUTs/ALMs, MAP/FIT registers, logical memory
bits and physical M10K/MLAB capacity. A minimum-memory-bit gate can miss a lost
bank if another unrelated bank grows. Verify each named required store and its
useful ports, not only the aggregate.

16.6 Safe execution environment
--------------------------------------------------------------------------

Use one immutable fit workspace per run and separate mutation worktrees. Before
mutation ensure a complete recoverable source baseline; after it verify the
restored digest. Do not trust a zero-byte backup after disk exhaustion.
Supervise only the process tree belonging to the job being controlled; never
kill all Quartus jobs based on timestamps or executable name.

Check disk space and report-preservation capacity. Stop creating ignored raw
intermediates indefinitely. These are prerequisites to trustworthy measurements,
not excuses for a new unrelated cleanup project once the prerequisite is met.

--------------------------------------------------------------------------

and the TESS -> NORMALS seam at 156.79 MHz. Those are path-subset interpretations

An unchanged block's different placement can change its subset result. [E12]

The normal product register already exists. The mask rewrite was bit-correct

Read current sources and the saved closure before deciding a new experiment.

17.2 Terrain laws that must survive
--------------------------------------------------------------------------

One TESS job is one 8x8-cell subpatch of one surface inside a 32x32-cell patch.
Origins are multiples of eight in 0..24. Own and neighbor levels encode strides
1,2,4,8. Morph is nonnegative Q16 with a 17-bit field, clamped above 65536.
Mesh source IDs here are 16 bits, not a different 32-bit command ABI field.

Plain top triangles use the fixed diagonal and order:
  (i00,i11,i10), then (i00,i01,i11).
Underside swaps b and c BEFORE the normal calculation. Keep exact output order,
not only an equivalent undirected set. World X/Z comes from the actual lattice
response; do not replace it with a convenient unrelated origin calculation.

Stitching uses the coarser shared-edge stride, max(own,neighbor), and the existing
plain/inner/annulus enumeration. The annulus handles corners, including the
collapsed inner rectangle at own level 2 next to 3. A simplified pair of regular
square-cell triangles is not equivalent for stitched jobs. Preserve all 1,024
own/four-neighbor combinations and shared emitted edge vertex sets.

Dual pages scan the 64 cell states. Plain run-cells emit only if every covered
base cell is SOLID. A stitched job with any non-solid underlying cell is rejected
before emission. This is not "all coarse levels reject any void"; use the actual
j_stitch condition. Legacy pages are treated solid, can still have stitched tops,
and emit no legacy underside. Preserve empty/reject and clamp diagnostics.

Only strictly interior vertices geomorph. Shared boundary vertices keep their
lattice heights; independently moving them needs a different per-edge morph
contract. A vertex needs one own lattice read, or own+two parents when morphed.
Thus a triangle uses three to nine reads. Keep the public fixed one-cycle
request/response contract and distinguish issue, response and arithmetic finish.

17.3 Selected deferred architecture
--------------------------------------------------------------------------

  captured one-job state
    -> solidity scan and, only if justified, compact registered hierarchy
    -> existing plain/inner/annulus enumerator
    -> stable registered triangle descriptor / segment setup
    -> fixed-latency lattice request and tagged response front end
    -> TWO reserved triangle-assembly register banks
    -> ONE tagged registered geomorph pipeline writing those banks
    -> oldest completed bank -> registered triangle seam
    -> shared-product normal engine with measured operand/rescale boundaries
    -> stable ready/valid output.

Not three parallel morph multipliers, not six parallel normal multipliers, not
a giant world cache, new clock domain or a changed terrain rendering law.
Two assembly banks are the mechanism that allows arithmetic latency without
letting a late result overwrite a new triangle. A FIFO after the old pend_last
bypass does not by itself supply that ownership.

17.4 Exact tagged geomorph pipeline
--------------------------------------------------------------------------

Initially retain every existing helper's rounding and saturation boundary:

  M0 capture {h,ha,hb,morph,bank,slot} at the parent-B response.
  M1 d_ab = sign_extend(hb)-sign_extend(ha), registered signed 34.
  M2 half = sat32((d_ab+1) arithmetic_shift_right 1), registered.
  M3 hc = sat32(ha+half), with a wide signed sum, registered.
  M4 d = sign_extend(hc)-sign_extend(h), registered.
  M5 product = signed_nonnegative(morph)*d, registered 52-bit representation.
  M6 step = sat32((product+32768) arithmetic_shift_right 16), registered.
  M7 y = sat32(h+step), registered and committed to the tagged bank/slot.

These are conservative initial semantic boundaries, not a promise that each
helper automatically fits at 100 MHz or a mandate to ignore a measured cheaper
staging. If M6 remains critical, separate the rounded quotient and saturation.
Do not merge away observable intermediate arithmetic to save a register.

Carry bank/slot and valid through all stages. Carry only needed operands: parentA
dies after coarse-height construction, morph after multiply, original h after
final add. Do not transport nine coordinates through eight stages.

The internal pipeline can be nonstalling once every result has a reserved
bank destination. The completion interface must nevertheless permit the
simultaneous direct/morph writes described below. Do not infer an impossible
single-write RAM or gate arithmetic by downstream ready without capacity.

Remove the architectural dependency:
  parent B returns now -> complete m_y now -> emit final triangle now.
Last read issued/returned is no longer final vertex complete. Publish only
when all three final-ready bits exist in the owned bank, on a later edge than
the final write rather than recreating a combinational bypass.

17.5 Intermediate saturation is observable — two decisive counterexamples
--------------------------------------------------------------------------

Let MIN=-2147483648 and MAX=2147483647.

  ha=MIN, hb=MAX:
    rounded half-difference is 2147483648 before saturation;
    half saturates to MAX;
    hc=MIN+MAX=-1.
  A single rounded average of ha+hb would give 0, a different height.

  h=MIN, hc=MAX, morph=65536:
    the rounded morph delta saturates to MAX;
    final height=MIN+MAX=-1, NOT hc.

Therefore the blanket statement "full morph always equals coarse height" is
not true across the whole admitted height-word domain of the current staged
reference. Preserve current reference behavior during timing repair and record
the contract discrepancy separately. Do not quietly change the oracle and call
it an optimization. [S03 §8.3]

A mathematically exact rounding identity can shorten later arithmetic:
  (x+2^(k-1)) >>> k = (x >>> k) + bit_(k-1)(x),
under a sufficient signed intermediate width and the stated input range.
Carry guard and saturation tests still matter. An overflow-prone fixed-width
cast is not licensed by an unbounded-integer identity. Coarse interpolation
and morph multiplication have separate rounding points; do not combine them.

A difference of signed 32 heights needs 33 bits; later narrowing a 34-bit temporary
may be possible with proof. Morph 65536 must not be reinterpreted as negative
by casting its 17-bit field directly to signed; use explicit zero sign extension.

17.6 Two-bank ownership and simultaneous completion
--------------------------------------------------------------------------

Reserve a bank before the first request of its triangle. Keep only one triangle's
address-fetch sequence active initially while older morph computations may
finish into the other bank. If both are occupied, stop admitting new triangles,
not accepting an already-issued fixed-latency lattice response.

Two banks contain576 coordinate payload bits (2*3*3*32) before metadata, original
heights, temporary operands and valid/issue state. Count the complete real
representation, not only this coordinate subtotal.

Tag each delayed request with bank, vertex slot and read kind:
  own/no-morph -> write X/Y/Z and mark final-ready;
  own/morph -> capture X/Z/original h, but NOT final-ready;
  parentA -> retain matching height until the tuple is captured;
  parentB -> create independent M0 tuple; final-ready waits for M7.

A live parentA temporary may be reused only after the corresponding M0 capture.
Do not read current pend_slot, live j_morph or a subsequently overwritten parent
height several cycles later. The token must own all operands it still needs.

A direct nonmorphed response and an older morph completion can occur together.
Commit both with separate per-slot register writes and merged ready masks.
Assert two final writers never target the same bank/slot on one edge; that is
an ownership defect, not a priority choice. A later RAM implementation requires
actual ports or credited completion queues and a new physical comparison.

An unmorphed younger triangle can finish before an older morphed one. Only the
oldest allocated complete bank may publish. The registered seam holds 305 payload
bits: 288 coordinates+16 source+1 surface, plus validity. Release the assembly
bank only when the complete packet has transferred into that owned seam and no
requests/morph tokens can still write it. Hold the seam stable while stalled.

No generation field is necessary for two internal banks if they cannot be
released with outstanding writes. Prove that invariant rather than adding tags
to obscure premature reuse. Idle includes the active job, delayed request,
owned banks, every morph valid, seam packet and normal-engine/result ownership.

Reset clears that ownership/valid state. Payload clearing is unnecessary if no
stale value can become valid; an untagged post-reset physical RAM value is
ignored under the fixed-response contract. Preserve diagnostic reset behavior.
TESS's existing emission counter counts publication to its output register,
not downstream transfer; do not accidentally count both bank completion and
seam publication. NORMALS' counter likewise has its own publication event.

17.7 NORMALS: keep the existing product register and exact signed law
--------------------------------------------------------------------------

For triangle(a,b,c), retain signed 33-bit e1=b-a and e2=c-a. Six products are
signed 66-bit; their three differences are signed 67-bit:
  Nx=e1y*e2z-e1z*e2y;
  Ny=e1z*e2x-e1x*e2z;
  Nz=e1x*e2y-e1y*e2x.
Each output is sat32((N+32768)>>>16). The bias is positive for BOTH signs.
These are unnormalized face normals, not unit or averaged vertex normals.
Degeneracy is determined from the three rounded/saturated output lanes.

Retain ONE shared multiplier and its current m_p_q. If actual timing requires,
register selected operands before it and split rescale as a separate change.
Do not instantiate six multiply expressions in six case arms. Carry term tag
with each product; accumulator selection must not read the live issue counter.
Keep busy until the last product is CONSUMED. Preserve last-lane next-value
publication rather than publishing pre-edge acc2.

The current conservative source schedule was modeled with accept edges 0,9,18,
not the eight-cycle claim in a comment. Measure actual RTL edge events before
promising a replacement II. An operand stage may add another cycle. That can
be a good trade for frequency; it is not one triangle/cycle from six serialized
products.

Do not narrow full edge differences to 27 or 32 bits for DSP convenience or raw
cross products to 64 without a valid domain proof. Do not obtain the underside
by negating the ALREADY ROUNDED top normal:
  rescale16(+32768)=1; rescale16(-32768)=0; -rescale16(+32768)=-1.
Winding inversion or full-width negation must precede the rounding.

18.2 Rounding coverage is specific to stage and domain
--------------------------------------------------------------------------

The ROW rescale rounding hole in terrain projection tests was real and the
later directed cases made it observable. The viewport MAD rounding is a different
operation: even viewport dimensions make its low rounding bit unreachable,
while odd dimensions can reach it. An unobservable mutation in an even-only
fixture is not proof the full legal odd-viewport contract is unnecessary.

Do not delete required arithmetic because normal game viewports happen to be
even, or claim the row-stage gap disappeared because the MAD test was explained.
Any narrowing of legal viewport configurations needs an explicit contract and
whole-machine effect review, not an opportunistic optimization during texture.

The inspected zhao_terrain_cmd middle stage now exists: it accepts unpacked
fields, reads the sealed patch list, verifies CRC before acting, then streams
records. Its two-pass strategy assumes the verified bytes remain stable through
the emission pass; preserve that producer/staging ownership obligation.

That does not repair the separate shell framing/ABI seam. The documented framer
carries 16 payload bytes while SubmitTerrainSet requires 32; the middle-stage
module does not decode the lost command bytes. Distinguish a built component
from a completed command path. This is deferred system work unless a specific
texture integration test actually requires the same seam. [E16]
