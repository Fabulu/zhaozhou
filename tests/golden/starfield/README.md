# Starfield golden vectors (spec/stars_and_flares.md S7)

`oracle.bin` — 343 sectors (kx,ky,kz in [-3,3]^3), 5 little-endian int32
per sector: `temp_x, temp_y, temp_z, netpos, flags`. Generated by the
external harness `oracle.c` (a transliteration of Noctis IV's galaxy hash,
lifted from noctis-iv-lr `noctis-0.cpp` `sky()` which itself translates the
original DOS hand-encoded 386 code), and verified BYTE-IDENTICAL three ways
before import (C oracle vs Python vs the Linoctis JS port; `cmp` at import
on 2026-08-16).

Consumed by `tests/render/render_star.cpp` `starfield_harness_equivalence`:
`zref::sky::starfield(kx,ky,kz)` must reproduce every record byte-exactly
BEFORE any rendering test of the starfield runs (spec S7: "the ZRef
transliteration must match byte-exactly before anything renders").

The record for a sector whose `flags != 0` means "no star here" (a
coordinate hashed exactly onto the 50000 sentinel); the oracle still
reports the arithmetic so the fold chain is exercised on every sector.
