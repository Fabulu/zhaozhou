1.5 The rescue is not a clean-sheet console restart

The expensive pattern is replicated arithmetic and long-lived fabric state.
The useful existing blueprints are:

* Exact arithmetic reuse: normals, terrain LOD and geometry LOD already reduced
  parallel farms by using cycles that the workload could afford.
* Memory-backed descriptor/identity transport: the texture Decrufter replaces
  asynchronous indexed fabric payload with synchronous, atomic records.
* Direct-indexed projected-vertex arenas: reuse results rather than projecting
  every triangle corner again.
* Quarter-square ROM arithmetic: small exact lookup memories replace bounded
  products without reducing colour precision.
* Shared FIELD services: a provider is a physical engine; its callers are not
  independent copies of that engine.

The replacement programme keeps the numerical laws, identifiers, ordered
retirement, memory protocol, terrain topology, and existing oracles. It replaces
how much arithmetic exists simultaneously and where intermediate state lives.

2.1 Change the vocabulary before changing totals

Use these six distinct terms everywhere:

INVENTORY: every implementation/probe/version found in the source tree.
SELECTED DESIGN: one explicitly chosen implementation/profile per function,
                with explicit physical instance counts and shared providers.
CURRENT MEASUREMENT: bytes/configuration match the selected instance closure.
HISTORICAL MEASUREMENT: a real measurement of a different or unverified closure.
PROPOSED ALLOCATION: a resource ceiling or scenario for an unqualified candidate.
UNPRICED REQUIREMENT: intended functionality with no applicable measurement.

A partial selected-design subtotal is not a mathematical lower bound on the
final optimized console. A sum of isolated fits is not a guaranteed upper bound
either: composition can change mapping, replication, pruning, packing and glue.
Replace "upper and lower bound at once" with "partial mixed evidence; missing
costs and composition effects are separately disclosed" unless actual bounds

4. MEMORY FIRST DOES NOT MEAN MEMORY WITHOUT A PORT BUDGET
================================================================================

4.1 Hardware rules for every proposed store [V01,V02]

Use synchronous addressed reads, explicit enables, and clocked writes. Do not
asynchronously reset or bulk-clear payload arrays. Reset control and validity;
initialize payload-independent truth through a bounded scrub or a validated
fill-before-use protocol. Specify mixed-port read-during-write behaviour and
prove the design does not depend on undefined collisions. An inferred memory
that quietly gains a wide bypass mux is not the intended architecture.

M10K geometry is consequential. Examples of supported symmetric widths include
256x40 in simple-dual-port operation and 512x20 in true-dual-port operation.
True dual port does not provide 256x40 with two independent wide reads. A
512x16 table with two reads is a natural quarter-square shape; a 128x38 table
with one write and one read is a natural coefficient shape. The fitter, not
logical-bit division alone, decides physical count. [V01]

For each bank, publish this small table before RTL:

  owner; depth; physical stride; payload width; validity method;
  read port(s), write port(s), clocks and capture enable;
  collisions forbidden/forwarded/old-data; reply latency;
  output capacity reservation; copies; M10K mode; expected minimum blocks;
  refill/boot/wrap cost; bandwidth per accepted semantic transaction.

4.2 Put the right state in RAM

Good candidates: descriptor payloads, matrix/pose rows, immutable coefficients,
per-context operands/results, projected vertices, triangle planes, bulk
validity with a deterministic scrub, and long-latency identity-side records.

Keep tiny hot control in registers: valid/ready stage bits, small queue pointers,
current arithmetic accumulators and a few active operands. Moving an accumulator
updated every cycle into one RAM port can slow the machine without reducing much
area. Move the cold context bank, not necessarily the active working register.

Replace an asynchronous context-table selection with a scheduled memory read
and an atomic captured record. Do not retain the old table as a synthesizable
reference in the production profile. Evidence shadows belong in simulation or
an explicitly separate lab build, as the texture work has established.

4.3 Avoid an all-machine arithmetic crossbar

This brief proposes LOCAL service domains: projection, pose, skin/normal,
terrain maintenance, and FIELD. A single universal multiplier with arbitrary
clients would create long buses, arbitration, head-of-line blocking and new
ALM pressure. Share within a bounded domain whose rates and lifetimes can be
proved. Connect the domains through compact queued records, not a global
multiported operand file.

4.4 Memory budget is a portfolio decision

Prefer a small working set in M10K over a whole-frame arena. Keep large frame
records in the existing local-SDRAM geometry arena with burst access and a
bounded on-chip working set. Do not move every projected vertex of 256 patches
into BRAM just because one patch fits. Do not send quarter-square arithmetic
lookups to external SDRAM: their required random-port rate makes that the wrong
kind of memory.

Do not choose every maximum-throughput ROM replica option simultaneously. The
culler, attribute engine and vertex replay store have alternatives with different
port counts. The correct portfolio is the smallest set of replicas that meets
the measured combined calendar, with ALM and M10K reserve still present.


5. THE TRANSACTION LAW FOR EVERY REPLACEMENT
================================================================================

One accepted job has one immutable identity and one owner. All of the following
travel as one logical record, even when physically stored in several banks:

  source/client, slot, generation, semantic opcode/axis, epoch, operands,
  output destination, saturation/degenerate flags and terminal status.

An input is accepted only if its complete future output storage has been
reserved, including work already in arithmetic pipelines. A RAM read and the
metadata that identifies its result must use the same accepted enable. When
stalled, the entire visible reply holds stable. Count accept and retire at their
actual handshakes, not at offered valid. Zero-work, culled, disabled, saturated
and rejected jobs have explicit terminal events; they must release every credit
exactly once.

Generation mismatch is not a strategy for reusing an owner too soon. The owner
must remain live until all possible children have returned or been cancelled
under a protocol that makes late returns distinguishable. Epoch wrap and reset
must be deterministic; a small generation tag does not protect an indefinitely
late response after enough reuse cycles.

For a shared arithmetic service, scheduling must not depend on an unregistered
far-away ready signal crossing the whole device and entering a multiply carry
chain. Use local queue capacity and designed credits. A delayed ready requires
skid capacity or earlier credit reservation; blindly registering ready can admit
one job past the limit. Existing texture credit is already registered in the
inspected owner. Do not rediscover a fix that is present. [S07,S36]

Every packet supplies tests for: full output stall; accept and retire together;
owner reuse; reset with work in flight; configuration epoch turnover; duplicate
and stale replies; zero/disabled work; and arbitration under worst burst demand.
One passing aggregate count cannot detect A-data plus B-metadata.


6. A SMALL REUSABLE ARITHMETIC LIBRARY, NOT A NEW FRAMEWORK
================================================================================

The names below are proposed names. They are not claims that these modules are
already in the tree. Implement only the primitives used by accepted packets.
The companion Python checks exercise their integer algebra, not Quartus mapping.

6.1 Exact unsigned-byte product via quarter squares

  Q[n] = floor(n*n/4), n=0..511
  a*b  = Q[a+b] - Q[abs(a-b)], for unsigned a,b in0..255.

The two square arguments have equal parity, so truncating each quarter-square
cancels exactly. No approximation and no product-bit loss. Q[511]=65280 fits16
bits; products are at most65025. Store a fixed512x16 table and read both
addresses with the same request/identity. One true-dual-port M10K is the first
mapping candidate for one accepted product each clock. Two single-read replicas
are a fallback to price, not a hidden extra cost.

The ROM may be initialized by a frozen MIF or by a 512-cycle boot sequencer. If
boot-filled, ready stays false until every entry is valid. The MIF, generator,
contents hash and table version are part of the specimen. Never compute n*n in
a synthesizable per-read path and call it a ROM. A generated case statement is
not enough evidence of block-memory inference.

For signed d in[-255,255], use sign(d)*QPRODUCT(abs(d),b). Restore the sign at a
wide exact width BEFORE any rounding bias/arithmetic shift. Negative ties are
where a superficially correct refactor often fails.

Suggested contract: req_valid/ready, a,b,tag; rsp_valid/ready,p16,tag. Either use
a globally stallable small pipe or reserve output slots for every accepted
request. Keep address calculation, ROM outputs, subtraction and tag aligned.
Pipelining more than the old leaf latency is allowed only through the caller's
explicit new latency/credit contract.

6.2 Full-width multiplication from byte products: for LOW-RATE work

For unsigned32 a,b with bytes a_i,b_j:

  a*b = SUM(i,j=0..3) QPRODUCT(a_i,b_j) << (8*(i+j)).

Sixteen exact byte products through one ROM multiplier give a full64-bit
product. For a square, four diagonal products plus six distinct cross products
are enough; add the cross products with one extra left shift. Signed forms
must preserve INT_MIN by using a widened unsigned magnitude or a two's-complement
correction. Do not take abs(INT_MIN) in its original signed width.

This is appropriate for terrain-maintenance/LOD setup if the calendar admits
it. It is NOT a blanket replacement for per-pixel PERSPUV or FIELD. A 16-cycle
product is not equivalent throughput to a one-cycle product.

Use a fixed microstep schedule and a narrow active accumulator. Avoid a large
variable shifter and arbitrary crossbar to select every byte/product position;
the schedule's small opcode ROM or explicit phases already knows the shifts.
The ROM engine is meant to remove the large multiplier and its selection fabric,
not wrap them in a more expensive general processor.

6.3 Full s32 by epoch-constant s32 using ONE native DSP lane

This is the projection fast profile's central candidate. It does NOT narrow
matrices or world coordinates.

Split two signed32 numbers as:

  a = aL + 2^26*aH       aL unsigned26; aH signed6 = a >>>26
  b = bL + 2^26*bH       bL unsigned26; bH signed6 = b >>>26

Then exactly:

  a*b = aL*bL + 2^26 * (aL*bH + aH*b).

Use one 27x27 signed hard multiplier on zero-extended aL and bL. Implement the
26-by-signed6 cross term as an explicit small shift/add tree:

  aL*bH = SUM(j=0..4, bit_j(bH)) aL<<j - bit5(bH)*(aL<<5).

Precompute H[h]=signed6(h)*b for h=0..63 in one 64x38 coefficient RAM. The
negative extreme (-32)*INT_MIN is2^36, so38 signed bits are deliberately used.
For two views, 128x38 fits one simple-dual-port 256x40 slice. Two views
times two update generations occupy all 256 entries and can still fit that
one-slice geometry. Explicitly select {generation, view, coefficient_index}
in the address, and prove that reads never mix generations. More contexts,
status bits or incompatible memory controls change this bill; do not assume
that every extra epoch is either free or automatically a second memory.

Use a 39-bit signed cross-term sum and a 65-bit reconstruction before proving the
final result fits the exact64-bit signed product. The small low product is
unsigned52; sign-extension errors here can pass normal camera tests and fail
only negative extremes. The companion model sweeps corners and random full
signed32 operands.

Build coefficient entries with shifts/adds at configuration time, not64 parallel
multipliers. For h=0..31 start from zero and add b; for h=-32..-1 start at
-(b<<5) and add b. Configuration build progress, RAM version and enabled jobs
belong to one epoch. A coefficient cannot change while products from its old
version are in flight unless separate banks/versioned reads implement that.

Pipeline the small cross-term tree, native product, ROM output and exact final
adder. This is not permission to put the ROM subtraction and every carry chain
in one clock. MapOnly must show exactly one hard27x27 per accepted physical lane,
not accidental DSP inference for the signed6 term. Register reset/enable styles
must allow the native DSP registers to be used.

This identity is mathematical. Its ALM, timing and M10K mapping are unmeasured.
Compare it to the existing full-width product in a registered harness before
composing nine lanes. Reject an implementation that saves DSP by exploding ALM.

6.4 Exact product with a configuration coefficient using byte tables only

For a fixed coefficient k, precompute T[d]=k*d for d=0..255. Reconstruct a signed
word from its unsigned bytes, then subtract its sign correction at full width.
Examples:

  s32 x: x*k = SUM(i=0..3) T[byte_i(x)]<<(8*i)
                 - (x<0 ? k<<32 :0).

  s33 x: use the same four low bytes and subtract k<<32 when bit32 is1.

The table is finite because k is fixed for the configuration epoch, not because
x has fewer possible values. Four reads per product per clock require four
single-read copies, two TDP copies if width permits, or a scheduled multi-cycle
engine. Count width slices as well as read copies. This is useful for viewport
scale, vertex fog and fixed lighting coefficients, not for arbitrary coefficients
changing every cycle.

6.5 Distributed arithmetic for fixed-coefficient dot products

For signed W-bit inputs x_j and constant coefficients c_j, store:

  T[mask] = SUM(j whose mask bit is1) c_j.

The exact dot product is the weighted sum of T evaluated on each common bit
plane, with the top sign bit NEGATIVE. This replaces hard multipliers with tiny
coefficient tables and add/shift recurrences. Choose one-bit serial, multi-bit
folded or fully pipelined profiles according to measured demand. Replicas buy
read ports; they are not free.

Keep the full integer sum until the original operation's rescale/clamp point.
Reassociating exact additions is allowed at a proven sufficient width;
reassociating across saturation or rounding is not. Validate coefficient update
lifetime, negative top-bit contribution, all-zero mask, maximum mask and
concurrent reads from different records.

6.6 Exact divide-by-nine/eleven without hidden constant multipliers

Geometry LOD uses nonnegative constant divisions. A nibble long-division table
needs only the finite pair(remainder,nibble):

  qdigit,new_remainder = divmod(16*remainder + nibble, divisor).

For divisors9 and11 together there are(9+11)*16=320 useful entries, with four
bits each of quotient digit and remainder. One 512x16 table can hold both when
serially reused. A 35-bit nonnegative numerator uses nine nibble steps; a 40-bit
container uses ten. Ceil uses the original numerator adjustment, not a different
rounding convention. Zero and maximum inputs are tested exactly.

This is a targeted way to prevent a supposedly "one multiplier" LOD block from
hiding additional constant-divider multiplier logic. If the mapper already
implements those constants efficiently in fabric, count the measured delta and
keep the better version.

6.7 No universal rounding wrapper

Material unit8 multiplication uses round-half-up divided by256. Terrain bake
uses TWO round-half-up rescale stages on each absolute endpoint before
subtracting. Attribute division/stepping implements the source's half-away-from-
zero behaviour. Projection has its own signed quotient construction and final
screen quantization. These must remain distinct labelled arithmetic contracts.
A library that "standardizes" all of them to one pleasant rounding function
would change the game while claiming bit-exact optimization. [S23,S26,S27]

8. PROJECTION: REUSE RESULTS, THEN REPLACE TWO FAT CORES WITH ONE SERVICE
================================================================================

8.1 Why this is the largest architectural packet

Both geom_project and terrain_project instantiate the common project_core.
Recorded full-width instances cost33 DSP each. The terrain wrapper submits all
three corners of every triangle to the core again. At fine terrain LOD, the
same33x33 lattice has1,089 positions but2,048 triangles*3=6,144 corner references.
The existing WCACHE/vertex-arena blueprint addresses exactly this redundancy.
It has not yet replaced the live corner projection path in the inspected source.
[S13–S18]

Eliminating repeated projection can save arithmetic CAPACITY, not just memory
traffic. It is the prerequisite for safely choosing a folded arithmetic engine.
The current two projection instances also replicate exact divider pipelines and
long metadata transport. Removing a core can therefore relieve ALMs as well as
DSPs; it is not merely moving the multiplier cost into general logic.

8.2 FIRST repair the reusable arena's non-power-of-two layout defect

The inspected default vertex arena declares:

  mem[0:ARENAS*DEPTH-1]; valid_q[ARENAS*DEPTH-1:0]
  DEPTH=1089; ARENAS=2; IW=$clog2(DEPTH)=11
  wr_addr={arena,index}; rd_addr={arena,index}
  open clears valid_q[arena*DEPTH+i].

The allocated physical range is0..2177, but arena1's addresses start at 2048.
Arena1/index130 addresses2178, already beyond the array. Arena1/index1088
addresses3136. Open clearing uses1089-stride while read/write use2048-stride.
This is a deterministic source-level mismatch, not an ALM prediction. The
existing directed suite usesDEPTH=16, so that test profile cannot expose it.
[S17,S18]

Choose ONE physical layout consistently:

  A. linear arena*DEPTH+index, sized for the complete allocation; or
  B. physically padded arena stride2^IW everywhere, including validity; or
  C. separate per-arena memories with local indices.

Option A is attractive for co-packing small working sets; option C can simplify
ping-pong/dual-view port ownership. Do not pad the
payload silently and quote the old bit count. First write a failing RTL test at
DEPTH=1089 with both arenas, including indices0,129,130,1088, reopen/clear,
concurrent independent accesses and boundary refusal. AddDEPTH=17/ARENAS=3 as a
second non-power-of-two case. Reintroducing concatenated indexing into an
unpadded implementation must make the test fail.

This review's Python counterexample establishes the address arithmetic. It does
not substitute for the agent's required RTL reproduction and regression run.

8.3 Store sufficient results and give them a real lifetime

The existing WCACHE payload is75 bits: two 21-bit screen coordinates,32-bit
legacy invw and behind1. The live depth/fog path also needs guarded clip.w31.
A minimal backward-compatible cache record is therefore at least106 bits before
additional status/epoch fields. Do not round this down by dropping the very
value canonical invw24/fogfactor need. Decide whether to store canonicaldepth
instead of legacy invw only after proving all consumers and adapters.

Cache identity must freeze: patch/page generation, top/underside surface,
vertex identity, field/deformation version, final morph state, camera/view,
viewport and depth-profile epoch. A lattice index alone is not a key if the
same index can be morphed differently in two jobs. Material/recipe/source
identity belongs to triangle/fragment records; do not make a vertex cache return
one triangle's material to all triangles sharing that vertex.

No associative cache is needed where the tessellator already supplies a bounded
vertex identity. Start with a direct-indexed working arena. Use accepted fills,
seal/drain, explicit invalidation and epoch retirement. Replace thousands of
resettable valid flops with a RAM valid/tag scheme only if reset/open/wrap starts
with a deterministic scrub, or a proved dense-fill/sealed-prefix contract.
Uninitialized tag RAM matching a generation by chance is unacceptable.

8.4 The read-port cost can be more important than the payload bit count

A cached triangle still needs three result reads. One read each clock leaves
6,144 lookup cycles per fine patch, even if only 1,089 expensive projections were
done. At 256 patches that is 1,572,864 read cycles, before geometry and stalls.
Caching is not a three-port memory for free.

The preferred small-working-set layout is THREE simple-dual-port read copies.
Broadcast each accepted fill to all three copies; each copy supplies one corner
lookup. A read and a write can occur together in each copy, so the design can
sustain three corner reads plus one broadcast fill per clock, provided reads
address a sealed working group and writes address a different unsealed group.
This avoids undefined same-address read/write collisions without a wide bypass.

Two true-dual-port copies are another option when fill and replay are separated:
they provide four total ports, enough for three reads while sealed, but a
broadcast fill consumes two of those ports. Do not claim three simultaneous
reads plus unrestricted broadcast writes from that layout. Banked memories
without replication are also possible, but EVERY stitch/LOD conflict needs an
explicitly budgeted replay rule, not a regular-grid assumption.

8.5 Whole-patch versus subpatch working sets

Whole-patch minimum-work profile:
 1,089 entries/view. A uniform 2Kx5 TDP layout for a 106-bit record uses 22 width
 slices per replica. That is a CONSERVATIVE LAYOUT, not the minimum: separating
 the first 1,024 rows (11 x 1Kx10 blocks) from the last 65 (6 x 512x20 blocks)
 gives a 17-block candidate, or three 512-row banks give an 18-block candidate.
 The extra address/bank muxes and their timing must be priced. Two replicas and
 two views therefore cost 68--88 M10Ks before ping-pong at those candidate
 geometries, before extra identity bits; unrestricted concurrent fill needs a
 different port allocation. Dividing logical bits by 10,240 alone is inadequate.

Preferred small-working-set profile:
 A 9x9 subpatch catalogue has 81 entries if the actual final-vertex identity
 remains within that catalogue. Co-pack two views and two ping-pong groups as
 4 x 81 = 324 rows in EACH of three simple-dual-port read copies. A 106-bit
 projection result plus one 8-bit generation and one valid bit is 115 bits;
 six 512x20 blocks provide a 120-bit row. Therefore:

   324 rows x 115 useful bits, rounded to 512x120, x 3 read copies
   = 6 M10Ks/copy x 3 = 18 M10Ks TOTAL in this proposed geometry.

 Address every copy with ((ping*2 + view)*81 + local_index), range-checked and
 width-proven. Do NOT concatenate the logical fields into an unpadded array.
 Broadcast accepted payload AND tag/valid updates to all copies. Fill targets
 the inactive group; replay targets the sealed group. Bank turnover waits for
 all outstanding reads and their consumers, not merely the last fill.

 This 18-block figure includes the three read ports and two-view ping-pong.
 It is a layout derivation, not a Quartus measurement. Additional per-vertex
 status can grow the record beyond 120 bits; then account another width slice
 per copy. Per-group origins/camera descriptors stay in separate small control
 storage. Tag validity still requires a deterministic scrub or dense-fill
 proof; an eight-bit tag does not solve reset or indefinite stale replies.

 A separately banked two-TDP-copy arrangement costs 48 blocks at the earlier
 straightforward geometry (6 slices x 2 copies x 2 views x 2 groups). Keep it as
 a locality/port-scheduling fallback, not the preferred memory budget. The
 co-packed 18-block design is why small working sets deserve deliberate layout
 design rather than a payload-bit estimate followed by accidental replication.

The 81-entry bound is an OBLIGATION to prove over the tessellator's stitch,
coarse-parent/morph and surface cases, not permission to ignore a vertex outside
it. Expand the catalogue or use explicit spill/refusal handling if necessary.
Existing queued terrain rearchitecture remains authoritative for topology.

At 16 subpatches/patch this profile performs at most1,296 distinct catalogue
projections/patch/view, versus1,089 for a whole-patch cache and6,144 uncached
corner projections. A canonical final-position key is essential: two outputs
with the same local lattice index but different morph results cannot alias.

8.7 BackendA: three full-width DSP products reused over the rows

Use THREE full s32xs32 product lanes, cost target9 DSP total. For each vertex,
compute rowX, rowY and rowW in three issue clocks. Preserve the full accumulator,
translation term, one rescale16 and saturation exactly. Pipeline product and

not three plus a restart bubble for every vertex.

Replace the two cores' six divide lanes with ONE exact quotient pipeline accepting

The 31-step recurrence is already in project_core. Carry{owner,axis,sign,flags},

Do NOT substitute an approximate reciprocal because it is easier to share.
Preserve denominator guards, signed quotient construction, saturation detection,
behind results and final quantization. The core currently emits behind-eye

8.8 BackendB: full-width one-vertex/clock at the same nine-DSP target

one per matrix product, rather than restoring two 33-DSP cores. Each lane uses

One set of three exact quotient pipelines then accepts X,Y,W concurrently.

9. POSE DECODE: ONE ARITHMETIC WORKER, RAM MATRICES, EXACT RESULTS
================================================================================

9.1 What already exists [S19]

The pose decoder shares one matrix engine between parent*local and
absolute*inverse-rest, but that matrix engine still computes three full32x32
products per output element. The quaternion converter has nine 16x16 product
sites. The decoder's18-DSP map is supported by source identity, not merely an
ancient comment. Do not assume the quaternion's theoretical submultiplier
packing happened because a source header estimated it.

9.2 Replacement shape, target3 DSP

One pipelined full32x32->64 product service can execute BOTH quaternion terms
and affine matrix products. Small signed16 operands are sign-extended explicitly
for quaternion work; there is no need for a separate hard multiplier bank.
A microstep record names bone, matrix operation, output element, product term,
operand addresses and accumulator destination. It is a bounded local sequencer,
not a programmable console-wide ALU.

Store ancestor matrices, inverse-rest rows, current local/absolute matrices and
result palettes in synchronous RAM. Keep only the current operands and one or
few active full-width accumulators in registers. One output element sums its
three products plus the translation term before the existing rescale16/saturate.
Do not round each product. Keep parent-before-child ordering and the original
quaternion nine-product formulas/shift11 rounding; quaternion normalization is
not introduced. Root displacement and rest translation retain their old stage.

One bone may need nine quaternion products plus up to 72 matrix products before
simple identity/root shortcuts. At one issued product/clock the arithmetic floor
is81 clocks/bone; read scheduling, pipeline drain and output stalls add overhead.
A 32-bone palette therefore is not promised in the old~1,600 clocks. Measure actual
palettes-per-frame CACHE MISSES, not visible creature instances. The existing
pose-cache design intentionally shares a decoded pose across suitable instances.
Cold-start and clip transitions are part of the demand, not optional tests.

A recognized identity/translation inverse-rest matrix can use an exact fast
path, but the generic input port accepts a full matrix. Either check the actual
matrix shape at runtime with a generic fallback, or prove and enforce the asset
contract. Do not silently discard non-identity inverse-rest rotations.

9.3 Qualification

Compare complete palette bytes for all bones, maximum bone count, root motion,
negative half ties, saturation, concurrent cache lookups, parent indices,
pose-epoch change and mid-decode reset. Schedule cold miss bursts against the
full-frame skin/lighting workload. Target3 DSP is conditional on that deadline.
A 6-DSP two-worker fallback is a disclosed additional three-DSP allocation, not
a reason to hide the overrun; recover it from another priced lever if needed.


10. POSITION SKIN AND WORLD NORMALS: JOINT INPUT FETCH, SEPARATE CLEAN ENGINES
================================================================================

10.1 Do NOT set MUL_LANES=1 and call it solved

Current GEOM.SKIN admits lane counts1,3,6, not2. The measured one-lane alternative
is not a new two-lane architecture and its latency/throughput is not suitable
for the current120,000-vertex frame figure. The default three-lane implementation
uses9 DSP and its full blended case is documented at 12 clocks/vertex.120,000*12
is1.44Mclocks, already outside a 20%-reserved1.333M window. [S21,S13]

A two-lane target is a NEW schedule with overlapping records, not a parameter
flip. It should cost6 DSP for two full32x32 products and issue the 18 products of
a two-bone position transform in nine clocks. Pipeline the accumulation/weight
finish and overlap the next record so restart/drain bubbles do not turn9 into
15. The gate is measured initiation interval <=11 on the mandatory workload,
not a nine-product-issue diagram.

10.2 Put the palette at the front, not in every context

A compact skin job carries vertex, two bone handles, pose epoch, weights, source
and output reservation. Read the two bones' rows from one palette owner and
broadcast the same coefficient fetch to position and normal transforms when
appropriate. Do not copy two 12x32 matrices into every queued vertex in two
separate blocks. Keep a small row window in registers; keep the palette and
waiting context payload in RAM.

Budget the read schedule: two product operands per clock may need two coefficient
reads, while packed normal transformation can consume the same coefficients.
A row-wide read is not an unlimited multiport memory. Give the row cache/banks
explicit widths, phases and conflict rules. Repeat a row fetch only when that
is cheaper than an extra permanently replicated memory port and the calendar
allows it.

This does not mean bolting world-normal math onto the current position-skin
critical path. It means an input-side shared fetch followed by distinct pipelined
workers and a source-tagged completion join. The existing position block stays
the oracle while the new pair is qualified.

10.3 Expose the world-normal arithmetic's real widths [S20]

For legal weight0 in0..64, each row dot combines three signed32 matrix entries
with signed8 packed-normal components. Its magnitude is bounded by3*2^38,
so a signed41-bit row dot is sufficient. The weighted blend of two row dots has
magnitude <=64*3*2^38, so signed47 bits suffice over that legal domain. Prove the
bound in the source and test it at extremes; do not merely slice a 64-bit value
and hope. If the existing accepted domain includes other weight bit patterns,
retain their defined behaviour with a larger proven width or existing rejection
protocol. This is a range proof, not authorization to change legal weights.

The current source expresses three squares on64-bit direction registers after
a separate reduction state. The synthesis tool need not prove that dynamic
invariant before sizing a product. Once the guard has established every
abs(direction)<2^30, explicitly capture signed31-bit reduced components and
square their unsigned30-bit magnitudes. Do not leave the width proof implicit
in an earlier FSM state and then infer a 64x64 multiplier. The output can be
sign-extended back to its existing64-bit port without storing64 bits per lane.

10.4 Zero-DSP matrix-by-packed-normal products

A signed32 matrix coefficient times a signed8 normal component can be assembled
from four unsigned-byte products plus exact sign correction. Two concurrent
32x8 product lanes use eight quarter-square ROM lanes; they process18 matrix
terms in nine issue clocks. Target hard-DSP cost of that transform: zero.

For legal complementary weights, compute the exact blend as:

  64*dotB + weight0*(dotA-dotB).

Use explicit small-width shift/add for the seven-bit weight rather than a wide
implicit64x64 product. Preserve the unrounded direction. Position finishing has
its own rescale/rounding; normal finishing deliberately does not make a unit
vector, because the eventual Lambert quotient owns the only normalization
rounding.

10.5 One small DSP for exact squared magnitude

Split each unsigned30-bit reduced magnitude m into15-bit L,H:

  m*m = L*L + (2*L*H <<15) + (H*H <<30).

One native small product lane reused over three terms per component computes
three component squares in nine issue clocks. Keep the sum wide enough for
3*(2^30-1)^2, then feed the exact existing integer-square-root law. Target one
physical DSP, with all results and sign/degenerate metadata reserved by vertex.
The map must confirm that the lane was reused instead of replicated by three
function calls.

10.6 The root latency must be hidden, not hand-waved

A single32-step nonpipelined root cannot serve a new vertex every9–11 clocks.
Use a separately counted bank of exact roots or a qualified pipelined/folded
exact root. As an initial schedule, four roots can cover a service interval of
nine only if measured complete turnaround including handshakes is <=36 clocks.
If it is longer, add capacity or revise the schedule explicitly. These roots
consume ALM/context storage even when they consume zeroDSP.

Do not steal FIELD's root capacity because the module name is shared. That
engine already has a constrained program deadline. Share only through a tested
provider calendar that includes both workloads, otherwise keep local workers.

10.7 Faster range reduction without changing negative values

The existing normal FSM repeatedly arithmetic-shifts all components together.
An equivalent candidate uses a leading-magnitude count to choose
k=max(0,bit_length(maxabs)-30), shifts all lanes byk, and then applies ONE extra
shift if the maximum absolute shifted value is still >=2^30. That correction
matters for negative values because arithmetic shift rounds toward minus
infinity. A simple leading-zero formula without the correction is wrong near
negative power-of-two boundaries.

Preserve the counter's meaning: the inspected reduced_o increments per reduction
step, not literally once per vertex despite its description. Decide/document
semantic counters deliberately. Keep reduced vectors, magnitude and source
identity paired. The Python model compares the candidate reduction to repeated
shifting, including the negative-boundary counterexample.

10.8 Acceptance

Complete position and normal results must match the current ratified reference
on legal extremes, cancellation to zero, negative ties, full weight endpoints,
zero normals, two-bone mixtures, pose changes, saturation and arbitrary output
stall. Compare the combined pipe under 120,000-vertex and actual Duo/light
profiles. Target position6 DSP + normal1 DSP is an allocation, not yet a map.
Reject a design that saves two DSP but adds an uncontrolled multiported palette
or roots/context machinery that worsens the whole ALM budget.


11. CULLING: MOVE FRAME-CONSTANT PLANE MATH INTO COEFFICIENT RAM
================================================================================

11.1 Preserve conservative visibility, including exact ceiling roots

Current GEOM.CULL derives five frustum planes from the two stored view matrices,
computes plane-normal length ceilings on configuration, and tests an instance's
sphere against active views. Plane components need33 signed bits. The radius
multiplies an unsigned length ceiling. Rounding a ceiling down can incorrectly
remove visible geometry. Row2/far-Z semantics must not be invented. [S22]

The old workload row does not reliably distinguish one plane test from one
instance across views. Do not serialize by ten based on that number. First
instrument accepted instances, active views, planes tested/early-outs and actual
configuration traffic. Meanwhile use the throughput-preserving zero-DSP
candidate below as the architectural reference.

11.2 Exact four-input distributed dot

For a selected plane store16 sums of the four coefficients(px,py,pz,lenceil):

  T[mask] = selected sum of(px,py,pz,lenceil).

Process bit planes of(center_x,center_y,center_z,radius). The result reconstructs
px*x+py*y+pz*z+radius*lenceil exactly; add the original plane translation term
at its original scale and apply the original comparison. Keep signed inputs,
unsigned positive length represented in a sufficiently wide signed table and
the negative top-bit contribution. A 37-bit table entry is a conservative
container for the selected sums here; prove final68-bit comparison sufficiency
against the existing source.

Five planes*two views*16masks=160 entries. A 160x37 one-write/one-read table fits
a candidate256x40SDP slice. Initialize tables at configuration using additions,
not a multiplier bank. Coefficient extraction and length calculation happen once
per view configuration, not per instance.

11.3 Two physical profiles

Folded profile: eight table reads in parallel and four byte steps per32-bit dot.
Eight read copies give an eight-M10K coefficient budget per epoch. This spends
four issue phases per plane; use it only if the measured instance deadline allows.

Pipeline profile: four stages, each handling an eight-bit group with eight
independent coefficient reads.32read copies, hence32 M10K in the first SDP
mapping. The top group includes the negative sign-bit contribution. With staged
weighted additions it can accept one plane job/clock, matching the current
plane cadence without assuming spare rate. Carry one compact instance/plane
identity through it. More pipeline registers may be needed for 100MHz.

Table replicas buy ports and preserve bandwidth; they do not require separately
computed coefficient sets. Broadcast configuration writes into all replicas,
with a double-buffer/dirty epoch rule that prevents a live instance seeing a mix
of two camera matrices. The wider field/register old matrix forest can move to
RAM because configuration/preparation is not the per-instance hot path.

11.4 Configuration squares without permanent DSPs

A bit-serial exact square accumulator or the byte-product primitive can compute
plane-length squares during configuration. Keep the existing exact integer-root
recurrence and ceiling correction. Configuration work is rare, but still has a
ready/dirty deadline: publish measured complete setup latency and do not admit
instances against partially prepared planes.

Target runtime/config hardDSP count: zero. This is NOT a measured replacement
for the current15. Its table replication and adder trees must beat the selected
ALM/memory portfolio; a zero-DSP culler that makes the FPGA overflow ALMs fails.
The unchanged conservative-cull oracle, on-frustum tangency, extreme matrices,
two-view disagreement and configuration races are mandatory tests.


12. ATTRIBUTE PLANES AND SEEDS: THE HIDDEN FARMS MUST NOT BE OMITTED
================================================================================

12.1 Do not let "adds per pixel" hide setup multipliers [S25–S27]

GEOM.ATTRSETUP calculates three edge constants at the coordinate origin and then
three coefficient-weighted sums for N0,dNdx,dNdy. Its current implementation
performs all those products together for each requested attribute. Its readiness
also has a response bubble; it is not automatically a one-attribute/clock
throughput implementation just because its expressions are combinational.

RASTER.ATTRINTERP and ATTRSTEP both seed a tile with:

  N0 + dNdx*tile_x + dNdy*tile_y + dNdx/2 + dNdy/2.

Those wide tile-start products are not removed by the later add-only pixel walk.
Count the selected path, not both the old divider-per-pixel path and its
replacement, unless they really coexist as selected hardware.

12.2 Compute the geometric coefficients once per triangle

The winding-normalized screen vertices determine w0(0),w1(0),w2(0), and six
coordinate differences. That work is common to every colour, UV, depth, fog and
emission attribute. Store a triangle geometry descriptor in RAM and reuse it.
Where GEOM.SETUP already has equivalent edge coefficients, consume them through
an exact checked adapter instead of calculating the same six products again.
Do NOT use top-left coverage bias in attribute weights: raster acceptance bias
and the mathematical interpolation numerator are different quantities.

The source's wide containers may contain provable sign-extension redundancy,
but arbitrary truncation is forbidden. Keep current external widths initially;
use a proved compact internal representation and exact sign extension at seams.

12.3 Coefficient tables calculate all three planes without DSPs

For each triangle build eight entries indexed by a three-bit attribute mask:

  TN0[mask] = sum of selected(w0(0),w1(0),w2(0))
  TX [mask] = sum of selected(-dyBC,-dyCA,-dyAB)
  TY [mask] = sum of selected(dxBC,dxCA,dxAB).

For every bit position of(va,vb,vc), the three tables contribute to the three
plane sums. The sign bit contributes negatively. After reconstruction, shift
TX/TY results by the existing PIXEL_SHIFT8. No intermediate rounding. The
original48-or-smaller edge-sum and24-bit gradient-sum containers produce a
conservative96-bit combined table record; validate the exact bounds with the
current coordinate contract before changing a width.

A table build uses additions and stored geometric coefficients. It is not
another hidden multiplier bank. Count the shared GEOM.SETUP coefficient
provider once, with the extra table-build work in its schedule.

Profiles, all exact and all initially proposed:

  Serial bit-plane: one table read/clock,32 steps/attribute. About three
   256x40SDP slices for the 96-bit record. For genuinely sparse setup demand.
  Four-bit folded: four independent table reads/clock,8 steps/attribute.
   Four read copies*three width slices =12 M10K first candidate.
  Fully pipelined: eight such bit groups,32 total read copies.96 M10K first
   candidate, one attribute/clock once the pipe is filled.

The last profile is expensive in memory, not magic. Two triangle-table epochs
can fit in the shallow logical depth, but writes, live pipeline readers and
per-triangle fill/drain still require a proved bank/version schedule. An
unbounded context table would increase physical depth and may double width
slices; do not quote the two-epoch count for 64live triangle tables.

Use the smallest profile that meets measured(attributes*triangles) demand,
including fog/emission lanes and thin-triangle bursts. The 1,089-vs6,144 projection
saving does NOT eliminate per-triangle attribute setup. At the maximum synthetic
all-fine-patches count, seven attributes per triangle alone can exceed a nominal
frame issue budget; a workload/capacity conflict must be exposed, not solved by
pretending all triangles have flat attributes or secretly lowering detail.

12.4 Exact tile seeds without hard multipliers

First reuse plane seeds as the SAME triangle advances through adjacent tiles:
adding16*dNdx or16*dNdy is a shift/add. This is legal only with a known triangle
identity and known tile offset; never inherit the previous triangle's seed.
Keep a per-active-triangle checkpoint in RAM and a compact last-tile key.

For arbitrary tile starts, multiply the two signed12-bit tile coordinates by
the fixed gradients with an explicit signed-bit recurrence. A single96-bit
accumulator over 12 bit positions computes both products through table sums of
{0,dNdx,dNdy,dNdx+dNdy}; the top bit is negative. This costs zeroDSP and replaces
two wide operators. A four-bit-group version reduces it to three steps by
replicating the small coefficient table/adder network. Preserve the two half-
pixel terms exactly; the gradients' multiple-of 256 property must be checked at
its producer, not assumed from a stale comment.

All cold plane and row-seed records live in RAM. Keep the current active
96-bit pixel accumulator in registers. Moving an accumulator to a single-port
RAM without a recurrence schedule would add bubbles rather than cure ALM use.

12.5 Keep the quotient/remainder stepping blueprint

ATTRSTEP already avoids dividing every pixel by seeding rows and stepping the
Euclidean quotient/remainder pair. Preserve negative-region handling, zero
crossing reseed, covered-pixel order and the original half-away-from-zero law.
Do not put a second per-pixel divider next to it as a permanent production
checker. Its old path is an oracle/fallback configuration, not an extra default
physical datapath.

Share a bounded seed-divider service across attributes only after testing row
bursts and sign crossings. Context RAM must store each row's exact sign/step/
remainder/area identity. More attributes are more work, even when not more
physical divider lanes. The emitted colour/fog/emission lanes must retain their
own source ordering.

Acceptance: complete numerator-plane equivalence over full legal vertices and
attributes, exact pixel-centre sampling, all negative tie cases, degenerate and
clipped triangles, sign crossings, every semantic attribute and realistic tile
order. Then measure setup+seed+step together. This packet has a zero-DSP target
but must not turn the remaining memory/ALM budget into a new crisis.


13. TERRAIN MAINTENANCE: SEPARABLE TABLES AND REUSED EXACT ARITHMETIC
================================================================================

13.1 Normals: credit the existing saving and preserve the existing queued brief

Normals already uses one shared33x33 multiplier. Do not rewrite it back into six
products or advertise eighteen-to-three as new work. Its current visible-triangle
throughput must be reconciled with TESS: the 2,000normals/frame workload concerns
deformation update activity and is not proof that a face-normal stage attached
to every emitted triangle needs only2,000 evaluations. [S06,S13,S35]

Keep the terrain rearchitecture document already delivered on main as the
specific topology/timing plan. It covers annulus stitching, all neighbouring-LOD
combinations, void/underside handling and a normal-product pipeline cut. This
brief supplies its resource-accounting and memory-first context, not permission
to replace its topology with a regular-grid shortcut.

If normals must run for every visible triangle, consider caching/reusing
unchanged face results under a complete deformation/morph/surface key, or a
faster shared arithmetic schedule. Do not derive a height-gradient normal that
changes the flat-face cross-product/rounding law just to save multipliers.

13.2 Bake's largest improvement is work elimination, not narrower coordinates

The current bake places a 33x33 lattice, computes dx²+dz² at each vertex and
applies a stencil followed by an exact two-endpoint delta. Its X coordinate
only depends on column and its Z coordinate only on row. [S23,S24]

For one immutable stamp/patch command:

  generate33 placed X coordinates and store(dx_i)²;
  generate33 placed Z coordinates and store(dz_j)²;
  evaluate d² at vertex(i,j) with X2[i]+Z2[j].

That replaces2*1089 distance-square evaluations with 66 plus RAM reads. Each
coordinate difference remains exact signed33 after reproducing the original
placed-coordinate wrap. Each square is unsigned66; their sum is67. Two 33x66
stores use four 256x40SDP slices in the first mapping. Captured command epoch,
column/row and stencil state must stay paired with their read results.

Reuse one full-width three-DSP product engine for the 66square preparations,
radius square and the two absolute endpoint products where its scheduling
allows. Do not instantiate a separate multiplier inside a table-fill helper.
Target entire bake hard-arithmetic allocation:3 DSP, not a guaranteed17-to-three
measured result; the 17 is historical evidence.

13.3 Remove lattice-coordinate multiplies with an exact DDA

The source computes a+trunc(((b-a)*i+16)/32) and wraps the final result to 32 bits.
For negative spans, arithmetic right shift is not C++ truncation toward zero.
Use Euclidean division span=32*q+r,0<=r<32. Maintain quotient/remainder of
N_i=span*i+16, starting atN_0=16. On increment:

  quotient +=q; remainder +=r;
  if remainder>=32: remainder-=32; quotient++.

Convert floor to truncation by adding one only when N_i<0 and remainder!=0.
Then add a and perform the original32-bit wrapping narrow. This handles inverted
extents exactly. A naive floor-shift implementation fails those cases. Generate
all33 positions once; do not rebuild the multiplier through an unrelated helper.

13.4 Do NOT simplify the bake delta incorrectly

The current law is:

  g(depth)=rescale_s32(rescale_s32(depth*stencil,16),8)
  delta=g(from)-g(to).

It is NOT rescale((from-to)*stencil,24). The absolute endpoint form telescopes
across deferred updates; the difference form accumulates different rounding.
Keep both rounds and each endpoint's defined rail behaviour even when the two
products share one engine. The companion check demonstrates a counterexample
to the tempting fused/difference forms. [S23]

Preserve no_bake corner protection, breach/heal state, radius rejection,
zero-radius behaviour, patch budgets and FIFO deferral. The meets plane is
1,089 bits of stored results: give it synchronous bit/row RAM with an explicit
four-corner read schedule rather than defaulting to 1,089resettable flops.
The breach phase can use two adjacent row reads and a sliding two-bit window;
it does not need four independently addressed whole-memory read ports.

13.5 Count the actual deadline, especially the divider

A 64-patch admission budget is not proof that64complete bakes fit the same frame.
The stencil divider still has a per-vertex cost after squares are cached. Measure
worst command completion and allowed deferral at the required frame boundary.
Use a bounded interleaved exact divider if the existing serial one limits the
required service. Do not claim a square optimization fixes a divide bottleneck.

A further zero-DSP bake profile can use byte products or precomputed absolute-
depth coefficient tables. It is eligible only when the complete schedule wins.
A tree of large ROM lookup adders that consumes the ALMs saved elsewhere is not
a success.

13.6 Terrain LOD: zero-DSP byte products are a credible candidate

The current terrain LOD already sequences six distance squares and eight ladder
products per descriptor through one unsigned32-bit multiplier. It keeps two
exact roots and combines both cameras by the finer decision. [S31]

Use one quarter-square byte engine: a 32-bit square needs10distinct byte
partials, a 24x16 ladder product six, a 32x16 relaxed RHS eight. Six squares
consume60product slots; six left sides36; two right sides16:112byte-product
slots, plus root32 steps and control/handshake overhead. A simpler generic bound
of 14 products*16slots+32=256core clocks/descriptor is useful as a conservative
starting schedule, NOT a measured latency.

At 256 patches*16 subpatches*256 clocks this is1,048,576core clocks. That is within a
1.333Mreserved window before additional stalls, so this is worth implementing
and measuring, unlike blind serialization of the already-constrained FIELD
engine. Preserve all strict/relaxed comparisons, hysteresis, minimum hold,
non-monotonic deviations, both-view choice and geomorph outputs. Store waiting
histories and operands in the owner’s existing memory, not a duplicate array.

13.7 Geometry LOD: remove hidden constant arithmetic before widening a farm

The existing six-DSP block already shares its five main products. Keep that
reuse. Explicitly prove the widths of proj/error/boundary products and price
one native full-width product engine, target3 DSP. Divisions by9 and11 can use
section6.6 if they are spending additional DSPs or large combinational logic.
Do not infer a free saving solely from one multiply statement: its two constant
dividers and operand widths must be mapped. Preserve e==0 rules and exact
coarsen/refine inequalities. [S32]

A shared geometry/terrain maintenance worker is optional, not the default.
Only combine them when the full calendars—including bake bursts—fit one
provider and local arbitration does not create a new long critical route.


14. LIGHTING, FOG AND NORMAL DETAIL: REQUIRED COSTS, NOT OPTIONAL BLANK ROWS
================================================================================

14.1 Resolve the executable law before RTL [S28,S29]

The GEOM.LIGHT contract identifies an exact existing shade law, but its inspected
entry point still takes a triangle rather than an already produced normal.
First do the golden-pinned reference refactor into a shared normal-based
primitive, with the original triangle function as a wrapper. Do not write a new
oracle and compare it against an RTL implementation of the same invented law.
Do not adopt the older normal-map report's approximate rsqrt/NR proposal as
though it superseded the later exact lighting contract.

Required behaviour includes independent-light clamping, moving lights,
ambient/spill, the selected additive-emission feature, fog ordering, strongest-
four selection where ruled, terrain base lighting and detail response. Record
all selected features in the accounting profile, including their interpolation
and storage cost. Emission zero is an exact off switch, not implicit permission
to cut emission from the required product to make the budget look healthy.

14.2 Reuse what is actually light-independent

Compute a skinned world normal and its exact magnitude once per vertex, not once
per light. Compute fixed light vectors/colours/configuration tables once per
epoch. Reuse the same Lambert/attenuation response for gain and additive emission;
only the colour application differs. Keep independent lights' negative terms
from subtracting other lights' illumination: clamp each light's(raw+detail)
before accumulating its colour. Saturate the aggregate where the law says,
not after every contribution.

For epoch-constant sun vectors, use section6.5 coefficient tables to evaluate
the normal dot product without runtime hard multipliers. Normal magnitude is
still the exact shared producer result. The subsequent exact signed quotient
can use a local pipelined or interleaved divide service whose capacity is counted
across every selected light. A service interface is not a zero-cost divide.

For point lights, distinguish per-frame/per-instance terms from genuine
per-vertex terms. Full raw-product identities such as
N·(L-V)=N·L-N·V and |L-V|²=|L|²+|V|²-2L·V can expose reuse, but ONLY if the
ratified code has no intervening saturation/rounding/normalization that the
transformation crosses. Treat them as candidate factorizations requiring a
source-level proof and oracle differential, not as approved substitutions.

14.3 Colour and detail arithmetic belong in bounded tables where possible

Unsigned8-bit colour applications use quarter-square lanes. Wider intensity or
signed emission needs its own range proof; do not force every gain into8 bits
if the additive law intentionally exceeds unity. For a fixed per-epoch light
coefficient, byte tables offer exact products without reducing the coefficient's
precision. Share tables and response terms only where their epoch/source identity
is the same.

The chosen normal-detail store is a resident tiling64x64x16 tile. Its physical
memory ports, both views, mip/UV mapping and update rules must be counted. It
avoids an extra TMU lookup, but is not free M10K. A signed detail component8
multiplied by fixed sun direction/strength is an excellent small coefficient-
table candidate. Preserve the exact per-light detail sign and clamp, and do not
fold all suns into one coefficient before a nonlinear per-light clamp.

14.4 Vertex fog factor can use four coefficient memories, zero DSP

The current factor uses dist=far-w and epoch-constant k. For signed32far and
unsigned31w, dist fits signed33. Precompute T[d]=k*d for unsigned8-bit d;
each table entry fits signed40 bits. Reconstruct the product from the four low
bytes of dist and subtract(k<<32) when its sign bit32 is1. This is exact for the
entire port range, not just plausible fog distances. Four one-read256x40SDP
copies are the initial four-M10K candidate for one factor/clock. [S09]

Keep far<=near/disabled/behind cases CLEAR, use the original+32768 then>>>16,
and clamp to[0,65536] at the original point. Capture or version the configuration
with the vertex. The configured reciprocal k is produced once per epoch by an
existing properly counted provider or a bounded setup routine; do not add a
per-vertex reciprocal here.

14.5 Lighting must earn its reserved allocation

The 79-DSP design subtotal intentionally has a remaining 15-block pool. Price a
complete lighting service with representative and worst admitted lights,
normal inputs, exact roots/divides, selection logic, gain/emission and detail.
Measure accepted vertices*lights and service demand across all clients. Four
lights times120,000vertices is480,000 evaluations before terrain or other modes;
that multiplication belongs in the calendar before choosing a serial core.

If the proposed local lighting service exceeds its pool, do not suppress the
row. Use the extra priced shell-colour ROM savings, a larger share of BRAM for
fixed-coefficient arithmetic, or a different tested provider schedule. Unknown
lighting throughput or area prevents the global 94-DSP acceptance verdict.

15. FIELD AND THE REST OF THE MACHINE: COMPLETE THE COVERAGE, DO NOT BILL GHOSTS
================================================================================

15.1 FIELD's shared providers stay shared [S30]

FIELD V3's multiplier bank has four physical wide lanes. Long-op LEN, curve,
rotation/noise/normalize/spline paths may request those lanes through ports;
follow the actual provider interface before assigning DSP to each caller.
Conversely, a service containing an additional multiply/divide of its own must
be counted separately. Provider edges are not necessarily module-instance edges.

Keep the four-lane12-DSP allocation as the default rescue plan. The existing
FIELD throughput is not generously over-provisioned, so reducing it to one lane
because a pose decoder can tolerate serialization is not justified. Qualify the
complete representative FIELD programs, including rival-service refusal,
writeback conflicts, square-root bank occupancy and admission reserve. A scalar
microbenchmark of one multiply says nothing about a vector program deadline.

15.2 RF memory needs production parameters, not scalar-probe optimism

The inspected FIELD RF has four register-residue banks and three read copies.
Its stored width is32*LANES, not always32. AtLANES4 a 128-bit word needs four
256x40SDP width slices before other constraints; four banks*three copies*four
slices is a 48-M10K first geometry estimate, not the scalar twelve-block result.
Actual depth/contexts and map reports decide the final count.

The three copies support real simultaneous operands and residue crossing. Do
not remove them without a new read-port schedule and throughput proof. Already
inferred RAM is not a new thousands-of-FF opportunity. Inspect which active
records still live in logic, move those cold records if beneficial, and retain
the minimum genuinely necessary multiport storage.

Root/sine/coefficient memories must have explicit external provider ownership,
initialization and collision rules. A folded root engine can store cold contexts
in RAM while keeping its current remainder in registers. RAM cannot perform
several independent recurrence updates through one write port per cycle unless
the schedule accounts for them.

15.3 Command/memory/video/audio/input

Do not rewrite these to chase DSPs they do not use. Reconcile them through the
actual shell hierarchy and any separately selected external roots. Address
ALM-heavy queues with the successful texture discipline: bounded RAM payload,
small local pointers, synchronous read, whole-record hold, no duplicate
production shadows. Preserve crossing-domain FIFO primitives and synchronizers.
Never replace a CDC FIFO with a single-clock SRAM wrapper to reduce its count.

FRAMECTL/scanout/framebuffer residency, SDRAM burst packing, command framing,
write-data reservation, CRC/counter crossings and arbitration remain functional
requirements. Moving descriptors into SDRAM may increase traffic on the very
arbiter whose bandwidth is already reserved. A resource reduction that causes
scanout starvation is not accepted. Payload depths may only be reduced from
observed/proved occupancy plus required burst reserve, not from a quiet demo.

15.4 Geometry memory/front-end/clip/setup

GEOM.PARAMBUF is currently a record decoder/validator, not a giant on-chip
vertex arena. Its projected-vertex, triangle and chunk layouts describe local
SDRAM records. Do not claim to save megabytes of BRAM by "moving PARAMBUF to
SDRAM" when the architecture already does that. The actual work is the allocator,
quota seal, burst frontend, small on-chip working cache and correct record
extensions for fog/emission. [S24b]

Preserve malformed-coordinate rejection, vertex-count bounds, frame-generation
checks and null chunk rules. Byte enables and record packing must match the
physical memory frontend. Dead old source fields are not permission to break an
external record ABI without its producer/consumer adapter and golden tests.

SETUP's geometric edge terms are the correct provider candidate for section12's
attribute-coefficient table. CLIP, perspective projection and normal lighting
must agree about behind-eye terminal records and newly generated vertices. Clip-
generated attributes need the same selected arithmetic law as original vertices;
they are not a free exception to the setup/lighting bill.

15.5 Particles, forge, surface, compositing and 2D

Enumerate each selected particle expansion/record/soft-fade, forge primitive/
cliff, surface sheet/stamp, gather and2D plane/sprite function. Classify products
as per-frame/per-command/per-vertex/per-pixel, constant coefficient or dynamic,
and already shared versus private. Most bounded colour/coverage products are
candidates for section6.1; coordinate squares and nonlinear effects need the
wide-domain/byte-partial or exact recurrence rules instead.

Keep already optimized SURFACE.STAMP rather than budgeting its historical
28-DSP predecessor. Do not equate a function's absence from the old full-fit
ledger with absence of its MapOnly evidence. Do not add the old FIELD reference
or geometry probe wrappers into this bill to "be conservative"; conservatism
means explicit unknown current costs, not counting mutually exclusive designs.

Unpriced required functions in these categories must get rows before the final
allocation is accepted. The 15-DSP remainder is not a claim that all these rows
sum to two; it is a cap that forces the full functional selection to be made and
measured before closure.

15.6 Source/function coverage report required from the agent

Output a table covering EVERY selected root and EVERY external arithmetic
provider, including zero-DSP leaves. Columns:

  physical owner | selected version/parameters | current evidence | call rate |
  external providers | DSP | ALM | M10K ports/copies | remaining action.

Every omitted mandatory feature is an error. Every deliberately excluded
reference/probe/version has a reason. A missing fit target is a measurement-
setup task, not proof the module has never been measured by another runner.
A proposed product profile is not a claim the runtime now composes those blocks.

This review examined the dominant arithmetic implementations and their
contracts, the actual texture path, the production accounting structure, the
separate ledgers, and selected memory/service consumers. It did NOT physically
synthesize every repository module. The coverage table is a required completion
artifact precisely because a whole-machine verdict cannot come from another
shortlist of expensive blocks alone.


16. GLOBAL ALM, MEMORY AND BANDWIDTH ACCEPTANCE
================================================================================

16.1 The objective is a Pareto improvement in the constrained machine

Do not force every local experiment to reduce every metric. A culler can spend
M10K to removeDSP while the shared projector removes bothALM andDSP. But the
COMPLETE accepted portfolio must meet all hard resource limits, the owner’s
reserve and clock/workload targets. Every local increase needs a named global
budget allocation, not "memory is cheap" or "the fitter will sort it out".

Keep two kinds of ALM evidence:

  structural: named registers/muxes/arrays/comparators removed; inferred RAM;
  physical: matched map and fitted ALM/MLAB/register/timing measurements.

A declared4,096-bit array is not necessarily4,096fabric registers. An array
whose last consumer was removed may already have vanished. Conversely, one
synthesized diagnostic comparator can keep an entire obsolete reference table
alive. Inspect the mapped entity/logic cone. No source line-count or register-
bit-to-ALM exchange formula is an adequate replacement.

16.2 Memory planning ledger: examples, NOT a claim that everything fits

These counts depend on the exact ports and selected modes described earlier.
They exclude many existing RAM users and are not an additive "spare memory"
claim. Use the native geometry table [V01], not simply ceil(logicalbits/10240).

In particular, choosing whole-patch ping-pong, fully pipelined attribute DA,
pipelined culling and every replicated vector bank can exhaust553 M10Ks. The
small subpatch cache and folded attribute profile exist to avoid that. The
projection fast backend keeps the nine-DSP target when the smaller cache no
longer permits a three-clock projection schedule.

16.3 Where ALM is expected to fall, and how to test that expectation

A. One projection service replaces two: fewer wide row/output datapaths and
   fewer exact divider lanes. In BackendA, six old divider lanes become one;
   in BackendB, six become three. Cold riders/results move to RAM.
B. Pose uses one product/accumulator worker instead of separate quaternion and
   three-term matrix farms; matrices/scratch stay in RAM.
C. Position/normal share coefficient fetch rather than duplicating large bone
   matrices in every active record. Proven widths remove unnecessarily wide
   normal products and comparator trees.
D. Bake removes1,089-per-vertex square work, two lattice multiplies and packed
   resettable meets state in favour of tiny square/row memories and DDA.
E. Attribute setup reuses geometric coefficients, then coefficient ROMs replace
   wide multiplier farms. The selected recurrence keeps active state local.
F. Production retains no migration shadow datapaths. Debug evidence is provided
   by simulation/trace reads or a separate lab image, not a permanent second
   machine.

Each statement is an architectural mechanism, not an ALM magnitude prediction.
Before integration, record the old hierarchy entities expected to disappear and
the replacement entities expected to appear. After map, reconcile them. If the
old large arrays remain, the packet is not decrufted regardless of green tests.

16.4 Keep physical timing honest

Report setup, hold, recovery/removal and relevant I/O/domain constraints, not
only a selected internal-onlyFmax. Port-heavy characterization can distort
headlineFmax; deleting inconvenient boundary paths is not timing closure.
Use registered production-shaped wrappers for new services and then fit their
real neighbour seams. Preserve the actual board/framework clock obligations.

Inspect whether the dominant path is logic delay, interconnect, fanout or memory
access before choosing the next change. The old owner-to-RCP family was largely
wire delay and its credit flag was already registered. Do not add a redundant
flag or rewrite a correct counter because of a misleading node name.

16.5 Deadline acceptance is per shared physical resource

For each provider define job types, work per job, worst admitted arrival burst,
queue capacity, arbitration, initiation interval, latency, configured epochs and
client deadline. Measure wall-clock frame completion with the entire selected
workload, not the sum of isolated perfect-service rates.

Include view duplication, top/underside terrain, stitch/morph work, cache misses,
pose cold starts, point-light changes, beam/particle bursts, material sample
counts, memory refills, tile conflicts and scanout reserve. If capacity caps are
not intended to occur together, encode the actual admission/governor rule that
prevents it. An unenforced sentence saying "unlikely to coincide" is not a
hardware budget.

Do not lower the 100 MHz target to justify slow arithmetic, or remove the 20%
working reserve from a scheduling calculation merely because it was close.
Where 20% was a proposed planning reserve rather than a frozen rule, label it as
such and use the real ratified admission budget for acceptance.


17. FIT-SPARSE EXECUTION AND RUN SURVIVAL
================================================================================

17.1 Spend expensive fits on decisions

Stage0: source/range/protocol checks and simulation.
Stage1: small exact-tool mapping experiments for inference/ports/DSP structure.
Stage2: one production-shaped subsystem candidate that passed the cheap gates.
Stage3: a meaningful integrated milestone and final closure seeds/settings.

Do not full-fit every ROM lane, every arithmetic identity and every documentation
correction. Do not rerun the lost D0 attribution fit: its correctness is tested,
and its physical effect belongs in the next legitimate texture checkpoint.
Do not run forty long leaf fits to build a DSP bill when MapOnly can answer the
specific resource question and the existing ledger already has relevant data.

A no-target block needs a complete source closure and selected parameters before
mapping. Generate that from the existing graph/tooling, inspect it, and register
it in the proper target file. That is necessary measurement preparation, not an
invitation to author an elaborate new synthesis orchestration framework.

17.2 Minimum mapping experiments worth doing

Q:512x16dual-read quarter-square, including boot/MIF and real output hold.
H:one full-s32 hybrid coefficient multiply with matched native reference.
V:viewport/fog table profiles and their actual port replication.
A:production-depth vertex arena, both views and real read/write schedule.
C:one cull DA stage with production coefficients, then selected complete profile.
S:position/normal two-lane front and exact square/root capacity.
P:one selected attribute-table/seed profile.
B:bake square tables+shared worker;terrain LOD byte worker.

These are microarchitecture questions. Keep a bad map result with its specimen
and explain why the candidate was rejected. Do not start a full fit of a design
whose map still contains the very DSP farm it was supposed to delete.

17.3 Small run-discipline fix; no monitoring project

Use an isolated immutable worktree/staging directory per long specimen. Keep
logs/results outside a source directory that normal editing/pulling rewrites.
Record UTC start time, local time, unique run ID, parent wrapperPID, actual
Quartus stagePIDs, tool/device, selected top/parameters, source/config digests,
free disk at start, and planned result directory BEFORE launch.

A queue waits for a SPECIFIC predecessor's terminal marker, not just a moment
when no quartus_fit process happens to exist between compile stages. One shared
lock covers map,fit,STA and receipt collection. A waiting shell is allowed;
two contenders releasing from the same generic-idle condition are not a queue.
Do not stop a valid fit simply to simplify the shell list.

On completion or failure write an atomic terminal status, final byte hashes,
exit code, final stage, elapsed WALL time and available logs. Preserve any valid
completed stage separately. A sum of elapsed durations for overlapping jobs is
not CPU-hours and is not wall-clock time lost. Record the actual reason for a
termination when known; external stop without attribution remains unknown.

Do not assume a frozen source digest proves no restart occurred: runID/start
receipt/process identity do. This avoids the earlier habit of inferring a launch
time or elapsed duration too precisely from commit timestamps.

17.4 Full-fit milestones after current texture work

F1:accepted memory-colour/vertex-fog subsystem checkpoint, with real neighbours.
F2:projection cache+chosen shared service+canonical-depth/epoch transport.
F3:pose/position/normal/cull/attribute composition after local maps are accepted.
F4:terrain maintenance integration under the existing queued terrain plan.
F5:actual selected console/resource profile, then constrained functional console.

Combine milestones when a larger coherent checkpoint is ready; do not serialize
development behind every fit. The sequence is a ceiling on redundant experiments,
not a promise that exactly five fits can settle every unexpected timing failure.
Additional fits require a named unanswered decision and a falsifiable expected
structural change. Purely cosmetic edits do not earn another full run.

Do not implement every speculative fallback. Choose between BackendA/B and
folded/pipelined DA profiles from demand+map evidence, then fit the coherent
portfolio. Otherwise branch combinatorics can consume more time than Quartus.

19. ACCEPTANCE, REJECTION AND WHAT MUST NOT BE CLAIMED
================================================================================

19.1 A packet is complete only when all four accounting questions are answered

  What existing physical structure was removed?
  What replaced it, including memory ports/control?
  Which selected functional/protocol behaviour stayed exact?
  What does the appropriate physical/workload measurement actually show?

A new candidate beside an old active structure is development, not yet a saving.
A removed source field whose old hardware was already optimized away has no
extra credited saving. A new table that maps into fabric rather than M10K has
not met the memory-first objective. A held reply whose tag/epoch can advance
independently is a correctness failure even when counters conserve traffic.

19.2 Final product gate

  physical DSP blocks <=94;
  full selected profile, including new mandatory functions and providers;
  ALMs, registers, MLAB/M10K and external bandwidth within actual product budgets;
  100MHz/relevant domain timing closed under actual constraints;
  all mandatory frame/deadline/admission profiles and reserve satisfied;
  no unknown required cost, unresolved skipped pipeline or unsupported feature;
  source identity and parameterization reproducible;
  current functional references and adversarial tests passed.

An informative partial report can be useful without any of these final claims.
Do not label a row "green machine" when its source list contains probes or its
consumer is not built. Do not discard dirty historical counts as zeros. Do not
turn a failing hardware gate into a documentary permission to ship it.

19.3 Explicit non-solutions

* More investors or a larger FPGA are not this brief's rescue mechanism.
* Global multstyle=logic is not an ALM-aware design.
* Arbitrarily reducing matrix width, world range, normal precision or colour bits
  is not a bit-exact implementation optimization.
* Serializing a saturated shared provider is not a throughput-preserving saving.
* A monolithic table for arbitrary 32x32 multiplication is not feasible here;
  the hybrid/coefficient/partial-product designs deliberately avoid that.
* Running every block's best isolated settings at once does not prove the
  integrated console can meet those settings.
* Deleting the oracle during migration does not make a smaller production build
  more correct. Keep reference sources out of the synthesized shipping closure.
* Passing a small/different-parameter test does not qualify the selected profile.
* Printing a detector is not asserting it; asserting zero without proving traffic
  reached it is not evidence; a self-test that duplicates the implementation's
  mistake is not an independent control.

19.4 When a proposed architecture fails

Keep the valid arithmetic derivation and the failed physical receipt. Diagnose
whether the failure is mapping, ports, interconnect, latency, workload or lost
semantic identity. Choose the listed alternative profile where it addresses
that cause. Do not respond to every failure with a full-island rewrite or by
inventing a new subsystem around the existing bloated one.

If the admitted complete workload and minimum verified implementations cannot
fit94 DSP and the ALM/memory/timing budgets simultaneously, document the exact
constraint conflict and the alternatives. That conclusion requires real complete
evidence; it cannot be inferred from today's mixed-vintage subtotal. Conversely,
a plausible79+15allocation is not proof that such a conflict has been solved.

22. COMPANION CHECKS: WHAT WAS EXECUTED AND WHAT WAS NOT
================================================================================

The ZIP contains standard-library Python checks runnable without network access:

  python checks/check_arithmetic.py --output arithmetic_results.json
  python checks/check_accounting.py --output accounting_results.json

Run without Python's -O option: assertions are load-bearing. The committed
agent implementation still needs its own RTL tests, mutant controls and mappings.
The scripts here are deliberately independent integer/address/acceptance models,
not a replacement HDL simulator, an inferred netlist or the repository census.

Arithmetic groups cover:
  exhaustive byte quarter-square identity and a corrupted-table counterexample;
  exact bilinear intermediates and an early-rounding counterexample;
  signed fog products and negative rounding;
  full signed-32-bit hybrid products, corners and deterministic random values;
  viewport and signed-33-bit fog coefficient-table reconstruction;
  signed coefficient distributed arithmetic for culling, planes and seeds;
  normal-vector width/reduction/squaring and a negative-boundary counterexample;
  negative-span DDA and separable terrain squares;
  bake endpoint rounding/telescoping and invalid fusion counterexamples;
  exact constant-nine/eleven nibble division;
  arena address-stride counterexample and corrected non-power-of-two layouts;
  workload calendar arithmetic, explicitly NOT observed hardware throughput;
  co-packed three-read memory geometry and identity/collision address checks.

Accounting fixtures check seventeen small acceptance cases: inclusive parent/
child overlap, duplicate physical paths, unknown required cost, wrong units,
wrong parameters/source identity, stale evidence, missing required lighting and
external providers, two real instances versus two clients of one provider,
map-versus-fit scope, retained failed policy, the hard <=94 cap, identifiable
immutable dirty specimens and selected labelled evidence. These fixtures do not
exercise the current repository loader: port them to its ACTUAL loading/selection
path and mutation-test that path, as section 2 requires.

The included JSON reports record deterministic counts and counterexamples, the
executed script hash, and per-group pass status. Runtime seconds are diagnostics,
not performance benchmarks. Re-running in a clean directory is recorded in the
package's reproducibility report. The checks do not establish the claimed DSP
packing, memory inference, ALM costs, output rate or final console closure.

A failed independent arithmetic check is a reason not to implement that formula.
A passed independent arithmetic check is permission to test an implementation,
not a claim that one already exists or that Quartus will implement it cheaply.
